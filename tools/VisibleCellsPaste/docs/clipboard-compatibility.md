# 클립보드 읽기와 호환성

상태: 0.1.0 구조화 XML과 제한적 Biff12 날짜 숫자 보완. 실제 Ctrl+C의 결과는 [시험 보고서](test-report.md)에 별도 기록합니다.

## 선택한 데이터 계약

원본을 다시 읽거나 사용자 문서에 임시 붙여넣기 하지 않고 Windows 클립보드에서 스냅샷을 확보합니다. 형식 이름, sequence, 행·열 개수, 구조 확정 여부, 타입별 항목 및 형식 근거를 묶습니다. 실제 빈칸은 Empty 한 항목이며 String의 빈 문자열과 구분합니다. Number·Boolean·Error·String을 서로 추측 변환하지 않습니다.

기본 형식은 Excel의 등록 형식 XML Spreadsheet입니다. DateTime 위치에 원래 숫자가 없으면 같은 sequence의 Biff12에서 원시 숫자를 보완하며 XML의 나머지 모든 항목과 좌표·타입·값이 일치해야 합니다. HTML/TSV로 자동 강등하지 않습니다. 구조화 형식 또는 타입·모양 증거가 부족하면 0개 수정으로 중단합니다. 한 행/한 열/단일 셀만 허용하고 2차원 표는 펼치지 않습니다.

| 범주 | 읽기·보존 기준 | 실제 검증 상태 |
|---|---|---|
| Number | 표시 문자열이 아닌 실제 숫자. 날짜는 원시 숫자 계약 | D17/D18 PASS: 실제 날짜/시간/백분율·1900/1904·필터·빈칸 표본. D10은 별도 |
| String | 앞자리 0·긴 ID·공백·개행·탭·수식처럼 보이는 문자 그대로 | D09/D11/D14 |

## 파서 방어

32 MiB 총 페이로드·50,000항목·차원/확장 인덱스 한도를 할당 전에 확인합니다. Biff12 ZIP은 압축 전후 길이·CRC·항목 수·파일 경로·중복 항목·관계와 레코드 경계를 별도로 제한합니다. 허용된 내부 데이터만 메모리에서 읽고 매크로·수식 토큰·외부 관계를 실행하지 않습니다. 선언된 거대 차원을 그대로 배열 크기로 사용하지 않습니다. DTD·외부 엔터티·네트워크·스크립트를 허용하지 않습니다. 오류는 사용자 셀 쓰기 전에 격리합니다. XML 자료형을 현재 로캘로 바꾸지 않고 Trim·빈 줄 삭제·마지막 개행 제거로 개수를 맞추지 않습니다.

클립보드 읽기 전후 sequence를 비교하고 점유·변경에는 제한된 재시도만 합니다. 현재 클립보드를 비우거나 교체하지 않습니다. 정상 스냅샷 뒤 다른 앱이 새로 복사한 데이터를 오래된 내용으로 복원하지 않습니다.

## 필수 M0 표본

실제 Excel 셀에 85 / 문자열 00123 / 빈칸 / 한글 및 셀 내부 줄바꿈 / 마지막 빈칸을 만들고 실제 Ctrl+C로 복사합니다. 같은 파일, 다른 파일, 독립 Excel 프로세스를 구분합니다. 형식 이름과 synthetic fixture의 타입·수·순서만 기록하며 실제 사용자 클립보드 덤프는 수집하지 않습니다.

외부 시험 코드가 XML 문자열을 클립보드에 넣은 시험은 파서 시험이며 Excel Ctrl+C 증거가 아닙니다. Excel Range.Copy COM 호출은 별도 자동화 시험이며 실제 사용자 Ctrl+C/UI 시험과 구분합니다. 자동 로드가 차단된 환경에서 별도 시험 assembly를 로드해 데이터를 읽어도 제품 설치·자동 시작 통과로 기록하지 않습니다.

## 복사 출처와 잘라내기 구분

현재 구현은 클립보드 소유 창의 PID가 EXCEL인지 확인하고 해당 프로세스의 CutCopyMode=1을 요구합니다. 같은 프로세스는 연결된 Application의 모드, 다른 프로세스는 그 소유 PID로 제한된 Excel native object model에서 모드만 읽습니다. 원본 셀 내용·활성 범위를 다시 읽지 않습니다. 모드가 2이거나 Preferred DropEffect에 이동 표시가 있으면 거절합니다. 출처·모드를 확인할 수 없으면 거절하므로 원본 Excel을 열어 둔 상태에서 Ctrl+C한 입력이 필요합니다. 이는 원본이 닫힌 뒤 남아 있는 클립보드를 항상 지원한다는 계약이 아닙니다.

## 실제 날짜 표본

1900·1904 원본 각각의 세로 복사에서 Empty/45200/0.5/0.125/Empty/45500.75/Empty를 확인했습니다. 필터 복사에서는45200/Empty/45203,1900 날짜 경계에서는59/60/61을 원시 숫자로 확인했습니다. 가로45200/0.5/0.125 및 숫자85를00085로 표시한 표본까지 총7개에서 독립 디코더와 제품 파서 결과가 일치했습니다.

설치된 메뉴로1900 원본의 날짜·시간·백분율45200/0.5/0.125를1904 대상의 가시E2/E5/E8에 붙여넣어 raw숫자가 그대로 유지됨을 확인했습니다. 대상0.0000 표시형식과숨긴E3/E4/E6/E7을보존했고자체Undo로원래값을복구했습니다. 달력 날짜를 같게 만들기 위한1462일 보정은 수행하지 않습니다. 이결과는실제시험한Office빌드와표본에한정합니다.

## 읽기 경합의 실제 시험

다른 시험 프로세스의 메시지 전용 창이 OpenClipboard를 소유한 상태를 PID로 확인한 뒤 제품의 형식 읽기와 형식 열거를 실행했습니다. 각각 VCP-CLIPBOARD-BUSY로 약126/121ms에 중단했고 sequence·소유자·포맷 목록이 동일했습니다. 이 시험은 데이터를 비우거나 교체하지 않았습니다. 읽는 중 새 복사로 내용이 교체되는 경우의 실제 통합 시험과 구분합니다.

## 남는 호환성 제한

모든 Excel 버전이 같은 형식·차원·타입 메타데이터를 제공한다고 가정하지 않습니다. 현재 파서는 XML DateTime만으로 숫자를 추정하지 않습니다. 검증된 Biff12 보완 자료가 있으면 원래 숫자를 쓰며 없거나 두 형식이 일치하지 않으면 0개 수정으로 거절합니다. 실제 날짜·시간·다른 날짜 체계 시험 범위는 D17/D18에 기록합니다. 오류 값은 #NULL!, #DIV/0!, #VALUE!, #REF!, #NAME?, #NUM!, #N/A, #GETTING_DATA를 해석하며 #SPILL!·#CALC! 등의 새로운 오류는 거절합니다. 1900/1904 원본 날짜 체계 추정과 자동 보정은 하지 않습니다. 빈 문자열 결과의 상수 저장 구별과 별도 프로세스 잘라내기 식별은 실제 결과를 확인한 범위만 설명합니다. 확정 못한 입력을 일반 텍스트로 추정해서 쓰지 않는 것이 현재 정책입니다.

별도 연구에서는 실제 BIFF8 표본의 RK 레코드에 원래 숫자45200이 있음을 확인했습니다. 따라서 모든 클립보드 형식에 원시 값이 없다고 주장하지 않습니다. XML/HTML 표본에는 없었으며, BIFF8/CFB 제품 어댑터는 도입하지 않았습니다. 0.1.0은 별도 Biff12 ZIP의 제한적 날짜 보완 경로를 사용합니다. [native 형식 조사](native-format-research.md)에 연구 범위와 미완료 조건을 기록했습니다.
