# 구조와 실행 경계

상태: 2026-09-26 후속 DLL `7080305a…`의 실제 설치·자동 로드·붙여넣기 및 Undo 후 두 UI 종료 PASS. 자동 검사 284개·실제 회귀 60개·R17도 통과했습니다. 이전 `8741b19f…` 종료 FAIL은 보존하며 동일 DLL의 제거·재설치·실제 숨김 값 보존도 확인했습니다. 배포 판정은 시험 보고서·외부 기록을 따릅니다. [시험 보고서](test-report.md) 참조
저장소 근거: docs/tools/visible-cells-paste/original-specification.md, docs/design/0010-visible-cells-paste-com.md. 이 개발 원본은 배포 ZIP의 실행 의존성이 아닙니다.

## 구성

| 경로 | 책임 |
|---|---|
| src/addin | COM 연결·정상 시작·고유 우클릭 메뉴·현재 Excel 이벤트·명령 재진입 방지 |
| src/clipboard | Win32 클립보드 한정 읽기·sequence 검사·불변 타입 스냅샷·엄격한 XML 파싱·한정된 Biff12 날짜 숫자 보완 |
| src/core | 셀 타입·제한·정렬된 대상 계획·개수 일치·확인 사유. Excel 없이 시험 |
| src/excel | 현재 선택 확보·지원 제외 검사·백업·연속 구간 쓰기·검증·전역 상태 복원 |
| src/undo | 최근 성공 한 번·실패 복구·충돌 판단·복구 미완료 잠금 |
| installer / build | 일반 사용자 소유 등록·정상 종료 요구·재현 제작·패키지 해시 |
| tests | 합성 fixture·순수 로직·실제 Excel·실패 주입. 사용자 배포와 시험 전용 기능 분리 |

COM 추가 기능은 연결받은 Application만 사용합니다. 복사 원본을 현재 활성 Range로 다시 읽지 않습니다. 값 쓰기 COM 접근은 Excel의 실행 스레드에서 수행하며 Excel 객체를 병렬 수정하지 않습니다. 메뉴 표시와 연결만으로 사용자 셀·클립보드를 스캔하지 않습니다.

## 상태 전이

Idle → Snapshot → Validate·최초 Backup → Confirm(필요할 때) → Revalidate·Backup 갱신 → Apply → Verify → CommitUndo → Completed.

쓰기 전 실패·취소는 0개 수정입니다. 쓰기 이후 실패·취소는 Rollback → VerifyRollback으로 갑니다. 복구 확인 실패는 RecoveryRequired이며 성공 메시지를 내보내지 않고 후속 쓰기를 차단합니다. COM 호출 하나가 부분적으로 쓴 뒤 실패할 수 있으므로 마지막 성공 구간만 복구 대상으로 삼지 않습니다.

## 경계 보존

현재 단일 워크시트의 유한한 연속 한 열 선택을 캡처하고 CountLarge 한도를 먼저 확인합니다. SpecialCells 결과는 원래 선택과 교차합니다. 숨김 행·열을 재확인하고 실제 행 번호로 정렬하며 중복·다른 시트·선택 밖 주소를 거절합니다. 확인 창 뒤에 객체·주소·가시 상태를 다시 검증합니다.

원본과 대상 개수는 정확히 같아야 합니다. 실제 빈칸도 개수에 포함합니다. 표 열 검사는 보이는 대상만 보지 않고 같은 표 열의 숨김/비선택 행 수식을 포함합니다. 대량 제한에 걸리는 전체 열 선택을 UsedRange로 줄여 허용하지 않습니다.

## 쓰기와 복구

전체 대상의 원래 상수 타입·값, 실제 빈칸 여부, Formula2/Formula 종류와 표현, 변경 가능한 표시 형식을 메모리에 보관합니다. 빈 원본은 Value2=null로 내용만 지웁니다. 실제 Excel probe에서 상수·수식 제거와 기존 표시 형식 보존을 확인했으며, ClearContents가 만들던 기본 Undo 기록을 피합니다. 문자열은 수식으로 실행되지 않게 쓰고 타입·HasFormula·형식을 다시 확인합니다. 다중 영역 전체에 배열을 한 번에 대입하지 않습니다.

연속 대상은 타입·수식 속성·형식이 같을 때 구간으로 읽고 씁니다. 혼합 상태는 개별 셀로 확인하며 배열/병합/spill처럼 안전 여부를 확정 못하는 혼합 플래그는 거절합니다. 검증 규칙은 원래 선택에 대해 SpecialCells를 한 번 조회하고 그 결과를 가시 대상 전체와 다시 교차합니다. 단일 셀 SpecialCells가 선택 밖까지 확장하는 경우와 숨긴 셀에만 규칙이 있는 경우를 각각 검사합니다. 이는 외부 COM 시험의 호출 수를 줄인 구현이며 설치된 추가 기능의 속도 보장이 아닙니다.

EnableEvents, ScreenUpdating, Calculation, StatusBar 등 실제 변경한 전역 속성은 시작값을 보관하고 모든 종료 경로에서 그 값으로 복원합니다. 시작값 getter는 쓰기 잠금을 설정하기 전에 모두 읽으므로 여기서 실패해도 셀·전역 상태를 변경하거나 busy를 남기지 않습니다. 상태 복원 실패도 성공과 구분합니다. 계산 결과가 바뀔 수 있는 의존 수식은 정의·서식을 직접 바꾸지 않는 한 숨긴 셀 보존 계약의 위반으로 보지 않습니다.

StatusBar 복원은 공용 함수로 처리합니다. 저장값을 그대로 할당하되 COM의 저장값이 Boolean false이면 실제 반환 타입·값을 확인합니다. 현재 Excel에서 false 할당이 문자열 FALSE로 남는 경우가 관찰돼, 이때만 확인된 빈 문자열 reset을 적용하고 Boolean false인지 다시 검사합니다. 실제 문자열은 변환하지 않으며 확인 실패는 state-restore-failed로 후속 쓰기를 차단합니다. 시작값 getter가 실패한 경우와 복원 setter·검증이 실패한 경우는 구분합니다.

스냅샷·백업은 기본 경로에서 디스크에 저장하지 않습니다. 사용자 시트에 숨김 백업·이름·주석을 추가하지 않습니다. 실패 주입은 시험 빌드에서만 제공합니다. 외부 통신·Evaluate·원본 자동 저장·원본 새로 고침·전역 키 바인딩 변경을 사용하지 않습니다.

## 날짜 숫자 보완

XML Spreadsheet가 원시 숫자 대신 DateTime을 제공하면 같은 클립보드 sequence의 Biff12를 제한적으로 읽습니다. ZIP 크기·압축 해제 합계·CRC·경로·관계 파일·레코드 길이·좌표를 검증하고, XML과 native의 모든 비날짜 위치·타입·값이 일치할 때만 날짜 위치를 원시 Number로 보완합니다. 날짜 문자열을 파싱하여 숫자를 재계산하지 않으며 1900/1904 체계 사이의 달력 보정도 하지 않습니다. 원본 통합문서를 열거나 셀을 다시 읽지 않습니다. 지원을 확정하지 못하면 쓰기 전에 중단합니다.

## 연결 종료 정리

상태바 복원 중 COM 객체가 이미 사라져도 타이머·관찰자·보유 참조를 finally에서 정리합니다. 완료 후 안내의 상태바 복원 실패는 best effort 경계에서 처리하며 자기 상태 소유 표시는 finally에서 해제합니다. 그 밖의 예상하지 못한 오류도 나머지 정리를 생략하지 않습니다. COM 객체 식별 비교도 획득한 각 IUnknown 포인터를 획득 순서에 맞춰 finally에서 해제합니다. 연결/종료의 실제·순수 검증 범위는 시험 보고서에서 구분합니다.

성공 후 상태 표시줄 안내는 best effort입니다. 안내를 표시하는 COM 접근이 실패해도 이미 완료한 붙여넣기·Undo 결과를 “변경 없음”이나 실패로 바꾸지 않습니다. 이는 쓰기 중 전역 상태 복원 실패를 성공으로 처리하는 규칙이 아닙니다. 복구 진행 안내에서 오류가 나더라도 백업 복구를 생략하지 않습니다. 오류 안내는 현재 작업이 쓰기 전 중단됐는지, 검증된 복구를 마쳤는지, 확인이 필요한 상태인지를 구분합니다.

## 0.1.1 COM 참조 수명 수정

0.1.0 게시 후 실제 메뉴 사용과 Excel 종료를 결합한 합성 시나리오에서 3회 종료 실패를 확인했습니다. 당시 덤프에는 CLR RCW 정리 중 COM Release 호출 경로가 관찰됐습니다. 2026-09-26 초기 수정본의 두 UI 종료는 통과했지만 후속 후보 `8741b19f…`는 붙여넣기 성공 뒤 정상 종료에서 BEX64/c0000409가 재현됐습니다. 새 덤프가 없으므로 같은 스택·객체·원인이라고 단정하지 않습니다.

각 COM 참조를 얻은 범위와 반환 책임을 명시합니다. Ribbon callback 인자·연결 때 받은 추가 기능 인자는 해당 경로의 finally에서 한 번 반환합니다. OnConnection의 Application 인자 획득 한 번은 추가 기능이 소유하고 연결 정리의 마지막에 반환합니다. 엔진과 Undo 관찰자는 이를 빌리며 해제하지 않습니다. 같은 RCW를 다시 받더라도 실제 획득 횟수에 따라 정리합니다. IDTExtensibility2의 custom은 설치된 PIA와 동일한 [In] 참조 배열 계약을 사용합니다.

대기 작업은 취소·연결 해제·실행 실패 때 정리하며 엔진에 소유권을 넘긴 뒤 다시 해제하지 않습니다. PreparedPaste는 Workbook·Worksheet·Selection 참조의 수명을 소유하고, 임시 Range·Collection·열거자·스냅샷 읽기 참조는 획득 범위에서 반환합니다. 같은 작업이 재진입해 거절돼도 바깥 실행의 참조를 폐기하지 않습니다. 명령·확인창·쓰기·상태 타이머 callback 도중 연결 종료가 들어오면 새 작업과 안내를 막고 마지막 활성 callback이 끝날 때 타이머·pending·엔진·Application을 정리합니다.

Undo 이벤트는 ComEventsHelper 대신 전용 IDispatch sink로 연결합니다. callback의 DISPPARAMS·VARIANT를 읽거나 관리 객체로 바꾸지 않고 기존 14개 DISPID만 처리하므로 사용하지 않는 이벤트 인자를 RCW로 생성하지 않습니다. Cancel 인자에는 쓰지 않습니다. 자기 connection point 획득과 Advise cookie만 소유하고 Unadvise 실패에도 connection point를 반환하며, Dispose 뒤 늦은 이벤트는 무시합니다. 연결 불가 시 Available=false로 Undo를 제공하지 않습니다. 이 변경은 확인된 참조 경계를 줄인 보완이며 특정 이벤트 RCW가 종료 충돌 원인이었다는 결론이 아닙니다.

정상 값 쓰기·숨김 보존·백업·복구 정책은 유지합니다. 공유 Application을 작업마다 강제 해제하거나 FinalReleaseComObject·강제 GC로 소유권 관리를 대신하지 않습니다. 후속 결정은 ADR-0013과 시험 보고서에서 관리합니다. x64/x86 각각 36개 native 이벤트·수명 검사, 연결 46개, 안내/진입 26개 개별 통과는 실제 Excel 종료·32비트 Excel 실행 검증과 구분합니다. 후속 전체 빌드의 9종 284개와 실제 60개 회귀·wrapper의 파일/선택/전역 타입·값 복원, 생산 DLL의 R17 4종 거절은 통과했습니다. 외부 시험 엔진과 기존 설치 추가 기능이 공존한 60개 결과를 새 설치본의 자동 로드·종료 검증으로 확대하지 않습니다. 이후 같은 생산 DLL을 실제 설치한 두 정상 시작에서 메뉴 붙여넣기 및 별도 붙여넣기·Undo 뒤 UI로 닫고, 지연 관찰에서 프로세스 소멸과 새 Excel 오류·WER 없음도 확인했습니다. 외부 엔진 회귀와 설치된 추가 기능의 UI 결과를 각각 기록하며 모든 종료 조건이 해결됐다고 단정하지 않습니다. 동일 DLL의 제거 후 자체 메뉴 부재·다른 메뉴 유지, 재설치 후 자동 메뉴와 실제 붙여넣기도 확인했습니다. 붙여넣기 뒤에만 숨김을 풀어 숨긴 원래값 102/103/105/106이 유지됐음을 직접 확인했습니다. 재설치 사용 뒤 저장하지 않고 닫아 123초 후 프로세스 부재·새 Excel 오류/WER0·합성 파일 SHA 불변도 확인했습니다. 최종 문서 재포장·게시 근거는 별도 기록으로 연결합니다.

## 구현과 관찰의 구분

설계한 검사와 구현한 코드는 실제 Excel의 모든 동작을 증명하지 않습니다. XML 제공 여부, 끝 빈칸·빈 문자열, 별도 프로세스, 구조 변경, 기존 Undo 기록, 표 자동 채우기와 부분 실패는 실제 시험 결과로 제한합니다. 자동 로드 검증을 외부 시험 assembly의 직접 실행으로 대신하지 않습니다.
