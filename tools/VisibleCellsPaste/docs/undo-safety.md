# 최근 한 번 되돌리기의 안전 조건

상태: 0.1.0 보수적 Undo 구현. 실제 통과 항목은 [시험 보고서](test-report.md)의 U01–U17을 따릅니다.

## 사용자가 기대할 수 있는 범위

성공한 가장 최근 붙여넣기 한 번의 원래 값을 같은 Excel 프로세스 메모리에 보관합니다. 정상 실행 직후 원래 선택에서 자체 메뉴로 되돌립니다. 새 작업이 쓰기 전에 검증에서 중단되었다고 기존 기록을 무조건 지우지 않습니다. 파일을 닫거나 Excel을 다시 시작한 뒤 복구하는 영구 백업이 아닙니다.

복구는 실행 중 원래 Workbook·Worksheet 객체에만 연결합니다. 파일 이름·시트 이름·주소가 같다는 이유만으로 다른 객체를 찾지 않습니다. 다른 통합문서가 활성 상태면 이전 파일 뒤에서 수정하지 않고 원래 대상 파일 안내 또는 무효화 결과를 보여줍니다.

## 유효성 게이트

| 근거 | 거절 조건 |
|---|---|
| 이벤트 연결·감지 능력 | 구독 실패, 상태 조회 실패, 이벤트가 꺼진 채 시작하거나 Undo 시 꺼져 있음 |
| 편집 유효 기간 | 도구 소유 작업 외 SheetChange, 선택 변경, 시트·통합문서 전환, 구조·수명 이벤트 등 감지 |
| 원래 객체·이름·주소 | 닫힘/교체/이름 변경, 선택 또는 대상 절대 주소 변화 |
| 사후 상태 | 대상 전체의 값 종류·수식 여부·Formula 속성·표시 형식이 실행 직후와 불일치 |
| Excel Undo 상태 | 실행 직후 기본 Undo가 비활성인 기준만 허용. 활성·조회 불가 기준에서는 자체 Undo도 비활성화. 나중에 기본 Undo가 활성으로 바뀌면 거절 |
| 구조 안전성 | 현재 워크시트 또는 그 안의 표에 기존 SortFields가 하나라도 있거나 조회 실패면 최근 Undo를 제공하지 않음. 붙여넣기 뒤 정렬 설정이 생겨도 거절 |

선택을 바꾸는 것만으로도 기록을 무효화할 수 있는 의도적인 제한입니다. 즉시 되돌릴 때에도 우클릭이 실제 선택을 바꾸었다면 이전 선택을 강제로 복원하여 실행하지 않습니다. 사용자 편의를 위해 수명 조건을 느슨하게 만들지 않습니다.

현재 UndoEpoch는 SheetSelectionChange, SheetChange, SheetActivate/Deactivate, NewWorkbook, WorkbookOpen, WorkbookActivate/Deactivate, WorkbookBeforeClose, WorkbookBeforeSave, WorkbookNewSheet, WindowActivate/Deactivate, SheetBeforeDelete를 관찰합니다. 설치된 Excel 15.0 PIA에서 AppEvents IID와 DispId·서명을 확인하고 관찰자 파일의 .NET Framework 컴파일을 통과했습니다. 등록 성공과 실제 이벤트 발생은 별개이며 U03–U07/U13 시험 증거로 동작을 확정합니다. 이벤트 콜백은 Cancel 플래그나 Excel 전역 설정을 바꾸지 않습니다.

## 구조 변경 감지의 한계

값과 주소 비교만으로 같은 값 행의 이동을 알아낼 수 없습니다. SheetChange는 사용자나 외부 링크에 의한 셀 변경을 알리는 이벤트이며, Microsoft 문서는 모든 구조 변경이 반드시 이 이벤트로 통지된다고 보장하지 않습니다. [공식 API 설명](https://learn.microsoft.com/en-us/office/vba/api/excel.application.sheetchange)

실제 Excel에서 같은 값의 대상 행을 다른 열 기준으로 Range.Sort한 시험은 SheetChange도 기본 Undo 활성화도 발생시키지 않았습니다. 초기 구현은 이 시험에서 잘못 복구했으며 U04 결함으로 기록했습니다. SortFields는 정렬 전 0에서 정렬 후 1로 바뀌어 범위·키 메타데이터가 남는 것을 별도 probe로 확인했습니다.

이를 보완하여 현재 구현은 작업 직후와 Undo 직전에 워크시트 Sort 및 그 안의 모든 ListObject.Sort의 SortFields가 비어 있어야 합니다. **이미 정렬 설정이 남아 있는 시트나 표에서는 방금 붙여넣은 작업이라도 자체 되돌리기를 제공하지 않습니다.** 설정을 자동 지우거나 사용자의 정렬 상태를 바꾸지 않습니다. 수정 후 U04·표 정렬·기존 정렬 제한·정상 즉시 Undo 회귀 결과는 시험 보고서에 기록합니다.

이벤트·객체 식별·선택 수명·Undo 상태·정렬 메타데이터를 함께 검사합니다. 행 삽입/삭제·정렬·같은 값 이동은 실제 Excel에서 각각 시험합니다. 정렬 후 메타데이터까지 지우는 외부 자동화, 이벤트를 잠시 끈 외부 자동화, 추가 기능의 숨은 후속 작업, 공동편집과 Excel 내부 구조 변경의 완전 탐지는 보장하지 않습니다. 감지되지 않은 동시 자동화가 있는 환경은 v1 보장 범위 밖입니다. 안전 근거를 확보하지 못한 경로에서는 자체 Undo를 활성화하지 않습니다.

EnableEvents=False 또는 감지 기능을 사용할 수 없는 시작 상태에서도 시작 상태는 그대로 복원해야 합니다. 이 경우 복구 백업을 쓸 수 있더라도 사용자용 최근 작업 Undo가 제공된다고 주장하지 않습니다.

## 객체 교체의 실제 시험

0.1.0 후보의 소유 합성 파일에서 시트를 삭제하고 같은 이름·주소·붙여넣기 직후 값을 가진 새 시트로 바꾸는 경우, 같은 파일을 닫고 재열어 직후 값이 같아 보이는 경우, 다른 경로의 같은 파일 이름·시트 이름·주소·값을 여는 경우를 시험했습니다. 모두 잘못된 이전 값으로 복구하지 않고 거절했으며 새 객체의 값·타입·형식과 저장 파일 해시는 유지되었습니다. 실제 설치 메뉴의 즉시 Undo도 원래 가시 셀 값을 복구하고 숨긴 셀을 유지했습니다.

## 복구 자체의 실패

Undo 직전에 대상 전체를 검증하고 하나라도 다르면 0개 수정으로 거절합니다. 일부만 되돌리지 않습니다. 복구 단계에서 실패하면 영향 가능 주소·원래 오류·복구 오류를 구분하고 성공 표시를 하지 않습니다. 메모리 기록을 보존하며 후속 붙여넣기를 차단합니다. 사용자 문서에 자동 저장하거나 외부 파일로 백업을 몰래 기록하지 않습니다.

일반 실패 롤백은 이번 실행의 부분 쓰기를 되돌리는 절차이고, 사용자 Undo는 성공한 이전 작업을 엄격한 유효성 조건 아래 복구하는 절차입니다. 두 경로는 같은 값·수식 복원 및 검증 규칙을 사용합니다.

## Excel의 기본 실행 취소

Application.Undo를 호출해서 COM 작업 전체가 복구된다고 가정하지 않습니다. Ctrl+Z를 전역 가로채지 않습니다. COM 버전은 자체 우클릭 복구 메뉴를 사용하며 VBA 매크로 삽입으로 OnUndo를 연결하지 않습니다. [Application.OnUndo](https://learn.microsoft.com/en-us/office/vba/api/excel.application.onundo)의 등록 동작은 실제 연결을 검증한 경우에만 지원으로 기재합니다.

빈칸을 지우는 구현은 실제 probe를 거쳐 Value2=null을 사용합니다. ClearContents가 기본 Undo를 활성화하여 자체 Undo 조건을 막는 현상을 관찰했기 때문입니다. Value2=null 이후 실제 빈칸과 형식 보존·기본 Undo 비활성을 확인했고, 혼합 타입 및 전부 빈칸의 즉시 복구를 재시험했습니다. 이 관찰이 기존 다단계 Undo 기록 보존을 뜻하지는 않습니다.

**이 도구로 값을 쓰면 Excel의 기존 Ctrl+Z 기록을 사용할 수 없게 될 수 있습니다.** 실제 UI에서 두 칸을 차례로 입력해 기본 Undo가 활성인 상태를 만든 뒤, 도구의 우클릭 메뉴로 붙여넣자 기본 Undo가 비활성으로 바뀌었습니다(True→False). 이전 일반 편집 기록의 보존을 약속하지 않습니다.

도구의 성공한 최근 작업은 안전 조건을 만족할 때 자체 «마지막 붙여넣기 되돌리기» 메뉴로 복구합니다. 이 메뉴가 Excel의 이전 다단계기록까지 복원하는 것은 아닙니다. 다른 추가 기능과의 공존은 별도 U13/I06 시험입니다.
