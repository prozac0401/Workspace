# 설치·제거와 보안 진단

상태: 2026-09-26 후속 DLL `7080305a…`의 비승격 설치·정상 자동 로드·붙여넣기 및 Undo 후 UI 종료와 동일 DLL 제거·재설치를 확인했습니다. 실제 범위와 이전 후보의 종료 실패 이력은 [시험 보고서](test-report.md)에 보존합니다.

## 최종 사용자와 제작 환경

최종 사용자는 ZIP의 완성 배포물을 설치합니다. VBA 편집기, 모듈 가져오기, AccessVBOM, 매크로 수동 실행, Python·Node.js·개발 SDK를 요구하지 않습니다. C# COM 추가 기능의 DLL은 제작 환경에서 미리 컴파일합니다. .NET Framework 런타임과 Windows 데스크톱 Excel은 제품 적용 환경이며 실제 버전·비트수 실행 결과를 구분합니다.

설치 전 Excel 파일을 저장하고 모든 Excel을 종료해야 합니다. 설치·제거 사전검사는 열려 있는 Excel을 발견하면 명확히 중단합니다. Excel을 강제 종료하거나 통합문서를 닫거나 저장하지 않습니다. 실행 중 사전검사를 우회하지 않습니다.

## 소유 경계

기본 설치 위치는 %LOCALAPPDATA%\VisibleCellsPaste입니다. 현재 사용자 HKCU의 제품 전용 COM·Excel Addins 등록을 사용합니다. 설치 매니페스트에 제품 버전·파일·해시·소유 등록을 기록합니다. 등록·메뉴·설정·Undo 기록은 명단대조기와 선택범위 내보내기 등 다른 제품과 공유하지 않습니다.

제거는 자기 자동 로드 등록을 먼저 해제하고 소유 파일만 정리합니다. 기존 등록 충돌, 외부 수정 파일, 잠긴 파일을 성공적으로 제거한 척하지 않습니다. 다른 제품 폴더·PERSONAL.XLSB·사용자 통합문서·신뢰 센터 설정을 삭제하지 않습니다. 제거 재실행의 멱등성과 공백·한글·작은따옴표 경로는 실제 시험 항목입니다.

## 보안 진단

설치기는 전체 매크로 허용, 신뢰 위치 확대, AccessVBOM 활성화, 사용자 VBE 코드 주입, 그룹 정책 우회, 출처 표시 일괄 제거, 다른 추가 기능 비활성화를 수행하지 않습니다. COM 추가 기능도 조직 정책·서명 요구·Office 복원력 차단 대상이 될 수 있습니다. 매크로 파일을 쓰지 않는다는 사실이 모든 기관에서 실행 가능하다는 뜻은 아닙니다.

서명 없는 배포물입니다. 서명 인증서·조직 배포 승인·기관별 정책 설정은 미결정이며 정책 승인처럼 표시하지 않습니다. 사용자가 비활성화한 로드 상태를 감시하여 자동으로 되살리지 않습니다.

메뉴가 없으면 다음을 구분해 확인합니다.

1. 설치 파일과 해시 확인, Excel 비트수와 배포 DLL 일치.
2. 제품 전용 HKCU 등록 존재와 파일 경로 일치.
3. Office에서 제품이 차단·비활성화되었는지 확인.
4. 기관이 서명 또는 승인된 배포를 요구하는지 담당자 확인.

설치가 파일·등록을 만든 사실만으로 자동 로드 검증이 완료됐다고 안내하지 않습니다. 정상 시작에서 실제 메뉴와 콜백이 동작하는 증거가 필요합니다. 보안 승인 없이 설정을 낮춰 정상 경로로 만들지 않습니다.

## 로드 경로 검증

한글·공백·작은따옴표를 포함하는 설치 경로는 등록 파일 경로와 실제 CLR 로드를 함께 검증합니다. 최초 후보는 CodeBase의 퍼센트 이스케이프 때문에 정상 시작 시 DLL을 찾지 못했습니다. 등록을 RegAsm과 호환되는 원시 file URI로 수정했고 정상 시작에서 자동 연결·메뉴 콜백을 다시 확인했습니다. 분리 AppDomain에 합성 검사용 DLL을 실제 로드하는 순수 회귀와 제품 DLL의 Excel 정상 시작 증거를 구분합니다.

## 2026-09-24의 0.1.0 설치 수명주기

후보03을 한글·공백·작은따옴표가 포함된 소유 시험 경로에 업그레이드하고 정상 Excel 시작에서 자동 연결과 자체 메뉴 각 1개를 확인했습니다. 이 경로의 이전 후보에서는 실제 붙여넣기·Undo도 실행했습니다. 실행 프로세스는 Medium 무결성이며 관리자 그룹은 deny-only여서 승격 없이 수행했습니다.

Excel 실행 중 설치는 exit1로 거절했습니다. 정상 종료 뒤 제거는 exit0이었으며 제품 파일과 자기 등록을 제거하고 외부 합성 파일은 보존했습니다. 다시 제거해도 exit0으로 변경하지 않았습니다. 제거 후 정상 시작에서 자체 메뉴와 누락 파일 경고가 없고 기존 SelectionExport 메뉴는 유지되었습니다. 기본 LocalAppData 경로 재설치 후 설치 상태를 바꾸지 않은 두 번 정상 시작에서도 자동 연결과 자체 메뉴 각 1개를 확인했습니다. 다른 제품의 실제 동작 전체, 조직별 차단 정책, Office 32비트는 별도 미검증 범위입니다.

이 문서는 패키지 제작 전 확인한 시험의 스냅샷입니다. 최종 ZIP 해시와 그 ZIP을 설치한 후속 검증은 패키지 밖 배포 기록으로 연결하여, 자기 해시를 문서에 넣기 위한 반복 제작을 피합니다.

## 2026-09-26의 0.1.1 설치 수명주기

초기 수정본의 비승격 업그레이드와 두 정상 시작에서 자동 메뉴·붙여넣기 또는 Undo 후 자연 종료를 확인했습니다. 이후 상태바 복원 보완 후보는 비승격 제거·자체 메뉴 부재·다른 메뉴 보존·재설치가 통과했습니다. 설치 전후 보안 값과 외부 합성 파일도 보존했습니다.

그러나 재설치한 DLL `8741b19f…`는 실제 붙여넣기 성공 후 UI 종료에서 충돌했습니다. 새 이벤트·연결 수명 수정은 자동 검사 284개·외부 시험 엔진의 실제 60개 회귀·생산 DLL의 R17을 통과했지만 이를 새 설치본 종료 성공으로 취급하지 않습니다. 접근을 거부하는 잔여 Excel이 있어 한동안 새 설치가 차단됐습니다. 사용자가 해당 프로세스를 정리한 뒤 Excel 0개를 확인하고 DLL `7080305a…`를 비승격 설치해 파일·등록·보안 값 일치를 확인했습니다. 설치 검사나 보안 설정을 우회하지 않았습니다.

새 설치본의 정상 자동 메뉴로 붙여넣기만 수행한 경우와 별도 시작에서 붙여넣기·즉시 Undo한 경우 모두 UI의 저장 안 함으로 닫았습니다. 각각 540초·381초 이후의 독립 확인에서 해당 프로세스가 없고 새 Excel Application 1000/1001/1002 이벤트와 WER가 없었습니다. 수동 VBA·외부 Excel COM·디버거 없이 수행한 두 합성 시나리오입니다. 세 번째 개수 불일치 거절·빈칸 지움 확인 취소 뒤에도 기존 값 유지와 자연 종료를 확인했습니다.

같은 DLL의 비승격 제거는 exit0으로 자기 매니페스트·등록·파일을 정리했고 외부 합성 파일과 다른 추가 기능·보안 값을 보존했습니다. 제거 후 정상 시작에는 자체 두 메뉴와 누락 경고가 없고 기존 SelectionExport 메뉴가 남았습니다. 이어 같은 검증 ZIP을 다시 설치해 생산 DLL 해시·등록·LoadBehavior 3·소유 파일 및 보호 설정이 일치했습니다. 재설치 뒤 정상 자동 메뉴로 실제 붙여넣고 숨김을 풀어 원래 숨긴 값 102/103/105/106이 유지된 것도 확인했습니다. 제거 후 시작한 창의 종료 367초 및 재설치 사용 후 저장 안 함 123초의 독립 관찰에서 프로세스 부재·새 Excel 오류/WER0과 두 합성 파일 SHA 불변을 확인했습니다. 최종 문서 재포장은 시험한 7개 비문서 payload를 바꾸지 않으며 패키지·게시·다운로드 결과는 외부 배포 기록으로 확인합니다.
