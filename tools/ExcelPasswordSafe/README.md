# ExcelPasswordSafe 1.3.0

탐색기에서 Excel 파일 하나를 오른쪽 클릭하여 **열기 암호를 설정·해제·변경**하는 Windows용 도구입니다. 로컬 평가 후보이며 코드 서명·조직 배포 승인을 마친 제품이 아닙니다.

1.3.0은 흰색·회색 바탕과 짙은 남색·파란색 강조를 사용합니다. 선택한 파일, 할 일, 암호 입력을 카드로 나누어 한 창에서 확인합니다. 암호 처리·백업·검증 절차는 유지합니다.

## 설치와 사용

1. 제공된 MSI를 실행합니다. 현재 사용자에게 설치합니다.
2. Excel을 모두 정상 종료합니다.
3. `.xls`, `.xlsx`, `.xlsm`, `.xlsb` 파일 하나를 오른쪽 클릭하여 **Excel 암호 관리**를 선택합니다. Windows 11에서는 **더 많은 옵션 표시** 안에 있습니다.
4. 파일 경로를 확인하고 **암호 설정 / 암호 해제 / 암호 변경**을 선택합니다.
5. 필요한 암호를 입력하고 백업 안내를 확인한 뒤 실행합니다.

| 작업 | 필요한 입력 |
|---|---|
| 암호 설정 | 새 암호 + 확인 |
| 암호 해제 | 현재 암호 |
| 암호 변경 | 현재 암호 + 새 암호 + 확인 |

새 암호는 1~15자이며 대소문자를 구분합니다. 현재 암호를 모르는 파일의 암호 찾기, 시트·구조·쓰기 암호 해제는 제공하지 않습니다. 파일 없이 앱을 실행하면 파일을 선택할 수 있습니다.

## 필요한 환경과 지원 범위

Windows 10 버전 2004 이상 또는 Windows 11의 x64 PC, .NET Framework 4.8, Windows PowerShell 5.1, 설치된 데스크톱 Microsoft Excel이 필요합니다. Excel은 MSI에 포함하지 않습니다. 1.3.0의 실제 검증과 미확인 항목은 저장소의 `docs/delivery/excel-password-safe-ui-20261116.md`에 기록합니다. 이전 1.2.0 결과는 `docs/delivery/excel-password-safe-20261116.md`에 별도로 보존합니다.

로컬 고정 NTFS의 파일 하나만 처리합니다. 네트워크·이동식 드라이브·링크 경로·읽기 전용·잠긴 파일은 제외합니다. 동기화 폴더의 파일은 별도 로컬 복사본으로 작업하세요. `.xls`는 BIFF8 형식만 지원하며 확장자와 실제 형식이 다르면 변환하지 않습니다. 서명된 문서·VBA, 공유·쓰기 예약 파일과 발견된 Excel 4.0 매크로 시트는 지원하지 않습니다.

`.xls`의 구형 RC4 암호화는 보안상 한계가 있으므로 민감한 자료 보호용으로 권장하지 않습니다. 이 도구는 형식을 자동으로 바꾸지 않습니다. [Microsoft 암호화 명세](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-offcrypto/78b227ba-bb55-49d0-aa41-83644ca1963b)

## 원본과 백업

승인한 원본의 해시를 확인하고 백업을 만듭니다. 별도 Excel 인스턴스에서 복사본을 저장·다시 열어 검증한 뒤 원본 경로를 원자 교체합니다. VBA 자동 실행·이벤트·링크 갱신을 끕니다. 암호는 명령줄이나 평문 로그에 넣지 않고 현재 Windows 사용자 DPAPI로 전달합니다.

백업·기록은 `%LocalAppData%\ExcelPasswordSafe\Runs\실행ID`에 보관하며 **백업·기록 보기** 버튼으로 해당 폴더를 엽니다. `original.확장자`가 작업 전 원본 백업입니다. 같은 파일 폴더에 남는 `.eps-…recovery`도 교체 전 원본입니다.

**암호가 없던 원본의 백업과 recovery도 암호가 없습니다.** 백업 위치를 확인하고 필요가 끝나면 직접 정리하세요. 앱 제거는 백업을 지우지 않습니다. 작업 복사본과 임시 결과는 같은 폴더에 잠시 존재하며 비정상 종료나 정리 실패 후 남을 수 있습니다. 정리 실패 안내가 표시되면 해당 경로를 확인하세요.

실패·취소는 원본 교체 전에 멈춥니다. 교체 결과가 불확실하다는 안내가 나오면 다시 실행하기 전에 기록·현재 파일·백업·recovery를 확인하세요. 자동 롤백은 하지 않습니다. 복원하려면 Excel을 닫고 현재 파일을 별도로 보관한 뒤 원본 해시와 백업을 대조하여 복사합니다.

수식·값·시트·도형 목록 비교는 그림의 모든 픽셀, 삽입 개체 내부, 매크로 동작과 외부 참조의 완전한 동일성을 보증하지 않습니다. 대표 파일의 복사본으로 먼저 시험하고 결과를 Excel에서 확인하세요. Excel 보안 확인이 작업을 멈출 수 있으며 사용자 Excel을 강제 종료하지 않습니다.

## 오류와 제거

Excel이 실행 중이면 정상 종료하고 다시 시도합니다. 파일 열기 실패는 암호 오류뿐 아니라 손상·보안 제한일 수 있습니다. 파일이 변경되었거나 잠겨 있으면 다른 앱을 닫고 파일을 다시 선택하세요. 시간 초과·교체 상태 확인 오류에서는 결과에 표시된 실행 기록과 Excel 상태를 먼저 확인합니다.

제거는 **Windows 설정 → 앱 → 설치된 앱 → ExcelPasswordSafe → 제거**를 사용합니다. 프로그램과 이 도구의 메뉴만 제거하고 Excel 파일·기본 연결·백업은 보존합니다.

설치의 늦은 단계에 오류를 주입한 시험에서 파일과 메뉴가 되돌아간 뒤에도 설치 등록이 남았습니다. 설치 실패 후 앱 항목만 남거나 재설치해도 메뉴가 없으면 **같은 MSI를 다시 열어 프로그램 제거를 선택한 뒤 재설치**하세요. 레지스트리나 Windows 보안 설정을 직접 바꾸지 마세요. 이 복구 제한이 있는 평가용 패키지입니다.

## 소스 구성

`app/`은 WPF 창, `runtime/`은 엔진·Excel 작업 프로세스, `build/`와 `installer/`는 제작·MSI 검사, `tests/`는 합성 시험입니다. `upstream/1.1.0/`은 사용자가 첨부한 원본이며 MSI 실행 파일에 포함하지 않습니다. 개발 명세·설계·실제 시험 기록은 저장소의 `docs/`에서 관리합니다. 로컬 진단과 업무 파일은 배포 패키지에 포함하지 않습니다.

개발자는 저장소 루트에서 다음 명령으로 새 MSI와 시험 기록을 만듭니다. .NET Framework 4.8 C# 컴파일러와 WiX 4가 필요하며 기본 WiX 위치는 `.tools/wix/wix.exe`입니다.

```powershell
powershell.exe -NoProfile -File tools/ExcelPasswordSafe/build/build.ps1 -Version 1.3.0
```

결과는 `artifacts/excel-password-safe/build-1.3.0-실행ID/`에 생성합니다. `build/build.ps1`은 코어·앱·WPF 렌더와 MSI 정적 검사까지 수행합니다. 실제 Excel과 설치 수명주기 시험은 `tests/Test-ExcelSynthetic.ps1`, `installer/test-installer.ps1`로 별도 실행하며, 마지막 스크립트는 기존 제품 설치가 없는지 먼저 검사합니다. 제작 성공은 실제 메뉴 클릭·전체 Excel 버전·코드 서명 검증이나 공개 배포 승인을 뜻하지 않습니다.
