# ExcelPasswordSafe 5

탐색기에서 Excel 파일·폴더의 **열기 암호를 설정·해제·변경**합니다. 작은 창에서 필요한 암호를 입력하고 진행 상황과 결과를 차례로 확인합니다.

## 설치와 시작

MSI에서 설치할 폴더를 선택합니다. 기본 위치는 `%LocalAppData%\Programs\ExcelPasswordSafe`이며 신규 설치에서 변경할 수 있습니다. 현재 사용자에게 설치합니다. 업그레이드·복구는 기존 위치를 유지하므로 위치를 옮기려면 제거 후 다시 설치하세요.

Windows 10 버전 2004 이상 또는 Windows 11 x64, .NET Framework 4.8, Windows PowerShell 5.1과 설치된 데스크톱 Microsoft Excel이 필요합니다. Excel은 MSI에 포함하지 않습니다. 실행 전 Excel을 모두 정상 종료하세요.

| 시작점 | 방법 |
|---|---|
| Excel 파일 하나 | 오른쪽 클릭 → **Excel 암호 관리 → 암호 설정 / 암호 해제 / 암호 변경** |
| 폴더 | 오른쪽 클릭 → **Excel 암호 관리 → 암호 설정 / 암호 해제 / 암호 변경** |
| 탐색기 빈 공간 | 같은 메뉴의 작업을 선택하면 현재 폴더를 처리 |
| 시작 메뉴 | **Excel 암호 관리** → 파일 또는 폴더 선택 → 작업 선택 |

Windows 11 메뉴는 **더 많은 옵션 표시** 안에 있습니다. 폴더 작업은 모든 하위 폴더를 포함합니다. 경로와 파일 수를 확인하고 필요한 경우 대상 목록을 펼쳐 보세요. 메뉴에서 고른 작업은 입력 화면으로 바로 이어집니다.

## 입력 → 진행 → 결과

| 작업 | 입력 |
|---|---|
| 암호 설정 | 새 암호 + 확인 |
| 암호 해제 | 현재 암호 |
| 암호 변경 | 현재 암호 + 새 암호 + 확인 |

새 암호는 1~15자이며 대소문자를 구분합니다. 기본은 마스킹이고 필요할 때 암호 표시를 선택할 수 있습니다. 입력 오류는 같은 화면에서 수정합니다. 탐색기 메뉴에서 시작하면 작업을 다시 고르지 않으며 입력 화면의 **취소**는 창을 닫습니다. 앱을 직접 실행해 작업을 고른 경우에는 **뒤로**로 작업을 바꿀 수 있습니다. 입력 단계를 나가거나 작업을 마치면 암호를 지웁니다.

원본 교체·백업 안내를 확인한 뒤 해당 작업 버튼을 누릅니다. 원본을 백업하고 암호와 내용을 검증한 결과만 원본 경로로 교체합니다. 지원하는 `.xlsx`·`.xlsm`은 Excel을 시작하지 않고 문서 내용을 그대로 보존하며 암호를 처리합니다. 다른 지원 조합은 Excel에서 저장·다시 열어 검증합니다. 폴더에는 같은 암호를 적용하므로 현재 암호가 다른 파일은 실패할 수 있습니다. 암호 찾기나 시트·구조·쓰기 보호 해제는 제공하지 않습니다.

진행 중 현재 파일·완료 수·시도 수를 표시합니다. 취소는 현재 암호 처리나 Excel 확인이 끝날 때까지 기다릴 수 있습니다. 이미 성공한 파일은 다른 파일의 실패·취소 때문에 되돌리지 않습니다.

결과에서 완료·건너뜀·실패·취소/미처리를 확인합니다. **실패 N개 다시 시도**는 안전한 실패 파일만 빈 암호 입력 화면으로 돌려보내며 성공한 파일을 제외합니다. 자동으로 다시 실행하지 않습니다. 교체나 정리 상태가 불확실하면 재시도 대신 **백업·기록 보기**로 확인하세요. 앱을 직접 실행한 흐름의 **다른 작업**은 원래 대상 범위를 새로 확인합니다.

## 실패 보고서와 백업

폴더의 한 실행 안에서 안전한 실패는 **최초 포함 최대 3회** 처리합니다. 최종 실패가 있으면 **실패 보고서 열기**로 파일명·전체 경로·이유·시도 수를 확인합니다. 보고서는 `%LocalAppData%\ExcelPasswordSafe\Runs\배치ID\failure-report.xlsx`에 저장하며 입력 대상에서 제외합니다. 실패가 없으면 만들지 않습니다. 파일 경로가 포함되므로 공유 전에 확인하세요. 암호는 기록하지 않습니다.

백업은 파일 작업의 `%LocalAppData%\ExcelPasswordSafe\Runs\실행ID\original.확장자`, 폴더 작업의 배치 폴더 아래 각 시도 폴더에 보관합니다. **백업·기록 보기**로 엽니다.

정상 완료·안전한 실패·취소 뒤에는 해당 실행의 작업 복사본·임시 결과·암호 전달 파일과 확인된 중복 recovery를 정리합니다. **원본 백업은 보존하며 암호 없는 원본의 백업도 암호가 없습니다.** 필요가 끝난 백업은 확인 후 직접 정리하세요.

교체·Excel 종료·정리 상태가 불확실하면 필요한 복구 파일을 보존하고 안내합니다. 바로 다시 실행하지 말고 현재 파일·백업·기록을 확인하세요. 복원하려면 Excel을 닫고 현재 파일을 별도 보관한 뒤 원본 해시와 백업을 대조하여 복사합니다. 자동 롤백은 하지 않습니다.

## 지원 범위와 복구

`.xls`(BIFF8)·`.xlsx`·`.xlsm`·`.xlsb`를 지원하며 형식을 자동 변환하지 않습니다. 처리할 문서는 로컬 고정 NTFS에 있어야 합니다. 네트워크·이동식·링크·오프라인·읽기 전용 파일은 제외합니다. 동기화 폴더는 별도 로컬 복사본으로 작업하세요. 서명된 문서·VBA, 공유·쓰기 예약 파일과 발견된 Excel 4.0 매크로 시트는 지원하지 않습니다.

`.xls`의 구형 RC4 암호화는 보안상 한계가 있어 민감한 자료 보호용으로 권장하지 않습니다. [Microsoft 암호화 명세](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-offcrypto/78b227ba-bb55-49d0-aa41-83644ca1963b)

파일 열기 오류는 현재 암호·손상·보안 제한을 함께 확인하세요. 사용자 Excel을 강제 종료하지 않습니다. 직접 처리에서는 원본 패키지 전체 바이트를 보존하지만 매크로를 실행하거나 모든 문서의 Excel 정상 열기를 검사하지는 않습니다. Excel 처리의 내용 비교도 모든 그림·삽입 개체·외부 참조를 완전히 검증하지 않으므로 대표 파일의 복사본으로 확인하세요.

‘Excel 상태를 확인할 수 없어 중단했습니다’가 나오면 실행 기록과 열린 Excel을 먼저 확인하세요. 이 상태에서는 안전 여부를 확인하기 전 자동·수동 재시도를 제공하지 않습니다.

설치 실패 후 앱 항목만 남거나 재설치해도 메뉴가 없으면 **같은 MSI를 다시 열어 프로그램 제거 후 재설치**하세요. 레지스트리나 Windows 보안 설정을 직접 바꾸지 마세요. 제거는 **Windows 설정 → 앱 → 설치된 앱 → ExcelPasswordSafe 5 → 제거**입니다. 프로그램과 자기 메뉴만 제거하고 문서·기본 연결·백업·보고서는 보존합니다.

## 소스와 빌드

`.xlsx`·`.xlsm`의 직접 처리는 64MiB 이하의 지원 OOXML·Agile 암호 조합에 적용하며, 새 암호 재복호화·전체 패키지 바이트 비교·무결성과 잘못된 암호 거절을 확인합니다. `.xls`·`.xlsb`, 큰 파일이나 지원 밖 암호 조합은 기존 Excel 경로를 사용합니다. 손상·암호 오류·무결성 실패를 다른 경로로 우회하지 않습니다. 직접 검사에는 ZIP 파트 10,000개·총 비압축 256MiB·메타데이터 XML 16MiB 제한이 있으며 이를 초과하거나 구조가 잘못된 파일은 원본을 유지하고 실패로 표시합니다.

Excel이 필요한 폴더 작업은 프로그램이 소유한 Excel 하나를 재사용합니다. 파일별 백업·검증·원자 교체와 최대 3회 안전한 재시도는 두 경로에서 유지합니다.

버전 5는 암호 계산 안에서 Windows의 SHA 객체를 재사용하며 기존 100,000회 반복, 원본 백업·암호·무결성·전체 내용 검증을 유지합니다. 같은 작은 파일을 작업별로 3쌍씩 비교한 전체 엔진 시간의 중앙값은 설정 4.45→3.61초, 해제 3.76→3.03초, 변경 6.65→3.61초였습니다. 한 PC의 합성 표본이며 모든 파일의 보장 시간은 아닙니다. 사용 방법은 같으며 측정 조건과 최종 검증 범위는 [추가 지연 개선 기록](https://github.com/prozac0401/Workspace/blob/excel-password-safe-v5/docs/delivery/excel-password-safe-latency-20261117.md)을 참고하세요.

`app/`은 단계형 WPF 화면, `assets/`는 제품 아이콘, `runtime/`은 파일·폴더 엔진과 Excel worker, `crypto/`는 직접 암복호화와 읽기 전용 패키지 검사입니다. OfficeIMO의 고정 소스와 MIT 라이선스는 `crypto/THIRD-PARTY-NOTICES.txt`에 기록하며 설치본에도 고지를 포함합니다. `build/`·`installer/`는 제작·설치 검사, `tests/`는 합성 시험, `upstream/1.1.0/`은 수정하지 않은 첨부 원본입니다. 현재 근거는 `docs/delivery/excel-password-safe-latency-20261117.md`, 버전 4의 당시 근거는 `docs/delivery/excel-password-safe-single-file-20261117.md`에 구분합니다. 로컬 진단·사용자 기록·업무 자료는 배포하지 않습니다.

.NET Framework 4.8 참조와 WiX 4, `crypto/compiler-lock.json`의 고정 .NET SDK/Roslyn 컴파일러를 준비한 뒤 저장소 루트에서 실행합니다. 기본 위치는 `.tools/wix/wix.exe`, `.tools/dotnet/dotnet.exe`이며 다른 위치는 빌드의 `-Dotnet` 인수로 전달합니다. 설치된 제품의 직접 처리에는 SDK·Python·NuGet runtime이 필요하지 않습니다.

KDF 구현은 Windows 시스템 `bcrypt.dll`을 사용합니다. vendor 원본은 보존하고 `crypto/kdf-patch.json`으로 해시가 고정된 빌드 사본의 호출 하나만 연결합니다. 적용 내용과 원본 MIT 고지는 설치본의 제3자 고지에 포함합니다.

```powershell
powershell.exe -NoProfile -STA -File tools/ExcelPasswordSafe/build/build.ps1
```

자동 검사·화면 렌더·MSI 검사와 실제 Excel·탐색기·설치 시험을 구분합니다. 설치 시험은 기존 제품이 없는지 확인하고 전용 위치와 합성 자료로 수행합니다.
