# ExcelPasswordSafe 1.4.0

탐색기에서 Excel 파일 하나 또는 폴더 아래의 파일에 **열기 암호를 설정·해제·변경**합니다. 폴더 작업은 모든 하위 폴더의 지원 Excel 파일을 포함합니다. 미서명 평가 패키지이며 조직 배포 승인을 마친 제품으로 표시하지 않습니다.

## 설치와 사용

1. 제공된 MSI로 현재 사용자에게 설치하고 Excel을 모두 정상 종료합니다.
2. 파일 하나는 오른쪽 클릭 → **Excel 암호 관리**로 실행합니다. 기존 파일 메뉴와 사용 방법은 같습니다.
3. 폴더는 오른쪽 클릭 → **Excel 암호 관리 → 암호 설정 / 암호 해제 / 암호 변경**으로 실행합니다. Windows 11에서는 **더 많은 옵션 표시** 안에 있습니다.
4. 파일 경로 또는 폴더와 하위 대상 목록을 확인합니다. 필요한 암호를 입력하고 백업 안내에 동의한 뒤 실행합니다.

| 작업 | 필요한 입력 |
|---|---|
| 암호 설정 | 새 암호 + 확인 |
| 암호 해제 | 현재 암호 |
| 암호 변경 | 현재 암호 + 새 암호 + 확인 |

새 암호는 1~15자이며 대소문자를 구분합니다. 폴더에는 같은 암호를 적용하므로 현재 암호가 다른 파일은 실패할 수 있습니다. 암호 찾기와 시트·구조·쓰기 보호 해제는 제공하지 않습니다. 파일 없이 앱을 실행하면 파일을 선택할 수 있습니다.

폴더 작업은 승인한 목록을 순서대로 처리하며 나중에 추가한 파일을 포함하지 않습니다. 이미 성공한 파일은 다른 파일의 실패·취소 때문에 자동 복원하지 않습니다. 취소는 현재 Excel 호출이 끝날 때까지 기다릴 수 있으며 아직 처리하지 않은 파일은 별도로 표시합니다.

## 재시도와 실패 기록

폴더 작업의 안전한 실패는 **최초 시도 포함 최대 3회** 처리합니다. 파일 변경·백업 이상·교체 상태 불확실·남은 Excel·정리 실패에서는 자동 재시도를 멈춥니다. 검색 단계에서 접근하지 못한 항목은 시도 수 0으로 기록합니다.

최종 실패의 파일명·전체 경로·이유·시도 수를 화면에 표시하며 **실패 보고서 열기**로 XLSX를 엽니다. 보고서는 `%LocalAppData%\ExcelPasswordSafe\Runs\배치ID\failure-report.xlsx`에 저장합니다. 실패가 없으면 보고서를 만들지 않습니다. 안전 문제로 중단한 경우 미처리 항목도 함께 확인합니다. 작성 실패는 오류와 실행 기록 위치로 알립니다. 보고서에는 파일 경로가 포함되며 암호는 기록하지 않습니다.

## 원본·백업·중간 파일

파일마다 원본 해시를 확인하고 백업한 뒤 별도 Excel에서 복사본을 저장·다시 열어 검증합니다. 검증된 결과만 같은 경로로 원자 교체합니다. VBA 자동 실행·이벤트·링크 갱신을 끄며 암호는 명령줄·평문 로그 대신 현재 사용자 DPAPI로 전달합니다.

**백업·기록 보기**로 실행 폴더를 엽니다. 파일 작업의 `%LocalAppData%\ExcelPasswordSafe\Runs\실행ID\original.확장자`, 폴더 작업의 배치 폴더 아래 각 시도 폴더에 원본 백업을 보관합니다.

정상 완료·안전한 실패·취소 뒤에는 해당 실행의 작업 복사본·임시 결과·암호 전달 파일과 확인된 중복 recovery를 정리합니다. **원본 백업은 보존하며, 암호 없는 원본의 백업도 암호가 없습니다.** 필요가 끝난 백업은 확인 후 직접 정리하세요. 앱 제거는 백업·보고서를 삭제하지 않습니다.

교체·Excel 종료 상태가 불확실하면 필요한 복구 자료를 보존하고 경로를 안내합니다. 정리 오류가 있으면 중간 파일이 남을 수 있습니다. 바로 다시 실행하지 말고 현재 파일·백업·recovery와 기록을 확인하세요. 자동 롤백은 하지 않습니다. 복원할 때는 Excel을 닫고 현재 파일을 별도 보관한 뒤 원본 해시와 백업을 대조하여 복사합니다.

## 필요한 환경과 지원 범위

Windows 10 버전 2004 이상 또는 Windows 11 x64, .NET Framework 4.8, Windows PowerShell 5.1과 데스크톱 Microsoft Excel이 필요합니다. Excel은 MSI에 포함하지 않습니다. `.xls`(BIFF8), `.xlsx`, `.xlsm`, `.xlsb`를 지원하며 형식을 자동 변환하지 않습니다.

로컬 고정 NTFS 경로를 사용합니다. 네트워크·이동식 드라이브·링크·오프라인·읽기 전용 파일은 제외합니다. 동기화 폴더는 별도 로컬 복사본으로 작업하세요. 서명된 문서·VBA, 공유·쓰기 예약 파일과 발견된 Excel 4.0 매크로 시트는 지원하지 않습니다. 파일 열기 오류는 암호·손상·보안 제한을 함께 확인해야 합니다. 사용자 Excel을 강제 종료하지 않습니다.

`.xls`의 구형 RC4 암호화는 보안상 한계가 있으므로 민감한 자료 보호용으로 권장하지 않습니다. [Microsoft 암호화 명세](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-offcrypto/78b227ba-bb55-49d0-aa41-83644ca1963b)

수식·값·시트·도형 비교는 그림 픽셀·삽입 개체 내부·매크로 동작·외부 참조의 완전한 동일성 보장이 아닙니다. 대표 파일의 복사본으로 확인하고 결과를 Excel에서 검토하세요. 실제 시험·미확인 항목은 저장소의 `docs/delivery/excel-password-safe-folder-20261116.md`에 기록합니다. 1.2.0·1.3.0 검증은 당시 기록으로 보존합니다.

## 설치 복구와 제거

설치 실패 후 앱 항목만 남거나 재설치해도 메뉴가 없으면 **같은 MSI를 다시 열어 프로그램 제거를 선택한 뒤 재설치**하세요. 이전 늦은 설치 실패 시험에서 파일·메뉴가 되돌아가도 제품 등록이 남는 제한을 확인했으며 이번 기능 추가로 해결된 것으로 표시하지 않습니다. 레지스트리나 Windows 보안 설정을 직접 바꾸지 마세요.

제거는 **Windows 설정 → 앱 → 설치된 앱 → ExcelPasswordSafe → 제거**를 사용합니다. 프로그램과 자기 파일·폴더 메뉴만 제거하고 Excel 파일·기본 연결·백업·보고서는 보존합니다.

## 소스와 빌드

`app/`은 WPF, `runtime/`은 파일·폴더 엔진과 Excel worker, `build/`·`installer/`는 제작·MSI 검사, `tests/`는 합성 시험입니다. `upstream/1.1.0/`은 첨부 원본으로 보존하며 설치 실행 파일에 포함하지 않습니다. 명세·설계·검증은 저장소 `docs/`에서 관리하고 로컬 진단·업무 파일은 배포하지 않습니다.

저장소 루트에서 다음 명령을 실행합니다. .NET Framework 4.8 C# 컴파일러와 WiX 4가 필요하며 기본 WiX 위치는 `.tools/wix/wix.exe`입니다.

```powershell
powershell.exe -NoProfile -STA -File tools/ExcelPasswordSafe/build/build.ps1 -Version 1.4.0
```

산출물은 `artifacts/excel-password-safe/build-1.4.0-실행ID/`에 생성합니다. 자동 검사·WPF 렌더·MSI 정적 검사와 실제 Excel·Explorer·설치 수명주기 결과를 구분합니다. 설치 시험은 기존 제품이 없는지 먼저 확인하고 전용 시험 위치와 합성 자료만 사용합니다.
