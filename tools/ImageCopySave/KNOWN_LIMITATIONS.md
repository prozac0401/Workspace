# 알려진 제한과 미검증 항목

현재 요구는 [v1.2 변경 계약](../../docs/tools/image-copy-save/ImageCopySave_Requirements_v1.2.md)의 공통 클래식 메뉴와 관리자 설치 방식의 자체 포함 무서명 MSI다. Windows 11 기본 메뉴의 ‘더 많은 옵션 표시’와 Windows 10 형식의 직접 메뉴를 구분해 검증한다. 이전 sparse identity 경로는 제품 MSI의 필수 단계가 아니다. [최신 결과](../../docs/delivery/image-classic-msi-20260927.md)에서 실제 통과 항목과 미완료 항목을 확인한다. native183 격리 복구는 이번 필수 조건에서 제외하고 명시적 [현재 사용자 시험](../../docs/tools/image-copy-save/current-session-testing.md)을 사용한다.

상태: 개발 평가 · 2026-09-27(KST) · **공통 메뉴·MSI 인수 진행 중** · 전체 G0/M3 및 상용 배포 승인으로 분류하지 않음

이전 full MSIX의 일반 사용자 설치는 신뢰 오류 `0x800B0109`, 이전 비상승 unsigned sparse 등록은 `0x80073D2B`로 차단됐습니다. 이후 관리자 sparse 등록·정리와 SYSTEM 진단 MSI·일반 사용자 등록은 통과했습니다. 신뢰 저장소를 변경하지 않았으며 이 과거 결과를 현재 클래식 MSI의 실패로 적용하지 않습니다. [서명 시도 기록](../../docs/delivery/image-copy-save-signing-20260927.md)과 [관리자 등록 기록](../../docs/delivery/image-admin-install-20260927.md)을 보존합니다.

1. 저장 명령은 실제 로컬 폴더 배경의 공통 클래식 메뉴에 있습니다. Windows 11 첫 메뉴 자체에 표시하는 것은 필수가 아니며 ‘더 많은 옵션 표시’에서 접근합니다. 이미지가 없을 때 완전 숨김, 무상주, 기존 ‘새로 만들기’와 기본 연결 보존은 유지합니다. 현재 PC에서 클래식 직접 표시의 실제 저장·복사·조건부 숨김을 확인했으며, 두 모드의 전체 인수와 반복·원상복구 결과는 최신 기록에 별도로 표시합니다. 실제 Windows 10 OS는 미검증입니다.
2. 정상 제품 후보는 404개 자체 포함 파일과 두 COM·다섯 verb를 가진 무서명 MSI입니다. 관리자 설치·누락 파일 복구·0.1.1 업데이트·제거·고의 실패 롤백·재설치가 실제 통과했습니다. 최종 0.1.1 설치 상태이며 이번 실행에서 재부팅 요구는 없었습니다. 첫 UAC 요청 취소와 업데이트 후 시험기 JSON 읽기 실패는 별도 기록했고, 읽기 수정·회귀 후 나머지를 완료했습니다. 설치는 정상 관리자 승인이 필요하고 제품 사용은 비상승입니다. 사용 중인 DLL로 Windows가 재시작을 요청할 수 있으며, 설치기가 Explorer를 강제 종료하거나 재부팅하지 않습니다.
3. 이전 Windows Server 2025 관리자 CI의 77개 엔진/helper 시험과 63개 native 시험 PASS는 당시 소스의 결과입니다. 이번 통합 후보는 로컬에서 다시 빌드·시험하며 최신 수치와 미실행 이유는 [시험 결과](TEST_RESULTS.md)에 기록합니다. 기본 격리 모드는 생성 실패 시 자동 전환하지 않습니다. 명시적인 두 동의 옵션으로 현재 사용자 클립보드 모드를 별도 실행할 수 있습니다. native 시험은 Invoke·Explorer·등록·설치를 실행하지 않으므로 G0 또는 AT를 승격하는 근거가 아닙니다.
4. 코덱은 .NET WPF가 제공하는 Windows WIC 기본 코덱을 명시적으로 선택합니다. native C++ IExplorerCommand/IObjectWithSite와 WinExe helper를 실제 클래식 Explorer 메뉴에서 연결해 복사와 저장을 확인했습니다. GetState의 빠른 제외·느린 판정 위임, 호출 문맥 판정, 비모달 결과 안내·취소·같은 보기 선택을 구현했습니다. 모든 포커스 전환·취소 버튼·탭 경합이 검증된 것은 아닙니다. WPF의 화면 비표시 렌더링은 실제 Windows 입력/포커스 시험을 대신하지 않습니다.
5. PNG의 내장 ICC(명시적 sRGB ICC도 포함), 비표준 gamma/chromaticity, HDR 및 고비트·애니메이션은 거절합니다. 무프로파일/명시적 sRGB 화면 이미지 범위입니다. JPEG는 8비트 회색/3성분의 지원 프레임과 IFD0 방향만 처리합니다. CMYK·ICC·MPO는 거절합니다.
6. PNG가 있으면 우선하며, bitmap 계열은 원래 게시된 형식이 합성 형식보다 앞서는 Windows 열거 순서를 따릅니다. 생산자가 독립 표현을 낮은 품질 순서로 게시하면 공개 API만으로 원본과 합성을 구별할 수 없어 그 순서를 따릅니다. BMP/DIB는 INFO40/V4/V5 헤더의 24/32비트 BI_RGB 또는 표준 마스크의 32비트 BI_BITFIELDS만 받습니다. 16비트·팔레트 BMP·RLE·비표준 마스크·색 프로파일은 거절합니다. 32비트 BI_RGB의 예약 바이트와 CF_BITMAP은 알파 계약이 없어 불투명 처리합니다. 투명도는 PNG 또는 명시적 알파가 있는 DIBV4/V5로 유지합니다.
7. 경로는 고정 로컬 디스크를 대상으로 하며 UNC·매핑/가상 드라이브·장치 경로·ADS·reparse/online-only 경로를 거절합니다. 로컬 확보 상태여도 reparse 속성이 남은 클라우드 폴더는 보수적으로 거절할 수 있습니다. 실제 OneDrive·DLP·보안 제품 조합은 미검증입니다. 경로 보호는 상위 디렉터리에 읽기/목록 권한을 요구합니다. 이동·교체 차단은 시험했지만 처리 도중 DOS 드라이브 매핑 변경이나 기존 디렉터리의 reparse 설정 변경까지 방어한다고 보장하지 않습니다.
8. 클립보드 게시 준비와 잠금 이전 실패는 보존하도록 구현했습니다. EmptyClipboard 이후 OS 게시 실패는 전체 복구를 보장하지 않으며 오류에 변경 가능성을 표시합니다. Copy 도중 시퀀스가 바뀌면 보수적으로 중단하며, 다른 앱의 지연 렌더링에 의한 변화도 중단시킬 수 있습니다. Capture는 잠근 동안 확보한 스냅샷을 처리하며 시퀀스 변화만으로 그 스냅샷을 폐기하지 않습니다.
9. GetClipboardData의 멈춘 지연 렌더러는 별도 worker 제한시간으로 처리합니다. 실제 helper와 합성 공급자의 시험에서15초+취소 유예1초 후 종료3, 자식0, 무출력파일, 공급자 생존을 확인했습니다. 프로세스 시작 후 oplock break를 관측하고 내부 event로 취소해 무변경·종료3·자식0을 확인했지만 break의 원인 PID를 식별하지 않아 정확한 helper I/O 단계 진입을 입증하지 못했습니다. 그림판·Office 등 실제 외부 공급 앱, public Ctrl+C와 최종 취소 UX는 미검증입니다. 강제 종료·전원 차단 시 잔재가 가능하고 커밋 직후 응답 유실은 완료 여부 불확실로 표시합니다.
10. 재인코딩 PNG가128MiB를 넘으면 출력·clipboard 게시를 거절합니다. 이전 엔진/helper CI에서는 실제 읽기/쓰기 ACL 거부와 전용128MiB VHD의 실제 디스크 부족·정리를 검증했습니다. 실제50M픽셀·dimension 경계는 순차 fixture로 확인했지만 payload128MiB/buffer256MiB 모든 경계 종단 시험·전원 차단은 미완료입니다. 4K P50/P95는 합성 gradient/alpha의 엔진 저장/읽기 값이며 메뉴·helper·clipboard·사용자2초 목표의 합격 결과가 아닙니다.
11. 그림판의 대표 복사·붙여넣기·저장 경로는 현재 사용자 시험에서 확인했습니다. Word·PowerPoint·메일·메신저와 모든 외부 앱의 투명도·압축 결과는 미검증입니다. 조직의 DLP·배포 승인 결정은 별도이며 정책 우회를 수행하지 않았습니다. 사용자의 내부용 무서명 MSI 결정과 조직 전체 배포 승인을 구분합니다.

12. native Invoke 시퀀스를 helper/worker까지 전달하도록 변경했습니다. 복사 게시 잠금·저장 읽기 잠금에서 기준값을 비교하고, 잠금 이후 지연 렌더링은 허용합니다. 결과는 제한된 pipe로 전달하며 원래 폴더의 PNG 경로만 선택 후보로 받습니다. 같은 보기 창·현재 폴더·가시성·전경 루트가 맞을 때만 선택합니다. 이 코드와 순수 정책 시험이 실제 호출·탭 전환의 통합 증거는 아닙니다. 새 보호 경로의 격리 clipboard 시험과 실제 Explorer 시험 결과를 구분해야 합니다. [설계 결정](../../docs/design/0017-image-copy-save-invocation.md)과 [PC 확인 절차](../../docs/tools/image-copy-save/local-verification.md)를 참조하세요.

이전 병렬 helper 시험 중 read 오류1418을 재현했고, Capture에 고유한 창 핸들을 적용한 뒤8회×4개 반복과 전체 회귀를 통과했습니다. Windows의 NULL 핸들 내부 경쟁 원리까지 직접 입증한 것은 아닙니다. metadata-only 조회 방식과 원본 보호·무덮어쓰기 계약은 유지합니다.

자동 시험의 실제 실행 결과와 44개 항목별 상태는 [시험 결과](TEST_RESULTS.md)를 참조하세요.
