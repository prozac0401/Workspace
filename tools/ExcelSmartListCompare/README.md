# Excel 명단 비교 R13 평가 후보 사용 안내

**0.2.0-rc.13 평가 후보 · 새 안내·목록 교체 확인, StatusBar 기존 실패·설치 검증·출하 대기**

R13은 담은 목록의 요약에서 수정한 범위를 선택한 뒤 **첫 번째 목록 바꾸기**를 누르도록 안내하는 작은 문구 개선입니다. 비교 규칙과 목록 교체 동작은 유지합니다. 이 문서는 새 후보용 안내이며, 기존 R12 설치 파일에는 새 요약 문구가 들어 있지 않습니다.

R13은 집중 소스 확인과 새 XLAM 후보 제작·저장 소스 대조, 실제 새 안내·첫 목록 교체 한 흐름을 확인했습니다. 상태표시줄 복원은 FAIL이며 이 결과를 명시적으로 수용하는 평가 조건을 기록했습니다. 설치 확인과 EXE·ZIP 제작·게시가 남아 있습니다. 현재 공개 파일은 아래 R12 릴리스에서 받습니다. 전체 검증 완료판이나 안정판으로 안내하지 않습니다.

설치 파일은 코드 서명이 없으며 회사 PC에서는 승인된 설치 절차를 따라야 합니다. 기존 실제 취소 완료 안내와 Excel 상태표시줄 복원 문제는 이 문구 변경으로 해결하지 않았습니다. 다른 Windows·Office 환경과 전체 설치 수명주기 확인도 별도입니다.

상태표시줄에 `FALSE`가 남아 Excel의 평소 상태 표시가 가려질 수 있습니다. 필요한 통합문서를 저장한 뒤 Excel을 정상 종료하고 다시 열어 상태를 확인하세요. 이 절차가 원인을 해결하거나 재발을 막는다는 뜻은 아닙니다. 이번 합성 흐름의 원본·이전 결과 보존을 모든 업무 자료의 무손실 보장으로 확대하지 않습니다.

두 목록의 값과 개수가 같은지 확인합니다. 같으면 짧게 알려주고, 차이가 있으면 새 Excel 파일에 표시합니다.

## 설치하기

64비트 Windows와 PC에 설치된 데스크톱 Excel이 필요합니다. Mac과 브라우저용 Excel은 지원하지 않습니다.

아래 절차는 검증을 마친 RC13 설치 파일이 게시된 뒤 사용합니다. 현재 RC13 EXE·ZIP은 제작하지 않았습니다.

1. 작업 중인 파일을 저장하고 Excel 창을 모두 닫습니다.
2. **ExcelSmartListCompare-0.2.0-rc.13-Setup.exe**를 실행하고 **설치**를 누릅니다.
3. Excel의 **추가 기능** 탭에서 명단 비교 버튼을 확인합니다. 셀을 우클릭해도 사용할 수 있습니다.

ZIP은 모두 푼 뒤 `Release` 폴더의 **Install.cmd**를 실행합니다. 현재 Windows 계정에 설치하며 관리자 권한·Python·VBA 편집기는 필요하지 않습니다. 제품 폴더는 Excel의 신뢰할 수 있는 위치로 등록되므로 제품 파일만 보관하세요. 회사 정책으로 차단되면 회사의 승인된 설치 절차를 따르세요.

## 두 목록 비교하기

1. 제목을 빼고 첫 목록의 셀을 선택한 뒤 **첫 번째 목록 담기**를 누릅니다.
2. 필요한 경우 **담은 목록 확인**으로 가져온 위치와 값의 일부를 확인합니다.
3. 같은 Excel에서 두 번째 목록을 선택하고 **두 번째 목록 담아 비교**를 누릅니다.

순서와 가로·세로 방향은 상관없습니다. 같은 값이 양쪽에 두 번씩 있으면 같고, 한쪽에 두 번·다른 쪽에 한 번 있으면 개수가 다릅니다. Ctrl로 여러 범위를 선택해도 목록 하나로 비교합니다.

## 차이 결과 읽기

**명단비교_결과** 시트에는 값이나 개수가 다른 항목만 나옵니다. 위쪽에서 두 목록의 출처·시각·비교 개수·제외 개수·설정을 확인하세요. 8행은 열 제목이고 9행부터 차이가 표시됩니다.

- **차이**: 첫 목록에만 있음, 둘째 목록에만 있음, 개수가 다름 중 하나입니다.
- **비교한 값**: 메일 주소나 대소문자 설정 등을 적용해 비교한 값입니다.
- **첫/둘째 목록 원본 값 (예)**: 각 목록에서 처음 발견한 셀의 값입니다.
- **첫/둘째 목록 개수**: 해당 값이 각 목록에 몇 개 있는지 보여줍니다.

추가 개수와 원본 셀 위치는 G:J열에 보관합니다. 필요하면 **F~K열 머리글 선택 → 우클릭 → 숨기기 취소**로 펼치세요. ‘더 많은 개수’는 두 목록의 개수 차이입니다. 예를 들어 첫 목록 3개·둘째 목록 1개이면 첫 목록이 2개 더 많습니다. 원본 값과 셀 위치는 예시 하나이며, 그 셀이 잘못됐다는 뜻은 아닙니다.

결과 파일은 원하는 위치에 직접 저장하세요. 원본과 이전 결과는 바뀌지 않습니다. 기본 설정에서는 비교가 끝나면 기억한 첫 목록을 비웁니다. 실패·취소·경고 거절 시에는 유지합니다.

## 담은 목록 확인하기

**담은 목록 확인**은 **이미 담아 둔 첫 번째 목록**을 보여줍니다. 지금 선택한 셀을 새로 읽는 기능은 아닙니다.

**요약**에서 출처·담은 시각·전체 개수·제외 개수·설정을 확인하고, **값과 위치**에서 값의 일부와 원본 셀 위치를 확인하세요. 위치는 최대 1,200개·같은 비교값당 5개, 오류 위치는 최대 200개를 표시합니다. 표시하지 않은 개수도 안내합니다. 비교할 때는 표시 한도와 관계없이 전체 개수를 셉니다.

원본을 수정해도 담은 값은 자동으로 바뀌지 않습니다. 수정한 범위를 선택하고 **첫 번째 목록 바꾸기**를 누르세요. **첫 번째 목록 비우기**는 기억한 목록만 지웁니다. Excel을 완전히 종료해도 기억한 목록은 사라집니다.

## 비교 설정 바꾸기

**추가 기능 탭 → 비교 설정** 또는 **셀 우클릭 → 명단 비교 → 비교 설정**을 엽니다. 체크하면 켜집니다. 처음에는 세 항목 모두 꺼져 있습니다.

| 설정 | 체크했을 때 |
|---|---|
| 메일 전체 주소 비교 (@ 뒤 포함) | `@` 뒤까지 비교합니다. 꺼져 있으면 앞부분만 비교합니다. |
| 대소문자 무시 | `ABC`와 `abc`를 같게 봅니다. 꺼져 있으면 구분합니다. |
| 비교 후 첫 목록 유지 | 첫 목록을 남겨 다른 목록과 이어서 비교합니다. |

첫 목록을 담은 동안에는 메일·대소문자 설정을 바꿀 수 없습니다. 먼저 목록을 비운 뒤 바꾸고 다시 담으세요. 작업 중에는 모든 설정이 잠깁니다.

마지막 설정은 다음 실행에도 기억합니다. **기본값으로 되돌리기**는 세 항목을 모두 끕니다. 먼저 첫 목록을 비워야 합니다.

## 비교할 때 알아둘 점

- 숨긴 셀·필터로 가려진 셀·빈칸·오류·표 제목과 합계는 뺍니다. 일반 범위의 제목은 직접 빼고 선택하세요. 오류를 제외하고 같으면 제외 개수를 함께 알립니다.
- 숫자 `123`과 문자 `123.0`·`1.23e2`는 같습니다. 문자 `00123`은 다르게 봅니다. 병합 셀은 비교할 수 없으며 계산 중이면 끝날 때까지 기다리세요.
- 한 목록은 보이는 선택 셀 **100,000개**, 한 셀 **4,096자**, 원문 합계 **5,000,000자**까지입니다. 입력 한도까지 항상 완료된다는 뜻은 아닙니다. 값 길이·서로 다른 값의 수·PC 부하에 따라 시간 제한으로 중단될 수 있습니다.
- **작업 취소**나 Esc로 취소를 요청한 뒤 종료 안내를 확인하세요. 두 목록을 같은 행 수로 나누면 잘못된 차이가 생길 수 있습니다. 나누려면 같은 비교값이 양쪽에서 같은 묶음에 들어가야 합니다.
- 별도 Excel 프로세스끼리는 목록을 공유하지 않습니다. VBA 실행 후에는 Excel의 기본 실행 취소 기록이 유지되지 않을 수 있습니다. 명단을 외부 서비스로 보내지 않지만, 결과 파일을 공유할 때는 담긴 원본 값을 확인하세요.

## 업데이트·제거하기

파일을 저장하고 Excel을 닫은 뒤 새 설치 파일을 실행합니다. EXE로 설치했다면 **Windows 설정 → 앱 → 설치된 앱 → Excel 명단 비교 → 제거**, ZIP으로 설치했다면 **Uninstall.cmd**로 제거합니다.

비교 설정은 업데이트·제거 후에도 같은 계정에 남습니다. 초기화하려면 설치된 도구의 **비교 설정 → 기본값으로 되돌리기**를 사용하세요. 설치 오류를 문의할 때는 사용자 경로가 들어간 로그를 그대로 공개하지 마세요.

[현재 공개된 R12 배포 파일](https://github.com/prozac0401/Workspace/releases/tag/excel-smart-list-compare-v0.2.0-rc.12)


## 소스 후보와 검증 기록

현재 저장소 소스의 릴리스 식별자는 `0.2.0-rc.13`입니다. PR13 소스 전환 후 명시한 집중 검사 13 PASS를 확인했습니다. 기존 ASCII/UTF-8 5쌍 PASS, RC12 대비 선택 안내·버전 외 제품 입력 불변, PowerShell AST 두 건과 packager AST·합성 방어 네 건 PASS도 유지합니다. 오래된 시트명 기대값 검사는 이름으로 명시해 집중 목록에서 제외했고 기존 실패를 보존합니다. 전체 suite 통과가 아닙니다.

사용자의 임시 VBA 프로젝트 접근 승인 후 격리 BuildOnly로 새 XLAM을 제작했습니다. 첫 제작은 후보 저장 전 audit 파일 교체 오류로 실패했고, 같은 소스의 새 출력 경로에서 한 번 재시도해 성공했습니다. 두 제작 시도 모두 없던 AccessVBOM 값을 임시 DWORD 1로 설정한 뒤 값 부재 상태로 정확히 복원했고 소유 Excel의 자연 종료를 확인했습니다. 저장한 XLAM의 VBA 7개 모듈·RibbonX 소스 대조도 PASS입니다. 첫 소스 audit의 oletools 누락 실패와 기존 문서 환경으로 재실행한 성공을 각각 기록합니다. 새 의존성을 설치하지 않았습니다.

BuildOnly 자체는 후보 기능 시험을 실행하지 않았습니다. 이후 첫 native 시도는 실제 StatusBar FAIL을 포함한 부분 실행 FAIL과 미완료로 종료했습니다. 별도로 기존 R12 UI 분리를 Workbooks 열거로 처리한 준비 결함을 확인했으며 메뉴 상태 간섭의 원인은 확정하지 않습니다. 정확한 이름의 Item으로 확인한 두 번째 실제 UI 한 흐름은 끝까지 완료했습니다. 담은 Alpha/Beta/Beta와 이전 확인 파일은 원본 한 Beta를 Gamma로 의도적으로 수정해도 유지됐습니다. 실제 기존 Replace 클릭 뒤 새 확인 파일에는 Gamma·서로 다른 값 3개·추가 개수 0개가 반영됐고, 요약 A14/B14의 전체 안내는 두 줄·14항목으로 보였습니다. 두 번째 native 전체 판정은 8개 typed globals 중 StatusBar만 String `FALSE`로 바뀌어 FAIL입니다. 이를 PASS로 바꾸지 않습니다.

후보 해시는 같고 cleanupErrors 없이 소유 Excel이 자연 종료했습니다. 기존 제품·Setup 파일 10개와 등록·신뢰 위치·보안·비교 설정은 보존됐으며 Options의 Pos 값은 원래 값 확인 후 그 값만 복원해 최종 기준 일치를 확인했습니다. 첫 native의 Pos 복구도 별도 PASS로 보존합니다. 기존 R12 설치·등록을 업그레이드·제거하지 않았고 영구 보안 설정을 바꾸지 않았습니다.

최신 배포조건 재분석·조정 요청에 근거해 개발 담당이 [ADR-0022의 좁은 평가 수용](docs/ADR-0022-R13-known-statusbar-evaluation.md)을 채택했습니다. 실제 StatusBar FAIL만 명시적 opt-in으로 수용하고 다른 전역·원본·이전 결과·보안·설치 보존·소유 정리·자연 종료는 계속 필수입니다. 최종 파일 게시나 회사 승인을 뜻하지 않습니다. 실제 후보·BuildOnly·저장 소스·소스 집중 13개·native 평가 기록의 해시 연결과 평가 수용을 대조했습니다. 기본 게이트는 실제 native FAIL을 거절하고 명시적 opt-in만 해당 FAIL을 수용했습니다. 실제 포장 명령은 T11 미실행 기록을 기대한 종료 코드 1로 거절했으며 출력 폴더·ISCC·설치를 시작하지 않았습니다. 이 결과는 패키징 성공이 아닙니다.

T11의 비공개 동일 후보 엔진 설치·비교·결과·제거는 별도 일반 사용자 Windows·Excel 환경에서 확인할 항목으로 NOT_RUN이며, 최종 EXE의 실제 설치도 NOT_RUN입니다. 기존 R12 공개 자산·다운로드와 [Draft PR #13](https://github.com/prozac0401/Workspace/pull/13)을 유지합니다. `fullAcceptancePassed=false`와 안정판 금지, 과거 실패·미실행을 유지하며 R12 한정 시험 생략 결정은 R13에 적용하지 않습니다.
