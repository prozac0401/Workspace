# Excel Smart List Compare 0.2.0 RC8

**선택한 셀들을 하나의 목록으로 읽고, 다음 목록과 비교하는 Excel 추가 기능입니다.**

2026-09-16: RC7 실기에서 발견한 취소 오류 전달과 설치 폴더의 제거 실행을 보완했습니다. 우클릭 메뉴는 열 때마다 현재 목록 상태로 구성하며, 실행 문구는 **두 번째 목록 담아 비교**입니다. [RC8 검증 기록](docs/RC8_COMPLETION_REPORT.md)과 [설계 결정](docs/ADR-0010-Cancellation-and-removal.md)을 확인하세요.

> **RC8은 Esc 실기 검사와 최초 대화형 설치 실패로 배포 보류 상태입니다.** 비교 2회는 취소되지 않고 지연 보호로 중단됐으며, 바꾸기 1회는 완료됐습니다. 설치는 같은 파일 재시도에서 성공했지만 최초 접근 거부 원인은 미확정입니다. 원본과 저장된 이전 결과는 보존됐습니다. 서명 없는 시험 후보이며 현재 판정은 [RC8 검증 기록](docs/RC8_COMPLETION_REPORT.md)을 따릅니다.

빌드용 VBA 프로젝트 접근은 승인된 임시 허용 후 원복했습니다. 일반 설치에는 이 권한이 필요하지 않습니다. RC5의 이전 문구 변경·제작 과정은 [RC5 기록](docs/WORDING_UPDATE.md)에 보존합니다.

## 1. 사용 흐름

첫 번째 목록을 선택하고 **[첫 번째 목록 담기]**를 누르세요.
이어서 두 번째 목록을 선택하고 **[두 번째 목록 담아 비교]**를 누르세요.

**목록**은 선택한 셀 전체, **항목**은 그 안의 값 하나입니다. 이름·메일주소·일반 텍스트를 모두 비교할 수 있습니다. 담긴 상태는 **첫 번째 목록: 42개 항목**처럼 버튼 옆과 상태표시줄에 표시합니다. 항목 수는 제외 규칙을 적용한 실제 비교값의 개수이며, 같은 값이 여러 셀에 있으면 각각 셉니다.

버튼은 Excel의 **추가 기능** 탭과 셀/행/열 및 표의 우클릭 **명단 비교** 메뉴에 둡니다. 비교 모드나 방향 선택은 없습니다. 이번 버전은 `Ctrl+Shift+M`을 자동 등록하지 않습니다.

| 첫 번째 목록 | 두 번째 목록 | 해석 |
|---|---|---|
| `B2:K2` | `D5:D14` | 가로 목록 ↔ 세로 목록 |
| `A3:A12` | `C8:L8` | 세로 목록 ↔ 가로 목록 |
| `B3:D8` | `H2:H19` | 사각형의 18셀 ↔ 세로 18셀 |
| `B2` | `H9` | 한 셀 ↔ 한 셀 |
| Ctrl로 선택한 여러 영역 | 다른 선택 범위 | 각각의 선택 전체가 하나의 목록 |
| 첫 번째 파일의 범위 | 두 번째 파일의 범위 | 같은 Excel 실행 세션 안에서 비교 |

**중요한 변경:** `A1:B20`도 두 목록이 아니라 **40셀짜리 목록 하나**입니다. 가로·세로·사각 범위를 지원하면서 두 열을 임의로 둘로 쪼개면 선택 의도가 모호해지므로, v0.1의 자동 두 열 분할을 없앴습니다. 항상 첫 번째 목록 담기 → 두 번째 목록 담아 비교로 진행합니다.

첫 번째 목록의 값은 메모리의 독립 스냅샷으로 보관합니다. 비교할 다른 파일을 같은 Excel에 열어 둔 뒤 첫 파일을 닫거나 그 파일의 내용을 나중에 바꿔도 이미 담은 첫 번째 목록은 변하지 않습니다. 같은 범위를 다시 실행해도 취소하지 않고 현재 값과 비교합니다. 담아 둔 목록을 없애려면 **첫 번째 목록 비우기**, 현재 선택으로 바꾸려면 **첫 번째 목록 바꾸기**를 사용합니다. 실패·경고 거절·취소 시 첫 목록을 유지하도록 처리합니다. 실제 취소 입력과 보존 확인 범위는 [RC8 기록](docs/RC8_COMPLETION_REPORT.md)을 따릅니다. 비교를 마치면 담긴 목록과 개수 표시를 비우고 **첫 번째 목록 담기**로 돌아갑니다.

현재 우클릭 **명단 비교** 메뉴는 열 때마다 첫 번째 목록의 유무를 확인합니다. 목록이 있으면 **두 번째 목록 담아 비교**, **첫 번째 목록: n개 항목**, **첫 번째 목록 비우기 / 바꾸기**로 내용을 구성하고, 없으면 **첫 번째 목록 담기**를 제공합니다. 실제 메뉴 표시의 확인 범위는 [현재 검증 기록](docs/RC8_COMPLETION_REPORT.md)을 따릅니다.

첫 번째 목록은 같은 Excel 실행 세션의 메모리에 보관하며, 독립 실행한 다른 `Excel.exe` 프로세스와는 공유하지 않습니다. 사용자는 파일을 각각 열거나 첫 파일에서 둘째 파일을 열어도 증상이 같다고 확인했습니다. 이 보고를 파일 열기 방식의 문제로 단정하지 않습니다.

## 2. 실제로 읽는 셀

필터에서 남은 셀과 수동으로 숨기지 않은 행·열의 셀만 읽습니다. 여기서 '보이는 셀'은 현재 모니터에 스크롤해서 보이는 위치라는 뜻이 아니라 **Excel에서 숨김 처리되지 않은 셀**이라는 뜻입니다.

- 여러 영역은 합쳐 하나의 목록으로 취급하고, 선택 영역이 겹쳐도 같은 셀 주소는 한 번만 읽습니다. 서로 다른 셀의 같은 값은 중복으로 셉니다.
- Excel Table 및 AutoFilter로 확인되는 제목 셀과 Table의 합계행 셀만 제외합니다. 같은 행의 다른 열에 있는 일반 데이터까지 제외하지 않습니다.
- 일반 범위의 첫 행을 임의로 제목이라고 추측하지 않습니다. 일반 범위는 제목을 빼고 선택해 주세요.
- 빈칸, 공백뿐인 값, 수식 결과 `""`는 제외합니다. 오류 셀은 별도 건수로 보고하며, 오류가 있으면 원본 전체가 완전히 같다고 표시하지 않습니다.
- 한 셀만 선택했을 때 주변 영역으로 확대해 읽지 않도록 별도 처리합니다.
- 병합 셀이 들어 있으면 해석을 추측하지 않고 중단합니다.

전체 행·열도 허용하되 `UsedRange`와 교차한 구간까지만 검사합니다. 서식 때문에 사용 범위가 부풀어 있으면 실제 값이 적어도 안전 상한에 걸릴 수 있습니다. 이때 원본을 자동 청소하지 않고, 작은 실제 값 범위를 다시 선택하도록 안내합니다.

## 3. 제한과 지연 경고

RC3의 실제 대용량·일반 Windows 설치 검증은 [검증 보고서](docs/WINDOWS_ROBUSTNESS_REPORT.md)를 따릅니다. 100,000셀은 안전 상한이며 모든 입력의 처리 완료를 보장하는 성능 수치가 아닙니다.

다음 숫자는 **보수적으로 정한 초기 운영 기본값**이며 Excel 실측 성능 보장치가 아닙니다. 설정 화면은 없고 개발 상수로 관리합니다.

| 조건 | 기본값 / 동작 |
|---|---|
| 한 목록의 가시 셀 수 | 100,000개까지. 초과하면 값 읽기 전에 중단 |
| 지연 경고 | 이번 선택 + 이미 담은 첫 번째 목록의 가시 셀 수 합계 20,000개 이상 |
| 가시 영역 조각 | 500개부터 경고, 5,000개 초과 시 중단 |
| 가시성 검사 대상 | `UsedRange`로 줄인 뒤 200,000셀부터 사전 경고, 2,000,000셀 초과 시 중단 |
| 한 셀의 텍스트 길이 | 4,096자 초과 시 전체 작업 중단. 잘라서 비교하지 않음 |
| 목록 전체 텍스트 길이 | 5,000,000자 초과 시 중단 |
| 처리 중 취소 | Esc로 취소 요청. 실제 입력·반복 시험 범위는 RC8 검증 기록 참조. Ctrl+Break 미실행 |
| 지연 보호 | 제어권이 돌아오는 체크포인트에서 활성 처리 약 30초를 넘으면 중단 |

셀 수 안전 상한은 빈칸·제목 등을 제외하기 **전**의 가시 셀 수입니다. 겹친 여러 선택 영역의 사전 계산은 보수적으로 중복 계산할 수 있으나, 실제 값 집계에서는 셀 주소를 중복 제거합니다.

값을 읽기 전에 크기/가시성을 먼저 확인합니다. 큰 스캔이면 가시성을 확인하기 전에도 경고합니다. 경고창의 기본 버튼은 **아니요**입니다. 확인 후에는 모드를 묻지 않고 같은 작업을 계속합니다. 실행 예상 시간을 임의로 '몇 초'라고 단정하지 않습니다.

30초는 하드 실시간 타임아웃이 아닙니다. `SpecialCells`, `Value2`, Excel의 내부 화면/시트 처리 같은 개별 COM 호출이 끝나기 전에는 VBA가 강제로 끊을 수 없습니다. 이 때문에 셀 수·조각 수·문자 수의 사전 제한도 함께 둡니다. 큰 목록은 범위를 나눠 실행하세요. [현재 취소 시험과 제한](docs/RC8_COMPLETION_REPORT.md)

## 4. 비교 규칙

| 첫 번째 목록 | 두 번째 목록 | 판정 |
|---|---|---|
| 숫자 `123` | 텍스트 `123`, `123.0`, `1.23e2` | 일치 |
| 텍스트 `00123` | 숫자 `123` | 불일치 |
| `USER@a.com` | `user@b.com`, `user` | 일치 |
| ` mailto:user@a.com ` | `user` | 일치 |
| `ＡＢＣ１２３` | `abc123` | 일치 |
| ` 홍길동 ` | `홍길동` | 일치 |
| `홍 길동` | `홍길동` | 불일치 |
| 텍스트 `1,234` | 숫자 `1234` | 불일치 |

정렬 순서는 무시하고 **비교키별 개수**를 비교합니다. `김철수 ×2`와 `김철수 ×1`은 다릅니다. 이메일 도메인을 버리므로 도메인만 다른 동일 ID는 같은 값으로 취급합니다. 이것이 같은 사람이라는 보장은 아니며 사용자가 요청한 비교 규칙입니다.

앞뒤 공백, 반복 공백, 탭/개행/NBSP, 일부 복사·붙여넣기에서 생기는 보이지 않는 문자, 전각 ASCII 영숫자 등을 정리합니다. 모든 Unicode 동등성을 판정하는 정규화는 아니며 한글 자모 분해/결합을 강제로 통일하지 않습니다. 표시 이름을 포함한 `이름 <user@domain>`이나 여러 주소가 담긴 셀은 이메일 주소 파서로 해석하지 않습니다.

값은 `Value2`로 읽습니다. 숫자 123을 셀 서식으로만 `00123`처럼 표시한 경우의 비교값은 123입니다. Excel이 이미 숫자를 반올림해 잃은 정밀도는 복구하지 않습니다. 긴 사번/ID는 원본부터 텍스트로 보관해야 합니다. 날짜/통화 서식의 의미를 추가로 추측하지 않습니다.

계산 중에는 실행을 거절합니다. 수식을 강제 재계산하지 않으므로 **수동 계산 모드에서 오래된 결과가 남아 있는 경우는 사용자가 계산 완료 후 실행**해야 합니다.

## 5. 결과 및 원본 보호

차이·중복·오류가 없으면 간단한 일치 안내만 표시합니다. 차이/중복/오류가 있으면 원본과 별개의 새 결과 통합문서를 만듭니다.

결과 열: 상태 / 비교키 / 첫 번째 목록 원본 예 / 첫 번째 목록 개수 / 두 번째 목록 원본 예 / 두 번째 목록 개수 / 첫 번째 목록 잔여 / 두 번째 목록 잔여 / 첫 번째 목록 주소 / 두 번째 목록 주소.

출처·항목 수·중복 및 제외 요약에도 같은 목록 이름을 사용합니다. 한쪽에만 있는 값은 **첫 번째 목록에만 있음 / 두 번째 목록에만 있음**으로 표시합니다.

출처 범위와 담은 시각, 빈칸/오류/제목·합계 제외 건수를 함께 기록합니다. 원본 예와 주소는 해당 비교키의 첫 번째 셀입니다. 개인정보를 클라우드로 보내거나 외부 서비스를 호출하지 않습니다.

이전 결과를 재사용해 덮어쓰지 않습니다. 결과는 자동 저장하지 않으며 필요하면 사용자가 저장합니다. 원본처럼 보이는 `=...` 텍스트가 결과 시트에서 수식으로 실행되지 않도록 텍스트 형식과 위험 접두문자 처리를 적용했습니다.

## 6. 설치/삭제 — 사용자와 제작자를 분리

### 단일 EXE 설치 프로그램

RC8 단일 EXE는 해당 버전의 XLAM과 설치 파일을 내장합니다. EXE를 실행하고 설치 버튼을 누르면 설치·업데이트하며, Windows 설정의 설치된 앱에서 제거할 수 있습니다. [설치 안내](docs/ONEFILE_INSTALLATION.md)와 [현재 검증 범위](docs/RC8_COMPLETION_REPORT.md)를 확인하세요. [기존 공개 릴리즈](https://github.com/prozac0401/Workspace/releases)와 로컬 RC8 후보를 구분합니다.

### 완성된 Release 폴더를 받은 사용자

1. 업무를 저장하고 Excel 창을 모두 닫습니다.
2. 압축을 풀고 `Install.cmd`를 실행해 설치를 확인합니다.
3. 이후 Excel을 열면 추가 기능 탭 및 우클릭 메뉴에서 사용합니다.

**RC6부터 업데이트는 새 Release의 Install.cmd만 실행합니다.** 설치된 RC1~RC6의 버전을 감지해, 한 번의 확인으로 이전 제품 파일과 자동 실행 등록을 제거한 뒤 새 버전을 설치합니다. 같은 버전은 다시 설치하고, 더 최신 버전·알 수 없는 기록은 보존합니다. 처리 가능한 설치 실패는 이전 파일·등록으로 복구하며 외부 동시 변경은 보존하고 경고합니다. 중단됐다면 Excel을 닫고 새 설치기를 다시 실행하세요. [설계](docs/ADR-0007-Replace-previous-installation.md)와 [현재 설치 검증](docs/CONTEXT_MENU_REPORT.md)과 [RC6 설치 설계 검증](docs/UPGRADE_REPORT.md)을 참고하세요.

삭제는 같은 패키지의 `Uninstall.cmd`, 또는 설치 폴더의 `Uninstall.cmd`를 실행합니다. 일상 사용에 Python/PowerShell 실행은 필요하지 않습니다. 설치/삭제 도구에는 Windows PowerShell이 필요합니다.

사용자별 설치 위치: `%LOCALAPPDATA%\ExcelSmartListCompare`.

**RC4부터 `Install.cmd` 더블클릭으로 설치 준비까지 처리합니다.** 실제 PC에서 `Restricted` 정책 때문에 RC3 실행이 차단된 후 수동으로 성공했던 절차를 포함했습니다. 사용자·컴퓨터 그룹 정책이 없고 유효 정책이 `AllSigned`가 아니면 같은 폴더의 `Setup.ps1` 한 파일의 다운로드 차단 표시를 해제하고, 설치 프로세스에만 `RemoteSigned`를 적용합니다. PowerShell 명령을 직접 입력할 필요가 없으며 제품 설치 확인창은 유지합니다. 실행 정책의 영구 설정은 바꾸지 않고, 해당 파일의 차단 해제는 유지됩니다.

그룹 정책이나 유효 `AllSigned` 설정이 있으면 파일 차단을 해제하거나 실행 정책을 낮추지 않고 기존 정책으로 실행합니다. `Uninstall.cmd`와 `Test_Excel.cmd`도 같은 준비를 거칩니다. [실행기 설계](docs/ADR-0005-Process-scoped-launchers.md), [RC4 검증과 제한](docs/WINDOWS_LAUNCHER_REPORT.md)을 확인하세요. 제작자용 `Build_Release.cmd`는 기존 절차를 유지합니다.

관리자 권한은 요구하지 않습니다. 설치는 해당 제품 경로를 HKCU의 Excel `Options/OPEN[n]`에 등록합니다. RC2부터 제품 폴더만 Excel 신뢰 위치로 자동 등록하며 하위 폴더는 제외합니다. 이 폴더의 파일은 매크로 알림 없이 실행될 수 있으므로 제품 파일만 보관하세요. 기존 사용자 신뢰 위치는 보존하고, 제거 시 자기 설치가 만든 변경되지 않은 항목만 삭제합니다. [설계와 요구 변경](docs/ADR-0003-Product-trusted-location.md), [RC2 검증 결과](docs/WINDOWS_TRUST_LOCATION_REPORT.md)를 참고하세요.

RC3는 XLAM과 새 설치 기록의 실제 저장 경로를 확인합니다. AppData가 별도 경로로 리디렉션되는 터미널에서는 기존 설치를 보존하며 종료 코드 6으로 중단합니다. 일반 Windows 파일 탐색기에서 `Release\Install.cmd`를 실행하세요. [경로 검증 설계](docs/ADR-0004-Physical-install-path.md)를 참고하세요.

설치·제거 중 Excel 프로세스를 만들지 않습니다. 제거 시 정확히 일치하는 자기 경로 등록과 소유 파일만 삭제하며 설치 폴더에 추가된 다른 파일은 남깁니다. 다른 추가 기능, `PERSONAL.XLSB`, 사용자 통합문서는 삭제하지 않습니다.

### 소스 패키지를 사용하는 제작자

소스 ZIP과 사용자용 Release ZIP은 별도입니다. 소스에서 시작하면 `Build_Release.cmd`로 먼저 제작합니다. `Install.cmd`는 완성 XLAM이 없는 패키지를 거절합니다. 빌드에는 Windows Excel과 허용된 VBA 프로젝트 접근 권한이 필요합니다.

권한이 허용되지 않은 환경에서는 빌드를 멈추고 이유를 안내합니다. 설치기가 `VBA 프로젝트 개체 모델에 대한 액세스 신뢰`, 모든 매크로 허용, PowerShell 실행 정책의 영구 설정을 바꾸지 않습니다. RC4의 실행 프로세스 한정 준비는 위 절차를 따릅니다. 신뢰 위치 변경은 사용자가 요청한 이 제품 폴더 한 곳으로 제한합니다. 조직 정책이 사용자 신뢰 위치를 차단하면 종료 코드 6으로 중단하며 우회하지 않습니다.

권장 배포 방식은 **승인된 개발 환경에서 제작자가 한 번 빌드 → 완성된 Release 폴더만 사용자에게 배포**입니다. 그러면 사용자는 VBA 편집기나 프로젝트 접근 권한을 건드리지 않고 설치 스크립트만 실행합니다. 단, `.xlam` 매크로 실행과 설치 스크립트 자체는 해당 조직의 허용 정책을 따라야 합니다. 회사 환경에 따라 서명/승인 배포가 필요할 수 있습니다. 무조건 무경고·무승인 설치를 보장하지 않습니다.

### 제작자 빌드

`Build_Release.cmd`를 실행합니다. 내부 작업은 다음과 같습니다.

- 새 정상 Excel 프로세스의 소유 PID를 확인하고 빈 추가 기능에 ASCII VBA 소스를 가져옵니다.
- XLAM 형식으로 저장·닫은 뒤 제품 메타데이터와 RibbonX 메뉴 정의를 기록하고, 저장한 파일을 다시 열어 버전과 정규화/Excel 통합 테스트를 실행합니다.
- 메뉴 등록 진입점을 확인합니다.
- 성공했을 때만 `dist/ExcelSmartListCompare.xlam` 및 사용자 배포용 `Release/` 폴더를 만듭니다.

`Release/EXCEL_TEST_RESULT.txt`에는 실제 빌드 PC에서 저장된 XLAM을 실행한 결과가 남습니다. 원시 계정·레지스트리 로그는 배포하지 않습니다.

`Test_Excel.cmd`는 이미 빌드하거나 설치한 추가 기능을 Windows Excel에서 테스트합니다. 보호 보기/매크로 차단/PowerShell 정책 등으로 실패할 경우 승인된 배포 절차를 사용해야 합니다. 전체 보안 수준을 낮추지 마세요.

## 7. 충돌 방지 원칙

`Application.OnKey`로 단축키를 자동 등록하지 않습니다. 기존 다른 매크로가 잡은 키를 덮거나, 해제 과정에서 다른 프로그램의 매핑을 날릴 위험을 피하기 위해서입니다. 키보드 실행이 필요하면 사용자가 Excel 빠른 실행 도구 모음에 본 기능을 한 번 등록해 Excel 자체 접근키를 사용하는 방식이 적합합니다.

컨텍스트 메뉴는 XLAM의 제품 고유 RibbonX ID로 등록합니다. 기존 도구 모음과 이전 제품 메뉴를 정리할 때는 자기 태그만 제거합니다. 메뉴 전체 초기화, 다른 추가 기능 해제, 전역 키보드 후킹, 별도 상주 프로세스, 포트 사용, 클립보드 변경을 하지 않습니다. 실행 중 재진입을 막고 Excel의 계산 모드를 바꾸지 않습니다.

Esc 입력을 받을 수 있도록 처리 중 키보드 입력을 유지하며 재진입은 차단합니다. 처리 중 원본이나 선택을 편집하지 말고 완료 또는 취소를 기다리세요. 결과 생성 중 잠시 바꾼 `ScreenUpdating`, `EnableEvents`도 오류/취소 경로에서 복원합니다. 상태표시줄은 마지막 표시가 본 도구가 쓴 내용일 때만 이전 내용으로 되돌립니다.

설치/삭제는 Excel이 열려 있으면 중단합니다. 사용자 Excel을 강제 종료하지 않습니다. 빌드·진단은 자신이 만든 Excel만 정상 종료합니다. 설치/삭제 중복 실행에는 전용 잠금을 사용합니다. 업데이트는 소유 파일 백업과 원자적 매니페스트 교체를 사용하며 실패 시 복원합니다.

Excel VBA 실행 후 기본 실행 취소(Undo) 기록 보존, 모든 타사 추가 기능과의 완전한 무충돌, 모든 Excel 버전에서 같은 체감 속도는 보장하지 않습니다. 현업 환경 실기 검증 항목에 포함했습니다.

**v0.1 제거:** 기존 v0.1을 `.xlam`으로 직접 등록했다면 먼저 그 추가 기능을 해제하세요. `PERSONAL.XLSB`에 직접 넣은 코드는 이 설치기가 임의로 지우지 않습니다. v0.1의 기존 `Ctrl+Shift+M` 등록도 v0.2가 가로채거나 초기화하지 않습니다.
