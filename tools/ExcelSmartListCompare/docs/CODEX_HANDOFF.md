# Windows 빌드·실기 검증 인계

상태: **R12 문구 교정 배포 · 기능 테스트 미실행** · 2026-09-21

현재 안내는 [R12 사용 안내](RC12_USER_GUIDE.md), 제작·게시 결과는 [R12 기록](RC12_RELEASE_REPORT.md)을 따른다. 비교 로직은 R11을 유지한다. R12의 기존 테스트 생략은 사용자의 명시적 요청과 [ADR-0020](ADR-0020-R12-wording-release.md)에 한정한다. 제작에는 `Invoke-IsolatedExcelCandidate.ps1 -BuildOnly -ExpectedReleaseVersion 0.2.0-rc.12`와 `package_r12.py`를 사용한다. 임시 VBA 접근은 명시적인 허용을 받은 경우에만 선택하며 제작 후 원복한다.

## RC10 당시 기준과 후속 검증 참고

- 제품 안내: [RC10 설치·사용](RC10_USER_GUIDE.md)
- 배포 파일·해시·게시 확인: [RC10 게시 기록](RC10_PUBLICATION_20260920.md)
- 실제 기능·화면 시험: [사용성 검증](USABILITY_RC10_REPORT.md)
- 설치·재시작·복원·취소의 판정: [전체 흐름 기록](RC10_END_TO_END_REPORT.md)
- 배포 결정: [ADR-0017](ADR-0017-RC10-publication.md), [고정한 검증 요약](../evidence/rc10/validation.json)

현재 소스는 이 저장소의 tools/ExcelSmartListCompare/src입니다. 로컬 ExcelE2E-* 폴더는 과거 시험 사본이며 현재 유지보수 소스가 아닙니다. 처음 받은 지시와 소스 ZIP은 [원본 보존 폴더](../archive/README.md)에 있습니다.

RC10의 XLAM은 실제 기능·UI 시험과 대조한 고정 파일입니다. 사용자 설치 패키지, 개발 소스, 검증 자료를 분리해 게시했습니다. 게시 성공을 설치 수명주기·실제 처리 중 취소·상태표시줄 형식 복원의 통과로 해석하지 않습니다. RC8·RC9의 기록은 당시 파일의 근거로 보존합니다.

## 후속 작업 순서

1. [제품 명세](../../../docs/tools/excel-list-compare/specification.md), [인수 기준](ACCEPTANCE_TESTS.md), 최신 검증 판정을 읽고 이번에 확인할 조건을 고릅니다.
2. UTF-8 VBA를 수정했다면 export_ascii.py로 가져오기용 소스를 동기화하고 Python 회귀를 실행합니다. 정적 검사와 실제 Excel 검사는 별도로 기록합니다.
3. 새로운 XLAM을 제작할 때는 이미 허용된 개발 환경 또는 별도로 승인된 개발 권한을 사용합니다. 제품 사용자의 보안 설정을 바꾸지 않습니다.
4. 시험 대상 해시를 고정하고 직렬화 VBA·RibbonX를 소스와 대조합니다. 동일 바이트로 기능·표시·취소·수명주기를 확인합니다.
5. Invoke-IsolatedExcelCandidate.ps1의 소유 프로세스·자원·기존 설치 사전 검사를 따릅니다. 사용자 Excel이나 문서를 종료하지 않으며 원시 기록은 artifacts 아래에만 둡니다.
6. 아직 확인하지 못한 실제 처리 중 취소, 상태표시줄 형식 복원, 단일 EXE·새 설치 수명주기는 결과를 확인한 뒤에만 판정을 갱신합니다. 도구 실패와 제품 실패, 소유 프로세스 정리와 정상 종료를 구분합니다.
7. 새 파일은 RC10의 고정 입력·배포 자산을 덮어쓰지 않고 새 버전·별도 경로로 제작합니다. 사용자 안내와 검증 자료를 나누고 소스·파일 해시·실행 결과·게시 결정을 연결합니다.

## 확인 범위

다른 Office 빌드·x86, 모든 추가 기능과의 공존, 조직 배포, 전원 손실과 코드 서명은 별도입니다. 과거 실패와 미실행 기록은 그대로 보존하고, 새 결과가 어느 파일과 환경에 해당하는지 적습니다.
