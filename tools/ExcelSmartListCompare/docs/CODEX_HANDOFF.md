# Windows 빌드·실기 검증 인계

이 폴더는 Excel 명단 비교 v0.2 소스입니다. README와 [Windows 실제 실행 보고서](WINDOWS_E2E_REPORT.md)를 먼저 읽으세요. Windows 실행기·안전장치 시험·수정은 진행했으나 VBA 접근 차단으로 XLAM과 설치 수명주기 검증은 미완료입니다. TEST_REPORT는 최초 Linux 작성 단계의 기록입니다.

## 목표

현재 비교 정책과 UX를 유지하면서 Windows Excel에서 컴파일·실행·설치·삭제를 검증하고, 최종 사용자가 `Install.cmd` 한 번으로 설치하는 완성된 `Release` 폴더를 제작합니다. 실제 승인된 배포 환경에서 필요한 코드 서명은 별도 절차로 수행합니다. 서명된 것처럼 가장하지 않습니다.

## 바꾸지 말 것

- 비교 모드/방향 선택 화면을 추가하지 않습니다.
- 모든 Selection을 하나의 명단으로 취급합니다. 두 열 자동 분할을 복원하지 않습니다.
- 가로↔세로, 부분 범위, 사각형, 다중 영역, 다른 통합문서, 가시 셀만 비교합니다.
- 값과 개수를 모두 비교하고 텍스트 앞자리 0은 보존합니다.
- 실패/취소에 A를 지우지 않고 원본을 수정하지 않습니다.
- 전역 단축키 자동 등록, 타 메뉴 초기화, 타 추가 기능 해제, 강제 프로세스 종료를 하지 않습니다.
- 매크로/PowerShell/VBA 접근 정책을 낮추거나 우회하지 않습니다.

## 작업

1. `src/*_utf8.*`를 기준으로 코드 검토합니다. Office 타입과 단일 셀/다중 Area의 실제 동작을 확인합니다.
2. 수정한 경우 `python tests/export_ascii.py`로 가져오기 파일을 동기화합니다.
3. Python 참조 테스트를 실행하되 이를 VBA 실행 성공이라고 보고하지 않습니다.
4. 권한이 허용된 Windows Excel에서 `Build_Release.cmd`를 실행합니다. 컴파일·통합 테스트 실패를 실제 오류에 맞춰 수정합니다.
5. `docs/ACCEPTANCE_TESTS.md`의 설치/삭제/오류복원/가시성/성능 경계를 실제 검증합니다.
6. 실측 결과에 따라 성능 상수만 보수적으로 조정할 수 있으나 변경 이유를 기록합니다. 예상 시간을 실측 없이 단정하지 않습니다.
7. `Release`에 완성 XLAM과 설치/삭제 스크립트 및 실제 테스트 결과를 넣습니다. 소스 빌드 권한을 최종 사용자에게 요구하지 않도록 합니다.

Windows Excel을 실행하지 못한 항목은 미검증으로 남깁니다. 모든 타사 추가 기능과 무충돌 또는 Undo 보존을 무조건 보장하지 않습니다.
