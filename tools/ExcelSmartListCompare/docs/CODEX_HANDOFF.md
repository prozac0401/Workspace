# Windows 빌드·실기 검증 인계

상태: 0.2.0 RC8 시험 후보, Esc 실기 실패로 배포 보류 · 2026-09-16. 현재 파일의 최종 판정은 [RC8 검증 기록](RC8_COMPLETION_REPORT.md)을 따른다. 오류 18 주입 검사의 PASS는 실제 키 입력 취소의 PASS가 아니다. 다음 수정은 물리 입력과 UI 도구 입력의 수신·처리를 구분하는 재현부터 시작한다.

## 후속 문구 교정 · 2026-09-17

Excel 화면·결과표·사용 안내와 설치·제거 문장을 한국어로 다듬었습니다. 표시용 문자열과 결과표 두 행의 높이를 바꾸었으며 비교·설치 기능은 유지합니다. 새 소스의 Python 검사와 설치기 컴파일 확인은 [문구 검수 기록](KOREAN_WORDING_REVIEW.md)을 따릅니다. **새 XLAM과 배포용 EXE는 만들지 않았습니다.** `RC8-Payload.json`과 기존 시험 파일도 갱신하지 않았습니다. 현재 소스와 과거 고정 입력의 해시가 달라지는 것은 의도된 상태이며, 새 파일을 제작·실행 검증하기 전에 고정 해시만 바꾸면 안 됩니다.

결과 요약의 `목록 남은 항목` 등 새 문구에 맞춰 실행 검사의 기대값을 바꿨지만 해당 Excel 검사를 이번에 실행한 것은 아닙니다. 승인된 개발 환경에서 XLAM 제작 후 결과표·안내 창의 줄바꿈과 실제 취소·설치·제거 검사를 이어가세요.

## 변경과 근거

RC7의 메뉴 구성은 유지한다. `getContent`는 메뉴를 열 때마다 현재 첫 번째 목록으로 내용을 만든다. RC8은 [실제 실패 기록](UNLOCKED_UI_REPORT.md)에 따라 오류 18 전달, 체크포인트의 취소 처리 재설정, 기본 상태표시줄 복원과 설치 폴더 CMD 제거 실행을 보완했다. [ADR-0010](ADR-0010-Cancellation-and-removal.md)에 근거와 한계를 기록한다. 최초 GUI 제거 접근 거부는 재현되지 않았으며 원인이 확정된 것으로 표시하지 않는다.

- 선택 전체를 한 목록으로 담고 다음 선택을 비교한다. 가시 값·중복 개수·텍스트 앞자리 0을 보존하며 원본과 이전 결과를 덮어쓰지 않는다.
- 같은 Excel 프로세스의 메모리 스냅샷을 공유한다. 모드 선택·두 열 자동 분할·전역 단축키·상주 프로세스를 추가하지 않는다.
- 설치 엔진은 Excel을 시작하지 않고 자기 LocalAppData 파일과 HKCU 등록을 관리한다. 조직 정책·AllSigned·외부 파일·알 수 없는 설치 기록은 보존한다.
- 설치 폴더의 CMD는 새 임시 복사본으로 실행 제어를 넘겨 자기 삭제 후에도 엔진 종료 코드를 반환한다. 복사본에는 업무 데이터가 없으며 TEMP에 남을 수 있다.

## 재검증 절차

1. 원래 명세, README, [추가 도구 개발 기준](../../../docs/policies/tools.md), 관련 ADR을 읽는다.
2. VBA UTF-8 소스를 수정하고 `python tools/ExcelSmartListCompare/tests/export_ascii.py`로 ASCII 가져오기 파일을 동기화한다.
3. Python 참조·실행기 검사와 실제 Excel 검사를 구분한다. `windows-context-menu-content.ps1`은 정상 시작, 8종 메뉴 내용, 창 전환과 비교를 검사하지만 실제 메뉴 클릭 증거가 아니다.
4. 승인된 개발 환경에서만 XLAM을 제작한다. 임시 VBA 접근 허용이 승인된 경우에도 Excel 종료 후 시작 전 상태를 확인한다. 설치 사용자에게 VBA 프로젝트 접근을 요구하지 않는다.
5. 실제 저장 파일의 VBA·RibbonX를 원본과 대조하고 같은 해시로 취소·자동 로드·재설치·제거를 검증한다. `windows-cancellation-propagation.ps1`과 `windows-status-checkpoint.ps1`은 소유한 개발 Excel 세션에서 메모리 안에만 검사 코드를 넣으며, 호스트가 원문·개발 권한·종료 후 파일 해시를 확인해야 한다.
6. `windows-onefile.ps1`은 설치·실패 복구·업데이트·제거·특수 경로·설치 폴더 CMD 자기 삭제를 검증한다. 기존 설치나 Excel이 있으면 실행하지 않는다. 시험 호스트 충돌과 제품 오류를 구분하고 분할 실행 시 그 사실을 기록한다.
7. 설치기 함수의 격리 회귀 23개와 신뢰 위치 23개는 실제 설치 수명주기와 별도로 기록한다. 업무 Excel을 강제 종료하지 않는다. 빌드 소유 프로세스만 별도 정리했다면 정상 종료로 바꾸어 기록하지 않는다.
8. RC8 포장은 `package-excel-wording-release.py --installer-version 0.2.0-rc.8`을 사용한다. 5개 VBA와 XML의 소스 해시, 설치기 해시와 실제 메뉴·취소 PASS가 필요하다. EXE는 `RC8-Payload.json`으로 입력을 고정한다. 최종 배포 후보는 실제 시험한 바이트여야 한다.
9. 문서 strict 빌드·생성 링크·ZIP 무결성을 확인한다. 사용자 경로·계정·레지스트리와 원시 진단은 로컬에 두고 공개 요약만 포장한다. 현재 작업은 로컬 결과물 제공이며 공개 게시 여부를 혼동하지 않는다.

## 별도 인수

다른 Office 빌드·x86, 물리 키보드 직접 입력·Ctrl+Break, 조직 배포, 전원 손실, 모든 추가 기능의 공존과 코드 서명은 별도다. 상태표시줄의 문자열 `FALSE`는 Excel 기본 False 표식으로 취급한다. 이벤트 비활성 시 기존 도구 모음 갱신 한계와 이전 실패 기록을 보존한다. 실행하지 않은 검사는 PASS로 표시하지 않는다.
