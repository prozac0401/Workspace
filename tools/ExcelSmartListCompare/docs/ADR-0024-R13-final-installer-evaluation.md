# ADR-0024 · R13 최종 설치 파일과 대표 비교로 평가 출시

상태: 채택 · 최종 설치·대표 비교·게시 미실행

날짜: 2026-10-04

결정 담당: 도구 개발·검증 담당

관련 요구사항·정책: [최초 명세](../../../docs/tools/excel-list-compare/specification.md)의 REQ-EXCEL-014~017, [R13 명세](../../../docs/tools/excel-list-compare/r13-specification.md)의 R13-01~03, [추가 도구 개발 기준](../../../docs/policies/tools.md), [정책 문서 작성 규칙](../../../docs/policies/documentation.md).

대체·대체됨 관계: [ADR-0021](ADR-0021-R13-focused-wording-evaluation.md)·[ADR-0022](ADR-0022-R13-known-statusbar-evaluation.md)의 단일 T11 설치→비교→제거 흐름을 평가 출시의 필수 근거로 삼는 조건과 [ADR-0023](ADR-0023-R13-current-account-trial.md)의 RC11 정확 원복 경로를 이번 동일 후보에 한해 아래 최종 EXE 설치·대표 비교·RC13 유지 경로로 부분 대체한다. ADR-0022 원문·StatusBar 예외와 실제 FAIL, 기존 T11 부분 실행·복구 기록은 수정하지 않는다.

## 맥락

사용자가 각 단계의 과도한 시험과 확인된 요구 없는 선제 복잡도 증가를 금지하고 현재 작업의 필수성을 재평가하도록 했다. 같은 RC13 XLAM의 새 안내·스냅샷 유지·실제 Replace 흐름은 이미 완료됐다. 제품 변경은 안내 한 줄과 버전이며 비교·설정·설치 엔진은 변경하지 않았다. 이를 반복하거나 전체 GUI·성능·취소·설치 suite를 다시 실행할 근거는 없다.

기존 T11은 공식 엔진 Upgrade·자동 로드·제거의 부분 실행을 남겼지만, 잠금 화면에서 대표 비교·결과는 실행하지 못했다. 후속 복구는 Codex LocalCache의 실행 view에서 확인됐다. 사용자가 일반 PowerShell로 실행한 읽기 진단은 실제 제품 폴더·5파일의 부재와 기존 관리 파일·OPEN·제품 신뢰의 보존을 확인했다. 이 환경 차이를 문구 패치 회귀나 native 설치 PASS로 해석하지 않는다.

사용자는 릴리스까지 진행하고 직접 설치·시험을 돕겠다고 했으며, 검증 후 현재 PC에 남길 버전으로 **최종 RC13을 설치하고 계속 사용**을 선택했다. 따라서 RC11 파일 복구→재업그레이드→제거→재복구를 실행하지 않는다. 최종 RC13의 정상 설치가 현재 설치를 정상화한 사실을 확인하는 경로로 복구 책임을 마친다. 이를 RC11 원복 완료로 표시하지 않는다.

## 결정

같은 XLAM SHA-256 `484419befa0cd763635b1f9592cff43bd13e657e19d5a693d76a78fa071ed14e`와 동결 제품 소스 7개를 유지한다. 완료된 BuildOnly·VBA 7개 모듈/RibbonX audit·집중 소스 13 PASS·새 안내/Replace·설정 보존·소유 종료 증거를 해시가 같은 범위에서 재사용한다. 후보를 다시 빌드하지 않는다.

1. 최종 EXE를 비공개 artifacts 아래 한 번 제작한다. 현재 소스·기존 실제 근거·이 결정의 해시·RC13 유지 선택을 연결한다. 이 준비는 설치·공개가 아니며 `publicationReady=false`다. T11 미완료를 PASS로 쓰지 않는다.
2. 사람이 일반 Windows에서 그 EXE를 설치한다. 정상 Excel 시작과 실제 설치 경로의 RC13 XLAM·버전·해시를 읽기 기록으로 연결한다. 설정·정책·다른 추가 기능은 보존한다. 보안 확인 화면은 사람이 판단하며 정책을 우회하지 않는다.
3. 합성 목록 Alpha/Beta/Beta와 Alpha/Beta/Gamma를 한 번 담아 비교한다. 각 목록 3개·제외 0개, Beta의 첫 목록 초과 1개와 Gamma의 둘째 목록 초과 1개가 결과에 나타나는지 확인한다. 합성 원본 보존, 소유 문서 정리와 Excel 정상 종료도 확인한다. 이미 완료한 새 안내·Replace 흐름은 반복하지 않는다.
4. 사람의 실제 관찰과 설치 경로의 읽기 기록을 최종 EXE·XLAM·소스 해시에 연결한다. EXE를 다시 제작하지 않고 같은 바이트의 ZIP·체크섬·검증 안내를 완성한다. 그 근거와 PR·문서 검증을 확인한 뒤 평가 prerelease로 게시한다.

전체 historical registry·파일 시각·SDDL 문자열의 완전 일치는 이번 문구 패치의 출시 필수조건으로 삼지 않는다. 원본 자료·사용자 비교 설정·다른 추가 기능·설치 소유권·정책 보존은 유지한다. 새 제품 파일·제거 관리 파일·제품 등록의 공식 설치 변경과 Office의 관찰된 외부 값은 구분해 기록하며 전체 레지스트리나 과거 값을 덮어쓰지 않는다. 보안·소유권의 의미 있는 차이나 설명하지 못한 변경은 무시하지 않는다.

## 검토한 대안

- RC11 먼저 복구한 뒤 전체 T11 재실행: 같은 파일을 반복 교체하고 제거·원복을 늘린다. RC13을 계속 사용하려는 현재 선택과 맞지 않는다.
- 비교·결과만 확인하고 기존 T11을 PASS로 변경: 실제 일반 Windows 설치 연결의 미확정과 부분 실행을 숨기므로 채택하지 않는다.
- 최종 EXE 설치·대표 비교 후 RC13 유지: 실제 배포할 동일 EXE를 확인하고 불필요한 제거·원복을 줄이므로 채택한다.

## 영향과 이행

이 결정은 서명 없는 `focused-wording-evaluation` prerelease에만 적용한다. `fullAcceptancePassed=false`, `stablePublishAllowed=false`를 유지한다. StatusBar Boolean False→String FALSE 실패의 좁은 수용과 공개 안내는 ADR-0022 그대로다. 안정판·회사 배포 승인이나 다른 환경 검증으로 확대하지 않는다.

기존 packager의 기본 T11 경로는 유지한다. 새 최종 설치 후보 준비와 실제 확인 후 완성을 구분하며 준비 파일만으로 공개 가능하다고 표시하지 않는다. Source/Verification 자산에 과거 82 PASS / 기존 기대값 1 FAIL / 스냅샷 누락 2 ERROR와 현재 T11 부분 상태를 보존한다. 개인 경로·레지스트리 값·ACL·진단·사람의 원시 답변은 비공개로 남긴다.

## 실패와 복구

설치 실패·정확한 후보 불일치·결과 오류·원본/설정/다른 추가 기능/정책 보존 실패·소유 종료 실패 시 게시를 중단하고 실제 상태를 남긴다. 자동 재설치나 제거·과거 설정 덮어쓰기를 수행하지 않는다. 설치가 현재 환경을 정상화하지 못하면 원래 제품 복구 책임은 남으며 관찰한 실패에 필요한 좁은 복구만 별도 판단한다. 업무 통합문서나 사용자 Excel을 강제 종료하지 않는다.

## 검증

필요한 자동 확인은 준비/완성 경계의 최소 방어, 실제 EXE·설치 XLAM·payload·소스·증거 해시 연결, 버전·ZIP 구성·체크섬·공개 범위, 문서 strict·관련 로컬 링크다. 제품 전체 suite와 완료된 native 흐름은 반복하지 않는다.

최종 EXE 실제 설치와 대표 비교는 아직 NOT_RUN이다. T11은 PARTIAL / NOT_RUN_INCOMPLETE로 보존하고 새로운 최종 설치 확인 결과와 분리한다. PR 병합·태그·GitHub Release·다운로드 갱신은 실제 자산과 필요한 결과가 갖춰진 뒤 진행한다.
