# ADR-0010 · 취소 오류 전달과 설치 폴더의 제거 실행

상태: 시험 구현, 실제 Esc 취소 실패로 배포 보류 · 날짜: 2026-09-16 · 결정 담당: 사용자 마무리 요청에 따른 제품 보완

관련 요구·정책: [RC7 실기 실패](UNLOCKED_UI_REPORT.md), [U03·P07·I07·I28](ACCEPTANCE_TESTS.md), [추가 도구 개발 기준](../../../docs/policies/tools.md). [ADR-0005](ADR-0005-Process-scoped-launchers.md)의 정책 준비와 [ADR-0009](ADR-0009-Single-file-installer.md)의 EXE·엔진 책임 구분을 유지한다.

## 맥락

RC7의 100,000셀 처리 중 UI 도구로 Esc를 입력했지만 비교가 완료된 사례가 있었다. 재시험에서도 취소 성공과 실패가 모두 관찰됐다. 정규화 함수의 `On Error Resume Next`는 문자열 변환뿐 아니라 Excel의 취소 오류 18도 무시할 수 있다. 설치 폴더에서 실행하는 CMD는 자기 파일과 현재 디렉터리가 삭제되면 이후 줄 실행과 종료 코드 전달에 실패했다. 최초 GUI 제거의 접근 거부는 재시험에서 재현되지 않았으므로 CMD 자기 삭제와 같은 원인으로 단정하지 않는다.

## 결정

- 순수 문자열 정규화에서 오류 무시를 제거한다. 선택 메타데이터의 선택적 COM 속성 조회에서도 오류 18은 상위 취소 처리로 전달한다. 화면 이벤트를 처리하는 체크포인트 전후에도 `EnableCancelKey`를 다시 설정한다. 전역 단축키·키보드 후킹·상시 키 감시는 추가하지 않는다.
- 시험의 COM 조회에서 기본 False가 문자열 `FALSE`로 관찰돼 그 표식도 Boolean False로 정리하는 방어 처리를 넣었다. Excel 자체와 PowerShell COM 변환 중 어느 쪽에서 문자열이 되었는지는 확정하지 않았다. 외부에서 의도적으로 미리 표시한 같은 문자열은 기본 표시로 복원될 수 있다는 제한을 기록한다. 상태표시줄의 이전 값이 Boolean이면 명시적인 `False`로 Excel에 제어를 돌린다. 이전 값이 사용자 문자열이면 그 값을 보존하고, 외부에서 바꾼 현재 문자열은 덮지 않는다.
- 같은 폴더에 설치 기록이 있는 `Uninstall.cmd`는 자기 CMD와 `Setup.ps1` 두 파일만 새 사용자 임시 디렉터리에 복사한 뒤 다른 배치 파일로 제어를 넘긴다. 복사본은 설치 기록을 갖지 않으므로 재복사하지 않는다. 기존 임시 경로가 있으면 덮어쓰지 않고 중단한다.
- 실제 엔진 실행 전 작업 디렉터리를 Windows 디렉터리로 옮긴다. 원래 폴더가 삭제돼도 종료 코드를 보관해 반환한다. 임시 실행 복사본은 남을 수 있으며 업무 데이터·설치 기록을 복사하지 않는다.
- 복사본에도 기존 실행 정책 준비를 적용한다. 그룹 정책·AllSigned를 존중하고, 허용된 경우 해당 `Setup.ps1` 한 파일만 준비한다. 사용자·컴퓨터의 영구 보안 설정은 변경하지 않는다.
- EXE 오류 안내는 설치와 제거를 구분하고 로컬 로그에 엔진 동작 이름을 남긴다. RC8은 새 XLAM·설치 엔진·실행기를 버전별 고정 해시로 포장한다. RC7 파일은 보존한다. RC8 배포 포장은 실제 메뉴·취소 검사의 PASS를 요구한다.

## 검토한 대안

키 입력을 전역 등록하거나 운영체제에서 상시 감시하면 다른 추가 기능과 사용자 단축키에 영향을 줄 수 있다. 현재 원인으로 확인한 오류 전달 경로를 먼저 보완한다. 실행 중인 CMD를 지운 뒤 남은 줄을 괄호 블록이나 CALL로 처리하는 방식은 실제 자기 삭제 시험에서 종료 코드가 깨져 채택하지 않았다.

## 영향과 이행

목록 비교 규칙, 메모리 스냅샷과 설치 기록 형식은 유지한다. 일반 사용자·HKCU 설치를 유지하며 RC7에서 RC8로 기존 교체 절차를 사용한다. 사용자용 설치에는 VBA 프로젝트 접근 권한이 필요하지 않다. 빌드 및 결함 주입 시험의 임시 개발 권한은 제품 설치 동작과 구분하고 원복 결과를 기록한다.

## 실패와 복구

복사·정책 준비에 실패하면 제거 엔진을 시작하지 않는다. 엔진의 실패 코드를 반환하며 다른 폴더나 추가 파일을 자동 삭제하지 않는다. EXE는 엔진 실패 시 관리 폴더와 앱 항목을 보존한다. 실제 검사에서 발견한 실패는 후속 성공 기록과 함께 남긴다.

## 검증

실제 Excel의 취소·목록 및 이전 결과 보존, 정확한 배포 해시의 메뉴·비교 회귀, 설치·업데이트·롤백·재설치·등록된 제거, 설치 폴더 CMD의 자기 삭제·오류 코드·한글 및 특수문자 경로·추가 파일 보존을 확인한다. 결과와 제한은 [RC8 완료 기록](RC8_COMPLETION_REPORT.md)을 따른다.

근거: Microsoft [EnableCancelKey](https://learn.microsoft.com/en-us/office/vba/api/excel.application.enablecancelkey)는 `xlErrorHandler`에서 사용자 중단을 오류 18로 전달한다. [On Error](https://learn.microsoft.com/en-us/office/vba/language/reference/user-interface-help/on-error-statement)의 `Resume Next`는 오류 다음 문장으로 계속 진행한다. [StatusBar](https://learn.microsoft.com/en-us/office/vba/api/excel.application.statusbar)는 `False`로 기본 표시를 복원한다.
