# RC9 · 임시 개발 접근 허용 후 제작·재검증

날짜: 2026-09-17 · 상태: **candidate-07 제한 평가판(LIMITED EVALUATION) 배포 결정. 전체 인수 NOT_MET, 실제 게시 확인 대기.**

사용자는 임시 VBA 프로젝트 접근과 후속 검증·릴리즈 작업의 자율 진행을 명시적으로 허용했다. 앞선 [RC7 오류 재실험](RETEST_20260917.md)의 허용 답변 대기는 해소됐다. 이 보고서는 승인 후 시작한 RC9 작업의 기록이며, RC7·RC8의 통과·실패 결과를 새 바이너리 결과로 사용하지 않는다.

후속 진단 충돌과 잔류 프로세스로 추가 설치 실기가 막힌 뒤, 사용자는 재시작·관리자 작업 없이 현재 가능한 상태를 릴리즈하도록 명시했다. [ADR-0015](ADR-0015-Limited-evaluation-release.md)에 따라 확인한 candidate-07 XLAM을 서명 없는 EXE·ZIP의 **제한 평가판 prerelease**로 준비한다. 전체 인수는 `NOT_MET`이고 raw StatusBar 복원 FAIL, 취소 PARTIAL, 자동 로드·전체 창/프로세스·새 EXE 수명주기 NOT_RUN과 환경 차단을 유지한다. 회사의 정식 도입·상용 승인과 구분하며 실제 파일 제작·게시는 별도 확인한다.

현재 RC9 `candidate-05`의 저장된 XLAM을 실제로 시험했다. 기본 용량 10가지와 대용량 3가지, 100ms 비교 취소는 확인했지만, 100ms 바꾸기는 취소되지 않고 100,000개로 교체됐다. 첫 바꾸기 시험의 호스트 비정상 종료 뒤 보조 코드를 보강해 재실행하자 시험과 Excel 종료는 완료됐지만 같은 취소 실패가 남았다. 새 릴리즈를 검증 완료로 표시하지 않는다.

후속 변경을 담은 `candidate-07`의 해시는 `61574c0f0acc68fb7b49507fa95c7201768515f4c5edfd563e3caf3915c19efc`다. 저장 전 코드 대조 5개와 저장된 파일의 직렬화 대조는 PASS지만 정상 Quit과 추가 15초 관찰 후에도 소유 Excel이 남아 빌드 전체 상태는 FAIL이다. 개발 접근은 복원됐고 수정 CMD로 설치한 파일의 해시도 일치했다. 이 파일의 실제 용량·선택·메뉴·보호 안내 결과는 아래에 따로 기록하며 candidate-05의 통과를 재사용하지 않는다.

적용 근거는 [원래 Excel 검증 지시](../../../CODEX_EXCEL_E2E_TEST_PROMPT.md), [추가 도구 개발 기준](../../../docs/policies/tools.md), [문서 작성 규칙](../../../docs/policies/documentation.md), [제품 명세](../../../docs/tools/excel-list-compare/specification.md)와 [인수 요구사항](ACCEPTANCE_TESTS.md)이다. 이 기록은 개발·검증 자료이며 공개 사이트에 추가하지 않는다.

## 허용 범위와 원복 계약

`tests/Build-ExcelCandidate.ps1 -ApprovedTemporaryVbaAccess`로 현재 사용자 Office의 `AccessVBOM` 한 값만 빌드 중에 임시 설정할 수 있다. 시작 전 존재 여부·형식·값을 기록하고, 빌드용 Excel을 종료한 뒤 원래 상태로 복원한다. 일반 사용자 설치에 이 개발 권한을 요구하지 않는다.

회사 정책·전체 매크로 허용·영구 PowerShell 실행 정책과 다른 추가 기능을 변경하는 권한으로 확대하지 않는다. 제품 설치·제거는 기존 소유권과 복구 계약을 유지한다. 테스트는 합성 자료와 소유 Excel만 사용하고 마지막에는 시작 전 설치 상태로 복원한다. 실행 호스트가 비정상 종료해 `finally`를 실행하지 못한 경우에는 불변 `access-before.private.json`을 근거로 해당 값의 실제 상태와 복원 여부를 따로 확인한다.

처음 허용은 실험을 진행할 권한이었고 후속 요청은 미완료 항목을 명시한 현재 파일의 평가용 배포 권한이다. 필수 인수 실패를 통과로 바꾸거나 서명·회사 배포 승인까지 받은 것으로 표시하지 않는다. 이미 허용된 임시 개발 접근을 다시 승인 대기로 분류하지 않는다. 현재 단계에서는 사용자의 원격 환경 제약에 따라 Excel·UAC·재시작을 추가 실행하지 않는다.

## 과거 실패와 이번 판정의 경계

RC7에서는 48자 고유값 각 20,000개가 끝까지 출력됐지만 각 50,000개 비교는 지연 보호로 중단됐다. 실제 Esc도 즉시 비교와 500ms 바꾸기에서 실패했고, 100ms·500ms 비교에서는 취소를 관찰했다. 기존 입력 100,000셀 상한은 정상 완료 보장이 아니었다. 이 내용은 이번 RC9 시험의 입력과 비교 근거이며 RC9 결과가 아니다.

candidate-05·07 시험 XLAM의 해시는 각각 고정했다. 사용자 요청에 따른 제한 평가판은 candidate-07의 관찰 범위·실패·미실행·원복 미완료를 함께 제공한다. 새 EXE·ZIP 해시와 실제 게시 여부는 별도 확정하며 포장 성공을 설치 실행 통과로 바꾸지 않는다. VBA 파일이 바뀌면 앞선 바이너리의 실기를 재사용하지 않는다.

2026-09-17: 사용자 허용 후 RC9 제작·재검증 기록을 분리했다. candidate-05·07의 실제 통과·실패와 진단 충돌을 보존했고, 추가 환경 복구가 불가능한 상태에서 현재 파일을 배포하라는 요청에 따라 제한 평가판을 결정했다. 전체 인수는 NOT_MET이며 실제 게시 확인은 대기 중이다.
