# Excel 명단 비교 R11 · 배포 후 사용자 검증

대상: **0.2.0-rc.11** · 이 문서는 사용자가 직접 따라 할 재현 절차와 기대 결과입니다. 아래 절차를 제공했다는 이유로 실제 검증을 완료한 것은 아닙니다. 배포 전 실행 결과는 [검증 기록](RC11_TEST_REPORT.md)에서 구분합니다.

업무 파일 대신 새 빈 통합문서에 예시 값을 입력하세요. 각 항목을 시작하기 전에 **첫 번째 목록 비우기 → 비교 설정 → 기본값으로 되돌리기**를 실행합니다. 문자 `00123`이나 `123.0`을 입력할 때는 해당 셀의 표시 형식을 먼저 **텍스트**로 바꿉니다. 오류 예시의 `=NA()`는 일반 셀에 수식으로 입력합니다.

결과는 `PASS / FAIL / NOT_RUN` 중 하나로 기록하고, 문제가 생기면 아래 기록 양식을 사용하세요. 작업이 너무 빨리 끝나 취소 입력을 하지 못했다면 취소 성공으로 적지 않습니다.

## 1. 설치와 두 설정 경로 · 약 3~5분

1. 업무 파일을 저장하고 Excel을 모두 닫습니다. R11 EXE를 실행해 설치합니다.
2. Excel을 열고 새 빈 파일을 만듭니다. **추가 기능 → 사용 안내**에서 `0.2.0-rc.11`을 확인합니다.
3. **추가 기능 → 비교 설정**과 **셀 우클릭 → 명단 비교 → 비교 설정**을 각각 엽니다.
4. 첫 경로에서 **대소문자 무시**를 체크한 뒤 두 번째 경로를 엽니다. 해제한 뒤 첫 경로도 다시 봅니다.

기대 결과: 두 경로에 메일 전체 주소·대소문자 무시·첫 목록 유지와 기본값 복원이 있고, 체크 상태가 서로 같습니다. 설정 메뉴를 열어도 결과 파일이나 첫 목록은 생기지 않습니다. 일반 설치에 관리자 권한·Python·VBA 프로젝트 접근 설정이 필요하지 않습니다.

## 2. 기본 비교와 동일 중복 · 약 2분

1. A1:A3에 `User@a.test`, `123.0`, `same`, B1:B3에 `User@b.test`, `123`, `same`을 입력합니다. A/B 열은 텍스트 형식으로 둡니다.
2. A1:A3을 선택해 **첫 번째 목록 담기**, B1:B3을 선택해 **두 번째 목록 담아 비교**를 누릅니다.
3. 새 비교로 A1:A2와 B1:B2를 모두 `a`, `a`로 바꾸어 같은 순서로 비교합니다.

기대 결과: 두 경우 모두 값·개수가 같다는 안내만 나오고 **결과 파일은 열리지 않습니다**. 비교 뒤 버튼은 **첫 번째 목록 담기**로 돌아옵니다. 원본과 다른 열린 파일은 바뀌지 않습니다.

## 3. 메일·대소문자 네 조합 · 약 3분

각 행마다 먼저 첫 목록을 비우고 해당 설정을 적용합니다. A1을 첫 목록, B1을 두 번째 목록으로 비교합니다.

| A1 / B1 | 전체 주소 | 대소문자 무시 | 기대 결과 |
|---|---|---|---|
| `User@a.test` / `user@b.test` | 꺼짐 | 꺼짐 | 차이 결과 생성 |
| 같은 두 값 | 꺼짐 | 켜짐 | 같음 안내, 결과 없음 |
| 같은 두 값 | 켜짐 | 꺼짐 | 차이 결과 생성 |
| 같은 두 값 | 켜짐 | 켜짐 | 도메인이 달라 차이 결과 생성 |
| `User@A.test` / `user@a.test` | 켜짐 | 켜짐 | 같음 안내, 결과 없음 |
| `ABC` / `abc` | 어느 쪽이든 | 꺼짐 / 켜짐 | 꺼짐은 차이, 켜짐은 같음 |

무시하기로 한 도메인·대소문자 차이 때문에 별도 **규칙으로 같아진 값** 시트가 생기지 않아야 합니다.

## 4. 숫자와 앞자리 0 · 약 2분

1. A1에 숫자 `123`, B1에 텍스트 `123.0`을 넣어 비교합니다.
2. A1을 숫자 `1000`, B1을 텍스트 `1E3`, 다음에는 `1e3`으로 바꾸어 비교합니다.
3. A1을 숫자 `123`, B1을 텍스트 `00123`으로 바꿔 비교합니다.
4. 대소문자 무시를 켜고 같은 순서를 반복합니다.

기대 결과: 1·2는 설정과 관계없이 같고 결과 파일이 없습니다. 3은 앞자리 0 때문에 다르며 차이 결과가 생깁니다. 숫자 정규화가 대소문자 옵션에 따라 달라지면 FAIL입니다.

## 5. 차이 결과의 개수·열 순서 · 약 2분

1. A1:A3에 `a`, `a`, `b`, B1:B2에 `a`, `c`를 입력합니다.
2. A1:A3을 담고 B1:B2와 비교합니다.
3. 결과 파일을 편집해 B1에 `이전 결과 보존`이라고 적어 둡니다. 파일은 닫지 않고 다른 비교를 한 번 더 실행합니다.

기대 결과: `명단비교_결과` 시트 하나에 8행 제목·9행부터 차이 3행이 나옵니다. B열 비교값, C열 첫 원문, D열 첫 개수, E열 둘째 원문, F열 둘째 개수, G/H열 남은 수, I/J열 대표 주소입니다.

| 비교값 | 첫 개수 D | 둘째 개수 F | 첫 남은 수 G | 둘째 남은 수 H |
|---|---:|---:|---:|---:|
| a | 2 | 1 | 1 | 0 |
| b | 1 | 0 | 1 | 0 |
| c | 0 | 1 | 0 | 1 |

새 비교가 기존 결과의 `이전 결과 보존` 값을 바꾸거나 파일을 자동 저장·닫으면 FAIL입니다. 첫 목록 유지가 꺼져 있으므로 성공 뒤에는 첫 목록 담기로 돌아와야 합니다.

## 6. 담은 뒤 설정 잠금 · 약 2분

1. A1에 `User@a.test`를 넣고 담습니다.
2. 두 경로의 **비교 설정**을 확인합니다. 메일 전체 주소·대소문자 무시·기본값 복원을 눌러 봅니다.
3. **비교 후 첫 목록 유지**는 켰다 끕니다.
4. **첫 번째 목록 비우기**를 누르고 설정을 다시 확인합니다.

기대 결과: 2의 세 항목은 비활성화되고 먼저 목록을 비우라는 안내가 있습니다. 3은 대기 중에 변경할 수 있습니다. 4 뒤에는 모든 항목을 바꿀 수 있으며 원본 셀은 그대로입니다. 담기·바꾸기·비교가 진행 중인 동안에는 모든 설정 변경을 막아야 합니다.

## 7. 선택적 첫 목록 재사용 · 약 3분

1. 기본값에서 **비교 후 첫 목록 유지**만 켭니다. A1:A2에 `a`, `b`를 넣어 담습니다.
2. **담은 목록 확인**으로 출처·개수 2개·담은 시각을 확인하고 확인용 파일을 닫습니다.
3. B1:B2에 `b`, `a`를 넣어 비교합니다. 원본 A1을 `수정됨`으로 바꾸고 B1:B2와 다시 비교합니다.
4. 유지 옵션을 끄고 B1:B2와 한 번 더 비교합니다.

기대 결과: 3의 두 비교는 모두 같고 결과가 없습니다. 첫 목록의 출처·개수·담은 시각은 바뀌지 않습니다. 원본 수정은 자동 반영되지 않습니다. 4의 비교가 성공하면 첫 목록을 비웁니다. 원본을 다시 반영하려면 사용자가 **바꾸기**로 새로 담아야 합니다.

## 8. 오류 제외와 유효 값 없음 · 약 2분

1. 일반 형식의 A1에 `a`, A2에 수식 `=NA()`, B1에 `a`를 입력합니다.
2. A1:A2를 담고 B1과 비교합니다.
3. 다시 A1을 담고 A2만 두 번째 목록으로 선택해 비교합니다.

기대 결과: 2는 결과 없이 **오류를 제외한 비교 대상이 같습니다**와 첫 목록 오류 1개·둘째 0개를 안내합니다. 3은 **비교할 값 없음**으로 안내하고 기존 첫 목록을 유지합니다. 오류만 있는 목록을 정상 일치로 표시하거나 자동으로 비우면 FAIL입니다.

## 9. 설정 기억과 기본값 복원 · 약 5분, 실제 재시작

1. 첫 목록을 비우고 옵션 세 개를 모두 켭니다. 임의의 첫 목록도 하나 담습니다.
2. 검증용 파일을 닫고 Excel 프로세스가 모두 종료되도록 정상 종료합니다. Excel을 다시 엽니다.
3. 두 설정 경로에서 체크 상태와 첫 목록 버튼을 확인합니다.
4. **기본값으로 되돌리기**를 누른 뒤 Excel을 다시 종료·실행합니다.

기대 결과: 3에서 옵션 세 개는 켜져 있지만 담긴 명단은 없고 **첫 번째 목록 담기**가 표시됩니다. 4 뒤에는 세 옵션이 모두 꺼져 있습니다. 같은 프로세스의 여러 창은 같은 설정을 보여야 합니다. 별도 프로세스는 시작 시 저장값을 읽으며 나중에 성공한 설정 저장이 다음 실행에 적용됩니다.

## 10. 선택·창·화면 조합 · 약 10~20분, 후속 범위

1. 같은 `a,b,a` 목록을 가로·세로·2차원·Ctrl 다중 범위에 배치하고 순서를 바꾸어 비교합니다. 겹쳐 선택한 같은 셀은 한 번만 셉니다.
2. 값이 다른 행·열을 숨기거나 필터로 제외하고 보이는 값끼리 비교합니다. 표 제목·합계와 옆의 일반 셀을 구분합니다.
3. 같은 Excel의 두 파일·여러 창에서 담기와 비교를 나누어 실행합니다. 첫 파일을 닫고 다른 파일의 두 번째 목록과 비교합니다.
4. 일반 셀·행·열·표, 일반 보기·페이지 레이아웃, Windows 배율 100%·150%에서 우클릭 메뉴와 설정을 확인합니다. 키보드로 메뉴를 이동합니다.

기대 결과: 순서·방향과 관계없이 전체 값별 개수가 일치하면 결과가 없습니다. 숨김·필터·표 제목·합계는 제외하며 제목 옆 일반 셀까지 제외하지 않습니다. 창을 바꾸어도 담긴 목록과 옵션이 같고 원본 닫기 후에도 비교됩니다. 메뉴가 중복되거나 잘리지 않고 비활성 항목과 현재 체크값을 구분할 수 있어야 합니다.

## 11. 실제 취소·바꾸기 취소 · 약 10~20분, 후속 범위

1. A1:A42에 `기준`을 넣어 담습니다. 비교 설정과 42개 항목 상태를 기록합니다.
2. B1:B100000에 서로 다른 약 48자 텍스트를 준비합니다. 예: 일반 셀 B1에 `=REPT("x",42)&TEXT(ROW(),"000000")`를 넣고 아래로 채웁니다. 계산 완료 후 진행합니다.
3. B 범위 비교를 시작하고 큰 선택 경고는 **예**로 진행합니다. 실제 읽기·비교·결과 작성 중 **작업 취소** 또는 Esc를 누릅니다.
4. **첫 번째 목록 바꾸기**에도 같은 입력을 적용합니다. 짧게 누르기와 약 0.5초 유지하기를 따로 기록하고, 첫 목록 유지 옵션을 끈 상태·켠 상태에서 확인합니다.

기대 결과: 확정 전에 실제 취소됐다면 취소 안내, 이전 42개·출처·시각·규칙 보존, 이번 미완성 결과 정리가 확인됩니다. 원본과 기존 결과는 유지해야 합니다. 시간 초과는 취소 성공이 아닙니다. 완료 후 입력한 경우는 완료로 기록합니다. 입력 후 응답까지 걸린 시간과 실제 최종 상태를 함께 남기며 즉시 취소를 보장한다고 판정하지 않습니다.

## 12. 대용량 시간·메모리 · 약 20분 이상, 후속 범위

한 목록씩 1,000·20,000·100,000셀로 아래 세 입력을 만듭니다. 텍스트는 약 48자로 맞추고 계산을 마친 뒤 비교합니다. 경고창을 읽고 응답한 시간은 처리 시간에서 분리합니다.

| 입력 | 재현 방법 | 기대 결과 |
|---|---|---|
| 같은 값 반복 | 두 목록을 동일 문자열로 채움 | 완료하면 같음 안내만, 결과 없음 |
| 고유값이 같고 순서만 다름 | 첫 목록은 x000001…x100000, 둘째는 역순. 앞에 x를 반복해 길이 맞춤 | 완료하면 같음 안내만, 결과 없음 |
| 고유값이 모두 다름 | 첫 목록 x 접두사, 둘째 y 접두사 | 완료하면 목록당 N개일 때 차이 2N행 |

각 경우 담기·비교·출력 시간과 작업 관리자에서 관찰한 Excel 메모리 최대값을 기록합니다. 가능하면 RC9·RC10도 같은 PC·입력으로 각각 비교합니다. 한 버전씩 사용하고 동시에 로드하지 않습니다. 100,000셀 상한 안에서도 시간 제한으로 중단될 수 있으므로 정상 완료와 보호 중단을 구분하세요. 보호 중단에서는 이전 첫 목록·원본·이전 결과가 유지돼야 합니다. 측정 없이 빨라졌다고 판정하지 않습니다.

## 13. 업데이트·재설치·제거와 정책 · 약 15~30분, 후속 범위

1. 기존 RC9 또는 RC10이 있는 검증용 PC에서 파일·버전·다른 추가 기능과 설정을 기록하고 R11로 업데이트합니다.
2. Excel 정상 시작과 R11 사용 안내·메뉴를 확인합니다. Excel을 닫고 같은 EXE로 재설치한 뒤 다시 확인합니다.
3. 검증용 제품 폴더에 별도 파일 `사용자보관.txt`를 만들고 Windows 앱 설정에서 제거합니다. 업무 파일·다른 추가 기능·그 별도 파일이 남는지 확인합니다.
4. Excel을 다시 열어 제품 메뉴가 없어졌는지 확인합니다. R11 재설치 후 이전 비교 설정이 남는지도 확인합니다.
5. 별도 검증 PC에서 열린 Excel, 회사 정책 차단, 설치 폴더 쓰기 거부 조건을 각각 시험합니다. 일반 업무 PC의 보안 정책은 검증을 위해 바꾸지 않습니다.

기대 결과: 설치 버전과 실제 로드 버전이 R11이고 메뉴가 한 세트만 보입니다. 열린 Excel을 강제로 닫지 않고 설치를 중단합니다. 제거는 제품이 관리하는 변경되지 않은 파일·등록만 정리하며 별도 사용자 파일과 비교 설정을 보존합니다. 거부·오류 때 이전 설치를 잃거나 성공으로 안내하면 FAIL입니다.

## 14. 상태표시줄 원래 상태 · 약 3분, 후속 확인

1. 새 검증용 Excel에서 아무 작업도 하기 전 하단 상태표시줄을 기록합니다.
2. 담기·일치 비교·차이 비교·비우기를 각각 실행하고 끝난 뒤 상태표시줄을 봅니다.
3. VBA 즉시 창 사용이 가능한 검증 환경이라면 실행 전후에 `? TypeName(Application.StatusBar), Application.StatusBar`를 기록합니다. 기본값을 시험할 때는 `Application.StatusBar = False`로 둔 뒤 즉시 다시 읽은 값도 함께 기록합니다.

기대 결과: 작업이 끝난 뒤 이전 상태의 값과 자료형이 보존됩니다. 원래 Boolean False였는데 String `FALSE`가 남으면 FAIL입니다. 설정 직후부터 String으로 읽히면 제품 작업 전 환경 동작과 제품 실행 후 결과를 나눠 기록합니다. 기존 RC9·RC10에서 관찰한 문제가 있으므로 R11에서도 실제 결과를 확인하기 전에는 해결됐다고 보지 않습니다.
