# RC9 · 설치 실행기와 진단 검증

날짜: 2026-09-17 · 상태: **실행기 회귀 통과. 이 기록만으로 RC9 실제 설치 인수 완료를 판정하지 않는다.**

## 이전 실패에서 확인한 사실

[RC8 최종 기록](RC8_COMPLETION_REPORT.md)의 첫 대화형 설치 로그는 `SLC_ENGINE_ACTION=Install` 후 약 2.4초에 `Access is denied.`를 출력하고 코드 5를 반환했다. 설치 본체의 오류 스택 출력은 없다. 완성된 XLAM을 설치하는 기존 `Install` 경로에는 명시적인 코드 5 반환이 없다. 별도의 `Build` 경로는 VBA 접근이 차단되면 코드 5를 반환하므로 두 작업을 구분한다. 제품·관리 폴더와 앱 등록은 남지 않았으며 같은 EXE 재시도는 성공했다.

이 사실은 CMD가 시작하는 Windows PowerShell 호스트 단계의 실패 가능성을 뒷받침한다. 하지만 당시 단계 표식과 자원 사용 기록이 없어 실행 파일 선택, 호스트 시작, 보안 제품, PC 부하 중 원인을 확정하지 못했다. 현재 실행 도구에서도 기본 호스트 시작이 접근 거부로 실패하고 명시적 Windows PowerShell 경로가 동작한 이력이 있지만, 두 문제가 같은 원인이라는 증거는 아니다.

## 변경

[ADR-0012](ADR-0012-System-PowerShell-launcher.md)에 따라 세 CMD 실행기는 Windows PowerShell 시스템 경로를 명시한다. EXE의 로컬 설치 로그에는 준비·본체의 시작과 종료, 설치 거래 단계, 예외 형식·HRESULT를 남긴다. 일반 CMD에는 진단을 별도로 켠 경우만 추가 표식을 출력한다. 원래 종료 코드를 유지하며 자동 재시도, ACL·그룹 정책·영구 실행 정책 변경은 추가하지 않았다.

`Setup.ps1`의 설치기 버전은 `0.2.0-rc.9`다. 현재 문구와 실행기 변경은 기존 RC8 바이너리에 포함된 것으로 간주하지 않는다. `RC8-Payload.json`은 변경하지 않았다.

## 실제 실행 결과

Windows PowerShell 5.1을 사용하는 합성 프로세스 시험이다. 실행기의 자식 프로세스 안에서 실제 버전이 `5.1.*`이고 실행 파일이 시스템 Windows PowerShell인지 단언한다. 외부 작업 도구에 지정한 셸 이름만으로 실행 환경을 추정하지 않는다. 실제 설치·Excel 실행은 하지 않았다. 테스트용 파일과 로그는 저장소의 로컬 `artifacts` 아래에만 둔다.

| 검사 | 실제 결과 |
|---|---|
| 실행기 Python 회귀 | PASS. 8개 테스트, 30.609초 |
| Restricted 프로세스와 다운로드 표식 | PASS. 세 실행기의 자기 Setup 파일만 차단 해제, 부모·영구 정책 보존, STA·작업 인자·종료 코드 0/2/37 전달 |

| Setup 누락·차단 해제 실패 | PASS. 준비 단계 실패 후 본체 미실행 |

재현 명령:

```powershell
python -m unittest discover -s tools/ExcelSmartListCompare/tests -p test_launchers.py -v
```

통과 원시 기록: `artifacts/excel-rc4-launchers/ec8f5f87/`. 앞선 `acad4a48/`도 8개 검사를 30.021초에 통과했으며, 최종 실행은 실제 자식 호스트 확인을 추가한 결과다. 경로의 `rc4`는 기존 실행기의 증거 폴더 이름이며 RC4 바이너리를 검사했다는 뜻이 아니다.

첫 실행 `artifacts/excel-rc4-launchers/331de5b4/`의 잠금 보호 두 하위 경우는 오류 문구 단언이 실패했다. 실제 종료 코드 4와 단계 표식은 정상이었다. Windows PowerShell이 긴 시험 경로를 포함한 오류 문장을 한국어 단어 중간에서 줄바꿈했기 때문에, 검사의 공백·줄바꿈 처리만 보완했다. 실패 원시 기록은 보존한다.

## 남은 구분

이 회귀 성공은 RC8의 간헐적 접근 거부 원인 해결 증거가 아니다. 새 XLAM·설치 파일의 고정 해시로 실제 일반 사용자 설치, 재설치, 제거, 새 설치 반복, GUI 동작을 확인해야 한다. 현재 기록은 64비트 호출 환경의 실행기 검증이며 32비트 호출에서 Sysnative 선택은 아직 실행하지 않았다. 실제 EXE 포장·설치 결과와 최종 배포 판정은 후속 완료 보고서에 기록한다.
