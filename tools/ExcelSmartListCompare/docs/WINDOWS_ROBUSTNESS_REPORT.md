# Excel RC3 · 실제 Windows 강건성 검증

실행: 2026-09-14~15 KST · 제품 엔진: 0.2.0 · 설치기: 0.2.0-rc.3 · 평가용 후보

## 실행 범위와 수정

Windows 11 Pro 10.0.22631, Excel 16.0.20326.20144 x64, Windows PowerShell 5.1.22621.6133의 실제 데스크톱 Excel에서 시험했다. 합성 통합문서와 명시적으로 생성한 Excel 프로세스만 사용했다. 기존 업무 파일, 다른 추가 기능, 전역 매크로·회사 정책·AccessVBOM·PowerShell 실행 정책을 변경하지 않았다.

RC3는 파일 핸들의 실제 설치 경로를 검사한다. 실행 호스트의 AppData/HKCU 리디렉션 때문에 일반 Excel이 설치한 XLAM을 찾지 못하는 문제를 실제로 확인했기 때문이다. 경로가 다르면 코드 6으로 중단하고 기존 설치를 되돌린다. 자세한 결정은 [ADR-0004](ADR-0004-Physical-install-path.md)를 따른다.

VBA는 RC1에서 실제 Windows Excel로 빌드한 검증 바이너리를 그대로 사용했다. 이번 수정은 설치기와 시험·문서이며 VBA를 재빌드했다고 표시하지 않는다. XLAM SHA-256은 `c6f55886c368294c4e21396366d0cf3c368605e965f3ca2bd153f2e75bc8ae86`이다.

## 일반 Windows 데스크톱 실제 시험

같은 SID·세션만으로 실행 환경이 같다고 간주하지 않았다. 일회성 현재 사용자 예약 작업(Interactive, Limited, 자동 실행 트리거 없음)으로 일반 데스크톱 환경에서 설치·실행했다. 이 작업은 시험 실행용이며 제품에 예약 작업이나 자동 시작 기능을 추가하지 않는다.

시간 초과 알림은 실제 캡처했다. 이번 Esc 입력 후 캡처는 이미 후속 비교로 넘어가 취소 알림 자체를 새로 촬영하지 못했다. Esc 입력 기록과 독립 결과 검사를 근거로 판정했고, 퀵가이드의 기존 취소 알림 사진은 RC1 실제 촬영본임을 유지한다.

## 추가 실제 Excel 경계값·반복 시험

아래 14개 성공 사례는 리디렉션된 실행 호스트에서 정상 시작한 실제 Excel로 수행했다. 동일 XLAM의 런타임 기능 증거이며 일반 데스크톱 설치 증거와 구분한다. 테스트 중 나타난 경고는 실제 화면을 읽고 응답했다.

| 사례 | 실제 결과 |
|---|---|
| 보이는 19,999셀 | 정확한 기준 건수 저장 |
| 보이는 20,000셀 경고 거절 | 기본 ‘아니요’ 확인, 기준 유지·후속 비교 정상 |
| A 15,000 + B 5,000 합산 경고 거절 | 기준 유지·부분 결과 없음 |
| 보이는 100,000셀 | 경고 수락 후 정확한 기준 건수 저장 |
| 보이는 100,001셀 | 상한 오류와 기준 유지·후속 비교 정상 |
| 500개 불연속 영역 | 경고 거절 후 기준 유지·후속 비교 정상 |
| 5,001개 불연속 영역 | 상한 오류와 기준 유지·후속 비교 정상 |
| 200,000셀 탐색 규모 | 경고 거절 후 기준 유지·후속 비교 정상 |
| 2,000,001셀 탐색 규모 | 상한 오류와 기준 유지·후속 비교 정상 |
| 한 값 4,096자 / 4,097자 | 4,096자 결과 보존 / 4,097자 거절·기준 유지 |
| 한 명단 5,000,000자 / 5,000,001자 | 허용값의 결과·건수 확인 / 초과값 거절·기준 유지 |
| 50회 연속 비교 | 50회 결과와 설정 검사, 최초 결과의 사용자 편집 보존. 총 약 206.8초 |

각 성공 사례에서 Excel 설정과 저장 원본의 해시를 확인했다. 개별 문자열 4,096자 시험 약 9.18초, 500만 자 시험 약 12.93초는 해당 시험의 호출·검증 구간 수치이며 일반 성능 SLA가 아니다. 경고 응답 대기 시간은 다른 사례의 총 시간에 포함되므로 계산 성능으로 제시하지 않는다. 50회 시험의 관측 메모리는 약 391~456MB 범위였으며 장기간 누수 부재를 증명하지 않는다.

## 설치 보호·보조 검증

- 실제 Windows CMD 보호 시험 11/11: Excel이 열린 상태의 설치·제거·빌드·시험 거절과 PID 보존, 동시 설치 잠금, 반복 제거, 누락된 XLAM 처리.
- 제품과 분리된 HKCU 가지에서 신뢰 위치·롤백 시험 23/23. 기존 위치, 외부 수정, 정책 거절, 설치 도중 오류, 구형 설치 기록을 포함한다.
- 실제 리디렉션 환경의 RC3 설치 시 코드 6, 이전 RC2 소유 파일 해시 보존 확인. 이후 그 환경의 시험 설치 제거 및 추가 합성 파일 보존 확인.
- Windows PowerShell 5.1 파서 검사 통과. 기존 Python 참조 시험 53/53은 보조 검사이며 실제 Excel 검증을 대신하지 않았다.

일반 데스크톱 수명주기·원복은 2026-09-15 01:41:51 KST에 완료했다. 시험에서 바뀐 Excel 창 위치는 기존 값으로 복원했고, 별도 실행 호스트의 프린터 이름 값도 초기 기록과 맞췄다. 보안·다른 추가 기능 범주는 전체 비교에서 일치했다. 임시 예약 작업과 시험용 Explorer 탭을 정리했으며 기존 Explorer 프로세스는 종료하지 않았다.

## 실패한 시도와 해석

이전 두 프로세스 시험은 일반 Excel이 실행 호스트의 설치 파일을 찾지 못해 VBA 실행 전에 실패했다. 일반 데스크톱 설치 후 두 프로세스 시험을 다시 수행해 통과했다.

시험 코드에서도 열린 파일의 공유 읽기, PowerShell의 Range 반환값 자동 열거, 배열 COM 전달, PS5 JSON 배열 및 종료 코드 해석 문제가 있었다. 실패 기록은 보존하고 별도 경로에 재시험했다. 대용량 재시험은 Excel 수식으로 결정적인 합성 값을 생성하고 첫값·끝값을 검사한 후 실행했다. 제품 입력은 계산된 문자열 값이다. 시험 코드 오류를 VBA 실패나 통과로 바꾸지 않았다.

최초 최대 차이 출력 시험은 시간 초과로 실패했다. 나중에 통합문서를 닫은 뒤 읽은 UI 문구만으로 기준 보존을 확정할 수 없어, 일반 Excel에서 중단 직후 기준을 직접 검사하는 별도 시험으로 다시 확인했다.
