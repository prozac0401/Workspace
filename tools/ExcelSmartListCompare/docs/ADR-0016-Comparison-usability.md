# ADR-0016 · 비교 전 확인과 결과 근거를 보여 주는 사용성 개선

상태: 채택 · 차기 소스 후보 0.2.0-rc.10의 구현 기준. 현재 공개 RC9에 반영된 기능으로 표시하지 않음

날짜: 2026-09-19

결정 담당: 도구 개발·검증 담당

관련 요구사항·정책: [제품 명세](../../../docs/tools/excel-list-compare/specification.md)의 REQ-EXCEL-018~024, [추가 도구 개발 기준](../../../docs/policies/tools.md), [정책 문서 작성 규칙](../../../docs/policies/documentation.md), [인수 요구사항](ACCEPTANCE_TESTS.md)

대체·대체됨 관계: 기존 비교·원본 보존·설치 계약을 유지한다. 차기 소스 후보에서 비교 성공 후 첫 목록 자동 비우기와 일치 안내만 표시하는 동작을 아래 결정으로 변경한다. [ADR-0015](ADR-0015-Recorded-release-results.md)의 공개 RC9 배포·검증 판정은 대체하지 않는다.

## 맥락

현재 공개 RC9는 첫 목록의 항목 수만으로 다른 파일의 어떤 범위를 언제 담았는지 확인하기 어렵다. 제외된 오류와 중복 값의 모든 위치를 제공하지 않으며 결과에 나온 원래 값 하나만으로 공백·대소문자·메일 주소 규칙 때문에 같아진 값을 구분하기 어렵다. 비교가 끝나면 첫 목록이 비워져 같은 기준 목록을 반복해서 담아야 한다. 차이가 없는 경우 결과 파일이 없어 비교 근거를 저장할 수 없다.

대용량 입력 안내의 단순 분할 권고도 수정해야 한다. A가 a,b이고 B가 b,a이면 전체 비교는 같지만 각 목록을 첫째 행과 둘째 행으로 나누어 비교하면 차이가 나온다. 순서를 무시하는 전체 개수 비교 계약에서 임의 행 분할은 올바른 대안이 아니다.

사용자는 도출한 사용성 개선을 순차적으로 구현하고 시험·적용하도록 요청했다. 이 결정은 소스 변경을 허용하는 범위이며 새 XLAM·설치 파일의 제작·실기·게시 완료를 뜻하지 않는다. [현재 RC9 검증 기록](RC9_APPROVED_RETEST_20260917.md)의 취소 PARTIAL, 상태표시줄 복원 FAIL과 새 EXE 수명주기 미검증은 해당 파일의 사실로 유지한다.

## 결정

### 비교 전에 기억한 목록을 확인한다

- **담은 목록 확인**은 파일·시트·선택 범위·담은 시각·유효 항목 수·제외 집계와 값 표본을 새 확인용 통합문서로 보여 준다. 확인용 문서는 비교 결과와 구분하며 첫 목록 상태를 바꾸지 않는다.
- 확인은 저장된 스냅샷을 사용한다. 원본이 바뀌거나 닫혀도 다시 읽지 않으며 실제 업무 파일을 수정하지 않는다.
- 비교 규칙 요약을 담기·확인·결과의 적절한 위치에 표시한다. 메일 주소의 도메인 제외와 숨김·필터·오류 제외를 원본 전체의 완전 일치로 오해하지 않게 한다.
- 같은 첫 목록으로 두 번째 목록을 바꿔 반복 비교할 수 있게 한다. 비우기·바꾸기는 명시적인 명령으로 제공하고 Excel을 종료하면 목록이 사라지는 경계는 유지한다.

### 결과를 요약과 근거로 나눈다

- 일치하는 경우에도 새 결과 통합문서를 만든다. 기존 원본·결과를 덮어쓰지 않고 저장은 사용자가 선택한다.
- 시트는 **요약**, **차이·중복**, **제외·발생위치**, **규칙으로 같아진 값**으로 나눈다. 요약은 차이·중복·제외의 핵심 개수, 비교 출처·시각, 비교 규칙과 상세 시트 안내를 먼저 보여 준다.
- 오류는 제외 이유와 위치 표본을 표시한다. 중복은 값별 개수와 발생 위치 표본을 함께 표시한다. 같은 값의 일부 위치를 근거로 특정 셀이 잘못됐다고 지목하지 않는다.
- 서로 다른 원문이 같은 비교값으로 모이면 그 원문 표본을 함께 표시한다. 정규화된 값이 같다는 사실을 원문이 동일하다는 뜻으로 표시하지 않는다.
- 상세 표본은 목록 하나당 최대 2,000개로 제한한다. 발생 위치 1,200개, 정규화 원문 변형 600개, 오류 200개이며 발생 위치와 원문 변형은 비교값 하나당 최대 5개다. 표본 저장 한도에 도달해도 전체 비교 개수의 집계는 계속한다.
- 생략한 발생·오류 수와 저장하지 못한 원문 변형 후보 수를 표시한다. 원문 변형 후보 수를 고유한 원문 종류 수로 과장하지 않는다. 표본은 모든 셀의 목록이나 오류 수정 대상 전체가 아니다.
- 모든 원문과 주소는 수식으로 실행되지 않는 텍스트로 기록한다. 기존 수식 실행 방지와 최대 문자열·작업 시간 보호를 유지한다.

### 처리·취소·실패 이후 상태를 분명히 한다

**작업 취소** 버튼과 **읽는 중 / 비교 중 / 결과 작성 중 / 취소 요청됨** 상태를 제공한다. 처리 단계와 취소 시도를 안내하되 버튼이나 키 입력을 받았다는 이유만으로 취소 완료라고 표시하지 않는다. 취소 요청, 취소 가능한 구간, 목록이나 결과를 확정한 구간을 구분한다. 취소·실패 안내에는 남아 있는 첫 목록의 개수와 재시도할 행동을 표시한다. 확정 전 실패는 이전 첫 목록을 보존하고 이번 작업의 미완성 결과만 정리한다. 확정된 결과를 취소 성공으로 표시하지 않는다.

현재 공개 RC9의 Esc 유지 안내는 해당 검증 한계를 함께 유지한다. 새 처리 단계 문구나 취소 안내를 구현하더라도 같은 최종 XLAM에서 실제 입력·최종 상태를 확인하기 전에는 일정 시간 내 취소를 보장하지 않는다.

### 대용량 분할 안내를 바로잡는다

공개 RC9 안내에서 임의 행 분할을 권하지 않는다. 분할이 필요하면 비교 규칙을 적용한 같은 값의 모든 항목이 양쪽에서 같은 묶음에 포함돼야 한다. 이를 확실히 나눌 수 없으면 전체 목록을 처리할 수 있는 다른 도구를 사용하도록 안내한다.

차기 소스 후보도 전체 비교값별 개수를 유지한 상태에서 결과를 만든다. 표본 저장 한도는 비교 대상을 줄이는 기능이 아니다. 전체 집계를 유지하지 않고 청크별 차이를 합치는 방식, 입력을 자동으로 잘라 비교하는 방식과 제한을 조용히 높이는 방식은 추가하지 않는다. 전역 집계를 유지한 내부 분할·성능 개선은 별도 실측 후 판단한다.

## 검토한 대안

- 긴 도움말만 추가: 구현 부담은 작지만 비교 순간의 출처·규칙·제외 여부를 확인하기 어렵다. 짧은 상태와 결과 근거를 함께 제공한다.
- 모든 발생 위치와 원문 저장: 완전한 추적에 유리하지만 큰 입력의 메모리·출력 비용을 키운다. 전체 개수는 유지하고 위치·원문은 명시적 표본 한도를 둔다.
- 비교 성공마다 첫 목록 비우기: 단발 작업에는 단순하지만 반복 비교에서 같은 선택을 다시 해야 한다. 스냅샷의 출처·시각과 비우기·바꾸기를 표시하면서 재사용한다.
- 일치 안내만 표시: 빠르지만 결과와 규칙을 저장하기 어렵다. 간결한 요약을 포함한 새 결과 통합문서를 만든다.
- 비교 규칙 설정 추가: 다양한 업무에 유리하지만 기존 모드 없는 비교 계약과 결과 해석을 바꾼다. 이번에는 기존 규칙을 명확하게 표시하고 규칙 선택은 별도 요구로 남긴다.

## 영향과 이행

첫 목록과 근거 표본은 현재 Excel 프로세스 메모리에만 보관한다. 별도 영구 저장·외부 전송·전역 단축키·관리자 권한·매크로 보안 정책 변경은 추가하지 않는다. 결과에 원문 표본이 늘어나므로 사용자가 결과 파일을 저장·공유할 때 그 내용도 포함된다는 점을 차기 안내에 설명한다.

README의 공개 RC9 안내와 차기 소스 후보 안내를 구분한다. 공개 다운로드·설치 안내에는 현재 RC9에서 쓸 수 있는 안전한 분할 지침만 먼저 고친다. 나머지 기능은 실제 반영된 최종 XLAM의 검증과 배포 파일 갱신 후 공개 사용 안내에 적용한다. 과거 검증 보고서와 고정된 릴리즈 기록은 수정하지 않는다.

## 로컬 후보 자동 패키징

후속 사용자 요청에 따라 필요한 소스 수정과 로컬 패키징을 자동으로 진행한다. `local-candidate`는 실제 XLAM의 직렬화 소스 대조, 동일 해시의 내장 기능 시험과 시험 인스턴스 정상 정리를 통과한 경우에만 만든다. 현재 작업 파일을 허용목록에 따라 스냅샷으로 보존하고 파일별 해시를 기록하므로 커밋되지 않은 변경도 검증한 그대로 추적한다. 기존 정식 배포의 전체 인수·깨끗한 커밋 요구와 RC9 전용 예외 프로필은 유지한다.

로컬 후보는 `LOCAL_PACKAGE_ONLY`, `fullAcceptancePassed=false`, `releaseApproved=false`로 표시한다. 미실행 UI·설치 검증을 통과로 바꾸지 않고 원시 계정 정보·레지스트리·로컬 진단은 패키지에 넣지 않는다. EXE 컴파일 성공은 설치·공개 게시 성공을 뜻하지 않는다.

별도 개발용 실행기는 고유 합성 파일로 시작한 새 Excel의 PID·시작 시각·창 소유권을 확인한 뒤 연결한다. 기존 Excel의 문서에는 연결하지 않으며 기존 제품 파일과 등록을 보존한다. 사용자가 허용한 VBA 프로젝트 접근의 일시 변경은 변경 전 저널과 값 재확인을 거쳐 수행하고, 종료 시 정확한 이전 값으로 복원한다. 조직 정책·전체 매크로 보안·신뢰 위치는 변경하지 않는다. 이는 설치기에 기존 Excel 거절 조건을 제거하는 변경이 아니다.

## 실패와 복구

표본 수집 실패·결과 작성 오류·취소 때 비교 대상을 조용히 누락하거나 성공으로 표시하지 않는다. 이전 첫 목록·원본·이전 결과를 보존하고 이번 미완성 결과만 정리한다. 사용자가 원본을 수정해도 기억한 목록은 자동 갱신하지 않으며 다시 담아야 한다는 사실을 표시한다. Excel 설정과 상태표시줄의 값·형식 복원은 기존 요구를 유지한다.

## 검증

1. 순서를 바꾼 같은 목록과 중복 개수 차이가 전체 집계에서 정확하며 임의 행 분할의 반례를 검사한다.
2. 빈칸·오류·필터·제목 제외 집계, 오류 위치, 중복 위치 표본과 모든 표본 한도·생략 수를 검사한다. 표본 한도를 넘겨도 전체 비교 개수는 같아야 한다.
3. 메일 도메인·공백·대소문자·숫자 표기 때문에 같아진 원문을 구분하고 앞자리 0 보존과 기존 정규화 결과를 회귀 검사한다.
4. 일치·차이·오류 포함 결과의 요약과 상세 시트가 정확하고 원문이 수식으로 실행되지 않는지 확인한다.
5. 첫 목록 확인·재사용·비우기·바꾸기, 원본 변경·닫기 뒤 스냅샷 유지, 오류·취소 시 이전 상태 보존을 검사한다.
6. 담기·바꾸기·비교·결과 작성 단계에서 실제 취소와 확정 경계를 확인하고 상태표시줄의 값·형식 복원을 검증한다. 주입 오류와 실제 Esc를 구분한다.
7. 실제 최종 XLAM에서 버튼·우클릭·창 전환·화면 잘림과 새 EXE 설치 수명주기를 확인한다. Python·소스 검사 성공을 이 검증의 대체로 표시하지 않는다.
8. 문서 strict 빌드와 공개 로컬 링크 검증을 실행한다. 자동 검사·실제 Excel·설치·게시 결과를 각각 기록한다.

2026-09-19: 사용성 개선의 차기 소스 후보 설계와 공개 RC9의 안전한 분할 안내를 분리했다. 실제 구현·시험·배포 상태는 제품 명세 대응표와 이번 검증 기록을 따른다.
