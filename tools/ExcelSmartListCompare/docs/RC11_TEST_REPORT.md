# Excel 명단 비교 R11 검증 기록

버전: 0.2.0-rc.11 · 날짜: 2026-09-20 · 상태: 필수 기능 검사 통과, 패키지 제작·게시 진행 중

[배포 범위 결정](ADR-0019-R11-release-scope.md)에 따라 빠른 필수 검사 후 게시하고, 오래 걸리는 실제 환경 검증은 [사용자 검증 안내](RC11_USER_VALIDATION.md)로 분리한다. 아직 실행하지 않은 항목을 PASS로 표시하지 않는다.

## 수정 과정에서 관찰한 결과

첫 빠른 검사에서는 새 대소문자 기본값과 맞지 않는 이전 참조 기대값 1개, 현재 설치 엔진을 그대로 복사하던 RC10 포장 시험 자료의 버전 불일치를 확인했다. 참조 기대값을 R11 요구로 수정하고, RC10 포장 시험은 명시적인 RC10 합성 자료로 고정했다. 제품의 버전·소스 일치 검사를 완화하지 않았다. 다음 146개 검사는 모두 통과했다.

전체 자동 검사 탐색을 처음 시작했지만 기존 실행기·감시기의 대기·시간 초과 반복 시나리오가 포함되어 있어 해당 시험 프로세스만 중단했다. 이 실행을 전체 PASS로 집계하지 않으며 이후부터 `run-essential-tests.py`의 명시적인 빠른 목록을 사용한다.

첫 두 실제 Excel 제작본은 저장·재열기와 `SLC_TestAll`을 통과했다. 새 설정 검사에 사용한 논리식의 괄호와 프로시저 호출 문법 때문에 컴파일 창이 열려 실행기가 제한 시간에 중단됐다. 해당 검사 호출을 명시적인 `Call` 문법으로 정리했으며 두 제작본은 배포하지 않는다. 오류 창 닫기와 제작 전용 프로세스 정리, 임시 개발용 접근 복원은 로컬 기록에 남긴다. 소유 PID·시작 시각·빈 통합문서를 확인한 잔여 프로세스 정리는 최종 제작본의 정상 종료 검사와 구분한다. 문법 수정 후 새 제작본에서 두 필수 함수를 다시 검사한다.

후속 검사에서 아직 생성하지 않은 임시 설정 항목을 삭제하는 정리 코드가 오류 5를 내는 것을 확인했다. 설정 값이 존재할 때만 삭제하도록 수정했다. 메뉴 생성 검사를 별도로 실행해 초기화 성공을 확인했고, Excel이 명령 연결에 사용하는 파일명·전체 경로·따옴표 표기 차이를 같은 파일과 같은 프로시저인지 확인하는 검사로 바꿨다. 이어서 MSXML의 기본 이름 공간 때문에 설정 항목 조회가 0개로 나오는 검사 오류를 재현하고, 명시적인 이름 공간을 사용하는 조회에서 3개를 확인했다.

이전 제작본은 메뉴 초기화와 정규화·19개 Excel 통합·12개 취소 판단 검사를 통과했지만, 설정 항목 XML 검사에서 실패했으므로 배포 대상에서 제외했다. 해당 Excel은 정상 종료됐으며 임시 개발용 접근과 RC9 설치 상태가 복원됐다.

XML 검사를 수정한 다음 파일은 보안 알림 대기 중 실행기 제한 시간이 끝났다. 임시 VBA 접근을 먼저 원래 값으로 복원한 뒤, 사용자 매크로 허용 후 같은 파일의 기능 검사를 재개해 전부 통과했다. 다만 그 세션은 정상 종료 요청 후 빈 Excel 프로세스가 남았으므로 실행 전체는 FAIL로 보존했다. 문서가 없는 정확한 제작용 프로세스만 확인해 정리했으며 정상 종료 PASS로 바꾸지 않았다.

최종 제작본은 같은 소스를 새 Excel에서 다시 저장·재열기한 파일이다. 위 표의 세 실제 함수, 파일 불변성, 정상 종료, 임시 접근 복원과 기존 설치 보존을 한 실행에서 모두 통과했다. 이전 제작본의 부분 통과를 최종 파일에 승계하지 않았다.

## 판정 경계

설정 저장 후 같은 모듈의 설정을 비우고 재읽는 검사는 실제 Excel 재시작 검사와 구분한다. 출력 오류·취소 코드를 주입한 복구 검사는 실제 Esc나 버튼 입력 검사를 대신하지 않는다. EXE 컴파일·payload 대조는 실제 설치·업데이트·제거 성공을 뜻하지 않는다.

R11의 대용량 성능, 실제 취소, 모든 메뉴·창·배율, 설치 수명주기 반복, 다른 Windows·Excel 환경은 배포 후 검증 대상으로 남긴다. RC9·RC10의 기존 상태표시줄 복원·취소 문제를 R11에서 해결됐다고 추정하지 않는다. 전체 인수는 미완료이며 `fullAcceptancePassed=false`다.
