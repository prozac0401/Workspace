# Excel 명단 비교 0.2.1 정식 배포 기록

- 작성일: 2026-10-05
- 상태: 정식 배포 준비 · 사용자 요청에 따른 일반 릴리스 채널
- 기준 소스: `94b3e3360e12c75479e6a901f4fe2271672001a1`
- 관련 요구: RC13 미제 해결과 평가판이 아닌 배포판 발행, 작업·시험 최소화
- 적용 정책: [도구 정책](../../../docs/policies/tools.md)
- 변경된 기능 명세: [상태표시줄 보존 요구](../../../docs/tools/excel-list-compare/stable-021-specification.md)

## 결함과 최소 변경

RC13에서 Excel 기본 Boolean False 상태가 작업 후 String FALSE로 바뀌는 실제 실패가 있었다. 이 PC의 별도 빈 VBA에서도 StatusBar에 False를 대입하면 문자열로 읽혔으므로 Excel 환경의 근본 원인은 확정하지 않는다. 제품이 전역 상태표시줄에 진행 내용을 기록하고 복원하던 경로를 제거했다. 이미 있는 제품 도구 모음에 진행·완료·취소 결과를 표시한다. 외부 상태나 기본 상태를 대입해서 복원하지 않고 처음부터 변경하지 않는다.

비교 규칙, 입력 제한, 목록 보존, 결과 파일·보고서, 설정 저장 형식은 유지한다. 설치 스크립트는 Version·InstallerVersion 두 문자열만 0.2.1로 바꿨다. Install/Uninstall 명령과 Inno 설치 동작은 변경하지 않았다. 모델·정규화·보고서·이벤트·RibbonX 소스는 기준 소스와 줄바꿈 정규화 후 동일하다.

새 회귀 검사 두 호출에 인수를 네 개 넘긴 준비 결함은 실제 Excel 컴파일 오류로 확인됐다. RunSelection은 필수 인수 두 개와 선택 인수 한 개를 받는다. 두 호출을 세 개로 수정했다. 실패한 후보·검사 기록은 삭제하지 않으며 해당 후보를 배포하지 않는다.

## 실제 검증

최종 후보 XLAM SHA-256:
`1361a63187616cbb311f7c006453c76e4e8f4b26365af26d89b3649d59d9bae5`

Windows 11 x64, Excel 16.0 build 20430의 별도 소유 Excel에서 저장한 같은 파일을 다시 열어 실행했다. 합성 문서만 사용했다.

| 검사 | 판정 | 확인 범위 |
|---|---|---|
| 집중 소스 계약 16개 | PASS | 상태표시줄 쓰기 금지, 실제 함수 서명과 호출 인수 개수, 기존 비교·원본·결과 계약 |
| 저장된 VBA 7개 모듈·RibbonX | PASS | 제작 소스 일치, 메뉴 연결, 검사 전후 같은 파일 해시 |
| SLC_UiProbe | PASS | 도구 모음과 설정 컨트롤 초기화 |
| SLC_StatusPreservationTests | PASS | 기본 Boolean 상태·외부 문구·문자열 FALSE 각각에서 담기·비교·취소 요청의 원시 종류/값 보존 |
| SLC_UsabilityTests | PASS | 기존 16개 설정·비교·상태 확인, 실패/취소 결과 복구, 표·샘플·수식 안전성 |
| 정리와 기존 설치 보존 | PASS | 소유 Excel 자연 종료, cleanupErrors 없음, 기존 RC13 파일·등록·신뢰 위치 보존, 임시 VBA 접근 원래 값 복원 |

기본 Boolean 상태 보존을 실제 확인한 새 후보는 이전 StatusBar FAIL과 구분한다. 이전 결과를 소급해서 PASS로 바꾸지 않는다. 첫 후보 `1f63d513c6ac40683d5ae20aa8542cd2077ff0e534306d1381ba5c5790af6ab0`는 소스 대조 PASS 후 추가된 회귀 검사 컴파일 FAIL로 거절했다.

최초 제작 도구의 결과 JSON 교체 오류도 별도 FAIL로 보존한다. 후속 도구는 완료한 각 단계 기록을 고유 파일에 먼저 보존한다. 저장 파일만 검사하는 경로에서는 VBA 프로젝트 접근 설정을 변경하지 않는다.

## 재사용한 근거와 제한

RC13 최종 EXE의 실제 설치·대표 비교·원본 보존·정상 종료 기록과 동일한 설치 동작을 재사용한다. 새 최종 EXE의 전체 설치·제거 수명주기는 반복하지 않았다. 새 포장에서는 실제 후보 해시, 설치 payload 해시, 기존 Inno 정의, ZIP 각 바이트를 연결한다. 공개 Build-Manifest.json에서 포장 소스 commit과 실제 파일 지문을 확인한다.

실제 Esc 취소는 이전 RC11의 compare/replace·설정 분기 8개 기록을 유지한다. 이번 검사는 내부 취소 요청과 실패 주입이며 실제 Esc·완료 팝업 화면의 새 재시험은 NOT RUN이다. 이전 팝업 관찰 미완료를 취소 처리 결함으로 단정하거나 새 PASS로 바꾸지 않는다. 취소 안내는 제품 도구 모음의 지속 결과에서도 확인할 수 있다.

다른 Office·Windows, 대용량 성능과 회사 정책 환경의 전체 인수를 주장하지 않는다. 코드 서명과 회사의 도입 승인은 별도다. 이번 사용자 요청은 일반 릴리스 채널의 정식 배포 승인으로 반영하며 과거 RC13의 평가 조건은 역사적 기록으로 남긴다.

원시 로그·사용자 경로·등록·보안 값은 저장소의 로컬 artifacts에만 보관하고 공개 ZIP에는 개인정보를 뺀 이 기록과 build manifest만 넣는다.
