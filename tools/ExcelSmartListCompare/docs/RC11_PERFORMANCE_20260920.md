# Excel 명단 비교 R11 · 12번 대용량 시간·메모리 검증

검증일: 2026-09-20 · 대상: **0.2.0-rc.11** · 상태: 12번 PASS — 정상 완료 8개·보호 중단 1개를 구분

[배포 후 사용자 검증](RC11_USER_VALIDATION.md)의 **12번**을 사용자의 후속 요청으로 실행했다. 앞서 배포 EXE로 설치한 R11을 사용했고, 같은 PC·합성 입력으로 공식 RC9·RC10 배포본도 비교했다. 13번 설치 수명주기 반복은 이번 범위에 포함하지 않는다. 제품 코드와 배포 파일은 수정하지 않았다.

R11의 9개 조합 중 **8개는 정상 완료**, **1개는 시간 제한으로 보호 중단**됐다. 100,000개씩 전부 다른 입력은 비교 전체 31.008초에 중단됐다. 첫 목록·원본·편집한 이전 결과 보존과 미완성 결과 정리를 확인했으므로 12번의 보호 동작은 PASS다. 이 입력의 차이 200,000행 출력을 완료했다는 뜻은 아니다. RC9·RC10의 18개 조합도 실행했다.

이 항목에는 속도·메모리 합격선이 정해져 있지 않다. PASS는 지정한 측정과 출력·보호 동작 확인을 마쳤다는 판정이며, 이전 버전보다 빨라졌거나 모든 상한 입력을 완료한다는 판정이 아니다.

## 입력과 측정 방법

각 목록은 A열·B열의 1행부터 N행까지이며 N은 1,000·20,000·100,000이다. 두 열을 텍스트 형식으로 지정하고 **모든 값은 정확히 48자**로 만들었다.

| 입력 | A열 | B열 |
|---|---|---|
| 반복 | `x` 48개를 모든 셀에 반복 | A열과 같음 |
| 역순 | `x` 42개 + 6자리 순번 | A열 고유값의 역순 |
| 전부 다름 | `x` 42개 + 6자리 순번 | `y` 42개 + 같은 순번 |

R11은 세 옵션을 모두 끈 기본값이다. RC9·RC10은 당시 기본 동작인 대소문자 무시가 적용된다. RC9는 성공 뒤 첫 목록을 비우고 RC10은 유지한다. 입력이 소문자 일반 문자열이어서 메일·숫자·대소문자 규칙 차이는 비교 결과에 영향을 주지 않는다. 이전 버전의 출력 정책 차이는 아래에 따로 표시했다.

시간은 설치된 XLAM의 공개 `SLC_Run` 호출부터 반환까지 고해상도 시계로 측정했다. 담기는 첫 목록 읽기이고, **비교 전체는 둘째 목록 읽기·대조·결과 작성·완료 처리까지** 포함한다. 경고에는 자동으로 예, 완료·중단 안내에는 확인으로 응답했다. 감지된 모든 알림창 대기 시간을 처리 시간에서 제외하고, 큰 선택 경고의 대기만 표의 별도 열에 기록했다. 알림 감지·응답 지연 때문에 이 시간은 사용자 조작을 포함한 벽시계 시간과 다르며 소수점 아래 수치는 해당 실행의 관측값이다.

**출력 구간은 새 결과 통합문서 창의 생성 이벤트부터 동작 반환까지 관측한 부분 시간**이다. 알림 대기는 제외하며, 표의 비교 전체에 이미 포함되므로 두 값을 더하지 않는다. VBA 내부 출력 함수 전체의 정밀 프로파일은 아니다. 결과 생성 전에 보호 중단되거나 결과를 만들지 않은 경우에는 `—`로 표시한다. 생성 후 중단된 경우에는 정리 시간까지 포함한 실패한 출력 시도 구간이다.

메모리는 대상 Excel PID의 Windows 프로세스 카운터를 자동 수집했다. 표의 `WS / Private`는 담기·비교 구간에서 관측한 **Working Set(RSS) / Private Bytes(커밋)** 최대값이며 단위는 MiB다. Private Bytes는 private working set과 다르다. 작업 관리자의 수동 화면 관측 대신 같은 운영체제 카운터를 사용했으며, 순간 최대를 빠짐없이 포착한 값이라고 보장하지 않는다. 표본 수집 목표 간격은 20ms이고, 54개 측정 구간의 실제 최대 표본 간격은 406.3ms였다. 원시 기록에는 각 동작의 시작 WS, 최대 WS·Private Bytes, OS가 보관한 프로세스 생애 최대 WS도 구분했다. 표에는 입력 준비·미리보기·검증 중의 최대값을 섞지 않았다.

매 실행에는 합성 원본과 편집된 이전 결과가 열려 있다. 준비·계산·저장·미리보기·결과 검사는 측정 시간 밖에서 수행했다. R11 → RC9 → RC10 순으로 **각 조합 1회**를 같은 관측 방식으로 측정했으며, 재현 준비 실행은 별도 보존했다. 백그라운드 부하를 고정한 반복 통계가 아니므로 보편적인 속도 향상률이나 최소 메모리 요구량으로 일반화하지 않는다. 이전 버전은 R11을 언로드한 뒤 로드했으므로 그 시작 과정의 메모리 영향도 완전히 배제하지 않는다.

## 보존·정리와 판정 경계

27개 측정 실행 모두 원본의 저장 상태·파일 SHA-256·전체 셀 값, 이전 결과의 열린 상태·편집값·미저장 상태, Excel의 이벤트·화면 갱신·사용자 입력 설정, 로드한 XLAM 해시를 확인했다. 보호 중단에서 미완성 결과가 남지 않았고 이전 첫 목록 상태가 유지됐다. 별도의 R11 재현에서는 보호 중단 뒤 **남아 있는 첫 목록을 원래 100,000개 값 전체와 다시 비교하여 일치·미출력·성공 후 비움**을 확인했다. 요약 메타데이터뿐 아니라 저장된 값과 개수를 실제 재사용할 수 있음을 검증한 결과다.

정상 차이 결과는 2N행의 모든 비교값과 첫째·둘째 개수, 남은 수를 확인했다. 같은 입력의 안내·통합문서 생성 여부와 완료 후 첫 목록 정책도 버전별로 확인했다. 보호 중단은 안내 문구로 판별했으며 실제 Esc 취소 성공으로 집계하지 않았다. R11과 RC10의 보존 검사는 첫 목록 미리보기의 출처·담은 시각·개수·규칙 등 전체 요약을 전후 대조했다. RC9는 공개 메뉴 XML의 첫 목록 상태·개수 보존을 확인했으며 R11과 같은 상세 미리보기 검사가 아니다.

각 측정 실행과 추가 복구 검증의 Excel은 정상 종료했다. 시험용 RC9·RC10 파일은 생성 소유권과 해시를 확인한 뒤 정리했으며, 설치된 R11 파일·시작 등록을 유지했다. 마지막 새 Excel에서 R11 버전·배포 해시·세 옵션 모두 꺼짐을 확인하고 정상 종료했다. 남은 Excel 프로세스는 0개다.

이 검증은 해당 PC의 12번에 대한 실행 결과다. 이전에 발견한 11번 취소 안내 확인 실패와 14번 상태표시줄 자료형 복원 실패를 수정하거나 상쇄하지 않는다. 13번과 다른 Windows·Excel 환경은 미검증으로 남으며 **`fullAcceptancePassed=false`**를 유지한다.

## 증거와 측정기 수정

합성 파일, 대화상자 캡처, 원시 메모리 표본, 실행 요청·응답, 버전 해시 및 assertion 결과는 로컬 `artifacts/excel-rc11-performance-20260920`에 보관한다. 최종 표의 근거는 `measurements/rc*-result.private.json`, 각 `*-timing.private.json`·`*-monitor.private.json`, `measurements/summary.json`, `measurements/final-cleanup.private.json`이다. 사용자 계정 경로가 들어 있는 원시 자료는 저장소나 공개 사이트에 올리지 않는다.

첫 R11 준비 실행 9개에서는 화면 상태 문구를 읽는 접근성 이벤트의 전달·조회 지연으로 출력 시작 시각이 부정확했다. 해당 관측 기록을 삭제하거나 정상 정밀 측정으로 바꾸지 않고, Excel COM을 읽지 않는 창 생성 이벤트 방식으로 측정기를 바꿨다. 최종 표의 R11·RC9·RC10은 모두 같은 수정된 방식으로 실행했다. 제품 코드·안전 상한·시간 제한·매크로 보안·VBA 프로젝트 접근 설정은 변경하지 않았다.

RC9 검사기를 다시 읽는 과정에서 캡처 번호가 초기화되어 R11 본측정의 `dialog-NNN.png` 파일이 이후 캡처로 덮였다. 해당 이미지 경로를 R11 화면 증거로 사용하지 않는다. 실행별 JSON의 실제 안내 문구·시각·검사 결과와 시간·메모리 표본은 보존되어 표의 근거로 사용했다. 추가 R11 보호 중단·재사용 검증의 캡처는 덮이지 않았으며, 종료 뒤 파일 시각을 대조하고 시나리오·시각별 사본으로 보존했다. 재사용 후 일치 안내는 이미지에서도 확인했다. 중단 창 캡처는 본문이 그려지기 전의 빈 화면이므로 그 이미지 대신 Windows 창에서 읽은 실제 안내 문구와 상태 검사를 근거로 삼았다. 근거는 `measurements/recovery-screenshots.private.json`, 경계는 `measurements/screenshot-collision.private.json`에 기록했다.

RC9의 첫 사전 실행에서는 성공 후 첫 목록을 유지한다고 잘못 가정했고, 병합된 제목의 비기준 셀 B1에 편집값을 넣었다. B1은 입력 직후부터 빈 값으로 읽혀 보존 검사가 성립하지 않았다. RC9 소스와 실제 상태에 따라 성공 후 비움으로 기대값을 바로잡고, 병합되지 않은 K1의 쓰기·즉시 읽기를 확인한 뒤 재측정했다. 첫 기록은 `measurements/rc9-calibration`에 보존하며 제품 실패나 최종 성능 표에 합산하지 않는다.
