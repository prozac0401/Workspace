# Excel 명단 비교 RC10 사용성 개선 검증 기록

상태: 소스 대조·합성 기능·기본 실제 UI 및 기존 RC9 파일 5개 물리 복원 확인 / 상태표시줄 복원 실패·실제 취소 인수 미충족·후속 설치 전체 인수 미완료 · 2026-09-20

대상: 0.2.0-rc.10. 개발 단계의 실제 결과를 보존하며, 2026-09-20 사용자가 현재 상태의 RC10 게시를 요청했습니다. [ADR-0017](ADR-0017-RC10-publication.md)에 따라 설치 안내와 검증 자료를 분리해 게시합니다. 전체 인수·회사 도입 승인은 하지 않았습니다.

[RC10 게시와 다운로드 검증](RC10_PUBLICATION_20260920.md)을 완료했습니다. 이 보고서의 과거 파일별 결과는 그대로 유지합니다.

## 변경 목적과 동작

[ADR-0016](ADR-0016-Comparison-usability.md)과 [제품 명세](../../../docs/tools/excel-list-compare/specification.md)의 REQ-EXCEL-018~024를 구현했습니다.

- 첫 목록의 출처·범위·담은 시각과 표본을 확인하고 같은 기준으로 반복 비교합니다.
- 일치 결과도 요약 / 차이·중복 / 제외·발생위치 / 규칙으로 같아진 값의 네 시트로 제공합니다.
- 목록별 발생 위치 1,200개, 원문 변형 600개, 오류 200개를 표본으로 보관하며 생략 수를 표시합니다. 원문별 빈도나 모든 위치의 제공을 보장하지 않습니다.
- 작업 취소 요청·처리 단계·완료·실패를 구분하고 확정 전 실패에서 첫 목록·원본·기존 결과를 보존합니다.
- 상태표시줄의 문자열 FALSE와 Boolean False를 구별하는 복원 처리를 구현했지만, 후속 Engine05에서 첫 목록을 담은 뒤 Boolean False가 문자열 FALSE로 바뀌는 실패를 재현했습니다. 원인과 해결은 아직 확정하지 않았습니다.
- 임의 행 분할 안내를 바로잡고 중간 합집합 사전을 제거했습니다. 기존 입력 보호 상한과 30초 보호는 유지하며 새로운 정상 완료량을 보장하지 않습니다.

단일 EXE의 준비 단계 접근 거부는 아직 해결되지 않았습니다. 직접 설치 엔진의 후속 Engine05에서도 상태표시줄 복원 검사가 실패해 나머지 설치 흐름을 완료하지 못했습니다. 기능 시험 소유 Excel의 정상 종료와 원본 해시 보존은 확인했습니다. 당시 자동화 환경의 RC9 파일·등록 비교는 일치했으나, 후속 물리 경로 조사로 원래 설치 위치 복원 완료 판정은 철회했습니다.

후속 Engine06은 설치 전용 범위로 재시작·같은 버전 재설치·제거·제거 후 시작·재제거를 확인했습니다. NoAddin 실기에서는 양성·음성 대조를 함께 사용해 제품 추가 기능과 도구 모음 부재를 확인했습니다. 정상 Quit 후 빈 소유 Excel이 남는 문제는 실패로 유지합니다. 새 설치는 실제 저장 경로 불일치로 실패했습니다. 자동화 환경에서 복원한 RC9 파일은 앱 전용 캐시로 연결됐습니다. 일반 Windows의 파일 5개 부재와 원래 등록 보존을 확인한 뒤, 2026-09-20 한국 시각 07:10:20에 일반 Windows 복원 창에서 실제 복원을 완료했습니다. 파일별 실제 경로·고정 해시·수정 시각·속성과 등록 전후 일치를 확인했으며 레지스트리·보안 설정은 변경하지 않았습니다. 복원 후 일반 Excel 재시작과 새 RC10 EXE 검증은 별도 미실행 항목입니다. 최신 관찰은 [전체 흐름 검증 기록](RC10_END_TO_END_REPORT.md)을 따릅니다.

앞선 상태 진단은 `Expecting object to be local` 오류로 추적 결과를 얻지 못했습니다. 2026-09-20에는 저장된 v2 사본을 새 Excel에서 열고 사용자의 직접 매크로 선택 후 단계별 추적을 확보했습니다. 세 조회 방식의 초기 반환값은 Boolean이지만 False를 설정한 직후 String으로 변해 담기 전 전제조건에서 중단됐습니다. 진단·제품 XLAM을 명시적으로 열지 않은 별도 빈 COM Excel에서도 같은 설정·조회 결과가 나왔습니다. 이는 발생 지점의 관찰이며 근본 원인이나 수정 완료 판정이 아닙니다. 두 소유 Excel의 정상 종료, 진단 사본 해시·검사 대상 보안 설정 보존 및 직렬화 소스 감사 PASS를 확인했습니다. 제품 VBA와 배포 파일에는 이번 추가 변경을 적용하지 않았습니다.

## 자동 빌드·검증·패키징

[Invoke-IsolatedExcelCandidate.ps1](../tests/Invoke-IsolatedExcelCandidate.ps1)은 고유 합성 파일로 새 Excel을 시작하고 해당 PID의 창에서만 연결합니다. 기존 사용자 Excel에 COM으로 연결하지 않습니다. 소유권 확인, 승인된 임시 접근 설정의 변경 전 저널·정확한 원복, 설치 보존, 후보 저장·재열기·실행을 기록합니다. 설치기의 열린 Excel 거절 조건은 유지합니다.

첫 시도는 실행 중인 기존 XLAM의 공유 잠금으로 해시 검사에서 실패했습니다. 보안 설정 변경 전 중단했고 실패 증거를 보존했습니다. 해시 검사를 공유 읽기로 고친 다음 시도에서 빌드·시험·정리·원복을 모두 통과했습니다. 후속 실행기에는 느린 구간을 구분할 COM 경계별 단계 기록을 추가했습니다. 원본 정밀도를 유지한 PID·시작 시각 검증으로만 소유 창을 관찰했습니다.

내장 시험의 실패가 사용자용 대화상자를 기다리지 않도록 비공개 실행기의 시험 호출에 오류 재전달 옵션을 추가했습니다. 사용자 명령의 안내는 유지하며 실제 결과 Workbook 참조만 정리합니다.

[로컬 후보 패키징 스크립트](../../../scripts/package-excel-local-candidate.py)는 이 동일 XLAM의 소스 감사·두 실제 시험·정상 정리를 요구합니다. 설치 ZIP·현재 소스 스냅샷·검증 ZIP과 선택적 EXE를 생성하며 산출물 경로와 해시는 출력의 Local-Candidate.json, RC10-Payload.json 및 OneFile-Build.json에서 확인합니다. 현재 작업 소스의 허용목록 스냅샷을 사용하므로 이전 커밋을 이번 구현으로 잘못 포장하지 않습니다. 원시 private JSON·계정·레지스트리·로컬 로그는 공유 ZIP에 포함하지 않습니다.

개발 단계의 포장 프로필은 local-candidate, 결정은 LOCAL_PACKAGE_ONLY, fullAcceptancePassed=false, releaseApproved=false입니다. EXE 컴파일은 실제 설치 성공으로 표시하지 않습니다. 기존 정식 배포 게이트와 RC9의 과거 예외 승인 범위는 변경하지 않습니다.

원래 EXE·XLAM 패키지 바이트는 유지합니다. 최신 검증 문서와 재현용 시험 소스는 별도 보충 검증 ZIP으로 제공하며, 이 자료가 원래 후보의 실패를 해결하거나 전체 인수를 승인하는 것은 아닙니다.

설치기의 `chcp.com` 호출을 시스템 명시 경로로 변경해 PATH·PATHEXT 의존성을 제거했습니다. 관련 합성·정적 검사 14개를 통과했으며 원래 후보와 구분되는 후속 로컬 패키지에 반영합니다. PowerShell 준비 호스트의 접근 거부는 별도 미해결 항목으로 유지합니다. 설치 전용 검증 범위를 추가한 실행기의 안전 검사 43개도 통과했습니다. 이 범위는 기존 기능 실패 기록을 덮지 않고 설치·재시작·제거를 별도로 검사합니다.

## 증거와 제한

로컬 비공개 증거는 저장소 artifacts/excel-rc10-package-20260919 아래 candidate-01(첫 실패), candidate-02(최종 실행), source-audit-02(독립 감사)에 보존합니다. 앞선 소스·문서 검사 증거는 artifacts/excel-usability-20260919에 있습니다. 원시 증거는 공개 사이트나 패키지에 포함하지 않습니다.

앞선 전체 실행기 회귀에서 자식 프로세스의 Windows 환경 변수 누락과 프로세스 생성 접근 거부를 관찰했습니다. 자식 환경의 누락은 보완했지만 접근 거부의 원인은 미확정이며, 환경 변수 누락만으로 실패 원인을 단정하지 않습니다. 전체 실행기 회귀 통과로 합산하지 않고 영구 환경은 변경하지 않았습니다. 이번 실행과 별개인 과거 RC9 실패·미검증도 소급해 통과로 바꾸지 않습니다.
