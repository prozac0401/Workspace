# ADR-0002 · 정상 시작 검증과 제품 전용 등록

상태: 채택 · 날짜: 2026-09-14 · 결정 담당: Windows E2E 수정 작업

관련 요구: 원격 E2E 지시 3~9절, 추가 도구 개발 기준. 조직 배포 승인을 의미하지 않는다.

## 맥락

시험 PC의 Excel 16.0.20326.20144 x64는 `/automation -Embedding`으로 시작하면 승인된 개발자 접근 설정에서도 VBProject 및 AddIns.Add를 거부했다. 일반 시작 후 소유 PID를 확인해 연결하면 두 작업이 가능했다. 다만 등록 API 경로는 Quit 후 창 없는 프로세스를 남겼다. 기존 방식은 설치 기록 쓰기 실패 시 등록만 남길 수도 있었다.

실제 Esc 시험에서는 입력 차단 설정 때문에 취소가 동작하지 않았으며 30초 지연 보호가 대신 실행됐다. Microsoft의 [Interactive 문서](https://learn.microsoft.com/en-us/office/vba/api/excel.application.interactive)는 False일 때 키보드와 마우스 입력을 차단한다고 설명한다. [EnableCancelKey 문서](https://learn.microsoft.com/en-us/office/vba/api/excel.application.enablecancelkey)는 Esc를 오류 18로 처리하는 경로를 명시한다.

## 결정

빌드는 새 매크로 없는 임시 통합문서로 Excel을 정상 시작하고, Hwnd의 PID가 직접 시작한 PID와 일치할 때만 연결한다. 개인 문서·템플릿을 읽지 않는다. 저장한 XLAM을 닫고 제품 문서 속성을 기록한 뒤 다시 열어 테스트한다. 테스트 이후 바이너리를 다시 저장하지 않는다.

Test_Excel.cmd도 같은 정상 시작을 사용한다. 실제 설치 파일이 존재해도 COM 자동화로 다시 여는 경로가 실패했으며 정상 시작에서 내장 19개 검사가 통과했다. 로드된 추가 기능은 Workbooks 열거에 나타나지 않을 수 있으므로 이름으로 찾고 정확한 경로를 확인한다.

설치·제거는 Excel을 시작하지 않는다. 해당 사용자 LocalAppData의 제품 파일과 HKCU Excel Options의 자기 XLAM 경로에 정확히 일치하는 OPEN 항목만 관리한다. 이는 앞선 실제 AddIns.Add 실행에서 관찰한 등록 형식이다. 관련 없는 OPEN 항목이나 설정은 건드리지 않는다. Excel 자동 로드와 메뉴 개수는 정상 시작으로 별도 검증한다.

처리 중에는 키보드 입력을 차단하지 않는다. 선택 Range는 미리 잡고 `mBusy`로 제품 명령 재진입을 거절한다. Esc는 기존 오류 처리 및 기준 보존 경로로 전달한다. 사용자는 처리 중 원본을 편집하지 않고 종료 또는 취소 후 다음 작업을 수행한다.

## 실패와 복구

기존 소유 파일을 백업하고, 임시 설치 기록을 같은 디렉터리에서 교체한 뒤 등록한다. 소유 기록이 커밋된 이후 중단된 설치는 그 표식으로 제거할 수 있다. 처리 가능한 예외에서는 자신의 등록과 변경 파일을 되돌린다. 백업과 같은 파일은 다시 쓰지 않으며 외부에서 바뀐 파일은 보존하고 경고한다. 프로세스 강제 중단·전원 단절의 모든 시점 복구는 이번 시험에서 검증하지 않았다. 기존 Excel이 있거나 제품 전용 잠금이 점유되어 있으면 중단하며 제품의 고정 파일 목록 외에는 삭제하지 않는다.

## 검증

최종 XLAM과 설치 스크립트의 실제 실행, 실패 주입, 재시작, 제거 및 제한은 [Windows E2E 보고서](WINDOWS_E2E_REPORT.md)에 기록한다. 이 결정은 타 Excel 버전 또는 조직 보안 정책의 호환성 보장이 아니다.
