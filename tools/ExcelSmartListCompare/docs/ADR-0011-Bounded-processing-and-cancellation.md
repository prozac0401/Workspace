# ADR-0011 · 처리 부하와 취소 확정 시점

상태: 구현, 실제 Excel 재검증 대기

날짜: 2026-09-17

결정 담당: 도구 개발 담당

관련 요구사항: [원래 검증 지시](../archive/CODEX_EXCEL_E2E_TEST_PROMPT.md), [인수 기준](ACCEPTANCE_TESTS.md) P07~P10, C03~C05, [추가 도구 개발 기준](../../../docs/policies/tools.md)

관계: [ADR-0010](ADR-0010-Cancellation-and-removal.md)의 취소 보완을 확장한다. 과거 실패 기록을 대체하지 않는다.

## 맥락

RC8의 실제 Esc 시험 3회는 실패했다. 사용자는 반복 시험 중 다른 PC 작업이 어려울 정도의 자원 점유를 보고했다. 당시 동시 자원 측정이 없어 제품 결함, 입력 전달 지연과 PC 부하의 기여도를 확정할 수 없다.

코드 검토에서는 값의 일괄 읽기와 별도로 각 셀에서 Excel의 행·열 속성을 다시 조회하는 반복을 발견했다. 문자열 정규화도 글자마다 전체 문자열을 연결했다. 선택 시나리오 시험은 각 경우의 원본과 결과를 마지막까지 보관해 14경우에서 최대 28개 문서를 열었다.

## 결정

- 행·열 시작 위치를 읽기 블록당 한 번 조회한다. 단일 사각형 영역에서는 중복 좌표 사전을 만들지 않는다. 여러 영역은 기존 중복 제거를 유지한다.
- 전각 ASCII 정규화는 필요한 문자 위치만 바꾼다. 그 밖의 Unicode 문자와 비교 규칙은 유지한다.
- 표 메타데이터 순회와 비교값 합집합 생성에도 취소 체크포인트를 둔다. 마지막 읽기와 결과 서식 작성 직후에도 확인한다.
- 첫 목록을 교체하기 전 상태표시 작업과 마지막 체크포인트를 마친다. 확정 직전 오류에는 이전 스냅샷을 보존한다. 짧은 확정 구간에서는 이벤트를 넘기거나 대화상자를 띄우지 않으며, 확정 뒤 상태 복원 실패를 취소 성공으로 안내하지 않는다.
- 선택 시나리오 시험은 이전 편집 결과 하나만 다음 경우까지 유지한다. 최대 동시 문서는 이전 결과·현재 원본·현재 결과 세 개다.
- 시험 실행기는 한 번에 하나만 실행하고 CPU·물리 메모리를 기록한다. 기본 사전 기준은 CPU 65% 이하, 메모리 사용 80% 이하, 여유 메모리 2GB 이상이다. 이는 시험 운용 기준이며 제품 지원 성능 보장이 아니다.
- 시험 자식은 낮은 우선순위로 실행한다. 기존 Excel이 있으면 기본적으로 시작하지 않는다. 제한시간 초과 시 정확히 식별한 시험 래퍼만 중단하고 남은 Excel을 기록한다. 사용자 프로세스는 종료하지 않는다.

## 검토한 대안

전역 키 감시, 단축키 재등록과 전체 Excel 종료는 제품 범위와 원본 보존 요구에 맞지 않아 도입하지 않는다. 별도 진행 대화상자는 새 UI와 Esc 처리 경로 검증이 필요해 이번 변경에는 포함하지 않는다. 셀 수 상한과 30초 보호값은 측정 없이 늘리지 않는다.

## 영향과 이행

새 소스의 버전은 RC9이다. 입력 선택, 숨김 제외, 정규화, 새 결과 생성과 일반 사용자 설치 계약은 유지한다. 과거 RC8 바이너리의 검증을 새 소스에 적용하지 않는다. 빌드·포장 도구도 RC9를 명시적으로 선택하고 정확한 파일 해시를 요구한다.

## 실패와 복구

확정 전 취소·오류는 이전 목록을 유지한다. 결과가 만들어지는 중 오류가 나면 그 작업에서 만든 임시 결과만 닫는다. 이미 완료한 결과와 업무 원본은 덮어쓰지 않는다. 감독 실행기의 강제 제한시간 종료는 Excel의 정상 종료를 보장하지 않으므로 잔여 프로세스 확인 전 다음 시험을 시작하지 않는다.

## 검증

실제 상태와 제한은 [RC9 안정성 기록](RC9_STABILITY_REPORT.md)을 따른다. 메모리 안에 취소 신호를 넣는 검사는 마지막 청크·결과 작성·상태 변경의 복구 경로만 입증한다. 실제 Esc 입력 성공과 구분한다. 최종 바이너리의 실제 키 취소, 설치 수명주기와 성능을 확인하기 전에는 출시 가능으로 표시하지 않는다.
