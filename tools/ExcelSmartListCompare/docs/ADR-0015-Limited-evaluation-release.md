# ADR-0015 · 확인된 범위를 명시한 RC9 제한 평가판

상태: 사용자 요청에 따른 제한 평가판 prerelease 게시 완료. 전체 인수 NOT_MET 유지

날짜: 2026-09-17

관련 문서: [제품 명세](../../../docs/tools/excel-list-compare/specification.md), [인수 요구사항](ACCEPTANCE_TESTS.md), [실제 재실험](RC9_APPROVED_RETEST_20260917.md), [작업 중 Esc 확인](ADR-0014-Foreground-held-Esc.md), [추가 도구 개발 기준](../../../docs/policies/tools.md), [문서 작성 규칙](../../../docs/policies/documentation.md)

## 배경과 사용자 요청

RC9 candidate-07은 실제 Excel에서 용량·선택·메뉴·입력 보호를 확인했지만 상태표시줄 원시 값 복원 실패와 취소·설치 인수의 미완료 항목이 남았다. 후속 진단에서 Excel이 비정상 종료했고 창 없는 시험 자식 프로세스가 남아 설치기의 기존 Excel 실행 보호가 작동한다. 원격 환경에서는 재시작과 관리자 작업을 할 수 없으며, 사용자는 이 제한을 전제로 현재 가능한 상태를 릴리즈하도록 명시적으로 요청했다.

이 요청은 현재 상태의 평가용 배포 권한이다. 회사의 업무 도입 승인·상용 품질 승인·코드 서명 승인이나 실패한 인수 요구의 면제를 뜻하지 않는다.

## 결정

- 배포 등급은 **LIMITED_EVALUATION**, GitHub 게시 형태는 **prerelease**로 한다. 기존 전체 인수 판정은 **NOT_MET**로 유지한다.
- 시험한 XLAM SHA-256 `61574c0f0acc68fb7b49507fa95c7201768515f4c5edfd563e3caf3915c19efc`를 그대로 포장한다. 새 EXE와 ZIP은 모두 서명 없는 평가용 산출물이며, 새 EXE의 실제 설치·재설치·업데이트·제거는 검증하지 않은 것으로 표시한다.
- Excel·UAC·재시작을 추가 실행하지 않는다. 창 없는 잔류 프로세스를 무시하도록 설치기의 보호를 완화하지 않는다. 현재 막힌 시험 PC에서 새 설치가 가능하다고 안내하지 않는다.
- `PASS`, `FAIL`, `PARTIAL`, `NOT_RUN` 및 환경 차단을 그대로 보존한다. 포장·게시 성공은 제품 전체 인수 통과와 별개다.
- 공개 안내는 검증된 기능·입력 범위와 알려진 실패·미검증 환경을 다운로드 전에 요약한다. 비공개 계정 경로·원시 레지스트리·사용자 로그·진단 파일은 넣지 않는다.

## 이번 파일의 평가 범위

| 항목 | 실제 확인 또는 제한 |
|---|---|
| 환경 | Windows 11 22631, Excel 16.0.20326.20144 64비트. 32비트 Office·다른 빌드·조직별 API 차단은 미검증 |
| 비교 | 용량 14조건·선택 14조건·네이티브 메뉴 5동작·입력 보호 안내 7조건 확인 |
| 완료 범위 | 48자 고유값 각 20,000개→40,000행, 동일값 각 100,000개→1행. 긴 문자열·총 문자 수는 검증 보고서의 별도 조건에 한정 |
| 큰 고유값 | 각 50,000·100,000개 × 48자는 약 30초 제한으로 결과 생성 실패. 100,000셀 안전 상한은 정상 완료 보장이 아님 |
| Esc | 바꾸기 100ms 요청 두 조건의 상태 보존만 키 입력 없는 대조와 비교한 추론 PASS. 취소 안내·직접 키 수신 미관찰, 순간 입력·다른 작업·일정 시간 내 취소는 미보장 |
| 복원 | 원시 StatusBar 값·형식 복원 FAIL. 후속 진단 충돌과 잔류 상태 미해결. 원본 파일 보존 검사와 별도 판정 |
| 설치·자동 시작 | 앞선 수정 CMD 설치와 동일 XLAM 해시는 확인. 새 EXE 전체 수명주기·자동 로드·전체 창 전환·추가 프로세스 격리는 미검증 |
| 전체 인수 | NOT_MET. 전체 기능·취소·복구·원복 완료로 표시하지 않음 |

## 대안과 후속 조건

전체 인수 완료까지 배포를 미루는 선택 대신, 사용자가 요청한 현재 파일을 제한 평가판으로 제공한다. 이 선택은 불확실성을 숨기거나 시간·보안·설치 보호를 제거하는 변경을 포함하지 않는다.

정식 인수 상태로 전환하려면 상태표시 복원 실패의 해결과 같은 최종 파일에서의 재검증, 남은 실제 취소·기능·창/프로세스·설치 수명주기·환경 원복 증거가 필요하다. 소스를 바꾸어 XLAM을 다시 만들면 앞선 파일의 통과를 새 파일에 재사용하지 않는다.
