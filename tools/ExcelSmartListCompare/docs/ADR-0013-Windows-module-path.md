# ADR-0013 · 설치 실행기의 모듈 검색 경로

상태: 채택 · 날짜: 2026-09-17 · 결정 담당: 사용자 요청에 따른 오류 재실험·개선

관련 요구사항·정책: [설치 인수 I17~I20·I31](ACCEPTANCE_TESTS.md), [추가 도구 개발 기준](../../../docs/policies/tools.md). [ADR-0012](ADR-0012-System-PowerShell-launcher.md)의 시스템 호스트 선택을 보완한다. 실행 정책과 설치 거래는 유지한다.

## 맥락

공개 RC7의 `Install.cmd`를 현재 PowerShell 7 호출 환경에서 실행하자 `Microsoft.PowerShell.Security`를 불러오지 못해 준비 단계에서 코드 1로 중단됐다. Windows PowerShell 실행 파일을 명시하는 RC9 소스도 상속된 `PSModulePath`를 그대로 사용한다. 기존 시험의 `run_ps`는 이 변수를 미리 제거했으므로 해당 경로를 검증하지 않았다.

독립 합성 모듈 경로를 CMD 자식에게 직접 전달한 새 시험에서 수정 전 설치·제거·진단 실행기 세 개 모두 같은 준비 실패를 재현했다. 이 오류는 RC8의 과거 `Access is denied.` 코드 5와 다른 관찰이며 동일 원인이라고 판정하지 않는다.

## 결정

세 CMD의 `setlocal` 범위에서 `PSModulePath`를 Windows 기본 모듈 폴더로 지정한 뒤 시스템 Windows PowerShell을 실행한다. 사용자·컴퓨터 환경변수와 부모 프로세스의 경로를 바꾸지 않는다. Windows PowerShell이 시작하며 추가하는 기본 모듈 위치는 호스트의 동작을 따른다. 외부 PowerShell 호스트가 물려준 모듈 경로를 제품 준비 단계에 사용하지 않는다.

회사 실행 정책과 `AllSigned` 판단, 자기 `Setup.ps1`만 차단 해제하는 기존 계약, 프로세스 한정 `RemoteSigned`, 원래 종료 코드는 유지한다.

## 검토한 대안

사용자가 PowerShell 7을 닫거나 환경변수를 수동 편집하도록 요구하면 정상 사용자 호출 경로에 불필요한 준비가 생긴다. 전역 환경변수 변경은 다른 프로그램에 영향을 주므로 채택하지 않는다. 모듈 오류 후 자동 재시도도 하지 않는다.

## 영향과 이행

변경은 새로 포장한 실행기에만 적용한다. 기존 공개 EXE·ZIP 및 RC8 고정 해시는 바꾸지 않는다. XLAM 비교 엔진과 설치 기록 형식에는 변화가 없다. 실제 신규 패키지의 설치·제거는 별도 검증한다.

## 실패와 복구

준비 실패에서는 본체를 실행하지 않는다. CMD 종료 시 `setlocal`이 상속 환경을 복원한다. 설치 본체가 시작된 뒤의 실패는 기존 거래·소유권·롤백 규칙을 따른다.

## 검증

`test_launchers.py`는 기존 환경을 정리하는 시험과, 정리하지 않은 모듈 경로를 CMD에 직접 전달하는 시험을 구분한다. 실제 시스템 보안 모듈 로드, 3개 작업·종료 코드 전달, 부모 모듈 경로·실행 정책 보존 및 다른 파일의 다운로드 표식 보존을 확인한다. 새 실행 기록은 후속 오류 재실험 보고서에 보존한다.
