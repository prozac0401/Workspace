# Excel 목록 비교 · 화면 용어 변경 기록

후속 수정과 현재 파일의 검증 결과는 [RC8 검증 기록](RC8_COMPLETION_REPORT.md)을 따른다. 아래는 해당 버전 당시의 기록이다.

도구 ID: ExcelSmartListCompare · 설치기 버전: 0.2.0-rc.5 · 날짜: 2026-09-15

상태: 새 XLAM으로 기능·문구·설치 수명주기를 검증한 **서명되지 않은 평가용 후보**. 데스크톱 잠금으로 새 화면의 육안 확인·클릭과 실제 Esc 입력은 미실행. 전체 인수나 상용 배포 승인을 뜻하지 않는다.

위 상태는 RC5 최초 실행 당시의 기록이다. 최신 RC7의 화면 확인과 Esc 취소 실패는 [잠금 해제 검증](UNLOCKED_UI_REPORT.md)을 따른다.

적용 정책: [추가 도구 개발 기준](../../../docs/policies/tools.md), [정책 문서 작성 규칙](../../../docs/policies/documentation.md)

## 사용자와 목적

사용자 피드백에 따라 선택 순서를 **첫 번째 목록 / 두 번째 목록**으로 표현한다. **목록**은 선택한 셀 전체, **항목**은 그 안의 값 하나를 뜻하며 이름·메일주소·일반 텍스트에 공통으로 사용한다.

## 요구사항과 구현

| 요구 | 변경 전 | 변경 후 | 구현 위치 |
|---|---|---|---|
| U01·U04 | 기준 담기 | 첫 번째 목록 담기 | 추가 기능 탭, 셀·행·열 우클릭 |
| U02·U04 | 기준 n건과 비교 | 두 번째 목록과 비교 | 동일 실행 버튼의 담긴 상태 |
| U02·U06 | 버튼에 섞여 있던 기준 건수 | 첫 번째 목록: 42개 항목 | 버튼 옆 읽기 전용 상태, 상태표시줄 |
| U01·U04 | 기준 비우기 | 첫 번째 목록 비우기 | 목록과 개수 표시 비우기 |
| U03·U04 | 선택 범위로 기준 교체 | 첫 번째 목록 바꾸기 | 현재 선택을 새 목록으로 담기 |
| U05 | 결과의 A / B | 첫 번째 목록 / 두 번째 목록 | 출처·항목 수·중복/제외 요약·열 제목·한쪽에만 있는 값·일치 안내 |

안내 문구:

> 첫 번째 목록을 선택하고 **[첫 번째 목록 담기]**를 누르세요.
> 이어서 두 번째 목록을 선택하고 **[두 번째 목록과 비교]**를 누르세요.

항목 수는 기존 제외 규칙을 적용한 실제 비교값의 개수다. 서로 다른 셀의 중복값도 각각 센다. 담긴 목록이 없거나 비교가 완료되면 상태를 숨기고 첫 번째 목록 담기로 돌아간다. 실패·취소 시에는 기존 목록과 버튼 옆 개수 표시를 유지한다.

결과표는 기존 10열과 데이터 시작 행을 유지하면서 제목 줄바꿈, 요약 행 높이와 열 너비를 조정한다. 기존 비교 규칙·스냅샷·원본 보호·취소·설치 계약은 유지한다. 문구 변경에 별도 ADR을 추가하지 않는다.

## 사용자 안내와 이전 기록

[README](../README.md), [퀵가이드](QUICK_GUIDE.md), [배포용 안내 원본](RELEASE_README.md), [인수 요구사항 U01~U06](ACCEPTANCE_TESTS.md), [인계](CODEX_HANDOFF.md)를 함께 갱신했다. 기존 Windows 테스트 스크립트의 결과 문자열·상태 위치·컨트롤 수 기대값도 새 UI에 맞췄다. 메뉴 구성은 실행 명령 4개와 읽기 전용 상태 1개다.

기존 RC1~RC4 보고서와 캡처는 당시 실행 증거로 보존한다. 퀵가이드에는 변경 전 화면임을 표시한다. 과거 검사 결과를 수정 소스의 실행 결과로 간주하지 않는다.

## 제작과 검증 대상

- 환경: Windows 11 23H2, 데스크톱 Excel 64비트 `16.0.20326.20144`, Windows PowerShell 5.1, 일반 사용자 권한.
- 사용자 요청: 문구 변경 후 릴리즈, 빌드 접근 권한은 임시 허용 후 원복, 잠긴 상태에서 가능한 작업 진행.
- 새 XLAM SHA-256: `e6eff07df465933f7159ab073b3cb656c23691d74f522733ca450f19a3f077de`
- RC3·RC4의 기존 XLAM 해시와 다르며, 다음 결과는 모두 위 새 파일에 대한 검사다. 설치 전·실행 후·재설치 후 해시도 확인했다.
- 시험 통합문서는 합성 값만 사용했다. 업무 파일을 읽거나 수정하지 않았다.

첫 빌드는 VBA 프로젝트 접근 차단으로 중단됐다. 이후 사용자 승인에 따라 현재 사용자 Excel의 `AccessVBOM` 한 항목을 빌드 중에만 허용했다. ASCII 소스를 가져와 XLAM 저장과 일반 제품 메타데이터 기록까지 완료했지만, 저장된 파일을 단독으로 다시 여는 단계가 정체되어 `Build_Release.cmd` 전체가 정상 종료되지는 않았다. 원인이 특정 대화상자였다고 단정하지 않는다.

저장된 파일을 별도 보관하고 접근 설정을 즉시 원복했다. 같은 파일을 기존 설치 절차로 제품 전용 신뢰 위치에 설치한 뒤 정상 Excel 시작에서 실제 VBA를 실행했다. 이어서 바이너리의 VBA를 추출해 클래스·정규화·주 모듈·통합문서 이벤트를 소스와 대조했다. VBE가 자동으로 바꾼 식별자 대소문자와 모듈 속성만 보정했으며, 문자열과 코드 본문이 일치했다. 이 경로로 검증한 파일을 `scripts/package-excel-wording-release.py`로 포장한다. 이전 XLAM의 재사용을 거절하고 소스 해시와 검증 대상 해시를 확인한다.

문구 검사는 Excel COM으로 공개 명령을 실행하고 실제 메뉴·셀 값을 읽은 결과다. 화면 캡처나 클릭 실기, 긴 제목의 육안 판독을 대신하지 않는다. 제목 줄바꿈과 행 높이 속성은 확인했다.

### 시험 도구와 복구 기록

선택 비교 실행 뒤 시험용 PowerShell 집계에서 JSON 배열을 중첩 배열로 세어 최종 개수가 잘못 표시됐고, 같은 프로세스의 자식 시험이 COM 참조를 해제해 부모 정리에도 오류가 있었다. 원시 결과의 문구·상태 31개, 내장 검사 호출, 자동 로드, 선택 시나리오 14개는 모두 통과했다. 별도 집계에서 전체 항목을 확인했고, 작업 통합문서가 0개인 소유 Excel만 정상 종료했다. 시험 실행기 자체의 종료 코드를 통과로 바꾸지 않는다.

설치 수명주기 검사에서 초기 환경과 달랐던 값은 테스트 Excel 창의 위치 한 개였다. 외부 변경이 없는지 확인하고 그 값만 복원한 후, 14개 설정 그룹의 완전 일치와 제품 미설치 상태를 다시 확인했다. 정체됐던 제작·진단용 Excel은 소유 PID를 확인해 정리했으며 사용자 Excel은 없었다. 계정·PID·원시 레지스트리·설치 로그는 저장소의 로컬 `artifacts`에만 보관한다.

## 미실행 항목과 후속 인수

- **실제 Esc 입력, 대량 경고 거절·오류 대화상자의 새 문구, 새 화면의 클릭·육안 확인·캡처**: 데스크톱 잠금으로 RC5에서는 미실행. U03의 바꾸기는 통과했지만 실패·취소 상태, U04의 안내 대화상자, U05의 일치 대화상자·시각적 배치는 소스 확인과 실기를 구분한다.
- RC3의 100,000개 대용량·지연 보호 실기, RC1의 Esc 캡처는 이전 파일의 기록이다. RC5에서 다시 실행한 것으로 표시하지 않는다.
- Office 32비트, 다른 Excel 버전, 회사 정책 실기, 전자 서명, 타사 추가 기능 전반의 공존·Undo 보존은 이번에 인수하지 않았다.
- 잠금이 해제된 검증 환경에서 새 문구를 클릭·확인하고 실제 Esc·경고 거절 후 첫 번째 목록과 개수 유지, 원본·이전 결과·Excel 설정 보존을 확인한다.

일반 설치에는 빌드용 VBA 프로젝트 접근 권한이 필요하지 않다. 제품 설치 폴더에 대한 기존 신뢰 위치 계약과 실행기의 프로세스 한정 준비만 적용하며 회사 정책·영구 실행 정책·전역 매크로 설정은 변경하지 않는다.

## 배포 점검

`python -m mkdocs build --strict`와 `python scripts/check-site.py`를 저장소의 기존 `.tools/docs-rc4` 문서 환경에서 실행해 통과했다. 수정 문서의 파일·이미지 링크 46개도 확인했다. 결과 요약은 배포 ZIP의 `Validation.json`에 담는다.

패키지에는 새 XLAM, 설치·제거·진단 실행기, 이 기록과 퀵가이드, 이번 검증 요약, 소스 커밋·파일 해시를 포함한다. RC4 실행기 보고서는 해당 실행기의 이전 검증 기록으로 구분한다. ZIP 내부 해시·무결성·오프라인 HTML 링크와 소스 ZIP의 가져오기 파일 일치를 확인한다. GitHub에는 RC5를 prerelease로 게시하며 RC4를 덮어쓰지 않는다.
