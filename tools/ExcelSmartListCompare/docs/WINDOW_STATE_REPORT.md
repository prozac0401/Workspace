# RC6 · 두 파일의 메뉴 상태 동기화 검증

도구 ID: ExcelSmartListCompare · 설치기 버전: 0.2.0-rc.6 · 날짜: 2026-09-15

상태: 서명되지 않은 평가용 후보. 실제 Excel COM 검사와 창 활성화 이벤트를 사용하며, 잠긴 데스크톱의 실제 우클릭·Esc 입력·화면 육안 검증은 구분한다.

적용 기준: [추가 도구 개발 기준](../../../docs/policies/tools.md), [문서 작성 규칙](../../../docs/policies/documentation.md), [ADR-0006](ADR-0006-Window-menu-state.md), [인수 요구 U07~U10](ACCEPTANCE_TESTS.md)

## 재현과 원인

RC5에서 두 파일을 미리 열었다. 첫 파일의 3개 값을 담은 후 둘째 파일로 전환하면 추가 기능 탭과 셀·행·열 우클릭 메뉴가 모두 **첫 번째 목록 담기**로 남고 개수 표시도 숨겨져 있었다. 그 버튼을 실행하면 실제로는 첫 목록 3개와 둘째 목록 2개를 정상 비교했다. 첫 번째 목록은 공유됐지만 창별 메뉴가 갱신되지 않는 표시 오류였다. 비교 완료 후 첫 창으로 돌아가면 그 창에는 비교 전 명령·개수가 남았다.

RC5에는 창 전환 이벤트 구독이 없었다. RC6는 `CSLCAppEvents`에서 창 활성화와 우클릭 직전 이벤트를 구독해 현재 창의 컨트롤을 공유 스냅샷에 맞춘다. UI 갱신은 셀값을 읽거나 선택·활성 파일을 바꾸지 않는다. 다른 Excel 프로세스에 데이터를 공유하지 않는다.

사용자가 선택한 실행 문구는 **두 번째 목록 담아 비교**다. 현재 선택을 두 번째 목록으로 읽고 즉시 비교한다. 첫 번째 목록 비우기·바꾸기와 개수 표시도 창 전환 시 같은 상태를 나타낸다.

## 검증 대상과 제작

- 환경: Windows 11 23H2, 데스크톱 Excel x64 `16.0.20326.20144`, Windows PowerShell 5.1, 일반 사용자.
- 새 XLAM SHA-256: `81d8b3e58aee1c352fbf19a1447581297a2e64d11edce9102523ebbbf7e07322`
- 저장된 VBA의 5개 구성 요소를 가져오기 소스와 대조했다. 문자열과 코드 본문은 일치하며 VBE 식별자 대소문자·모듈 속성만 보정한다.
- 내장 검사와 후속 창 전환·선택·설치 검사는 모두 위 파일을 사용한다. RC5 파일을 재사용하지 않는다.

이전 승인 범위에 따라 제작 동안만 VBA 프로젝트 접근을 허용했다. 일반 Excel에서 소스를 가져와 파일을 저장하고 제품 메타데이터를 기록한 뒤, 제품 설치 경로에서 새로 실행해 검증하는 경로를 사용했다. RC5에서 정체됐던 단독 재열기 단계까지 포함한 기본 `Build_Release.cmd` 전체 성공으로 기록하지 않는다. 빌드 보조 스크립트가 처음에 영어 통합문서 코드 이름을 가정한 오류는 실제 CodeName을 사용하도록 수정했다. 해당 실패 시도에서는 배포 파일이 생성되지 않았다.

70개 단언에는 16개 창 상태의 추가 기능 탭·셀·행·열 메뉴 검사와 내장 검사 결과·실제 비교 결과·수식 없음·활성 파일 보존·이벤트 유지·원본 파일 해시 보존을 포함한다. 구체적으로 다음을 확인했다.

1. 두 파일이 이미 열린 상태에서 첫 파일에 42개 항목 담기 → 두 번째 파일에도 같은 명령·42개 표시.
2. 두 번째 파일에서 비우기 → 첫 파일로 돌아가도 초기 상태.
3. 두 번째 파일에서 4개 항목으로 바꾸기 → 첫 파일에도 4개 표시.
4. 새 파일, 같은 통합문서의 새 창과 기존 창에서도 같은 상태.
5. 담은 목록의 원본 파일을 닫은 후 남은 파일에서 스냅샷 비교.
6. 비교 결과 창·첫 파일·다른 파일이 모두 초기 상태로 복귀.
7. 메뉴 재등록 반복 후 각 위치에 제품 메뉴 1세트, 활성 파일·이벤트와 원본 파일 해시 보존.

시험 파일은 합성 값만 사용한다. 초기 시험 준비 중 열린 파일의 해시 읽기는 파일 잠금으로 실패했고, 문서가 0개가 되는 Excel 상태에서는 툴바가 사라졌다. 최종 회귀 검사는 준비용 문서를 유지하면서 합성 파일을 저장·닫아 해시를 기록한 뒤 두 파일을 열고 준비용 문서를 닫았다. 실제 회귀 단계에는 비교할 두 파일이 열린 상태로 진입한다. 모든 문서를 닫은 채 Excel만 남긴 상태에서 다시 파일을 여는 경로는 이 통과 범위에 포함하지 않는다.

## 원복과 지원 경계

Excel을 모두 종료한 뒤 임시 VBA 접근을 원래의 미설정 상태로 복원했다. 시험 설치도 원래의 미설치 상태로 복원했으며 창 위치를 포함한 Office·PowerShell 관련 14개 레지스트리 그룹이 시작 전과 일치했다. 남은 Excel 프로세스는 0개이고 임시 예약 작업도 제거했다. 공개 배포에는 식별자 없는 요약만 포함한다. 원시 계정·PID·설치 로그·합성 통합문서는 로컬 `artifacts`에 보관한다. 일반 설치는 VBA 프로젝트 접근 권한을 요구하지 않는다.

실제 우클릭에 의한 `SheetBeforeRightClick`, 화면 배치·육안 확인, 경고·도움말·일치·오류 대화상자, 실제 Esc 입력은 잠긴 데스크톱에서 미실행이다. `WindowActivate` 및 CommandBar 명령 실행 결과로 대신 통과 처리하지 않는다. 대용량 최악 출력·지연 보호, Office x86·다른 버전·조직 정책·전자 서명·타사 추가 기능 전반의 공존은 이번 인수 범위가 아니다. 이전 RC1~RC5 캡처·보고서는 각 버전의 기록으로 보존한다.

비교할 파일은 첫 목록을 담은 Excel의 **파일 → 열기(Ctrl+O)**에서 열 수 있다. 별도로 실행한 Excel 프로세스와 Excel 완전 종료 후에는 목록을 공유하지 않는다.

## 배포 요약

최종 검사 결과와 해시는 설치 ZIP의 `Validation.json`, `BUILD_INFO.json`, `SHA256SUMS.txt`에 포함한다. `scripts/package-excel-wording-release.py --installer-version 0.2.0-rc.6`은 새 이벤트 소스·창 상태·업데이트 검사와 설치기 해시를 추가로 확인하며, 소스 커밋·ZIP 내부 해시·오프라인 링크를 검증한다. RC6는 평가용 prerelease로 배포한다.
