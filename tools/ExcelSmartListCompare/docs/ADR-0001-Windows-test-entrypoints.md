# ADR-0001 · Windows 검증 진입점과 종료 코드

상태: 채택(이 소스 후보의 구현 결정이며 조직 배포 승인은 아님)
날짜: 2026-09-14
결정 담당: 이번 Windows E2E 수정 작업
관련 요구사항: 원격 `CODEX_EXCEL_E2E_TEST_PROMPT.md` 3~5절, Workspace 추가 도구 개발 기준

## 맥락

한국어 Windows에서 원본 참조 테스트 4개가 UTF-8 소스를 CP949로 읽어 실패했다. 실제 `Build_Release.cmd`는 내부 PowerShell이 실패 코드 1을 반환해도 `pause` 뒤 성공 코드 0을 반환했다. 설치 자동화는 이 상태를 성공으로 오인할 수 있었다.

## 결정

Python 소스 읽기에는 UTF-8을 명시한다. 네 `.cmd`는 PowerShell 종료 코드를 즉시 보관하고 그대로 반환한다. 기본 확인창과 `pause`는 유지한다. 테스트 프로세스에만 `SLC_SETUP_NO_PAUSE=1`을 주면 마지막 대기만 생략한다.

명시적인 `-ConfirmProduct SLC-68A45C44-2026`은 해당 제품 설치·제거 확인만 생략한다. 기본값은 생략하지 않음이다. Office 경고, VBA 접근, 매크로, 신뢰 위치, 실행 정책에 영향을 주지 않는다.

종료 코드는 0=성공, 1=일반 실패, 2=사용자 거절, 3=Excel 실행 중, 4=제품 잠금 충돌, 5=빌드용 VBA 프로젝트 접근 차단이다. 5는 모든 Office 보안 오류를 포괄하는 코드가 아니다.

## 검토한 대안

표준 출력의 성공 문구만 판정하는 방법은 `.cmd` 오류 전달 결함을 숨긴다. 모든 확인을 끄는 전역 무인 옵션은 보안 경계가 불분명해 채택하지 않았다.

## 영향과 복구

사용자 설치 절차와 VBA 비교 규칙은 유지한다. 기존 설치 데이터 형식은 변경하지 않는다. 오류·취소를 성공으로 보고하던 호출자는 이제 비정상 종료 코드를 받을 수 있다. 테스트는 기존 Excel이 있으면 중단하고 임의로 종료하지 않는다.

## 검증

실제 실행과 제한은 [Windows E2E 보고서](WINDOWS_E2E_REPORT.md)에 기록한다. 사용자 거절 코드 2의 실제 확인창 조작은 잠긴 데스크톱으로 미실행이다. 설치 성공·업그레이드·제거 수명주기는 VBA 빌드 차단으로 미실행이다.
