# ADR-0012 · Windows PowerShell 실행 경로와 설치 단계 기록

상태: 채택 · 날짜: 2026-09-17 · 결정 담당: 사용자 요청에 따른 안정성 보완

관련 요구사항·정책: 실패한 설치 재검증 및 안정성 확보 요청, [추가 도구 개발 기준](../../../docs/policies/tools.md), [인수 요구 I17~I20·I26~I30](ACCEPTANCE_TESTS.md).
대체 관계: [ADR-0005](ADR-0005-Process-scoped-launchers.md)의 호스트 선택과 [ADR-0009](ADR-0009-Single-file-installer.md)의 로컬 진단을 보완한다. 실행 정책·설치 거래·제품 소유권의 경계는 유지한다.

## 맥락

[RC8 첫 대화형 설치](RC8_COMPLETION_REPORT.md)는 `Access is denied.` 한 줄과 코드 5로 실패했다. 같은 파일 재시도는 성공했다. 당시 기록에는 CMD 준비 단계와 설치 본체의 시작을 구분하는 표식이 없었다. 완성된 XLAM의 `Install` 경로에는 명시적인 코드 5 반환이 없고, 정상 예외 처리에서 출력하는 스택도 없었다. 별도의 `Build` 경로는 VBA 접근 차단에 코드 5를 사용한다. 따라서 이번 설치는 Windows PowerShell 시작 단계의 실패가 의심되지만, 당시 기록만으로 정확한 실행 파일·실패 호출·원인을 확정할 수 없다.

기존 실행기는 `powershell.exe`를 이름으로 두 번 실행했다. 설치 파일을 둔 위치나 PATH에서 이름이 같은 파일이 선택되는 상황을 제품이 통제하지 못했다.

## 결정

세 사용자 실행기 `Install.cmd`, `Uninstall.cmd`, `Test_Excel.cmd`는 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`를 명시한다. 32비트 호출 환경에서 `Sysnative` 경로가 존재하면 그 경로를 사용해 Windows의 기본 호스트를 선택한다. 제품 폴더나 PATH의 동명 실행 파일은 검색하지 않는다. 호스트가 없으면 작업을 시작하지 않는다.

EXE는 자식 프로세스 범위에서 `SLC_SETUP_DIAGNOSTICS=1`을 설정하고, 호출이 끝나면 기존 값을 복원한다. 기존 로컬 Setup Log에 다음 표식을 수집한다.

- CMD: 선택한 호스트, 제거 복사 준비, 정책 준비의 시작·진입·종료, 설치 본체 시작·종료.
- 설치 본체: 엔진 진입, 실제 호스트 실행 파일·버전·비트수, 잠금, Excel 사전 검사, 설치 계획·파일 읽기·쓰기·경로 확인·등록·완료, 실패 복구 또는 제거 단계.
- 처리한 오류: 실패 단계, 예외 형식과 HRESULT. 기존 예외 메시지·스택은 유지한다.

일반 CMD 실행에서는 별도 진단 환경 변수를 지정하지 않으면 추가 표식을 출력하지 않는다. 설치 파일·업무 내용·보안 설정을 진단 목적으로 추가 수집하지 않는다. 호스트 경로가 포함되는 원시 기록은 로컬에 보관한다.

## 검토한 대안

접근 거부를 만나면 전체 설치를 자동 재시도하는 방식은 거래가 시작됐는지 불명확한 실패를 숨길 수 있다. 재시도를 추가하지 않는다. 관리자 실행·ACL 변경·보안 정책 완화는 실제 원인에 대한 근거가 없고 기존 권한 경계를 넘으므로 적용하지 않는다.

기존 두 단계 정책 준비를 단일 PowerShell 프로세스로 통합하면 프로세스 수를 줄일 수 있으나 정책 적용 방식도 달라진다. 이번 변경은 기존 준비·실행 정책 계약을 유지한다.

## 영향과 이행

RC9 설치 엔진과 새로 포장한 EXE에 적용한다. 기존 RC8 고정 입력·바이너리와 당시 실패 기록은 보존한다. 사용자 설치 방법과 일반 사용자 권한, 기존 설치 기록의 호환성은 같다. 새 실행 파일은 별도 실제 설치·제거 검증이 필요하다.

## 실패와 복구

준비 실패 시 본체를 실행하지 않는다. 설치 본체와 준비 프로세스의 원래 종료 코드를 전달하고 자동 재시도하지 않는다. 설치 본체에 진입한 뒤의 실패는 기존 롤백 규칙을 따른다. 단계 표식의 부재만으로 보안 제품이나 PC 부하를 원인으로 확정하지 않는다.

## 검증

[RC9 설치 진단 검증](INSTALLER_RC9_DIAGNOSTICS.md)에 합성 실행기 시험과 실제 설치 시험을 구분해 기록한다. PATH 오염, 정책 보존, 준비·본체 실패 코드 보존, 기존 잠금 보호를 확인한다. 32비트 호출 경로와 실제 EXE UI 결과는 별도 실행 기록이 있을 때만 통과로 표시한다.
