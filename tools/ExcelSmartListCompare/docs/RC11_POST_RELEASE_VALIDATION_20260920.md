# Excel 명단 비교 R11 · 배포 EXE 설치 후 자동 검증

검증일: 2026-09-20 · 대상: **0.2.0-rc.11** · 방식: 실제 Windows·Excel 자동화

사용자가 지정한 [배포 후 사용자 검증](RC11_USER_VALIDATION.md)의 **1~11, 14번**을 먼저 실행하고, 후속 요청에 따라 **12번 대용량 시간·메모리**를 추가 실행했다. **13번 설치 수명주기 반복은 요청에 따라 제외**했다. 초기 EXE 설치는 1번의 필수 절차로 실행했다. 제품 코드와 배포 파일은 수정하지 않았다.

후속 실행을 포함한 집계는 **PASS 11개, FAIL 2개(11·14번), 사용자 지정 제외 1개(13번)**다. 11번은 데이터 복구와 사용자 안내의 판정을 나눴으며, 14번은 새 프로세스에서 자료형 변화를 재현했다. 12번은 R11의 정상 완료 8개와 시간 제한 보호 중단 1개를 구분했다.

## 설치 결과와 실행기 복구

첫 두 EXE 실행은 자동화 호스트의 MSIX 경로 가상화를 상속해 기존 설치 제거 단계에서 실패했다. EXE 종료 코드 7, 설치 엔진 코드 6을 기록했으며 기존 RC9 관리 파일 5개의 해시가 유지됨을 확인했다. 같은 EXE를 일반 Windows 사용자 프로세스로 실행한 설치는 엔진 코드 0으로 완료됐다. 이후 정상 시작한 Excel이 실제 설치 폴더의 R11을 로드했고 위 XLAM 해시와 일치했다. 처음 실패한 실행을 설치 성공으로 집계하지 않았다.

이 결과는 1번의 실제 설치 확인이다. 기존 버전이 있던 PC에서 설치했다는 이유로 제외한 13번 전체를 PASS로 올리지 않는다.

## 설정·화면·재시작 상세

첫 목록 대기 상태에서는 메일 전체 주소·대소문자 무시·기본값 복원이 비활성화되고, 유지 옵션만 바꿀 수 있었다. 공개 설정 동작을 직접 호출해도 잠긴 비교 규칙이 바뀌지 않았다. 첫 목록을 비우면 다시 변경할 수 있었다.

실제 작업 도중 도구 모음의 비활성 표시가 즉시 갱신되지 않는 실행을 관찰했다. 결과 작성 중에는 설정 메뉴와 담기·바꾸기·미리보기·비우기 버튼이 비활성화된 UI도 확인했다. 실행 중 COM을 통해 요청한 일부 설정 변경은 Excel이 작업 완료 뒤 처리했으므로, 이를 실행 중 방어 성공이나 실패의 근거로 사용하지 않는다.

설치된 같은 XLAM에서 `SLC_TestAll`은 2.983초에 정규화·19개 Excel 통합·12개 취소 판단 검사를 통과했다. 장시간 UI 검증 세션의 `SLC_UsabilityTests`는 범위 선택 오류 1004로 실패했다. 모든 검증용 Excel을 정상 종료한 뒤 새 프로세스에서 창을 숨기고 격리 실행한 재검사는 12.227초에 16개 설정·비교·상태 검사와 출력 오류·취소 주입 복구를 통과했다. 실행 중 공통 설정 변경 방어는 이 내장 검사로 확인했으며, 앞선 선택 오류나 실제 UI 갱신 지연을 없었던 일로 처리하지 않았다. 이 검사의 취소 주입 PASS는 11번의 실제 Esc 성공을 대신하지 않는다.

별도 Excel 프로세스 두 개는 시작 시 같은 저장값을 읽었다. 한 프로세스에서 설정을 바꿔도 다른 프로세스의 현재값은 변하지 않았다. 두 번째 프로세스의 마지막 저장값은 모든 검증용 Excel을 종료한 뒤 새 프로세스에서 복원됐다. 이어 세 옵션 모두 켜기와 모두 끄기를 각각 정상 종료·재시작으로 재검증했다.

메뉴 검사는 Windows 디스플레이 배율을 실제 100%와 150%로 바꿔 실행했다. 확대 배율의 긴 Excel 기본 우클릭 메뉴는 스크롤을 통해 접근했고, 제품 하위 메뉴와 설정의 항목 수·체크·비활성 표시·키보드 이동을 확인했다. 실행 후 원래 배율 100%로 복원했다. 다른 모니터 조합·다른 Excel 버전까지 통과한 결과는 아니다.

## 11번 · 실제 취소 결과

첫 목록은 `A1:A42`의 `기준`, 두 번째 입력은 `B1:B100000`의 서로 다른 48자 문자열이다. 계산 완료와 저장을 확인한 뒤 큰 선택 경고에 예로 응답했다. 운영체제 Esc 키를 검증용 Excel이 전면인 경우에만 전달했으며 취소 코드를 주입하지 않았다.

아래 시간은 초기 읽기 중 Esc 입력에서 공개 동작 반환까지의 관측값이다. 실제 키 누름은 약 20ms와 500ms로 나누었다. 최종 상태 API는 8개 모두 `취소 완료 · 이전 첫 목록 유지`였고, 목록 확인 자료의 출처·담은 시각·개수·규칙은 취소 전과 같았다.

| 동작 | 첫 목록 유지 | Esc 누름 | 입력→동작 반환 | 데이터 복구 |
|---|---|---|---:|---|
| 비교 | 꺼짐 | 약 20ms | 0.157초 | PASS |
| 비교 | 꺼짐 | 약 500ms | 0.145초 | PASS |
| 바꾸기 | 꺼짐 | 약 20ms | 0.146초 | PASS |
| 바꾸기 | 꺼짐 | 약 500ms | 0.187초 | PASS |
| 비교 | 켜짐 | 약 20ms | 0.155초 | PASS |
| 비교 | 켜짐 | 약 500ms | 0.141초 | PASS |
| 바꾸기 | 켜짐 | 약 20ms | 0.146초 | PASS |
| 바꾸기 | 켜짐 | 약 500ms | 0.190초 | PASS |

모든 행에서 새 미완성 결과가 남지 않았고, 원본 파일의 저장 상태·SHA-256과 이전 결과의 편집값·열린 상태가 유지됐다. 이 시간은 해당 PC·읽기 단계의 관측값이며 즉시 취소나 결과 작성 단계의 응답 시간을 보장하지 않는다.

실제 도구 모음 클릭으로 시작한 재검증에서도 Esc와 복구 상태를 관찰했지만, 화면에 남은 문구는 이전 목록 확인 안내였고 취소 완료 알림창은 수집되지 않았다. Esc가 알림창을 곧바로 닫았는지와 알림 생성 자체가 생략됐는지는 이 기록만으로 확정하지 않는다. 내부 상태만으로 사용자에게 취소 완료가 제대로 안내됐다고 판정하지 않았다.

별도의 실제 메뉴 클릭 실행에서는 UI가 `결과 작성 중`인 상태에서 늦게 Esc를 보냈다. 최종 안내는 `작업 시간이 길어져 중단했습니다`, 오류 코드 `-2147219401`이었다. 해당 실행은 **시간 제한 중단**이며 취소 성공으로 세지 않는다. 기존 42개 목록과 원본·이전 결과는 유지됐다. 따라서 11번 전체는 PASS로 승인하지 않는다.

## 12번 · 대용량 시간·메모리 후속 실행

앞서 설치한 동일 R11 배포본으로 9개 조합을 측정했다. 반복·역순 6개는 일치 안내만 표시했고, 전부 다른 1,000개·20,000개 입력은 차이 2,000행·40,000행을 정상 생성했다. 전부 다른 100,000개 입력은 비교 전체 31.008초에 시간 제한으로 중단됐다. 첫 목록과 원본·이전 결과 보존 및 미완성 결과 정리를 확인했으며, 차이 200,000행 정상 완료로 집계하지 않았다.

담기·비교 전체·그중 출력 관측 구간과 경고 대기를 분리했고, Excel Working Set 최고 관측값은 668.9 MiB였다. RC9·RC10과 같은 PC·입력을 사용한 비교, 관측 방식·표본 간격·메모리 지표 및 단일 실행의 한계는 [12번 상세 성능 기록](RC11_PERFORMANCE_20260920.md)에 남긴다. PASS는 측정과 기대 동작 확인의 판정이며 속도 개선이나 모든 상한 입력의 완료 보장이 아니다.

## 14번 · 상태표시줄 실패 재현

1. 모든 검증용 Excel이 종료된 뒤 새 Excel 프로세스를 정상 시작한다.
2. 제품 동작 전에 `Application.StatusBar`를 읽는다: 자료형 Boolean, 값 False.
3. 합성 값이 있는 A1을 담는다.
4. 같은 속성을 다시 읽는다: 자료형 String, 값 `FALSE`. 화면 하단에도 `FALSE`가 남는다.

제품 동작을 이미 실행한 별도 세션에서는 `Application.StatusBar = False` 직후부터 문자열로 읽히는 경우도 있었다. 이 환경 관측과 위의 **새 세션에서 제품 동작 전후 자료형이 달라진 재현**을 구분했다. 사용자 지정 문자열은 담기·일치·차이·비우기 뒤 보존됐다. 문자열 보존 PASS가 Boolean 복원 실패를 상쇄하지 않는다.

## 재시도와 판정 원칙

표 자동 확장으로 잘못 구성된 합성 자료, 지역화된 숫자 형식·안내 문구를 잘못 가정한 검사, 페이지 레이아웃의 중복 UI 요소 선택은 실행기 오류로 남기고 자료·선택자를 바로잡아 재검증했다. 제품 코드를 바꾸거나 실패 기대값을 완화하지 않았다.

처음 장시간 자동화 세션의 Excel 종료 확인은 실패로 보존했다. 이후 COM 참조 해제와 충분한 종료 대기를 적용한 별도 정상 종료·재시작 검증이 통과했다. 초기 세션 정리 결과를 정상 종료 PASS로 바꾸지 않았다. 전면 창이 달라 Esc를 보내지 않은 실행, 최종 상태를 너무 일찍 읽은 실행, 처리 중 UI를 포착하지 못한 실행은 취소 성공이나 제품 결함으로 단정하지 않는다.

## 증거와 최종 범위

원시 설치 로그, UI 트리, 프로세스 정보, 합성 파일, 화면 캡처, 실행 요청·응답 및 assertion 기록은 로컬의 `artifacts/excel-rc11-user-validation-20260920`에 보관한다. 사용자 계정 경로가 포함된 원시 자료는 공개 문서에 복사하지 않는다.

핵심 파일은 `checks.private.json`, `events.private.jsonl`, `install-native.private.log`, `statusbar-fresh.private.json`, `cancellation.private.json`, `native-cancellation.private.json`, `stable-native-cancellation.private.json`, `menu-matrix-100.private.json`, `menu-matrix-150.private.json`, `menu-matrix-150-page-retake.private.json`, `normal-three-options-retest.private.json`이다. 실패한 시도도 함께 남아 있으므로 원시 FAIL 개수를 곧바로 제품 결함 수로 읽지 않는다.

내장 검사의 최종 근거는 `fresh-selftest.private.json`이며 재시작 후 두 경로의 기본값 화면은 `defaults-ui.private.json`에 연결했다. 문서 strict 빌드와 생성된 15개 공개 페이지·404·검색·사이트맵·로컬 링크 검사를 통과했다. 새 검증 기록과 로컬 원시 자료는 공개 사이트 산출물에 포함하지 않았다.

1~11·14번 검증을 마친 정리에서 R11 로드 버전·XLAM 해시 불변, 세 옵션 모두 꺼짐, 창 DPI 96(100%)을 확인했다. 검증용 파일을 닫고 Excel을 정상 종료했으며 남은 Excel 프로세스는 0개였다. 설치한 R11은 유지했다. 근거는 `final-cleanup.private.json`이다. 12번 후속 실행의 원시 증거와 종료·복원 결과는 별도 성능 기록에 연결했다.

이번 PC의 기능·성능 결과와 제외한 설치 수명주기, 다른 Windows·Excel 환경을 구분한다. **전체 인수는 미완료이며 `fullAcceptancePassed=false`를 유지한다.**
