# 폴더 업무의 진행·인수인계 개선안

정책 ID: POL-007 · 상태: 제안 · 버전: 0.1 · 책임 역할: 업무 책임자·표준 담당

승인자·승인일·적용일: 미확정. 관련 정책: [기본 구조와 원본](workspace.md), [업무 키트와 일정](kits.md), [보관·보안·백업](archive-security.md). 기존 정책을 보완하며 대체하는 문서는 없습니다.

## 목적과 적용 범위

현재 정책은 자료의 위치와 네 가지 상태를 정하지만, 대기 중인 일을 언제 다시 확인할지, 무엇을 확인하고 완료로 바꿀지, 담당자가 바뀌면 어디서 이어갈지는 더 구체화할 수 있습니다. 반복 업무의 단계 폴더와 운영현황에 아래 항목을 필요한 만큼 적용하는 안을 제안합니다.

추가 기록은 기존 Overview·Schedule·Checklist·Issues에 넣습니다. 이미 같은 정보를 관리하는 사내 시스템이 있다면 그 원본의 링크만 연결합니다. 이 문서는 운영 방식에 대한 제안이며 FolderState에 기능이 추가되었다는 의미가 아닙니다.

## 추가할 아이템과 우선순위

우선순위는 현재 문서의 빈틈과 추가 기록 부담을 기준으로 한 제안이며, 실제 개선 효과는 아직 측정하지 않았습니다.

| 순서 | 아이템 | 줄이려는 불편 | 최소 추가 내용·위치 | 효과 확인 |
|---|---|---|---|---|
| 먼저 | 다음 행동과 대기 확인 | 진행 중인데 누구에게 언제 확인할지 모름 | Schedule에 담당·다음 행동·재확인일, 문제는 Issues 연결 | 기한 지난 회신·재확인 누락이 줄었는가 |
| 먼저 | 단계 완료 기준 | 파일만 있으면 완료로 보고 승인·전달을 빠뜨림 | MASTER의 Checklist에 결과물·완료 조건·확인 역할 | 완료 후 누락으로 되돌아간 단계가 줄었는가 |
| 다음 | 인수인계 한 줄 | 담당자 부재 때 자료와 다음 행동을 다시 물음 | Overview에 대행 역할·원본 링크, 기존 일정·이슈 연결 | 인수자가 원본을 열고 다음 행동을 설명하는가 |
| 다음 | 종료·재개 확인 | 보관 후 미결 업무가 사라지거나 사본을 각각 수정함 | Overview에 종료일·보관 경로, Issues에 잔여 행동·담당 | 보관본과 현재 작업 원본을 혼동하지 않는가 |
| 필요 시 | 업무 위치 바로가기 | Active가 많아 경로를 매번 다시 검색함 | 기존 팀 업무목록에 업무명·담당·원본 링크만 | 별도 문의 없이 해당 회차를 찾는가 |
| 필요 시 | MASTER·참고자료 갱신 계기 | 오래된 양식과 안내를 다음 회차에 다시 사용함 | 키트 버전과 변경 이유, 참고자료의 원본 링크·확인일 | 같은 낡은 양식 문제를 반복하지 않는가 |

## 규칙

### 다음 행동과 대기 확인

업무를 시작하거나 외부 회신을 기다리게 된 순간, 해당 일정에 행동을 맡은 역할과 다음 행동을 적습니다. 회신 대기에는 상대 역할과 재확인일을 함께 둡니다. 기존 마감일이 재확인일로 충분하면 같은 날짜를 다시 입력하지 않습니다.

| 상황 | 폴더 상태 제안 | 운영현황에 남길 것 |
|---|---|---|
| 아직 시작하지 않음 | 미착수 | 착수할 일정·담당 |
| 작업 중 또는 기한 내 통상 회신 대기 | 진행 중 | 다음 행동·담당, 대기 시 상대·재확인일 |
| 기한 초과 또는 결정 없이는 진행 불가 | 이슈 | 막힌 이유·해결 담당·다음 확인일 |
| 완료 조건과 필요한 승인·전달 확인 | 완료 | 기존 결과물·승인 근거 위치 |

재확인일에 회신 여부를 확인하고, 늦어진 일이 후속 일정에 영향을 주면 업무 책임자와 조치·일정을 정합니다. 조직별 알림·보고 기준은 [결정 목록](decisions.md)에서 정합니다. FolderState는 기한을 감시하거나 상태를 자동 전환하지 않습니다.

### 단계 완료 기준

MASTER를 고칠 때 단계마다 필요한 결과물, 완료로 판단할 조건, 확인 역할을 짧게 정의합니다. 매 회차에는 기존 결과물·승인 기록으로 조건을 확인하고 폴더 상태를 완료로 바꿉니다. 같은 완료 체크를 운영현황에 반복해서 만들지 않습니다.

예를 들어 입과안내 단계는 안내문 작성만으로 끝내지 않고, 대상·일정 확인과 발송 기록까지 필요한지 표준 담당이 정합니다. 승인 절차가 없는 업무에 새 승인 단계를 일괄 추가하지 않습니다. 보완 요청이 오면 이유를 기존 Issues에 남기고 진행 중 또는 이슈로 되돌립니다.

### 인수인계

휴가·담당 변경·타팀 전달 시 다음 세 가지를 확인합니다.

1. Overview의 원본 링크와 담당·대행 역할을 갱신합니다.
2. 인수자가 실제 계정으로 업무 원본과 필요한 결과물을 열 수 있는지 확인합니다. 접근이 안 되면 권한 담당에게 요청합니다.
3. 기존 Schedule·Issues를 함께 보고, 가장 가까운 다음 행동·마감·미해결 사항을 인수자가 확인했는지 한 줄 남깁니다.

인수인계를 위해 전체 폴더를 개인 공간에 복제하지 않습니다. 내부 기록에는 필요한 담당 정보를 적되 공개 문서에 실제 이름·계정·업무 경로를 입력하지 않습니다.

### 종료와 재개

종료 시 확정 결과물·승인 근거를 확인하고, 미해결 사항은 없음을 확인하거나 후속 업무의 원본 링크·담당·마감을 남깁니다. 인계되지 않은 일이 남아 있다면 종료 판단을 보류합니다. 이어서 조직의 보관 기준에 따라 회차 전체를 이동하고 Overview와 기존 업무목록의 원본 링크를 갱신합니다. 권한 있는 다른 담당자가 새 링크를 열 수 있는지 확인합니다.

보관한 업무를 다시 시작할 때는 보관 원본의 수정이 허용되는지 기록 담당과 확인합니다. 허용되면 공식 작업 위치로 옮기고 링크를 갱신합니다. 보관본을 고정해야 한다면 새 Active 후속 회차를 만들고 과거 기록 링크와 이어갈 결과물만 연결합니다. 두 위치에서 같은 업무를 독립적으로 수정하지 않습니다. 재개 이유·담당·다음 마감은 기존 운영현황에 남깁니다.

### 업무 위치와 표준 갱신

현재 업무를 찾기 어렵다는 사례가 반복될 때만 기존 팀 업무목록에 원본 링크를 추가합니다. 폴더별 상태와 세부 일정을 이 목록에 다시 복사하지 않습니다. 업무 종료·이동·담당 변경 시 해당 행만 고칩니다.

낡은 양식이나 반복 누락이 발견되면 회차 종료 때 MASTER 변경 후보로 한 줄 남깁니다. 표준 담당이 반영한 변경은 키트 버전·변경 이유로 기록하고 다음 회차부터 사용합니다. 진행 중인 회차를 자동 덮어쓰지 않습니다. 참고자료는 실제 재사용할 때 원본의 유효성을 확인하고 원본 링크·확인일을 갱신하는 안을 제안합니다.

## 예외

단일 담당의 짧은 업무라면 대행·인수인계 항목을 생략할 수 있습니다. 기존 업무 시스템이 담당·마감·이슈를 제공하면 별도 대장을 만들지 않습니다. 접근 제한·보관 고정 등 조직 기준과 충돌하면 업무·기록 담당이 적용 범위와 기간을 내부 결정 기록에 남깁니다.

## 실행 예시

다음은 가상 회차의 기존 운영현황에 넣을 내용입니다. 별도 파일을 반드시 만들 필요는 없습니다.

| 영역 | 예시 |
|---|---|
| Overview | 업무: 2026-10 과정운영 / 담당: 과정 담당 / 대행: 운영 대행 / 원본: 내부 회차 링크 |
| Schedule | 입과안내 / 다음 행동: 확정 인원 회신 확인 / 담당: 과정 담당 / 상대: 선발 담당 / 재확인일: 2026-09-21 |
| MASTER Checklist | 입과안내 완료 조건: 대상·일정 확인 및 안내 발송 기록 / 확인 역할: 과정 담당 |
| Issues | 회신 지연으로 발송 불가 / 해결 담당: 선발 담당 / 다음 확인: 내부 합의일 / 근거: 해당 메일 링크 |
| 인수 확인 | 운영 대행이 원본 접근과 다음 회신 확인 일정을 확인함 / 확인일: 실제 인계일 |

## 검증

한 회차에서 ‘다음 행동과 대기 확인’과 ‘단계 완료 기준’ 두 항목부터 시범 적용하는 안을 제안합니다. 시작 전 유사 회차에서 재확인 누락·완료 후 재작업 사례를 확인하고, 종료 때 같은 기준으로 비교합니다. 비교할 기록이 없다면 첫 회차를 기준선으로 삼고 절감 효과를 단정하지 않습니다.

인수인계가 있는 회차는 인수자가 원본을 열고 다음 행동을 설명할 수 있는지도 확인합니다. 기록에 들인 추가 시간과 실제 누락 사례만 기존 회고에 남기고, 도움이 없는 필드는 줄입니다. 도입 항목·점검 계기·유지 여부는 업무 책임자가 결정합니다.
