# 일을 이어서 하고 다른 사람에게 넘기기

정책: 일을 이어서 하고 다른 사람에게 넘기기 · 상태: 제안 · 버전: 0.3 · 책임: 업무 책임자·표준 담당

승인자·승인일·적용일: 미확정. 관련 정책: [자료를 둘 곳 정하기](workspace.md), [반복 업무 시작과 일정 관리](kits.md), [끝난 업무 보관과 자료 보호](archive-security.md). 기존 정책을 보완하며 대체하는 문서는 없습니다.

!!! info "같은 불편이 반복될 때 필요한 부분만 쓰세요"
    회신을 놓치거나, 완료 여부를 헷갈리거나, 다른 사람에게 일을 넘기기 어렵다면 아래 방법을 골라 씁니다. 처음 시작할 때 모두 적용할 필요는 없습니다. 짧은 일을 혼자 한다면 별도 인수인계 기록을 만들지 않아도 됩니다.

## 이 안내가 필요한 때

**지금 누가 무엇을 해야 하는지 기존 기록에서 알 수 있게 합니다.** 반복 업무를 맡은 사람과 이어받을 사람이 함께 쓰는 안내입니다.

기본정보(`Overview`), 일정표(`Schedule`), 확인 목록(`Checklist`), 문제 기록(`Issues`)에 꼭 필요한 내용만 덧붙입니다. 같은 내용을 회사 시스템에서 관리한다면 그곳으로 연결합니다.

이 안내는 업무 방법의 제안입니다. FolderState가 아래 일을 자동으로 처리하는 것은 아닙니다.

## 지금 겪는 불편부터 고르기

다음 순서는 제안입니다. 실제로 얼마나 도움이 되는지는 아직 확인하지 않았습니다.

| 언제 필요한가요? | 해 볼 일 | 어디에 적나요? |
|---|---|---|
| 누구에게 언제 답을 확인할지 자주 잊습니다. | 다음 할 일과 다시 확인할 날짜를 정합니다. | 기존 일정표 |
| 완료로 표시한 뒤 빠진 일을 발견합니다. | 끝내기 전에 확인할 조건을 정합니다. | 기본 폴더의 확인 목록 |
| 담당자가 없으면 어디서 이어갈지 모릅니다. | 대신 맡을 사람과 자료 위치를 적습니다. | 기존 기본정보 |
| 끝난 업무에 남은 일이 있었거나 사본을 따로 고칩니다. | 남은 일을 넘기고 작업할 위치를 하나 정합니다. | 기본정보와 문제 기록 |
| 업무폴더가 많아 찾는 데 시간이 걸립니다. | 기존 팀 업무목록에 바로가기를 둡니다. | 기존 업무목록 |
| 오래된 양식이나 잘못된 안내를 다시 씁니다. | 기본 폴더와 참고자료를 고칠 시점을 정합니다. | 기본 폴더의 버전 기록 |

첫 두 항목부터 살펴보고, 다른 사람에게 넘기거나 종료할 때 필요한 항목을 이어서 적용합니다. 폴더 검색이나 오래된 양식 문제가 없으면 마지막 두 항목은 추가하지 않아도 됩니다.

## 답을 기다리는 일을 놓치지 않기

일을 시작할 때 일정표에 담당자와 다음 할 일을 적습니다. 답을 기다리게 되면 **누구의 답을, 언제 다시 확인할지** 남깁니다. 이미 적힌 마감일에 확인하면 충분한 경우에는 같은 날짜를 다시 적지 않습니다.

| 상황 | 폴더에 표시할 상태 | 기록할 내용 |
|---|---|---|
| 아직 시작하지 않았습니다. | 시작 전 | 시작할 날짜와 담당자 |
| 작업 중이거나 약속한 날짜 안에서 답을 기다립니다. | 진행 중 | 다음 할 일과 담당자, 답을 줄 사람과 다시 확인할 날짜 |
| 약속한 날짜가 지났거나 결정이 없어 다음 일을 못 합니다. | 확인 필요 | 막힌 이유, 해결 담당자, 다음 확인 날짜 |
| 필요한 결과물과 승인·전달을 확인했습니다. | 완료 | 기존 결과물과 승인 기록을 찾을 위치 |

정한 날짜에 답이 왔는지 확인합니다. 답이 늦어 다음 일정에도 영향을 주면 업무 책임자와 조치 방법과 새 일정을 정합니다.

언제 알리거나 보고할지는 [회사에서 정할 항목](decisions.md)에서 정합니다. FolderState는 날짜를 지켜보거나 상태를 자동으로 바꾸지 않습니다.

## 완료로 표시하기 전에 확인하기

기본 폴더(`MASTER`)를 고칠 때 표준 담당자는 각 단계에 다음 내용을 짧게 적습니다.

- 어떤 결과물이 있어야 하는지
- 어떤 조건을 갖추면 끝난 것인지
- 누가 확인하는지

이번 업무에서는 이미 있는 결과물과 승인 기록으로 조건을 확인하고 폴더를 완료로 바꿉니다. 같은 완료 표시를 현황표에 다시 만들지 않습니다.

예를 들어 입과안내는 안내문 작성 후 대상·일정 확인과 발송까지 필요한지 정해 둡니다. 원래 승인 절차가 없는 일에 새 승인을 일괄 추가하지 않습니다. 수정 요청을 받으면 이유를 문제 기록에 적고, 상태를 진행 중 또는 확인 필요로 바꿉니다.

## 다른 사람에게 일을 넘길 때

휴가, 담당자 변경, 다른 팀으로의 전달 때 다음 순서로 확인합니다.

1. 기본정보에서 자료 위치, 담당자, 대신 맡을 사람을 고칩니다.
2. 일을 이어받는 사람이 자신의 계정으로 원본과 필요한 결과물을 열어 봅니다. 열리지 않으면 권한 담당자에게 요청합니다.
3. 함께 일정표와 문제 기록을 봅니다. 가장 가까운 할 일·마감·남은 문제를 확인했다는 기록을 한 줄 남깁니다.

예: “운영 대행이 자료를 열어 보고, 9월 21일에 확정 인원 회신을 확인하기로 함.”

전체 업무폴더를 개인 공간에 복사해서 넘기지 않습니다. 실제 이름·계정·업무 경로는 내부 기록에만 적습니다.

## 업무를 끝낼 때

1. 확정 결과물과 필요한 승인 근거를 확인합니다.
2. 남은 일이 없으면 보관합니다. 남은 일이 있다면 이어서 할 업무의 위치·담당자·마감을 적습니다.
3. 아직 담당자를 정해 넘기지 못한 일이 있으면 종료를 미룹니다.
4. 회사 보관 기준에 따라 업무폴더 전체를 옮깁니다.
5. 기본정보와 기존 업무목록의 링크를 고치고, 권한이 있는 다른 담당자가 열 수 있는지 확인합니다.

## 보관한 일을 다시 시작할 때

먼저 기록 담당자에게 보관한 원본을 수정해도 되는지 확인합니다.

| 확인 결과 | 할 일 |
|---|---|
| 보관 원본을 옮겨 수정해도 됩니다. | 공식 작업 위치로 옮기고 연결된 링크를 고칩니다. |
| 보관본을 그대로 남겨야 합니다. | `10_Active`에 이어서 할 업무폴더를 만듭니다. 과거 기록의 링크와 필요한 결과물만 연결합니다. |

같은 일을 두 위치에서 따로 수정하지 않습니다. 다시 시작한 이유, 담당자, 다음 마감은 기존 현황표에 적습니다.

## 자료 위치와 기본 폴더를 최신으로 유지하기

업무를 찾기 어렵다는 일이 반복되면 기존 팀 업무목록에 업무명·담당자·원본 링크를 둡니다. 폴더별 상태와 세부 일정은 다시 옮겨 적지 않습니다. 업무 종료·이동·담당 변경 때 해당 줄만 고칩니다.

오래된 양식이나 자주 빠뜨리는 내용을 발견하면, 업무를 끝낼 때 기본 폴더에서 고칠 점을 한 줄 남깁니다. 표준 담당자가 반영하고 버전과 이유를 적습니다. 바뀐 기본 폴더는 다음 업무부터 사용합니다.

기본 폴더의 단계는 시작 전으로 유지합니다. FolderState를 쓰면 `todo`만 저장합니다. 시험은 복사본에서 하고, 이미 진행 중인 업무를 자동으로 덮어쓰지 않습니다.

참고자료를 다시 쓸 때는 원본 내용이 지금도 맞는지 확인하고, 원본 링크와 확인일을 갱신하는 방법을 제안합니다.

## 예외

한 사람이 짧게 하는 일이라면 대신 맡을 사람이나 인수인계 항목을 생략할 수 있습니다. 기존 회사 시스템에서 담당자·마감·문제를 관리한다면 별도 대장을 만들지 않습니다.

접근 제한이나 보관본 수정 금지 등 회사 기준과 맞지 않으면, 업무·기록 담당자가 적용할 범위와 기간을 내부 결정 기록에 남깁니다.

## 도움이 되었는지 확인하기

업무 한 건에서 ‘답을 다시 확인할 날짜’와 ‘완료로 표시할 조건’부터 시험해 봅니다. 시작 전과 종료 후를 비교해, 회신 확인을 놓친 일과 완료 후 다시 고친 일이 줄었는지 봅니다. 비교할 이전 기록이 없으면 첫 업무의 결과부터 남깁니다.

인수인계가 있다면 일을 이어받는 사람이 원본을 열고 다음 할 일을 설명할 수 있는지 확인합니다. 업무폴더를 빨리 찾는지, 오래된 양식을 다시 쓰는 일이 줄었는지도 적용한 항목에 맞춰 봅니다.

추가로 기록하는 데 든 시간과 실제 누락 사례만 기존 업무 검토 기록에 남깁니다. 도움이 없는 입력 항목은 줄입니다. 무엇을 계속 사용할지는 업무 책임자가 결정합니다.
