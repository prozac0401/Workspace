# 자료를 둘 곳 정하기

정책: 자료를 둘 곳 정하기 · 상태: 제안 · 버전: 0.3 · 책임: 업무 책임자 · 근거: 원문 02 §1–4, §13, §18–19, §22–24

승인자·승인일·적용일: 미확정.

## 이 안내가 필요한 때

**새 자료는 임시로 모으고, 진행 중인 일은 한 폴더에 두고, 끝난 일은 폴더째 보관합니다.** 개인과 팀이 자료를 다시 찾고 다른 사람에게 일을 넘길 때 쓰는 기준입니다. 회사의 접근 권한과 보관 규정을 먼저 따릅니다.

아래의 `Work`는 업무자료를 두는 폴더입니다. 프로그램을 개발하는 저장소 `Workspace`와는 다른 곳입니다.

## 꼭 필요한 만큼만 정리하기 {#principles}

새 일을 시작하거나, 자료를 쓰거나, 일을 마칠 때 필요한 정리를 함께 합니다. 같은 내용은 기준이 되는 한 곳에서만 고칩니다.

아직 둘 곳을 모르겠으면 `00_Inbox`에 잠시 둬도 됩니다. 매일 비우거나 모든 파일의 이름을 바꿀 필요는 없습니다. 과거 자료 전체와 이미 보관한 폴더 안을 다시 정리하지 않습니다. 회사가 정한 백업·보관 점검과 업무 마감은 지킵니다.

지금 할 일을 고르려면 [지금 할 일 찾기](../quick-reference.md)를, 진행 상태를 표시하려면 [일을 하면서 상태 바꾸기](kits.md#events)를 보세요.

## 자료를 둘 폴더 여섯 개

```text
Work
├─ 00_Inbox        아직 둘 곳을 정하지 않은 자료
├─ 10_Active       지금 하는 일
├─ 20_Operations   다음에 복사해 쓸 양식과 안내
├─ 40_Reference    여러 업무에서 참고할 자료
├─ 80_Archive      끝난 일의 기록
└─ 90_Temp         지워도 되는 임시자료
```

| 폴더 | 무엇을 넣나요? | 언제 옮기거나 고치나요? |
|---|---|---|
| `00_Inbox` | 다운로드나 메일 첨부 등 새 자료 | 실제로 쓸 때 해당 업무폴더로 옮깁니다. |
| `10_Active` | 현재 하는 일의 파일과 기록 | 일을 마치고 보관 조건을 확인하면 `80_Archive`로 옮깁니다. |
| `20_Operations` | 복사해 쓸 기본 폴더(`MASTER`)와 업무 안내 | 담당자가 바뀐 업무 기준을 승인하면 고칩니다. |
| `40_Reference` | 여러 업무에서 참고할 정책과 설명서 | 내용이 현재에도 맞는지 확인할 때 고칩니다. |
| `80_Archive` | 끝난 업무의 폴더 전체 | 회사가 정한 보관 기간과 처리 방법을 따릅니다. |
| `90_Temp` | 없어져도 업무기록이 사라지지 않는 자료 | 사용을 마친 뒤 확인하고 정리합니다. |

한 번만 진행하는 프로젝트가 많으면 `30_Projects`를 추가할 수 있습니다. 같은 일을 `10_Active`와 `30_Projects` 양쪽에서 따로 수정하지 않습니다. 한 곳을 정하고 다른 곳에는 바로가기를 둡니다.

업무 순서를 나타내는 `01`, `02` 같은 번호는 각 업무폴더 안에서 사용합니다.

## 새 업무폴더 만들기 {#container}

교육을 한 번 운영하거나 한 달 비용을 처리하는 것처럼 **시작부터 종료까지 함께 관리할 일마다 폴더 하나**를 만듭니다. 예를 들어 `2026-10_AWS_과정운영`에는 10월 과정의 자료를 모읍니다.

1. 반복하는 일이면 `20_Operations`의 기본 폴더(`MASTER`)를 복사합니다.
2. `10_Active` 안에 두고 이번 업무에 맞게 이름을 바꿉니다.
3. 새 파일을 받으면 그 업무폴더의 해당 단계에 넣습니다.

첨부파일 하나를 받을 때마다 새 업무폴더를 만들지는 않습니다. 목적·일정·결과물을 따로 관리해야 할 때 새 폴더를 만듭니다. 처음 하는 일은 필요한 폴더만 만들고, 다음에도 반복할 때 복사용 기본 폴더로 만들지 검토합니다.

끝난 업무의 자료를 참고할 때는 `80_Archive`의 원본으로 연결합니다. 두 곳에서 같은 자료를 따로 고치지 않습니다.

## 같은 자료가 여러 곳에 있으면 기준을 하나 정하기 {#source-of-truth}

여기서 **원본**은 최신 내용을 확인하고 수정하는 기준 위치를 뜻합니다. 아래 표는 제안입니다. 실제 사용할 시스템과 담당자는 회사에서 정합니다.

| 찾으려는 정보 | 기준으로 삼을 곳 | 함께 정할 내용 |
|---|---|---|
| 최신 교육생 명단 | 교육관리시스템(LMS) 또는 확정된 Excel 파일 중 한 곳 | 파일·시스템 위치, 수정 담당자 |
| 주고받은 내용 | 회사 이메일 | 메일 시스템, 검색할 제목이나 날짜 |
| 최종 결과물 | 해당 업무폴더 | 폴더 위치, 승인 담당자 |
| 반복 업무의 순서와 양식 | 승인된 복사용 기본 폴더(`MASTER`) | 버전, 관리 담당자 |
| 폴더의 진행 상태 | FolderState를 쓴다면 `.folderstate.ini` | 상태를 판단하고 바꿀 담당자 |
| 공식 일정 | 일정표(`Schedule`) 또는 회사 일정 시스템 중 한 곳 | 기준일, 변경 내용을 알리는 방법 |
| 결정한 이유 | 해당 업무의 결정 기록(`Decision Log`) | 결정일, 근거를 찾을 위치 |

개인 초안과 팀 확정본을 양쪽에서 따로 수정하지 않습니다. 참고용 사본에는 원본 위치를 적습니다.

## 예외와 확인 방법

기본 분류로 자료를 찾기 어렵다면, 업무 책임자가 실제로 못 찾았던 사례를 보고 예외를 정합니다. 바꾼 기준은 내부 기록에 남깁니다.

업무 한 건을 골라 현재 폴더, 다음 마감, 결정한 이유, 최종 결과물을 찾을 수 있는지 확인합니다. 같은 불편이 반복되면 [일을 이어서 하고 다른 사람에게 넘기기](folder-workflow.md)에서 필요한 방법만 사용합니다.
