# 기본 구조와 원본

정책: 기본 구조와 원본 · 상태: 제안 · 버전: 0.2 · 책임: 업무 책임자 · 근거: 원문 02 §1–4, §13, §22–24

## 목적과 범위

현재 작업, 표준 원본, 종료 기록을 쉽게 찾고 인수인계하기 위한 기준입니다. 회사의 접근권한·보관 규정을 우선합니다. 업무용 Work와 개발 저장소 Workspace는 별개 공간입니다.

## 정리 노동을 줄이는 원칙 {#principles}

**정리가 일이 되지 않아야 합니다.** 자료를 다시 찾고 업무를 이어갈 수 있는 최소한의 분류만 유지합니다. 새 업무·착수·문제·완료·종료에 필요한 정리를 붙이고, 같은 정보는 원본 한 곳에서만 수정합니다.

Inbox는 위치 판단을 잠시 미뤄도 되는 곳입니다. 매일 비우기, 모든 파일명 표준화, 과거자료 전면 재정리, Archive 내부 재분류를 기본 업무로 만들지 않습니다. 조직에서 필요한 백업·보존 점검과 실제 업무 마감은 별도로 지킵니다.

상황별 선택은 [빠른 판단 기준](../quick-reference.md), 일상의 상태 변경은 [업무 사건과 상태](kits.md#events)를 참고하세요.

## 기본 폴더

```text
Work
├─ 00_Inbox
├─ 10_Active
├─ 20_Operations
├─ 40_Reference
├─ 80_Archive
└─ 90_Temp
```

| 위치 | 넣는 것 | 이동 시점 |
|---|---|---|
| Inbox | 아직 위치를 정하지 않은 새 자료 | 실제 사용할 때 해당 업무로 |
| Active | 현재 진행하는 회차 전체 | 종료 검토 후 Archive로 |
| Operations | MASTER, Playbook, Guide | 승인된 표준 변경으로 갱신 |
| Reference | 여러 업무에서 참고하는 정책·매뉴얼 | 유효성 검토 |
| Archive | 종료된 업무 컨테이너 | 조직의 보존·처분 기준에 따름 |
| Temp | 없어져도 업무기록이 손실되지 않는 자료 | 사용 완료 후 명시적 정리 |

비정기 프로젝트가 많으면 30_Projects를 추가합니다. 같은 업무를 Active와 Projects에서 동시에 관리하지 않고 위치 하나와 링크를 사용합니다. 프로세스 번호는 각 키트 내부의 업무 순서에 사용합니다.

## 새 업무 컨테이너를 만드는 기준 {#container}

새 회차이거나 목적·일정·결과물을 독립적으로 관리해야 하는 업무라면 새 컨테이너를 만듭니다. 같은 회차의 새 파일은 기존 컨테이너의 해당 단계에 둡니다. 첨부파일 하나를 받을 때마다 새 업무 폴더를 만들지 않습니다.

반복 업무는 MASTER를 복사합니다. 비정기 업무는 Active 안에 필요한 최소 폴더로 시작하고, 반복할 필요가 확인될 때 MASTER 후보로 삼습니다. 끝난 회차의 결과물을 다른 업무에서 참고할 때는 Archive 원본 링크를 연결하고 양쪽에서 별도로 수정하지 않습니다.

## 원본 시스템 {#source-of-truth}

| 정보 | 기본 제안 | 운영 시 적을 항목 |
|---|---|---|
| 최신 교육생 명단 | LMS 또는 확정 Excel 중 하나 | 원본·수정 담당 |
| 커뮤니케이션 | 회사 이메일 | 시스템·검색 단서 |
| 최종 결과물 | 공식 업무 컨테이너 | 경로·승인 담당 |
| 표준 프로세스 | 승인된 MASTER | 버전·관리 담당 |
| 단계 상태 | .folderstate.ini | 수동 판단 담당 |
| 공식 일정 | Schedule 또는 일정 시스템 중 하나 | 기준일·전달 방식 |
| 결정 이유 | 회차 Decision Log | 결정일·근거 위치 |

개인 초안과 팀 확정본을 양쪽에서 독립적으로 수정하지 않습니다. 참고 사본에는 원본 위치를 남깁니다. 분류 예외는 실제 찾기 실패 사례를 근거로 기록합니다.
