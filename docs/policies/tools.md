# 추가 도구 개발 기준

정책: 추가 도구 개발 기준 · 상태: 제안 · 버전: 0.2 · 책임: 제품·개발 담당

FolderState와 향후 키트 생성기·일정 계산기·상태 요약·메일 보관 도구는 같은 운영 정책을 참조합니다. 필요가 확인된 기능부터 별도 명세로 시작합니다.

## 최우선 구현 원칙: 확인된 요구와 필요한 최소 작업

2026-10-04 사용자가 모든 구현 단계의 최우선 원칙으로 확정했다. 이 개발 원칙의 확정은 회사 정책 전체의 승인을 뜻하지 않는다.

- 확인된 요구나 재현한 결함에 필요한 만큼만 구현한다. 미래에 필요할 것이라는 추측으로 기능·추상화·의존성·상주 동작·지원 조합을 늘리지 않는다.
- 사용자 데이터 보존을 충족하는 가장 작은 변경을 선택한다. 기존 구현은 입력과 보존 계약이 맞는 부분만 재사용한다.
- 단계마다 요구, 바꿀 동작, 완료를 판단할 최소 근거를 기존 작업 기록에 짧게 적는다. 별도 승인 절차나 보고 체계를 추가하지 않는다.
- 변경된 동작, 재현한 실패, 실제 데이터·설치 위험에 직접 연결되는 검증을 선택한다. 기존 성공 증거는 재사용하고, 완료한 수동 시험이나 무관한 전체 GUI·설치·성능·전체 suite를 반복하지 않는다.
- 필요한 근거가 확보되면 해당 단계의 검증을 마친다. 추가 시험은 새 변경·실패·미해결 우려가 있을 때만 확대한다. 관련 필수 검증과 실제 FAIL/NOT RUN은 보존한다.

| 계약 | 정의할 것 | FolderState의 현재 선택 |
|---|---|---|
| 목적 | 해결하는 업무·사용자 | 단계 상태 표시 |
| 소유 데이터 | 읽고 쓰는 정확한 대상 | 선택 폴더의 고정 메타데이터 |
| 금지 동작 | 하지 않는 행동 | 업무파일 열람·삭제·이름변경·하위 검색 |
| 범위 | 단일·일괄·재귀 | 폴더별, CLI 명시 목록만 일괄 |
| 복구 | 실패·중단·제거·버전 변경 | 복원 정보, 초기화, 아이콘 복구 |
| 권한 | 실행·설치·저장 위치 | 일반 사용자, HKCU, LocalAppData |
| 증거 | 테스트·수동검증·지원 범위 | 통합 테스트와 배포 게이트 |

## 확장 경계

상태변경에 하위 검색을 결합하지 않습니다. 키트 전체 초기화·상위 상태 요약은 별도 명령에서 범위를 선택하고 결과를 미리 보여줍니다. 일괄 처리에서는 성공·실패를 분리해 보고합니다.

이동·삭제·메일 처리처럼 업무 원본을 바꾸는 도구는 미리보기, 범위, 중복 실행 방지, 취소, 복구, 감사 기록을 설계합니다. 상태표시에 암묵적으로 결합하지 않습니다.

형식은 버전을 포함하고 알 수 없는 미래 버전을 덮어쓰지 않습니다. 로그는 목적에 필요한 정보만 로컬에 저장합니다. 외부 전송이 필요해지면 내용·대상·사용자 선택을 별도 명세로 공개합니다.

## 추가 절차와 검증

도구 제안 → 명세 → ADR → 구현 → 대응표 → 테스트 → 사용·복구 안내 → 설치 수명주기 검증 → 배포 기록으로 연결합니다. 공통 라이브러리는 실제 두 번째 사용처가 있을 때 추출합니다. 예외는 별도 ADR로 기록합니다. v0.1 최초 제안.

2026-10-04 · v0.2: 확인된 요구에 따른 최소 구현과 필요한 검증만 수행하는 원칙을 최우선 개발 기준으로 추가했다. 과도한 시험과 선제적 복잡도 증가를 금지하고 기존 실패·미실행 증거의 보존을 명시했다.
