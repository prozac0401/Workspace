# 보관·보안·백업

정책: 보관·보안·백업 · 상태: 제안 · 버전: 0.1 · 책임: 기록 관리·IT 담당 · 근거: 원문 02 §16–17, §20–22

## 종료와 보관

미완료·이슈·민감자료 위치를 검토한 뒤 회차 전체를 80_Archive/연도/업무종류 아래로 이동합니다. 내부 문서를 다시 세밀하게 재분류하지 않습니다. 원본 위치가 바뀌면 링크를 갱신합니다. FolderState는 이 이동을 자동으로 수행하지 않습니다.

보존기간은 임의의 공통 연수로 정하지 않습니다. 자료별 조직 기준, 담당, 기산점, 보존 중지 사유, 처분 승인 방식을 결정 목록에 기록합니다. 확정 전 자동 삭제는 없습니다. Temp도 필요한 기록의 유일한 사본이 아닌지 확인 후 정리합니다.

Legacy는 도입 기준일을 경계로 기존 위치에서 유지합니다. 재사용·인수인계가 필요한 경우만 새 구조에 편입합니다.

## 접근 통제와 공개 범위

교육생 명단·연락처·계정정보·비용·계약·업체 기밀·DRM 자료는 조직의 보안영역에 둡니다. 폴더명에 민감한 내용을 과도하게 노출하지 않습니다. Hidden/System 속성은 표시 설정이며 접근 통제가 아닙니다. 비밀번호는 키트에 저장하지 않습니다.

공개 페이지에는 업무 운영 정책·가상 예시·FolderState 사용법만 게시합니다. 실제 메일·명단·사용자 경로가 포함된 로그·화면은 게시하지 않습니다. 개인 초안과 공유 확정본의 원본과 권한을 구분합니다.

## 백업과 검증

Work 루트를 정할 때 백업 대상·담당·주기·복구 목표·권한·복원 방법도 정합니다. 동기화만으로 삭제·훼손 복원이 가능하다고 가정하지 않습니다. 도입 시 표본 복원 시험을 하고 조직 기준에 따라 재확인합니다. [결정 목록](decisions.md)에서 실제 서비스를 확정합니다.

보관 후 담당자가 바뀌거나 업무를 재개할 때는 [인수인계와 종료·재개 개선안 — 선택 적용](folder-workflow.md)에서 필요한 항목만 참고합니다. 조직별 보존 예외가 우선합니다.
