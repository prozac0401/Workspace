# 끝난 업무 보관과 자료 보호

정책: 끝난 업무 보관과 자료 보호 · 상태: 제안 · 버전: 0.2 · 책임: 기록 관리·IT 담당 · 근거: 원문 02 §16–17, §20–22

승인자·승인일·적용일: 미확정.

## 이 안내가 필요한 때

**끝난 업무는 폴더째 보관하고, 중요한 자료는 권한과 백업을 확인합니다.** 업무를 마치거나 저장 위치를 정할 때 쓰는 기준입니다. 보관 기간과 자료를 볼 수 있는 사람은 회사에서 정합니다.

## 끝난 업무를 보관할 때

1. 아직 끝나지 않은 일이나 확인할 문제가 있는지 봅니다.
2. 개인정보 등 주의가 필요한 자료가 알맞은 보안 위치에 있는지 확인합니다.
3. 업무폴더 전체를 `80_Archive/연도/업무종류` 아래로 옮깁니다.
4. 폴더 위치가 바뀌었으므로 연결된 링크를 고칩니다.

예를 들어 `10_Active/2026-09_AWS_과정운영`을 `80_Archive/2026/과정운영/2026-09_AWS_과정운영`으로 옮깁니다.

폴더 안의 문서를 다시 잘게 분류할 필요는 없습니다. 폴더 이동은 담당자가 합니다. FolderState가 자동으로 옮겨 주지는 않습니다.

## 자료를 언제까지 보관할지 정하기

모든 자료의 보관 기간을 임의로 똑같이 정하지 않습니다. 기록 담당자가 자료 종류별로 아래 내용을 [회사에서 정할 항목](decisions.md)에 연결해 남깁니다.

- 회사가 정한 보관 기간과 담당자
- 보관 기간을 세기 시작하는 날짜
- 삭제를 미루고 계속 보관해야 하는 사유
- 삭제 등 최종 처리를 승인하는 방법

기준이 정해지기 전에는 자동으로 삭제하지 않습니다. `90_Temp`도 필요한 기록이 그곳에만 남아 있지 않은지 확인한 뒤 정리합니다.

새 정리 방법을 쓰기 전의 자료는 기존 위치에 둡니다. 이를 이전 자료(`Legacy`)라고 합니다. 새 방법을 적용할 기준일을 정하고, 실제로 다시 쓰거나 인수인계할 자료만 새 구조로 옮깁니다.

## 중요한 자료를 보호하기

교육생 명단, 연락처, 계정정보, 비용·계약 자료, 업체 기밀자료, 사용 제한이 걸린 자료(DRM)는 회사가 허용한 보안 저장소에 둡니다. 필요한 사람만 열 수 있도록 권한을 정합니다.

폴더 이름에 민감한 내용을 지나치게 드러내지 않습니다. 비밀번호는 복사용 기본 폴더(`MASTER`)에 저장하지 않습니다.

Windows의 숨김(`Hidden`)·시스템(`System`) 속성은 화면에 보이는 방식을 바꿉니다. 다른 사람의 접근을 막는 기능은 아닙니다.

## 공개해도 되는 내용 확인하기

공개 페이지에는 업무 정리 안내, 가상 예시, FolderState 사용법만 게시합니다. 실제 메일·명단이나 사용자의 폴더 위치가 나온 로그·화면은 게시하지 않습니다.

개인 초안과 팀 공유 확정본은 기준 파일의 위치와 열 수 있는 사람을 구분해 둡니다.

## 백업하고 실제로 되살려 보기

업무자료를 둘 `Work` 폴더의 위치를 정할 때 다음 내용을 IT 담당자와 정합니다.

| 정할 내용 | 확인할 점 |
|---|---|
| 대상과 담당 | 어떤 자료를 누가 백업하나요? |
| 주기 | 얼마나 자주 백업하나요? |
| 복구 목표 | 문제가 나기 전 어느 시점까지, 얼마나 빨리 되살려야 하나요? |
| 권한과 방법 | 누가 어떤 방법으로 되살릴 수 있나요? |

동기화는 여러 곳의 내용을 같게 맞추는 기능입니다. 동기화만 사용한다고 삭제되거나 망가진 파일을 되살릴 수 있다고 가정하지 않습니다.

처음 사용할 때 일부 파일을 실제로 복원해 봅니다. 이후에는 회사 기준에 따라 다시 확인합니다. 실제 사용할 서비스는 [회사에서 정할 항목](decisions.md)에 남깁니다.

## 예외와 확인 방법

회사에서 따로 정한 보관 기준과 예외를 우선합니다. 담당자가 바뀌거나 보관한 일을 다시 시작할 때는 [일을 이어서 하고 다른 사람에게 넘기기](folder-workflow.md)에서 필요한 방법을 확인합니다.

보관한 업무폴더를 다시 찾을 수 있는지, 필요한 사람만 열 수 있는지, 시험한 파일을 백업에서 되살릴 수 있는지 확인합니다.
