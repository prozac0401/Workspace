# 반복 업무 시작과 일정 관리

정책: 반복 업무 시작과 일정 관리 · 상태: 제안 · 버전: 0.3 · 책임: 표준 담당 · 근거: 원문 02 §3–7, §14–15, §19

승인자·승인일·적용일: 미확정. 표준 담당은 반복 업무의 순서와 공통 양식을 관리하는 사람입니다.

## 새 반복 업무를 시작할 때 {#master}

**기본 폴더를 복사해서 이번 업무를 시작합니다.** 기본 폴더에는 매번 필요한 순서와 빈 양식을 넣어 둡니다. 이 문서에서는 폴더 이름에 맞춰 `MASTER`라고 부릅니다. 폴더와 양식을 묶어 ‘업무 키트’라고도 합니다.

1. `20_Operations`에서 필요한 `MASTER` 폴더를 복사합니다.
2. `10_Active`에 붙여 넣고 `2026-10_AWS_과정운영`처럼 이름을 바꿉니다.
3. 복사한 폴더의 기본정보(`Overview`)에 업무명, 사용한 키트 이름·버전, 만든 날짜를 적습니다.
4. 이번 업무는 복사본에서 진행합니다.

`MASTER`에 실제 업무자료를 작성하지 않습니다. 나중에 `MASTER`를 고쳐도 이미 진행 중인 업무를 자동으로 덮어쓰지 않습니다.

### 기본 폴더는 ‘시작 전’으로 두기

`MASTER`의 단계 폴더는 항상 **시작 전**으로 둡니다. FolderState를 사용한다면 각 단계에 시작 전을 저장합니다. 진행 중·완료·확인 필요는 이번 업무의 복사본에서 사용합니다.

기본 폴더를 만들거나 고칠 때 상태를 확인합니다. 시연이나 시험은 복사본에서 합니다. 그러면 새 업무를 시작할 때마다 모든 상태를 다시 바꿀 필요가 없습니다.

FolderState를 쓰지 않는 기본 폴더에는 상태 파일이 없어도 됩니다. 이때 ‘시작 전’은 아직 일을 하지 않았다는 뜻입니다. 프로그램이 상태를 자동으로 저장하거나 표시한다는 뜻은 아닙니다.

### 교육 운영용 기본 폴더 예시

```text
MASTER_과정운영
├─ 00_운영현황.xlsx
├─ 01_과정기본정보
├─ 02_강사및일정확정
├─ 03_교육생선발
├─ 04_입과안내
├─ 05_계정및시스템
├─ 06_OT준비
├─ 07_과정운영
├─ 08_설문및수료
└─ 09_비용및종료
```

`OT`는 교육을 시작하기 전 안내 시간을 뜻합니다. 비용처리용 폴더는 `00_현황` / `01_대상확정` / `02_증빙수집` / `03_내역작성` / `04_결재` / `05_완료`를 기본으로 합니다. 계정관리와 교육생선발용 폴더는 필요할 때 추가합니다.

## 업무 현황과 일정 적기 {#overview}

`00_운영현황.xlsx`에는 폴더만으로 알기 어려운 내용을 적습니다. 아래 영어 이름은 시트 이름의 예시입니다.

| 시트 | 적을 내용 | 같은 내용을 다시 적지 않기 |
|---|---|---|
| 기본정보(`Overview`) | 업무명, 기간, 담당자, 원본 위치, 키트 버전 | 각 폴더의 상태는 여기로 옮겨 적지 않습니다. |
| 일정표(`Schedule`) | 기준일, 할 일의 날짜·마감, 담당자 | 모든 항목을 달력에 다시 입력하지 않습니다. |
| 확인 목록(`Checklist`) | 한 단계 안에서 빠뜨리기 쉬운 확인사항 | 폴더의 완료 표시와 같은 체크를 반복하지 않습니다. |
| 연락처(`Contacts`) | 담당 역할, 조직, 필요한 연락 방법 | 필요 없는 개인정보는 적지 않습니다. |
| 문제·결정 기록(`Issues / Decision Log`) | 생긴 문제, 결정한 내용과 이유, 근거 위치 | 메일 전체를 복사하지 않습니다. |

### 날짜 정하기

교육 시작일을 `D`, 종료일을 `E`라고 놓고 아래처럼 일정을 준비할 수 있습니다. `D-30`은 시작 30일 전, `E+1`은 종료 다음 날입니다.

| 언제 | 할 일 |
|---|---|
| 시작 30일 전(`D-30`) | 모집 시작 |
| 시작 21일 전(`D-21`) | 모집 마감 |
| 시작 14일 전(`D-14`) | 교육생 선발 |
| 시작 10일 전(`D-10`) | 입과 안내 |
| 시작 7일 전(`D-7`) | 계정 준비 |
| 시작 3일 전(`D-3`) | OT 자료 확정 |
| 시작 하루 전(`D-1`) | 장소 확인 |
| 종료 다음 날(`E+1`) | 설문 |
| 종료 3일 후(`E+3`) | 수료 처리 |
| 종료 7일 후(`E+7`) | 비용 처리 |

이 표는 일정의 예시입니다. 실제 회사 일정으로 확정한 뒤 사용합니다. 휴일을 포함할지, 일하는 날만 셀지는 따로 정합니다.

회의나 승인 마감처럼 시간을 비워 두거나 알림이 필요한 일정만 개인 달력에 넣습니다. 일정이 바뀌면 공식 일정표를 먼저 고칩니다.

## 일을 하면서 상태 바꾸기 {#events}

FolderState를 쓴다면 담당자가 다음 시점에 해당 단계 폴더의 상태를 바꿉니다.

| 언제 | 할 일 |
|---|---|
| 새 반복 업무를 시작할 때 | 시작 전 상태의 `MASTER`를 `10_Active`에 복사합니다. 이름·기본정보·기준일을 입력합니다. |
| 한 단계를 시작할 때 | 해당 폴더를 **진행 중**으로 바꿉니다. |
| 문제가 생겨 다음 일을 할 수 없을 때 | **확인 필요**로 바꿉니다. 필요한 문제와 결정 이유를 기존 문제 기록에 적습니다. |
| 한 단계를 끝냈을 때 | 결과물과 필요한 승인·전달 여부를 확인하고 **완료**로 바꿉니다. |
| 업무 전체를 끝냈을 때 | 남은 일과 보관 조건을 확인하고 업무폴더 전체를 `80_Archive`로 옮깁니다. |

FolderState는 일을 시작하거나 끝낸 시점을 자동으로 알아내지 않습니다. 완료 판단과 폴더 이동은 담당자가 합니다. 남은 일이 있으면 종료를 미루거나, 이어서 할 업무의 위치·담당자·마감을 남깁니다.

### 기본 폴더에 진행 중이나 완료 표시가 남아 있으면

잘못된 단계만 한 번 **시작 전**으로 고칩니다. 그 상태를 복사해 받은 새 업무도 해당 단계만 바로잡습니다. 정상적인 기본 폴더를 복사할 때마다 전체 상태를 다시 입력할 필요는 없습니다.

**‘시작 전’은 상태를 저장하는 기능이고, ‘상태 표시 지우기’는 상태정보를 없애고 기존 아이콘을 돌려놓는 기능입니다.** FolderState v0.1은 하위 폴더의 상태를 한꺼번에 지우지 않습니다. PC에 설치된 아이콘을 사용하는 방식(`Local Mode`)의 복사본을 다른 PC에서 열면, 상태가 남아 있어도 [아이콘을 다시 표시해야 할 수 있습니다](../tools/folderstate/index.md).

## 예외와 확인 방법

업무 한 건에서 **무엇을, 언제까지, 누가 하는지** 찾을 수 있는지 확인합니다. 기본 폴더를 만들거나 고칠 때는 실제 업무자료가 없는지, 저장된 상태가 시작 전인지 확인합니다. 상태 표시를 쓰지 않는 기본 폴더는 상태 파일 없이 유지합니다.

단계를 바꾸면 표준 담당자가 결정 내용과 키트 버전을 남깁니다. 회신이나 인수인계에서 같은 문제가 반복되면 [일을 이어서 하고 다른 사람에게 넘기기](folder-workflow.md)에서 필요한 방법만 다음 버전에 반영합니다.

??? info "명령줄을 사용하는 경우"
    명령어와 상태 파일에서는 아래 값을 사용합니다. 화면의 이름만 바뀌었으며 저장되는 값은 같습니다.

    | 화면 이름 | 명령어에 입력하고 파일에 저장하는 값 |
    |---|---|
    | 시작 전 | `todo` |
    | 진행 중 | `doing` |
    | 완료 | `done` |
    | 확인 필요 | `issue` |

    FolderState를 사용하는 `MASTER`의 단계 폴더에는 `todo`만 저장합니다. 다른 상태 값은 실제 업무의 복사본에서 사용합니다. 상태 표시를 쓰지 않는 `MASTER`는 상태 파일 없이 유지할 수 있습니다. 자세한 명령어는 [문제 해결과 명령어](../tools/folderstate/troubleshooting.md)를 보세요.
