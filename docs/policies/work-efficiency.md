# 업무효율화의 확장 순서

정책: 업무효율화의 확장 순서 · 상태: 제안 · 버전: 0.1 · 책임 역할: 업무 책임자·표준 담당

승인자·승인일·적용일: 미확정. 관련 정책: [기본 구조와 원본](workspace.md), [업무 키트와 일정](kits.md), [파일과 이메일](files-email.md), [폴더 업무의 진행·인수인계 개선안](folder-workflow.md). 기존 정책을 보완하며 대체하는 문서는 없습니다.

!!! info "반복되는 불편에 따라 선택 적용"
    이 문서는 정리에서 업무 지식과 Agent까지 이어지는 운영 방향을 제안합니다. 현재의 10대 기본원칙을 유지하며 새 시스템이나 별도 대장을 필수로 만들지 않습니다. Work Inbox·지식 검색·AI·Agent의 도입이나 구현 완료를 뜻하지 않습니다. 사용할 도구, 데이터 접근권한, AI에 제공할 수 있는 정보와 실행 허용 범위는 조직별 미확정 사항입니다.

## 목적과 적용 범위

자료를 다시 찾고 업무를 이어가는 데서 출발해, 지난 업무의 경험을 다음 업무에 쓰고 반복 행동을 줄이기 위한 지도입니다. 개인·팀의 업무 운영과 향후 도구 검토에 적용합니다. 정리의 성공 기준은 깔끔함보다 재개 가능성이며, 기록과 도구가 늘어날수록 이 기준을 다시 확인합니다.

**한 단계를 건너뛰기보다, 현재 반복해서 불편한 지점을 다음 단계로 삼습니다.** 모든 단계를 완료해야 하거나 Agent까지 도입해야 하는 것은 아닙니다. 기존 기록과 도구로 충분하면 그 상태를 유지합니다.

## 일곱 단계의 지도 {#roadmap}

| 단계 | 바꾸려는 업무 경험 | 최소한의 적용 |
|---|---|---|
| 01 정리 | 다시 찾을 수 있게 한다 | 업무 컨테이너와 원본 위치 하나를 정한다 |
| 02 흐름 | 지금 어디까지 왔는지 알게 한다 | 유입된 요청을 판단하고 다음 행동·담당·필요한 마감을 연결한다 |
| 03 표준화 | 반복 업무를 매번 다시 생각하지 않는다 | 반복되는 순서와 완료 기준을 미착수 MASTER에 반영한다 |
| 04 기록 | 무엇을 했는지보다 왜 그렇게 했는지를 남긴다 | 중요한 결정·문제에 이유와 근거 위치를 남긴다 |
| 05 지식화 | 과거의 업무가 다음 업무의 입력이 되게 한다 | 지난 문제·결정·결과를 검색하고 적용 조건을 확인해 재사용한다 |
| 06 자동화 | 반복되고 규칙적인 행동을 기계에 넘긴다 | 반복 불편과 규칙이 확인된 작업부터 입력·결과·예외를 정한다 |
| 07 Agent | 정해진 원칙과 업무 흐름 안에서 실행을 맡긴다 | 허용 범위·판단 주체·중단 조건·복구 방법이 정의된 업무에 적용한다 |

입력 창구 정리는 ‘흐름’에, Decision Log는 ‘기록’에 연결됩니다. 도구를 검토할 때도 먼저 “이 지도에서 어떤 반복 불편을 줄이는가?”를 묻습니다. 예를 들어 FolderState는 폴더의 단계 상태를 보여주는 ‘흐름’을 돕습니다. 업무 판단, 지식 검색, Agent 실행까지 제공하는 도구로 해석하지 않습니다.

## 업무 발생점으로서의 Work Inbox {#work-inbox}

Work Inbox는 파일을 잠시 두는 `00_Inbox`보다 넓은 개념입니다. Email·Teams·전화·회의·구두 요청·시스템 알림·Excel에서 발생한 일을 놓치지 않고 판단하는 업무 진입점입니다. 원본을 한곳에 전부 복사하거나 모든 채널을 새 앱으로 옮긴다는 뜻은 아닙니다.

기존 업무목록이나 회사 시스템 중 한 곳을 판단·연결의 기준으로 정하는 안을 제안합니다. 이미 담당과 다음 행동이 명확한 업무는 바로 해당 회차에서 처리합니다. 여러 채널에 흩어져 누락이 반복되는 요청만 이 진입점에 연결합니다.

```text
Email · Teams · 전화 · 회의 · 구두 요청 · 시스템 알림 · Excel
                           ↓
                       Work Inbox
                           ↓
           해야 할 일 / 기다리는 일 / 참고 / 기록
```

| 판단 | 최소 행동 | 업무 원본과의 연결 |
|---|---|---|
| 해야 할 일 | 담당·다음 행동·필요한 마감을 정한다 | 기존 회차의 Schedule 또는 공식 업무 시스템에 연결한다 |
| 기다리는 일 | 상대 역할과 재확인 시점을 정한다 | 같은 일정 원본에서 대기를 관리한다 |
| 참고 | 실제 사용할 업무나 공통 참고 위치에 연결한다 | 필요 없는 사본과 별도 할 일을 만들지 않는다 |
| 기록 | 결정·승인·문제의 이유와 근거를 보존한다 | 기존 Decision Log·Issues와 원본 대화·결과물을 연결한다 |

한 요청에 행동과 기록이 함께 필요할 수 있습니다. 이 경우 같은 요청에서 일정과 결정 근거로 연결하고, 서로 다른 할 일로 중복 등록하지 않습니다. 메일·Teams·Excel에 같은 요청이 이어지면 기존 업무를 갱신합니다. 링크를 지원하지 않는 원본은 날짜·제목 등 다시 찾을 단서를 남깁니다. 전화·구두처럼 원본 기록이 없는 요청은 기존 업무 기록에 요청 내용·시점·요청 역할을 짧게 남깁니다.

입력할 항목은 **요청 요약과 원본 링크, 판단에 필요한 담당·다음 행동**부터 시작합니다. 이미 일정 원본에 있는 마감·상태를 Work Inbox에 다시 쓰지 않습니다. 회차에 연결했다면 그곳에서 진행하고, Work Inbox는 원본 연결만 유지하거나 접수를 끝냅니다. 대기 중인 일의 재확인 책임은 일정 원본에 남습니다. 매일 모든 입력함을 비우거나 모든 알림을 기록하는 의무는 두지 않습니다.

이 네 가지 판단은 FolderState의 새 상태가 아닙니다. 회신 대기의 상태 표시는 기존 [진행·인수인계 개선안](folder-workflow.md)을 따릅니다.

## 기록을 검색 가능한 업무 지식으로 {#knowledge}

“지난번에 이 문제를 어떻게 해결했지?”에 답할 수 있으면 업무 기록은 다음 업무의 입력이 됩니다. 파일은 결과물을, 메일은 대화와 승인 근거를, Decision Log는 선택한 이유를 설명합니다. 여기에 Issue의 문제 상황과 Result의 실제 결과를 연결해 같은 판단을 반복하는 수고를 줄입니다.

```text
File · Email · Decision · Issue · Result
                    ↓
            맥락과 근거가 있는 업무 지식
                    ↓
         검색 → 적용 조건 확인 → 다음 업무에 재사용
```

지식베이스를 별도로 구축하기 전에 기존 Issues·Decision Log·종료 기록부터 활용합니다. 다시 겪을 만한 문제에만 **검색할 수 있는 제목, 상황·조건, 선택과 이유, 결과, 원본 링크**를 남깁니다. 이미 있는 내용을 새 양식에 옮기지 않고 빠진 맥락만 보완합니다. 모든 파일·메일을 요약하거나 Archive를 전면 재분류하지 않습니다.

| 다시 찾으려는 것 | 기존 기록에서 남길 단서 | 다음 업무에서 할 일 |
|---|---|---|
| 같은 문제의 해결 방법 | 문제 이름·발생 조건·조치·실제 결과 | 이번 조건에도 맞는지 확인한다 |
| 선택의 이유 | 결정일·선택·주요 대안과 이유·근거 링크 | 근거가 바뀌었으면 새 결정을 남긴다 |
| 재사용할 결과물 | 결과물 원본·적용 회차·주의할 조건 | 원본을 참고하고 이번 업무의 결과는 해당 회차에서 관리한다 |
| 반복할 표준 | 승인된 MASTER·버전·변경 이유 | 확인된 개선만 다음 MASTER에 반영한다 |

과거의 성공 사례가 현재의 승인된 표준을 대신하지 않습니다. 실제 재사용 시 담당자가 원본의 유효성·접근권한·적용 조건을 확인합니다. 낡은 결론을 발견하면 해당 기록에 후속 결정의 링크를 남기고, 과거의 이유를 지우지 않습니다. 검색 도구나 색인을 검토하더라도 원본 시스템의 접근 범위를 따릅니다. 업무 지식의 재사용은 내부 운영을 뜻하며 실제 업무 기록을 공개 Handbook에 올리는 절차가 아닙니다.

## 자동화·AI 보조·Agent의 역할 {#ai-agent}

자동화는 반복되는 불편, 일관된 규칙, 누락·실수 사례가 확인된 뒤 검토합니다. 같은 내용을 두 번 입력한다면 먼저 원본을 하나로 줄이고, 그래도 남는 반복 행동을 자동화 후보로 삼습니다. 입력과 기대 결과, 예외 상황을 설명할 수 없는 업무는 먼저 흐름과 표준을 다듬습니다.

AI 보조는 허용된 자료에서 검색 단서를 찾거나 요약·초안·누락 확인을 돕는 용도로 검토할 수 있습니다. 업무 담당자는 제안의 원본 근거와 현재 조건을 확인하고 판단합니다. AI가 만든 요약은 메일·결정·결과물의 원본을 대신하지 않으며, 초안만으로 결정이나 완료가 확정되지는 않습니다.

**Agent는 무질서한 업무를 정리해주는 존재가 아니라, 이미 정의된 업무를 실행하는 존재다.**

여기서 Agent는 정해진 목표를 위해 자료를 확인하고 도구로 여러 행동을 이어가는 실행 주체를 뜻합니다. 실행을 맡기기 전에 아래 내용을 기존 업무 절차에 짧게 정하는 안을 제안합니다. 모든 행동마다 새 승인 절차를 만드는 대신, 업무에 이미 필요한 판단과 승인이 어디에 있는지 명확히 합니다.

| 정할 것 | 업무 절차에 남길 내용 |
|---|---|
| 실행 범위 | 사용할 입력·도구·대상, 허용된 읽기·수정·전달 행동과 완료 조건 |
| 판단 주체 | 업무 책임자, 사람이 판단할 예외와 기존 승인 지점 |
| 중단 조건 | 근거 충돌·입력 부족·권한 밖의 요청·예상과 다른 결과가 나오면 멈추고 담당자에게 연결할 조건 |
| 확인과 복구 | 실행 결과와 근거 위치, 실패 시 되돌리거나 사람이 이어갈 방법, 재실행 전 중복 처리 여부 확인 |

먼저 시험용 자료나 영향이 작은 업무 한 건에서 기대 결과와 중단·복구 방법을 확인합니다. 업무 원본을 바꾸는 작업은 실행 전 대상과 변경 내용을 미리 확인하고, 취소·복구 방법과 실행 기록을 남기도록 설계합니다. 되돌릴 수 없는 전달이나 변경은 실행 전 필요한 확인 지점을 정합니다.

사용할 AI 서비스, 제공 가능한 데이터, Agent 계정과 실행 권한, 사람의 검토·승인 범위는 조직이 결정해야 합니다. Work Inbox·지식 검색·AI·Agent의 미확정 항목은 [회사별로 정할 항목](decisions.md)의 DEC-026–028에서 관리합니다. 외부 전송이 필요하면 전송할 내용과 대상, 사용자가 선택할 방법도 먼저 정합니다. 이 문서 자체는 해당 도구 사용이나 업무 데이터 제공을 승인하지 않습니다.

## 예외

개인의 짧은 업무나 기존 시스템만으로 충분한 업무는 Work Inbox·지식 색인·자동화·Agent를 추가하지 않습니다. 업무·기록·보안의 기존 조직 기준을 우선합니다. 적용 범위나 예외를 정해야 한다면 업무 책임자가 관련 담당과 범위·이유·적용 기간을 기존 내부 결정 기록에 남깁니다.

## 실행 예시

가상의 과정운영 회차에서 전화로 일정 변경 요청을 받았다면, 기존 Schedule에 요청 요약과 다음 확인 행동을 남깁니다. 이어서 같은 내용의 메일이 오면 새 할 일을 만들지 않고 그 업무에 원본 메일을 연결합니다. 확정을 기다리는 동안에는 상대 역할과 재확인일을 같은 일정에서 관리합니다.

일정을 바꾸기로 결정하면 Decision Log에 선택 이유와 승인 근거를, 종료 때는 실제 영향과 결과물 링크를 남깁니다. 다음 회차에서 ‘일정 변경’을 검색해 같은 제약이 있는지 확인하고, 반복되는 누락은 MASTER의 확인사항에 반영합니다. 이 흐름이 안정된 뒤 반복 입력을 자동화하거나, 허용된 범위에서 AI가 일정 변경 안내 초안을 준비하도록 검토할 수 있습니다. 실제 일정 확정과 필요한 발송 승인은 기존 담당과 절차를 따릅니다.

## 검증

반복 불편이 있는 업무 한 건에 필요한 단계만 시범 적용합니다. 채널이 다른 동일 요청을 한 업무로 찾을 수 있는지, 기다리는 일의 담당과 재확인 시점을 알 수 있는지, 과거 문제의 이유·결과·원본을 찾아 다음 업무에 쓸 수 있는지 확인합니다.

자동화나 Agent를 검토한다면 정해진 입력으로 기대 결과가 나오는지, 예외에서 멈추는지, 실패 후 중복 처리 없이 사람이 이어갈 수 있는지도 확인합니다. 추가 기록 부담과 줄어든 누락·재작업을 기존 회고에 남기고, 도움이 없는 항목은 줄입니다. 실제 도입 여부와 효과는 아직 검증하지 않았습니다.
