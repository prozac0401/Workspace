# 반복되는 불편 줄이기

정책: 반복되는 불편 줄이기 · 상태: 제안 · 버전: 0.2 · 책임: 업무 책임자·표준 담당

승인자·승인일·적용일: 미확정. 관련 정책: [자료를 둘 곳 정하기](workspace.md), [반복 업무 시작과 일정 관리](kits.md), [파일 이름과 메일 정리](files-email.md), [일을 이어서 하고 다른 사람에게 넘기기](folder-workflow.md). 기존 정책을 보완하며 대체하는 문서는 없습니다.

!!! info "필요한 방법만 골라 쓰세요"
    이미 쓰는 기록과 도구로 충분하면 그대로 사용합니다. 아래 내용은 개인과 팀이 같은 불편을 줄이기 위한 제안입니다. 새 앱이나 AI를 반드시 도입해야 하는 것은 아닙니다. 사용할 도구, 열 수 있는 자료, AI에 줄 수 있는 정보와 맡길 일은 회사에서 아직 정하지 않았습니다.

## 어디서 자주 막히는지 보기 {#roadmap}

**반복해서 불편한 일 하나를 골라, 지금 쓰는 방법에서 조금 바꿔 봅니다.** 자료를 찾고 하던 일을 이어갈 수 있는지가 기준입니다. 아래 순서를 모두 끝낼 필요는 없습니다.

| 자주 겪는 불편 | 먼저 해 볼 일 |
|---|---|
| 1. 파일을 어디 뒀는지 모르겠습니다. | 업무마다 폴더 하나를 정하고, 최신 내용을 고칠 위치를 하나로 맞춥니다. |
| 2. 지금 무엇을 해야 하는지 모르겠습니다. | 다음 할 일, 담당자, 필요한 마감을 기존 일정표에 적습니다. |
| 3. 같은 일을 할 때마다 순서를 다시 생각합니다. | 반복되는 순서와 완료 조건을 복사용 기본 폴더(`MASTER`)에 넣습니다. 단계 상태는 시작 전으로 둡니다. |
| 4. 전에 왜 그렇게 결정했는지 모르겠습니다. | 중요한 결정만 이유와 근거 위치를 남깁니다. |
| 5. 전에 겪은 문제를 처음부터 다시 해결합니다. | 지난 문제와 결과를 찾아보고 이번에도 같은 방법을 쓸 수 있는지 확인합니다. |
| 6. 정해진 일을 똑같이 반복해서 입력합니다. | 입력할 자료, 원하는 결과, 예외를 정한 뒤 프로그램에 맡길지 검토합니다. |
| 7. 여러 도구에서 같은 순서의 작업을 반복합니다. | 맡길 범위와 사람이 확인할 때를 정한 뒤 AI 자동 실행 도구를 검토합니다. |

예를 들어 FolderState는 폴더의 진행 상태를 표시해 2번을 돕습니다. 다음 할 일을 판단하거나, 지난 자료를 검색하거나, AI 작업을 실행하는 기능은 제공하지 않습니다.

## 여러 곳에서 받은 요청을 놓치지 않기 {#work-inbox}

메일·Teams·전화·회의에서 받은 요청을 자주 놓친다면, **기존 업무목록이나 회사 시스템 한 곳에서 요청의 위치와 다음 할 일을 확인**하는 방법을 검토합니다. 이를 `Work Inbox`라고 부르기도 합니다. 파일을 잠시 두는 `00_Inbox`와는 다릅니다.

이미 담당자와 다음 할 일이 정해진 요청은 해당 업무에서 바로 처리합니다. 여러 곳에 흩어져 자주 빠지는 요청만 목록에 연결합니다. 대화와 파일 전체를 새 앱으로 옮길 필요는 없습니다.

| 받은 내용 | 할 일 | 적을 곳 |
|---|---|---|
| 내가 처리해야 합니다. | 담당자, 다음 할 일, 필요한 마감을 정합니다. | 해당 업무의 일정표 또는 회사 업무 시스템 |
| 다른 사람의 답을 기다립니다. | 답을 줄 사람과 다시 확인할 날짜를 정합니다. | 같은 일정표 |
| 나중에 참고할 자료입니다. | 사용할 업무나 공통 참고자료 위치에 연결합니다. | 기존 참고자료 위치 |
| 남겨야 할 결정·승인·문제입니다. | 이유와 근거 위치를 남깁니다. | 기존 문제·결정 기록 |

요청을 적을 때는 짧은 내용, 원본 링크, 필요한 담당자와 다음 할 일부터 남깁니다. 일정표에 이미 있는 마감과 상태를 목록에 다시 쓰지 않습니다.

같은 요청이 메일과 Teams에 이어서 오면 기존 항목을 고칩니다. 한 요청에 할 일과 결정 기록이 모두 필요해도 별개의 할 일로 중복 등록하지 않습니다. 링크가 없으면 날짜와 제목처럼 다시 찾을 단서를 남깁니다. 전화나 구두 요청은 내용·시점·요청한 역할을 기존 업무 기록에 짧게 적습니다.

해당 업무로 연결한 뒤에는 그곳에서 진행합니다. 요청 목록에는 원본 링크만 남기거나 접수를 끝냅니다. 답을 다시 확인할 담당자는 일정표에 남깁니다. 매일 목록을 비우거나 모든 알림을 기록할 의무는 없습니다.

이 표의 분류는 FolderState에 추가되는 상태가 아닙니다. 답을 기다릴 때의 상태는 [일을 이어서 하고 다른 사람에게 넘기기](folder-workflow.md)를 따릅니다.

## 지난 문제의 해결 방법을 다시 쓰기 {#knowledge}

지난번에 어떻게 해결했는지 찾을 수 있으면 다음 일이 쉬워집니다. 기존 파일, 메일, 문제·결정 기록을 먼저 활용합니다.

다시 겪을 만한 문제에만 아래 내용을 보완합니다. 이미 있는 내용은 새 양식으로 옮기지 않아도 됩니다.

| 찾고 싶은 것 | 남길 내용 | 다시 쓸 때 확인할 점 |
|---|---|---|
| 문제 해결 방법 | 찾기 쉬운 문제 이름, 발생 상황, 조치, 실제 결과 | 이번 상황에도 같은 방법이 맞나요? |
| 결정한 이유 | 결정일, 선택한 방법, 다른 방법과 비교한 이유, 근거 위치 | 그때의 근거가 지금도 맞나요? |
| 재사용할 결과물 | 원본 위치, 사용한 업무, 주의할 조건 | 이번 결과물을 따로 둘 업무폴더가 있나요? |
| 반복 업무의 순서와 양식 | 승인된 기본 폴더의 버전과 바뀐 이유 | 확인된 개선이 다음 기본 폴더에 반영됐나요? |

모든 파일과 메일을 요약하거나 보관 폴더 전체를 다시 분류할 필요는 없습니다.

다시 쓸 때는 담당자가 원본이 최신인지, 볼 권한이 있는지, 이번에도 쓸 수 있는지 확인합니다. 예전에 잘됐던 방법이라도 현재 회사가 승인한 업무 기준을 먼저 따릅니다. 바뀐 결론이 있으면 예전 이유를 지우지 않고 새 결정의 링크를 남깁니다.

검색 도구를 쓰더라도 원래 자료를 볼 수 있는 권한 안에서 사용합니다. 실제 업무 기록은 내부에서 활용하며 공개 안내 페이지에 올리지 않습니다.

## 반복 작업을 프로그램에 맡기기 {#ai-agent}

먼저 같은 내용을 두 번 적고 있는지 봅니다. 그렇다면 수정할 원본을 하나로 줄입니다. 그래도 남는 반복 작업이 있고 처리 규칙과 누락·실수 사례를 알 수 있을 때 자동화를 검토합니다.

**어떤 자료를 넣으면 어떤 결과가 나와야 하는지, 예상과 다를 때 어떻게 할지 먼저 정합니다.** 설명하기 어려우면 업무 순서부터 정리합니다.

### AI로 찾기·요약·초안 돕기

회사가 허용한 자료에서 검색할 단서를 찾거나 요약·초안·빠진 내용 확인을 돕게 할 수 있습니다. 업무 담당자가 원본과 현재 상황을 확인하고 판단합니다.

AI 요약은 원본 메일·결정 기록·결과물을 대신하지 않습니다. 초안이 생겼다고 결정이나 업무 완료가 확정되는 것도 아닙니다.

### AI에 여러 작업을 이어서 맡기기

자료를 확인하고 여러 도구로 작업을 이어서 하는 AI를 `Agent`라고 부릅니다. 예를 들면 자료를 찾아 안내문 초안을 준비하는 방식입니다.

맡기기 전에 기존 업무 절차에서 아래 내용을 정하는 방법을 제안합니다. 원래 필요한 판단과 승인을 확인하되, 모든 행동에 새 승인 절차를 붙이지 않습니다.

| 정할 내용 | 쉽게 확인할 질문 |
|---|---|
| 맡길 일 | 어떤 자료와 도구를 쓸 수 있나요? 무엇을 읽고, 고치고, 전달해도 되나요? 어디까지 하면 끝인가요? |
| 사람이 판단할 일 | 업무 책임자는 누구인가요? 예외와 기존 승인은 누가 확인하나요? |
| 멈출 때 | 근거가 서로 다르거나, 자료가 부족하거나, 권한 밖의 요청이거나, 결과가 예상과 다르면 누구에게 알리나요? |
| 결과 확인과 되돌리기 | 결과와 근거를 어디에 남기나요? 실패하면 어떻게 되돌리거나 사람이 이어가나요? 다시 실행할 때 같은 일이 두 번 처리되지 않게 어떻게 확인하나요? |

시험용 자료나 영향이 작은 업무 한 건에서 먼저 확인합니다. 예상한 결과가 나오는지, 필요한 때 멈추는지, 실패했을 때 되돌릴 수 있는지 봅니다.

업무 원본을 바꾸는 도구는 실행 전에 바꿀 대상과 내용을 보여주도록 만듭니다. 취소·복구 방법과 실행 기록도 마련합니다. 한번 보내거나 바꾸면 되돌릴 수 없는 일은 실행 전에 확인할 시점을 정합니다.

### 회사에서 먼저 정할 것

쓸 AI 서비스, 제공 가능한 자료, 실행 계정과 권한, 사람이 검토·승인할 범위는 회사가 정해야 합니다. 외부로 자료를 보내야 한다면 내용·받을 대상·사용자가 선택하는 방법도 먼저 정합니다.

아직 정하지 않은 내용은 [회사에서 정할 항목](decisions.md)의 DEC-026–028에서 관리합니다. 이 문서가 도구 사용이나 업무자료 제공을 승인하는 것은 아닙니다.

## 예외

짧은 개인 업무나 기존 시스템으로 충분한 일은 요청 목록·검색 도구·자동화·AI를 추가하지 않습니다. 회사의 업무·기록·보안 기준을 먼저 따릅니다.

적용 범위나 예외가 필요하면 업무 책임자가 관련 담당자와 이유·범위·기간을 정하고 기존 내부 결정 기록에 남깁니다.

## 예시: 전화로 교육 일정 변경을 요청받았다면

1. 기존 일정표에 요청 내용과 다음에 확인할 일을 짧게 적습니다.
2. 같은 내용의 메일이 오면 새 할 일을 만들지 않고 기존 항목에 메일을 연결합니다.
3. 확정 답을 기다리는 동안 답을 줄 사람과 다시 확인할 날짜를 같은 일정표에 둡니다.
4. 변경이 정해지면 결정 기록에 이유와 승인 근거를 남깁니다.
5. 업무 종료 때 실제 영향과 결과물 위치를 남깁니다.
6. 다음 교육에서 ‘일정 변경’을 검색해 이번에도 같은 조건인지 확인합니다. 자주 빠뜨린 내용은 기본 폴더의 확인 목록에 반영합니다.

이 방법으로 업무가 안정된 뒤에 반복 입력을 자동화하거나 AI로 안내문 초안을 만들지 검토할 수 있습니다. 실제 일정 확정과 필요한 발송 승인은 기존 담당자와 절차를 따릅니다.

## 도움이 되었는지 확인하기

불편이 반복된 업무 한 건에서 필요한 방법만 시험합니다. 같은 요청을 한 곳에서 찾는지, 기다리는 일의 담당자와 확인 날짜를 아는지, 지난 문제의 이유·결과·원본을 찾아 쓸 수 있는지 봅니다.

자동화나 AI 실행을 검토한다면 예상한 결과, 예외에서 멈추기, 실패 후 중복 처리 없이 이어가기도 확인합니다. 추가 기록 시간과 줄어든 누락·재작업을 기존 업무 검토 기록에 남깁니다. 도움이 없는 입력 항목은 줄입니다.

실제 도입 여부와 업무 효과는 아직 확인하지 않았습니다.
