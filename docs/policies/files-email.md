# 파일 이름과 메일 정리

정책: 파일 이름과 메일 정리 · 상태: 제안 · 버전: 0.2 · 책임: 업무 담당 · 근거: 원문 02 §8–12, §18

승인자·승인일·적용일: 미확정.

## 이 안내가 필요한 때

**파일은 이름으로 알아보고, 메일은 할 일이 남았는지로 나눕니다.** 업무 담당자가 받은 자료를 저장하고 나중에 다시 찾을 때 쓰는 기준입니다.

## 파일 이름 정하기

| 파일의 용도 | 이름을 붙이는 방법 | 예시 |
|---|---|---|
| 날짜가 중요한 기록 | 연월일 8자리, 내용, 문서 종류를 씁니다. | `20260912_강사미팅_회의록.docx` |
| 계속 내용을 고치는 대장 | 같은 이름을 유지합니다. | `교육생관리대장.xlsx` |
| 작업 중인 여러 버전 | `v01`, `v02`처럼 순서를 붙입니다. | `안내문_v02.docx` |
| 전달하거나 확정한 문서 | 실제 상태에 맞게 배포본·승인본·확정본을 씁니다. | `안내문_배포본.docx` |

`최종2`, `진짜최종`처럼 어느 것이 최신인지 알기 어려운 이름은 피합니다.

받은 파일의 이름을 모두 바꿀 필요는 없습니다. 어떤 파일인지 알아볼 만큼만 바꿉니다. 다른 문서에서 연결한 파일이나 폴더의 이름·위치를 바꾸면, 영향을 받는 링크와 새 위치를 기록합니다.

## 메일은 세 곳으로 나누기

| 메일함 | 어떤 메일을 두나요? | 다음에 할 일 |
|---|---|---|
| 받은 편지함(`Inbox`) | 아직 처리 방법을 정하지 않은 메일 | 내가 할 일이 있는지 확인합니다. |
| 할 일(`Action`) | 내가 처리할 일이 남은 메일 | 처리한 뒤 보관함으로 옮깁니다. |
| 보관함(`Archive`) | 처리가 끝난 메일 | 필요할 때 검색해서 찾습니다. |
| 회신 대기(`Waiting`, 선택) | 다른 사람의 답이나 처리를 기다리는 메일 | 답이 오면 다음 할 일을 확인합니다. |

회신 대기를 따로 관리하기 번거로우면 `Waiting` 없이 `Action`에 둡니다. 업무별 메일함을 너무 잘게 나누거나 매일 모든 받은 편지함을 비울 필요는 없습니다.

메일은 사용자가 옮깁니다. 이 안내를 적용하거나 FolderState를 설치해도 메일이 자동으로 이동하거나 삭제되지 않습니다.

## 첨부파일로 작업하기

이메일에는 주고받은 내용과 승인 근거를 남깁니다. 실제 작업한 파일과 결과물은 업무폴더에 둡니다.

1. 작업에 쓸 첨부파일만 해당 업무폴더에 저장합니다.
2. 저장한 파일로 작업하고 확정된 결과물을 같은 업무폴더에 둡니다.
3. 메일에서 할 일이 끝나면 메일은 보관함에 둡니다.

예를 들어 안내문을 메일로 받았다면, 이번 교육의 `04_입과안내` 폴더에 저장해 수정합니다. 모든 첨부파일을 따로 저장할 필요는 없습니다.

## 중요한 메일 남기기

중요한 승인, 비용 근거, 정책 결정은 나중에 확인할 수 있도록 원본 메일을 보존합니다. 결정 기록(`Decision Log`)에는 날짜·제목·원본을 찾을 위치를 적습니다.

메일 전체를 공개 GitHub에 올리지 않습니다. 메일 시스템을 더 이상 사용하지 않을 예정이면 기록 담당자와 다음 세 가지를 확인합니다.

- 어떤 메일을 남길지
- 어디에 저장할지
- 나중에 어떻게 다시 열어 볼지

## 예외와 확인 방법

업무 한 건에서 최종 결과물과 승인 메일을 각각 다시 찾을 수 있는지 확인합니다. 회사의 법무·기록 담당자가 별도로 정한 보관 기준이 있으면 그 기준을 따르고 내부 기록에서 연결합니다.
