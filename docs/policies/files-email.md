# 파일과 이메일

정책 ID: POL-003 · 상태: 제안 · 버전: 0.1 · 책임: 업무 담당 · 근거: 원문 02 §8–12, §18

## 파일명

날짜가 중요한 기록은 YYYYMMDD_내용_종류를 사용합니다. 예: 20260912_강사미팅_회의록.docx. 상시 사용하는 대장은 교육생관리대장.xlsx처럼 고정 이름을 사용합니다. 작업 버전은 v01, v02, 외부 전달본은 배포본·승인본·확정본으로 구분합니다. 최종2·진짜최종 같은 이름은 피합니다.

모든 수신 파일을 표준화하지 않습니다. 원본을 식별할 정도로만 수정하며 링크가 걸린 경로를 변경할 때 영향과 대체 위치를 기록합니다.

## 메일함

| 폴더 | 의미 | 다음 행동 |
|---|---|---|
| Inbox | 아직 판단하지 않은 메일 | 행동 필요 여부 판단 |
| Action | 내가 할 일이 남아 있음 | 처리 후 Archive |
| Waiting (선택) | 상대 회신·처리 대기 | 회신 후 재판단 |
| Archive | 처리가 끝난 커뮤니케이션 | 검색으로 찾기 |

프로젝트별 메일함을 과도하게 세분화하지 않습니다. 매일 모든 Inbox를 비우는 목표도 두지 않습니다. 이 정책 도입이나 FolderState 설치가 자동 메일 이동·삭제를 수행하지는 않습니다.

## 메일과 파일의 연결

이메일은 커뮤니케이션 원본, 업무폴더는 결과물 원본입니다. 실제 작업할 첨부만 회차 폴더에 저장합니다. 중요한 승인·비용 근거·정책 결정은 필요한 원본 메일을 보존하고 Decision Log에 날짜·제목·근거 위치를 남깁니다.

메일 전문을 공개 GitHub에 올리지 않습니다. 시스템이 종료될 예정이면 기록 담당과 보존할 메일·저장 위치·다시 열람할 방법을 확인합니다.

## 검증과 예외

결과물과 승인 근거를 각각 다시 찾을 수 있는지 확인합니다. 법무·기록 관리의 별도 보관 요구는 해당 내부 기준을 연결합니다. v0.1 최초 제안입니다.
