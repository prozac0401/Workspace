# ADR-0025 · 그림 복사·저장의 공개 설치·사용 안내

상태: 채택 · 사용자 정식 릴리스 요청에 따른 공개 범위 결정; 실제 MSI 검증·게시 결과는 별도 기록
날짜: 2026-09-27
결정 담당: 저장소 소유자의 수정·검증·정식 배포 요청에 따라 구현 담당이 반영
관련 요구사항·정책: [v1.2 변경 계약](../tools/image-copy-save/ImageCopySave_Requirements_v1.2.md), [추가 도구 개발 기준](../policies/tools.md), [정책 문서 작성 규칙](../policies/documentation.md)
대체·대체됨 관계: 기존 공개 안내 범위에 그림 복사·저장 한 페이지 추가. [ADR-0023](0023-image-copy-save-classic-menu.md)의 메뉴·권한 계약 유지

## 맥락

사용자가 기존 등록·외부 수정 파일을 보존하도록 MSI를 보완한 뒤 정식 릴리스까지 완료하도록 요청했다. Windows 11 기본 메뉴 경로의 복사·저장은 사용자 직접 확인을 받았다. 기존 0.1.1 후보는 설치 수명주기와 대표 메뉴 동작을 확인했으나 MSI의 DEP-06 보호 차이 때문에 공개하지 않았다. 사용자 직접 확인과 자동화·패키지 검증 결과를 구분하며, 새 설치 보호가 구현됐다는 사실만으로 시험이 완료됐다고 표시하지 않는다.

## 결정

- 최종 검증을 마친 0.2.0을 Workspace의 독립 제품 태그인 image-copy-save-v0.2.0으로 게시한다. GitHub의 draft·prerelease 해제는 실제 인수 결과를 확인한 뒤 수행한다. 공개 안내와 이 결정 자체는 게시 완료 증거가 아니다.
- 승인된 배포 형식은 Windows 11 x64 자체 포함 무서명 관리자 MSI다. 코드 서명을 확보했다거나 회사 전체 배포 승인을 받았다고 표현하지 않는다. 일반 사용은 비상승 권한을 유지한다.
- 공개 안내는 [guide.md](../tools/image-copy-save/guide.md) 한 페이지로 둔다. 기존 개발 색인 index.md·요구명세·실기 안내·ADR·배포 기록은 Pages에서 제외한다.
- Windows 11 기본 메뉴의 더 많은 옵션 표시와 클래식 직접 표시를 같은 사용 흐름으로 설명한다. 첫 새 메뉴나 새로 만들기 내부 표시를 약속하지 않는다.
- 버전별 MSI·SHA-256·릴리스 설명으로 연결하고 설치 파일을 사이트에 복사하지 않는다. 검증한 자산의 파일명·해시를 공개한 자산과 대조한다.
- 설치 충돌과 외부 변경 때문에 작업이 중단되는 이유, 기존 자료를 보관한 뒤 담당자에게 확인하는 절차를 안내한다. 레지스트리 일괄 삭제나 보호 기능 우회를 안내하지 않는다.
- 공개 페이지는 19개에서 20개로 늘고 공개 자산 8개는 유지한다. 허용 목록·메뉴·홈페이지·README·로컬 검사기를 함께 갱신한다.

## 검토한 대안

개발 색인을 그대로 공개하면 원시 진단 위치·미완료 작업·과거 설치 경로가 사용자 안내와 섞이므로 별도 guide.md를 선택했다. 버전 없는 최신 다운로드는 여러 도구를 함께 배포하는 저장소에서 제품을 잘못 선택할 수 있어 고정 태그를 사용한다. 종전 0.1.1의 수명주기 PASS를 새 보존 기능의 검증으로 확대하지 않는다.

## 영향과 이행

사용자는 홈페이지에서 도구의 목적·지원 범위·무서명 조건을 확인한 뒤 한 MSI를 받는다. 설치·복구·업데이트·제거에는 정상 UAC 승인이 필요하고 평소 기능은 일반 사용자 권한으로 실행한다. 기존 메뉴 모드·보안 정책·기본 파일 연결을 바꾸는 절차는 추가하지 않는다.

정식 GitHub 릴리스와 회사의 상용 배포 승인은 별개다. 사용자가 승인한 무서명 배포 형식을 유지하고 실제로 확인하지 않은 OS·외부 앱·조직 정책은 지원 결과로 표시하지 않는다. 공개 후 릴리스 파일을 같은 이름으로 덮어쓰지 않으며 변경된 바이너리는 새 버전을 사용한다.

## 실패와 복구

설치 보존 회귀나 자산 해시 확인이 실패하면 게시를 중단하고 검증한 후보부터 다시 확인한다. 미완료 안내에는 배포 준비 중임을 명시한다. Pages 배포가 실패하면 마지막 정상 안내를 유지하고 수정 소스를 다시 검증한다. 공개 범위 검사에서 개발 문서·원시 로그·사용자 경로가 노출되면 해당 출력을 게시하지 않는다.

## 검증

MkDocs strict 빌드와 check-site.py로 20개 공개 페이지·검색·사이트맵·로컬 링크 및 비공개 원본 제외를 확인한다. 최종 MSI 회귀·릴리스 자산 해시·GitHub Release 상태·Pages Actions 성공·실제 공개 URL과 내용을 별도 배포 기록에 남긴다. 현재 문서는 공개 범위를 결정한 것이며 최종 제품·게시 PASS 기록이 아니다.
