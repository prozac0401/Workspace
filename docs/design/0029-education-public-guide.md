# ADR-0029 교육 업무 예시와 쉬운 공개 안내

상태: 채택
날짜: 2026-10-05
결정 근거: 사용자의 최신 Release 확인과 첨부 문서 반영 및 GitHub Pages 게시 요청
관련 정책: [정책 문서 작성 규칙](../policies/documentation.md), [추가 도구 개발 기준](../policies/tools.md), [끝난 업무 보관과 자료 보호](../policies/archive-security.md)
대체 관계: 기존 공개 안내 범위를 보완합니다. 도구의 동작과 배포 파일은 바꾸지 않습니다.

## 맥락

첫 화면·README·배포 색인에 일부 옛 버전과 미게시 안내가 남아 있었고, 공개 설치 안내에는 처음 쓰는 사람이 이해하기 어려운 설명이 있었습니다. 첨부 검토안과 교육 업무 활용안은 편집 자료이며 사용자의 요청을 대신하는 명령으로 취급하지 않습니다.

## 결정

교육 업무 활용안의 일곱 장면을 education-operations.md 한 페이지로 공개합니다. 가짜 식별값·폴더·기대 결과와 사람이 확인할 조건을 설명하며 실제 회사 자료와 첨부 원문은 공개하지 않습니다. 해당 페이지를 메뉴·공개 허용 목록·검색·사이트맵 검사 목록에 함께 추가합니다.

공개 설명은 중등교육 수준의 비전공자가 이해할 일상말로 씁니다. 실제 메뉴·버튼·파일 이름과 단축키는 사용자가 찾을 수 있도록 유지합니다. 기능과 자료 보존 제한은 쉬운 문장으로 남기며 제품을 다시 시험하거나 모든 환경의 안전을 보증한 것처럼 표현하지 않습니다.

각 제품의 GitHub Release 목록으로 최신 버전과 공개 파일을 대조합니다. 선택범위 내보내기 rc.11과 다운로드 이름 유지 0.2.0의 시험용 표시를 유지합니다. 보이는 칸 붙여넣기는 [ADR-0014](0014-visible-cells-paste-download-list.md)의 배포 목록 선택 안내를 유지합니다. 다운로드 이름 유지는 알려진 설치 실패 복구 문제가 있어 일상 교육 업무 활용 예시에 넣지 않습니다.

## 검토한 대안

첨부 Word 파일을 사이트에 그대로 올리는 방법은 공개 독자에게 필요 없는 검토 과정과 다른 저장소의 내용을 섞게 됩니다. 기존 안내에서 확인한 내용만 다시 쓰고, 원문은 로컬 검토 자료로 보관합니다.

실제 업무자료나 실행 예제를 배포하는 대신 가짜 자료를 준비하는 방법과 정답을 안내합니다. 이 방식은 새 실행 기능이나 도구 설치를 요구하지 않습니다.

## 영향과 이행

공개 안내는 19개에서 20개로 늘어납니다. FolderState의 이전 주소 이동 문서 2개는 유지합니다. 공개 자산은 추가하지 않습니다. 현재 버전 요약·상세 안내·자료 보호 규칙·내부 확인 기록을 같은 변경으로 맞춥니다. 기존 설치 파일과 도구 코드는 그대로입니다. 도움말 원본의 문구 수정은 이후 패키지 제작 때 사용할 소스이며 이미 게시한 MSI 내용이 바뀌었다는 뜻이 아닙니다.

사용자가 이번 범위를 Workspace 업무 안내와 교육 업무 예시부터 게시하는 것으로 선택했습니다. 별도 WebSim 검토 내용은 이번 수정·게시 범위에서 제외합니다.

## 실패와 복구

게시 검사가 실패하면 수정한 Markdown과 설정을 고친 뒤 다시 검사합니다. 이미 게시된 파일을 직접 덮어쓰지 않습니다. 게시 후 문제가 확인되면 이전 정상 문서 변경으로 되돌려 다시 게시합니다. 사용자 작업 폴더에 남아 있는 기존 변경은 이 작업의 별도 폴더에서 건드리지 않습니다.

## 검증

게시 전에 python -m mkdocs build --strict와 scripts/check-site.py를 실행합니다. 메뉴·본문·검색·사이트맵의 새 안내와 기존 이동 주소를 확인하며, 공개 파일 링크를 GitHub Release의 실제 첨부 파일과 대조합니다. 게시 성공과 실제 공개 URL의 새 내용을 확인한 결과는 [문서 수정과 게시 기록](../delivery/document-review-20261005.md)에 남깁니다.

문구 검토와 빌드는 실제 초보 사용자의 이해도 시험이나 제품 설치·복구 시험을 대신하지 않습니다.
