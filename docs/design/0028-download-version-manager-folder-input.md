# ADR-0028 · DVM의 지정 폴더 감시와 0.2.0 설치 경로

상태: **채택, 0.2.0 기능 평가 prerelease 게시 완료**

날짜: 2026-10-04 KST · 결정 담당: 사용자 확인에 따른 개발 담당

관련: [0.2.0 명세](../tools/download-version-manager/next-version-specification.md), [추가 도구 개발 기준](../policies/tools.md), [이번 배포 기록](../delivery/download-version-manager-watcher-release-20261004.md)

대체 관계: 0.2.0은 [ADR-0026](0026-download-version-manager.md)의 브라우저 확장 입력·무상주·Store 필수 경로와 [ADR-0027](0027-download-completion-order.md)의 브라우저 완료 시각 입력을 대체한다. 두 ADR과 0.1.0 소스·버전·산출물·FAIL/NOT RUN은 역사적 근거로 보존한다.

## 맥락

사용자는 브라우저별 확장 설치 부담을 없애고 다른 웹 프로그램의 파일도 처리하기 위해 지정 폴더 감시와 일반 사용자 프로세스 유지를 채택했다. 이어 입력 규칙·최초 파일 정리·기본 다운로드 위치·로그인 자동 실행을 확인했고 실제 설치·구동 가능한 MSI 릴리즈를 지시했다. 각 구현 단계의 과도한 시험과 미확인 요구에 따른 선제적 복잡도 증가 금지를 최우선 원칙으로 둔다.

## 결정

한 사용자 세션의 작은 네이티브 프로그램이 선택 폴더 한 곳의 OS 변경 알림을 비재귀로 받는다. 확장·Store·Native Messaging 설치를 요구하지 않는다. 기존 C++ 파일 변경 엔진을 재사용하되 폴더 입력은 브라우저 완료 시각과 HKCU CompletionOrder를 사용하지 않는다.

최초 기존 이름 그룹은 미리보기에서 사용자가 최신 파일과 처리 여부를 선택한다. 원래 파일 선택은 그룹 보존이다. 번호 파일을 선택하면 다른 번호 파일을 표시된 파일명 순서로 처리한 뒤 선택 파일을 마지막에 원래 이름으로 이동한다. 각 단계의 같은/다른 내용 규칙을 적용하며 미리보기 이후 객체·크기·시간이 달라지면 남은 파일을 보존한다.

이후에는 정확한 원래 대상이 있는 새 `파일 (n)` 이름을 사용자 채택 관례로 연결한다. 3초 안정과 보호된 핸들 확보를 처리 가능 조건으로 사용한다. 앱 내부 완료의 증명으로 취급하지 않는다. 같은 대상의 신규 후보가 함께 대기하면 최신을 추측하지 않고 모두 보존한다.

위자드는 Windows Known Folder로 현재 다운로드 위치를 표시하고 기본 위치 추종 또는 사용자 폴더 선택을 제공한다. 기본 위치 추종은 앱 시작과 OS 사용자 폴더 registry 알림에서 경로를 다시 해석한다. 로그인 자동 실행은 기본 선택이며 설치 위자드에서 해제할 수 있다.

## 검토한 대안

브라우저별 확장은 다른 웹 프로그램까지 포함하는 범위와 한 번 설치 목표에 맞지 않는다. 수동 파일 선택만으로는 자동 감지 목표를 충족하지 않는다. 앱 DB·드라이버·서비스·프로그램별 감지 모듈은 확인된 요구가 없어 추가하지 않는다. 번호·수정 시각·파일 알림을 브라우저의 원래 이름·완료 시각으로 간주하는 방식은 사용하지 않는다.

## 영향과 이행

0.2.0의 MSI는 독립 제품/upgrade 식별자와 `DownloadVersionManagerWatcher` 설치 폴더를 사용한다. 기존 0.1.0과 브라우저 등록을 자동 제거하거나 변환하지 않는다. 기존 `version.json`, 확장과 legacy 빌드는 당시 구현을 보존한다. 새로운 `build-watcher.py`가 외부 runtime 없는 C++ 실행 파일과 단일 MSI를 제작한다.

구버전 확장이 여전히 활성화돼 있으면 같은 폴더에서 두 처리 방식을 함께 실행하지 않는다. 사용자가 구버전 확장을 중지·제거할 수 있도록 안내한다. 구버전 자료의 자동 삭제나 개인 Store 계정 업로드는 새 버전의 선행 작업이 아니다.

일반 사용자 LocalAppData·HKCU 설치와 선택한 HKCU 로그인 시작 항목을 사용한다. 서명 없는 기능 릴리즈이며 회사의 배포·상용 승인으로 분류하지 않는다.

## 실패와 복구

같은 이름의 두 객체만 읽고 이동한다. 신규 관찰값과 최초 정리의 target 관찰값을 보호된 핸들에서 대조한다. 기존 잠금·크기 우선 비교·streaming SHA-256·History 충돌 방지·rollback을 재사용한다. 이동 실패 시 기존·신규 객체를 모두 잃지 않도록 보존한다.

직접 덮어쓰기의 이전 바이트나 모든 앱의 완료 상태는 보장하지 않는다. 알림 누락·모호한 동시 후보·잠금·외부 변경은 보존한다. 전원 장애 자동 복구나 잔재 스캔은 없다.

기존 Win11의 MSI 제품 등록 rollback 실패와 재설치 1638은 미해결 역사 기록이다. 새 구조의 관련 설치 실패 복구를 별도 확인하며 설계 변경만으로 과거 결과를 PASS로 바꾸지 않는다.

## 검증

폴더 엔진의 동일/다른 내용·신규 객체와 시간·대상 부재/잠금·source/target 변경·rollback·강제 중단 8건, watcher 대표 세션 15건, 기존 그룹 처리 4건, 수정 후보의 설치/실행·repair·제거·파일 보존 5건, 화면 높이 수정 후보의 설치/실행·제거·보존 4건이 PASS다. 실제 위자드의 현재 기본 위치·체크·취소를 확인했다. 최종 안내 문구 수정에는 관련 설치 근거를 재사용한다. 표준 MSI 폴더 선택의 경로 표시·설정 전달·취소는 최종 파일에서 별도로 확인했다. 새 MSI late-failure의 제품 등록 rollback 실패는 제한으로 남으며 공개 tag·Release·두 자산 다운로드·checksum은 PASS이며 다음 로그인·실행 중 OS 위치 변경은 미실행이다. 실제 후보 지문과 한계는 이번 배포 기록을 따른다.

확인된 요구와 새 데이터·설치 위험에 필요한 검증만 수행한다. 브라우저별 전체 시험표·대용량 성능·과거 전체 수명주기를 관성적으로 반복하지 않는다. 동일 결정을 위한 중복 승인·보고 체계를 추가하지 않는다.
