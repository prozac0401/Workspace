# ADR-0018 · 원본 Undo를 보존하기 위한 출력 생성 분리

상태: 채택 · rc.10 구현 방향이며 실제 검증·배포 승인은 별도

날짜: 2026-09-26

결정 담당: 도구 개발·검증 담당

관련 요구사항·정책: [원작업지시](../tools/excel-selection-export/specification.md), [요구사항·인수 대응표](../tools/excel-selection-export/acceptance.md), [추가 도구 개발 기준](../policies/tools.md), [정책 문서 작성 규칙](../policies/documentation.md)

대체·대체됨 관계: [ADR-0009](0009-excel-selection-export-com.md)의 출력 생성 방식과 임시 데이터 경계를 보완한다. 독립 COM 추가 기능·현재 인스턴스 선택·사용자 설치와 저장 흐름 결정은 유지한다.

## 맥락

rc.9의 실제 메뉴 시험에서 원본을 편집한 뒤 활성화된 Undo가 내보내기 후 비활성화됐다. 원본 값·수식·저장 상태가 같다는 검사만으로 실행 취소 이력의 보존을 입증할 수 없었다. 사용자는 이 부작용의 원인 조사와 수정을 요청했다.

2026-09-26 현재 PC의 Excel x64 16.0 Build 20326에서 합성 원본의 UI 편집 후 각 동작을 분리해 조사했다. Interactive·ScreenUpdating·EnableEvents 변경과 빈 통합문서의 Workbooks.Add(-4167)는 Undo 활성 상태를 유지했다. 새 결과의 시트 이름 대입은 Undo를 비활성화했고, 그 동작을 제거한 뒤에는 Normal.Font.Name 대입에서, 두 동작을 제거한 뒤에는 셀 기록 단계에서 같은 현상이 발생했다. 원본을 쓰지 않더라도 같은 Excel 인스턴스의 결과 편집이 원본 Undo에 영향을 주는 것이 확인된 원인이다. 삭제된 내부 기록의 전체 구조나 개수까지 관찰한 것은 아니다.

완성한 .xlsx 파일을 바탕으로 원본 인스턴스에서 Workbooks.Add(template)를 호출한 분리 시험에서는 원본 Undo가 활성 상태를 유지했다. 이 관찰을 출력 경로 변경의 근거로 삼으며, 실제 메뉴의 여러 단계 Undo·Redo 보존은 별도 제품 회귀 시험으로 판정한다.

## 결정

1. 메뉴 클릭 때 원본 Application·Workbook·Worksheet·Selection을 고정하고, 원본의 값·허용 서식·병합·날짜 기준을 기존 DTO로 읽는다.
2. 새 숨김 Excel 인스턴스를 이 작업 전용으로 만들고, 기존 writer를 사용해 결과의 값·서식을 기록한다. COM은 허용된 STA 문맥에서 사용하며 원본 COM 객체를 작업용 Excel의 문서로 사용하지 않는다.
3. 작업용 결과를 검증한 뒤 사용자 임시 폴더의 제품 전용 GUID 경로에 .xlsx로 저장한다. 원본 파일이나 사용자 지정 결과 경로에는 저장하지 않는다.
4. 작업용 문서를 닫고 전용 Excel을 정상 Quit한다.
5. 원본 인스턴스의 Workbooks.Add(template)로 새 저장 전 결과를 만든다. 이 단계 뒤 원본 인스턴스에서 결과의 셀·서식·시트 이름을 다시 쓰지 않는다. 템플릿으로 만든 문서는 Path가 비어도 Saved=true일 수 있으므로 새 결과의 Saved=false만 설정해 닫을 때 일반 저장 확인을 유지한다. 이 플래그 대입은 원본 Undo 활성 상태를 유지한 분리 시험을 근거로 허용한다. 값·수식 없음·결과 구조를 읽어 재검증하고 임시 파일을 삭제한다.
6. Excel의 상태를 복원한 뒤 지연 완료 콜백에서 결과를 Activate하고 해당 결과 Hwnd에 전면 표시를 요청한다. 원본 Application의 ActiveWindow.Hwnd가 결과 창과 일치하는지 확인한다. 이 API 검사는 Excel 내부의 활성 창을 증명하며 OS 전면 표시는 실제 UI 관찰로 별도 검증한다. 데이터 검증만으로 결과 표시 성공을 대신하지 않는다. 사용자에게 보이는 결과는 원본과 같은 인스턴스에 있고 시트 한 개이며 Path가 빈 새 통합문서다. 보관할 때는 사용자가 Excel의 일반 저장을 사용한다.

## 검토한 대안

| 대안 | 판단 |
|---|---|
| 시트 이름 변경만 제거 | 기본 글꼴 대입에서도 Undo가 비활성화돼 원인을 제거하지 못한다. |
| 시트 이름과 기본 글꼴 대입 제거 | 셀 값 기록에서 같은 현상이 발생해 해결되지 않는다. |
| 원본 Undo를 별도 구현해 복원 | 다른 편집·추가 기능의 기록을 정확히 재구성할 수 있다는 증거가 없고, 기존 Excel의 실행 취소 동작을 대신하는 범위가 된다. |
| OOXML을 직접 작성 | 숨김 Excel 인스턴스 없이 만들 수 있지만 기존 writer의 값·오류·문자열·표시 형식 동등성을 새로 구현하고 검증해야 한다. 이번 수정에서는 기존 writer를 재사용한다. |
| 별도 Excel에서 완성 후 템플릿으로 새 결과 생성 | 원본 인스턴스의 셀·서식 쓰기를 피하면서 기존 값·서식 구현과 같은 Excel에서의 저장 흐름을 유지하므로 채택한다. |

## 영향과 이행

사용자 메뉴·선택·저장 위치 결정은 그대로다. 원작업지시의 원문은 수정하지 않는다. 최종 결과가 같은 Excel 인스턴스의 저장 전 문서라는 계약은 유지하되, 작업 중 선택 내용이 사용자 임시 폴더에 기록되는 데이터 경계가 새로 생긴다. 이 중간 파일에는 선택한 값과 허용 서식만 포함하며 원본 워크시트를 통째로 복제하지 않는다. 사용자 안내에 임시 저장과 정리 및 강제 종료 시 잔존 가능성을 명시한다.

전용 Excel 시작 비용과 로컬 임시 파일 읽기·쓰기가 추가된다. 작업용 인스턴스를 만들거나 임시 파일을 쓸 수 없는 환경은 명확한 실패로 처리해야 한다. 원본 인스턴스의 셀·서식 직접 쓰기로 되돌아가는 우회는 두지 않는다. 현재 버전은 서명 없는 0.1.0-rc.10 평가판이며 기존 공개 rc.9 설치 파일이 이 수정을 포함한다고 안내하지 않는다.

## 실패와 복구

작업의 성공·실패·취소 뒤 자신이 만든 작업용 문서·인스턴스·임시 파일만 정리한다. 불완전한 최종 결과가 생겼으면 그 결과만 닫는다. 원본과 다른 문서에는 자동 저장·Quit·강제 닫기를 적용하지 않는다. 변경한 원본 Excel의 전역 상태는 복원한다.

Excel 또는 Windows의 강제 종료에서는 finally 실행을 보장할 수 없어 중간 파일이 남을 수 있다. 이번 작업이 소유한 GUID 경로 밖을 정리하거나 다른 작업의 Excel 프로세스를 추측해 종료하지 않는다. 비정상 중단과 정리 실패의 실제 확인 여부는 검증 기록에 별도로 남긴다.

## 검증

[Undo 조사·수정 검증 기록](../delivery/excel-selection-export-undo-20260926.md)에 단계별 원인 조사와 rc.10 제품 결과를 구분한다. 원인 분리 시험과 최종 rc.10 빌드·x64 설치를 완료했다. 단위249개, 최종 설치본 API11사례·930개, 실제 메뉴에서 3단계 Undo·Redo를 확인한 8체크포인트·110개, 작업용 Excel 출력단계의 직접 취소17개 검사를 통과했다. 작업용 Excel 정상 종료와 임시 파일 정리도 확인했다. 모든 실패/취소 지점과 전체 인수 환경을 확인한 것은 아니다.

필수 회귀 항목은 실제 UI로 만든 여러 편집의 역순 Undo와 정순 Redo, 내보낸 결과의 독립성, 원본 값·수식·서식·저장 여부, 날짜 기준과 문자열·오류 타입, 같은 인스턴스의 저장 전 결과, 클립보드 보존, 전용 Excel·임시 파일 정리다. 원본 시험용 Excel은 최종 API Close+Quit 뒤에도 빈 프로세스가 남아 기존 종료 제한을 재현했다. 작업용 Excel 정상 종료와 구분하며 rc.9의 API 종료 실패와 전체 인수 미완료가 해소됐다고 표시하지 않는다. x86 실제 Excel·격리 환경·재부팅·전체 공존·완전 제거·조직 승인은 실제 수행 결과가 없으면 미실행으로 유지한다.
