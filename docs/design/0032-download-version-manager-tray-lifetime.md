# ADR-0032 · 감시 창 닫기와 트레이 수명 분리

번호 이관: 기존 로컬 ADR-0030의 결정·검증 기록을 보존하고, 최신 저장소의 교육 예시 화면 ADR과 번호가 겹쳐 0032로 옮겼다. 아래 상태는 2026-10-05 당시의 기록이다.

상태: 채택 — 2026-10-05 로컬 수정, 공개 MSI·현재 설치본 미반영

날짜: 2026-10-05 KST

결정 담당: 사용자 요청에 따른 개발 담당

관련 요구사항·정책: [REQ-DVM-NEXT-015·016·017](../tools/download-version-manager/next-version-specification.md), [추가 도구 개발 기준](../policies/tools.md), [문서 작성 규칙](../policies/documentation.md)

대체·대체됨 관계: [ADR-0028](0028-download-version-manager-folder-input.md)의 폴더 감시·설치 계약을 유지하고 감시 창 수명에 트레이 경로만 추가한다. [ADR-0031](0031-download-history-mtime-guidance.md)의 날짜·보존 안내와 기존 기록은 보존한다.

## 맥락

사용자는 현재 동작과 새 카드 UI를 확인한 뒤, 감시 창의 X·Alt+F4로 프로그램이 종료되지 않고 트레이에 남기를 요청했다. 숨겨도 감시 중·중지 상태와 화면을 유지하며 같은 창을 다시 열어야 한다. 현재 app은 기존 HWND, 세션 singleton과 안전한 감시 종료 흐름을 갖고 있어 이 경로를 재사용한다. 새 설정·팝업·서비스나 별도 감시 프로세스는 요구되지 않았다.

## 결정

트레이 아이콘 하나와 열기·종료 메뉴를 기존 감시 창에 연결한다. 일반 WM_CLOSE는 트레이 등록 성공을 확인한 뒤 기존 창을 숨긴다. 열기와 아이콘 더블클릭은 같은 HWND를 복원하고 활성화한다. 감시 스레드·이벤트·타이머를 다시 만들거나 상태를 초기화하지 않는다. 명시적 종료는 감시 중지·스레드 대기와 창 파괴의 기존 안전한 흐름으로 처리하고 트레이 아이콘을 정리한다.

최소화 버튼·로그인 자동 실행·시작 시 창 표시·감시 시작 정책과 초기 파일 그룹 확인 창의 닫기 취소는 유지한다. 기존 singleton의 두 번째 실행은 숨은 기존 창의 복원을 재사용한다. Windows 세션 종료 메시지는 일반 창 닫기와 구분하고 OS 종료를 숨김으로 바꾸거나 막지 않는다.

## 검토한 대안

작업표시줄로 최소화하는 방식은 창을 숨기고 트레이에서 다시 여는 요구를 충족하지 않는다. 별도 감시 프로세스·새 창·IPC 계층은 기존 HWND와 singleton으로 가능한 동작을 위해 복잡도를 늘린다. 명시적 종료까지 WM_CLOSE 숨김을 통과시키면 정상 종료 경로를 잃으므로 창 파괴와 숨김을 구분한다.

## 영향과 이행

이번 로컬 수정본의 X는 완전 종료가 아니다. 새 EXE 확인 전에는 기존 앱을 정상 종료하고 프로세스 종료를 확인해야 한다. 트레이 메뉴가 없는 이전 버전에는 확인된 기존 정상 종료 경로를 사용한다. 안전하게 종료할 수 없으면 정확한 새 EXE의 전체 시작 확인만 보류한다.

기존 로컬 0.2.1 버전·사용자별 HKCU·자체 포함 MSI 제작 정책을 따른다. 공개 0.2.0 MSI와 현재 설치본은 변경하지 않는다. 파일 처리 엔진·읽기 전용 보호·잠금·재시도·History 날짜·충돌 회피·JSON·상태 코드·로그 계약은 유지한다. 카드 UI를 다시 설계하지 않는다.

## 실패와 복구

최초 트레이 등록이 실패하면 창을 숨기지 않고 기존 로그에 오류를 남긴다. Explorer의 TaskbarCreated 알림을 받으면 같은 창·감시 상태를 유지하며 아이콘을 다시 등록한다. 재등록 실패로 접근할 수 없는 숨은 프로세스가 남지 않도록 창을 복원하고 실패를 기록한다. 새 팝업은 추가하지 않는다.

종료는 기존 파일 보호와 처리 대기를 유지한다. 설치 실패 복구는 승인된 snapshot 복원 가능 전용 Windows 환경이 없어 BLOCKED이며 실제 복구 PASS 0이다. 실사용 계정의 실패 주입·강제 종료·ACL/권한 변경·설치본 교체로 우회하지 않는다.

## 검증

X·Alt+F4 숨김과 작업표시줄 상태, 감시 중 임시 파일 처리·중지 상태 유지, 같은 창 반복 복원·최소화, 트레이 명시적 종료, 등록·재등록 모의 실패, TaskbarCreated 모의 이벤트와 기존 singleton 복원, 세션 종료 메시지를 집중 확인한다. 안전한 임시 폴더와 합성 파일만 사용한다. 모의 검증·코드 검토와 실제 Explorer 재시작·OS 세션 시험의 미실행을 구분한다.

최종 EXE·무서명 MSI를 기존 제작 경로로 생성하고 새 크기·SHA-256과 MSI에서 직접 추출한 payload EXE 일치를 기록한다. 이전 지문은 새 파일에 재사용하지 않는다. 실제 실행 파일 경로와 빌드·payload·런타임·설치본 반영도 구분한다. 최종 변경 뒤 영향을 받는 시험만 재확인한다.

새 카드 UI와 현재 동작은 2026-10-05 USER_CONFIRMED로 기록하되 이번 트레이 수정의 PASS로 확대하지 않는다. 앞선 집중 17 PASS와 core 57 PASS·진단 판정 8 PASS 재사용은 당시 근거로 보존한다. 새 결과·미실행·산출물 지문은 [트레이 작업 기록](../delivery/download-version-manager-tray-20261005.md)을 따른다.
