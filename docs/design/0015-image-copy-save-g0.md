# ADR-0015 · 그림 복사·저장의 G0 관문과 독립 엔진

상태: 부분 대체 · 메뉴 위치는 ADR-0016로 대체. G0 실증 의무와 독립 개발 경계는 유지  
날짜: 2026-09-24  
결정 담당: 도구 개발·검증 담당  
관련 요구사항·정책: [원본 명세](../tools/image-copy-save/ImageCopySave_Requirements_v1.0.md), [G0 검증 기록](../tools/image-copy-save/G0_Menu_Feasibility.md), [추가 도구 개발 기준](../policies/tools.md), [정책 문서 작성 규칙](../policies/documentation.md)  
대체·대체됨 관계: [ADR-0016](0016-image-copy-save-direct-menu.md)가 메뉴 위치와 해당 G0·AT-08 시험 위치를 대체한다.

> 2026-09-25 현재 상태: 사용자가 기본 ‘새로 만들기’ 내부 배치 조건을 해제했다. 현행 위치는 [v1.1 개정명세](../tools/image-copy-save/ImageCopySave_Requirements_v1.1.md)의 실제 로컬 폴더 빈 공간 첫 우클릭 메뉴 독립 명령이다. 아래 본문은 2026-09-24 당시 결정·조사 기록으로 보존하며 ‘미승인’·기본 New 시험 위치는 당시 상태다. 위치 승인만으로 G0를 통과한 것은 아니며, 변경된 최종 경로의 실기 검증은 NOT RUN이다.

## 맥락

사용자는 실제 파일시스템 폴더의 기본 ‘새로 만들기’ 안에 저장 명령이 있어야 하며, 지원 이미지가 없는 다음 메뉴에서는 명령 자체가 사라져야 한다고 확정했다. 일반 IExplorerCommand의 숨김 기능과 이 위치의 동적 숨김을 동일시하지 말라는 원명세 3.2~3.3을 따른다. Windows 11 첫 메뉴 접근과 일반 사용자 설치까지 함께 검증해야 한다.

M0 조사는 수행했으나 G0는 BLOCKED다. 공식 계약 검토와 읽기 전용 OS·등록 관찰을 수행했다. 기본 New 내부의 개별 명령 상태 콜백을 갖춘 최소 확장을 확보·설치하지 못했고 탐색기 UI 화면 시험은 NOT RUN이다. 문서 누락을 불가능성 증명으로 삼지 않으며, 확인한 Windows 11 Pro 23H2 x64 빌드 22631.6199를 제품 지원 인증 목록으로 표시하지 않는다.

## 결정

요청한 메뉴 위치·조건부 숨김·첫 우클릭 접근성·무상주·사용자별 설치 계약을 그대로 유지한다. 위치를 바꿔 제품을 완성했다고 보고하지 않는다. G0 통과 전에도 원명세가 허용한 M1 독립 이미지 엔진과 자동 시험을 진행한다. 이것은 새 제품 범위 승인이 아니라 명세에 이미 정해진 작업 경계다.

- Shell 후보는 짧은 문맥·형식 판정과 실행 위임만 담당한다. 이미지 바이트 읽기·디코딩·인코딩·파일 쓰기는 별도 helper 책임이다.
- 엔진과 메뉴의 완료 상태를 나눈다. 지원 형식의 빠른 판정 함수가 통과해도 실제 메뉴 위치·재평가가 통과한 것은 아니다.
- helper가 끝난 뒤에도 이미지는 유지되어야 한다. 지속성을 감시 프로세스로 대체하지 않는다.
- M2의 최종 Shell 연결 및 M3의 배포 완료 판정은 G0 실증 후 진행한다. 자동 시험을 전체 44개 수용시험의 실기 통과로 환산하지 않는다.
- 다른 도구의 등록·패키지 식별자·사용자 파일·기본 이미지 연결을 재사용하거나 변경하지 않는다. 원격 커밋·배포는 하지 않는다.

## 검토한 대안

| 대안 | 검토 결과 | 결정 |
|---|---|---|
| ShellNew 등록 값으로 구현 | 문서화된 생성 방법은 확인했으나 클립보드별 개별 항목 숨김 연결은 입증하지 못함 | G0 BLOCKED 유지 |
| IExplorerCommand + 패키지 identity | 일반 Windows 11 명령과 숨김의 공식 경로. 기본 New 내부 위치의 증거는 아님 | 기본 New 대체물로 채택하지 않음 |
| INewMenuClient | 문서상 IncludeItems는 폴더/비폴더 범주 플래그. 앱 명령 하나를 식별하는 계약이 아님 | G0 해결책으로 확정하지 않음 |
| 폴더 배경 별도 저장 명령 | 일반 메뉴 확장 검토가 가능하나 MNU-01과 AT-08 변경 필요 | UNAPPROVED 제안으로만 보존 |
| 고정·회색 메뉴, 가짜 New, 반복 레지스트리 수정, 감시기, 내부 후킹 | 원명세와 사용자 지시 위반 | 제외 |

공식 근거와 검토한 문서의 범위는 [G0 검증 기록](../tools/image-copy-save/G0_Menu_Feasibility.md)에 보존한다. 문서상 일반 메뉴가 가능하다는 사실과 본 제품의 작동 실증을 분리한다.

## 영향과 이행

현재 산출물은 독립 엔진의 개발·시험 결과이며 설치만으로 요청한 메뉴를 사용할 수 있는 완성 제품이 아니다. 엔진 실행용 개발 명령을 일반 사용자의 수동 등록·스크립트 사용 절차로 포장하지 않는다.

G0를 통과하는 방식이 나오면 동일 빌드의 설치·동적 메뉴·제거 증거를 먼저 보완한다. 패키지 identity가 필요한 구조라면 설치기에서 사용자별 등록과 제거를 처리하며 서명·정책 요구를 실제 확인한다. 서명 인증서나 조직 허용 정책은 미결정이며 임의의 인증서 신뢰·개발자 모드·그룹 정책 변경으로 해결하지 않는다.

위치를 바꾸려면 별도 요구 변경과 사용자 합의가 필요하다. 이 ADR의 채택 상태는 G0 유지에만 적용되고 변경안 승인이나 조직 운영 정책 승인을 의미하지 않는다.

## 실패와 복구

G0 미통과 상태에서 제품 설치·배포 성공을 표시하지 않는다. 현재 조사에서는 등록·클립보드를 변경하지 않았으므로 OS 등록 롤백 대상도 만들지 않았다. 이후 최소 확장은 앱 소유 등록만 제거하고 기존 메뉴·사용자 PNG·타사 파일을 보존할 수 있어야 한다. Explorer 강제 종료로 갱신 문제를 감추지 않는다.

엔진은 입력 검증·출력 준비를 마친 후 변경을 커밋한다. 저장은 대상 폴더의 앱 소유 임시 파일을 완성한 뒤 덮어쓰기 없이 최종 이름으로 전환하며, 실패·취소·충돌·동시 실행을 시험한다. 클립보드 갱신 준비 실패와 실제 교체 도중 실패의 보존 범위는 원명세 CPY-05 및 실패 한계에 따라 구분한다.

## 검증

G0 실기 시험은 기본 New 내부 표시, 상태 20회 전환, 잔재 없는 숨김, 첫 메뉴 접근, 일반 사용자 설치, 재설치·제거 보존을 포함한다. 현재 전부 NOT RUN이다. G0는 제품 개발 관문 차단 상태이며, NOT RUN은 수행하지 않은 개별 시험 상태다.

M1 자동 시험은 실제 실행한 것만 기록한다. 이후 M2에서는 호출 창·탭·폴더, helper 종료 후 그림판·Office·메일/메신저 붙여넣기, 투명도, 원본 보호를 확인한다. M3에서는 깨끗한 Windows 환경의 설치 수명주기와 기존 연결·기본 복사/붙여넣기 회귀를 확인한다. 실행 환경이 없거나 도구 접근이 제한되면 NOT RUN 또는 그 원인이 되는 BLOCKED를 명시한다.

2026-09-24: 원명세 G0 유지, 독립 M1 개발 허용, 메뉴·패키징 미실증 및 위치 변경안 미승인 상태를 기록했다.
