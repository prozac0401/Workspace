# ADR-0007 · 확인한 폴더에 적용하고 아이콘 저장 위치를 독립 변경

상태: 구현에 채택  
날짜: 2026-09-19  
결정 담당: 제품·개발 담당  
관련 요구사항·정책: [REQ-FS-UX-001~006](../tools/folderstate/usability.md), [최초 명세 §2·6·7·8·13](../specifications/01.md), [추가 도구 개발 기준](../policies/tools.md)  
대체·대체됨 관계: 없음. [ADR-0001](0001-engine.md)과 [ADR-0005](0005-explorer-refresh.md)의 데이터·복구 계약을 보완합니다.

## 맥락

관리 화면은 경로 입력과 상태 조회를 별도로 처리했습니다. A를 조회하고 B 경로만 입력하면 A 상태가 남은 채 B에 저장할 수 있었습니다. 상태 없는 새 폴더에는 이전 폴더의 아이콘 저장 방식과 결과 문구도 남았습니다.

아이콘 저장 위치는 상태 버튼을 눌러야 적용되므로 위치만 바꾸려 해도 상태 변경 시각이 갱신됐습니다. 이는 실제 업무 상태와 아이콘 표현을 구분하는 원칙을 사용 흐름에서도 분리할 필요가 있음을 보여줍니다.

## 결정

경로 입력과 확인된 작업 대상을 구분합니다. 경로를 편집하면 이전 대상·상태·결과와 변경 버튼을 무효화합니다. 폴더 선택·Enter·‘폴더 확인’으로 읽기를 마친 대상에만 작업을 허용합니다. 폴더를 확인할 때 저장된 상태와 아이콘 위치를 함께 읽고, 상태 없는 폴더는 Local을 기본값으로 사용합니다.

상태 유무·복구 필요·사용할 수 없음에 따라 가능한 버튼을 구분합니다. 읽기 실패 중 `recovery_pending`에는 복구 진입점을 유지합니다. 결과는 대상과 성공·주의·실패를 문구와 기호로 표시하며, 저장 후 조회가 실패해도 이미 완료한 저장 결과를 보존합니다.

Core에 `ChangeMode`를 추가하여 기존 상태·상태 변경 시각을 보존한 채 아이콘 저장 위치만 바꿉니다. 별도 저장 형식이나 새 트랜잭션 체계를 만들지 않고 기존 잠금·소유 확인·충돌 검사·복원 절차를 사용합니다. 상태 버튼은 저장된 모드를 유지하며, 라디오 버튼의 선택만 바꿔도 상태 변경에 암묵적으로 결합하지 않습니다. 작업 후 상태를 다시 읽으면 선택 표시를 저장된 모드로 맞추므로 미적용 위치 선택은 보관하지 않습니다. 문제 해결 버튼은 동봉 도움말 전체를 엽니다. 오류별 도움말 자동 분기와 전용 로그 조회 화면은 이번에 추가하지 않습니다.

## 검토한 대안

| 대안 | 이점과 비용 | 판단 |
|---|---|---|
| 경로 편집마다 자동 조회 | Enter가 불필요하지만 입력 중의 불완전한 경로 조회·오류와 대상 전환이 반복됨 | 명시적 확인 선택 |
| 모든 상태 변경에 확인 대화상자 | 대상 재확인 가능하지만 반복 작업마다 한 단계 추가 | 확인 대상 표시와 버튼 제어 선택 |
| 저장 위치 선택 후 현재 상태 다시 누르기 | 기존 구현을 유지하지만 상태 변경 시각이 바뀌고 미적용 선택을 구분하기 어려움 | 독립 명령 선택 |
| 읽기 실패 시 모든 작업 차단 | 간단하지만 중단된 작업을 복구할 수 없게 됨 | 복구 대기 상태만 복구 허용 |
| 화면 개선과 다중 선택·실행 취소를 함께 추가 | 반복 조작을 줄일 수 있으나 대상·동시 변경·복원 범위가 확대됨 | 별도 후속 명세로 검토 |

## 영향과 이행

상태 저장은 한 번 클릭을 유지합니다. 경로를 직접 바꿨다면 확인을 마쳐야 합니다. 처음 상태를 저장하는 폴더는 Local로 시작하며 필요하면 저장 위치를 별도로 바꿉니다. GUI와 탐색기는 단일 폴더를 유지합니다.

상태 파일 형식 2와 기존 명령은 유지합니다. 로컬 로그에는 `change-mode` 동작이 추가됩니다. 관리자 권한, 설치 위치, HKCU 등록, 자체 포함 MSI는 바꾸지 않습니다. **0.1.3 소스 반영 결정이며 공개 미배포입니다. 0.1.2 RC1 공개 설치 파일에는 미반영**입니다. 조직 운영 정책이나 상용 출시 승인을 뜻하지 않습니다.

## 실패와 복구

읽기 실패는 확인한 오류와 다음 행동을 표시하고 쓰기를 막습니다. 복구 대기일 때만 ‘아이콘 다시 표시’로 기존 중단 복구를 시작할 수 있습니다. 작업 결과와 후속 상태 조회 결과를 구분합니다.

모드 변경 실패·중단·동시 작업은 기존 엔진의 잠금·트랜잭션 복원·충돌 처리로 다룹니다. 외부 아이콘과 알 수 없는 메타데이터를 보존하며, 성공한 모드 변경 뒤에도 reset은 최초 사용자 설정을 복원해야 합니다.

## 검증

대상 A에서 B로 경로 편집, Portable A에서 상태 없는 B 선택, A 오류 후 정상 B 선택, 잘못된 경로와 복구 대기, 저장 성공 후 조회 실패, 네 상태 카드 표시를 확인합니다.

모드 전환에는 Status·Updated·추가 메타데이터 보존, Local↔Portable 왕복, 중단 쓰기·롤백·동시 작업·reset 호환성 시험을 요구합니다. WPF smoke 렌더와 문서 strict 빌드·로컬 링크 검사를 수행하고 실제 결과를 [2026-09-19 검증 기록](../delivery/folderstate-usability-20260919.md)에 남깁니다. 배율·화면 읽기·최초 사용자·공유 환경 시험과 새 설치본 수명주기는 실행 전까지 미검증입니다.
