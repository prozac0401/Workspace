# ADR-0006 · 두 도구의 공개 안내와 설치 파일 다운로드

상태: 채택 · 날짜: 2026-09-17 · 결정 담당: 저장소 관리

관련: 사용자 요청 — Excel도 안내 사이트에서 내려받고 수정 내용·사이트·Release를 게시. [정책 문서 작성 규칙](../policies/documentation.md), [Pages 운영](../delivery/pages.md).

대체 범위: [ADR-0004](0004-public-handbook.md)의 공개 대상에 Excel 명단 비교의 사용자 안내와 두 도구의 설치 파일 링크를 추가합니다. 명시한 문서·자산만 공개하는 방식과 개발 자료 제외 원칙은 유지합니다.

## 맥락

안내 사이트에는 FolderState 사용법만 있고 설치 파일 다운로드와 Excel 안내가 없어 사용자가 프로그램을 찾기 어려웠습니다. 소스의 문구 교정과 이전에 게시한 Excel 설치 파일을 같은 버전으로 설명하면 실제 화면과 안내가 달라집니다. RC7·RC8의 알려진 실패도 문구 수정만으로 해결되지 않습니다.

## 결정

- 홈페이지 상단에 프로그램 받기 바로가기를 추가하고 FolderState와 Excel의 설치 안내로 연결합니다.
- 탐색 메뉴에 두 도구를 모으고 `docs/tools/excel-list-compare/index.md` 한 페이지를 새로 공개합니다.
- MkDocs 허용 목록, 탐색 메뉴, `scripts/check-site.py`의 공개 경로를 함께 갱신합니다. 공개 페이지는 15개입니다.
- 설치 파일은 GitHub Release의 태그·파일명을 고정한 주소로 연결합니다. 제품이 다른 최신 릴리스로 연결될 수 있는 `releases/latest/download`는 사용하지 않습니다.
- 다운로드 전에 실제 파일 버전, 시험판 여부, 알려진 실패와 지원 환경을 설명합니다. 새 파일을 만들지 않은 변경은 기존 설치 파일에 반영됐다고 표시하지 않습니다.
- 개발 명세·설계·시험 기록·원시 진단·업무 파일을 공개 페이지에 복사하거나 사이트의 검색·사이트맵에 포함하지 않습니다. 필요한 제한은 사용자 페이지에 직접 요약합니다.

## 검토한 대안

설치 파일을 `docs/assets`에 넣는 방법은 사이트 게시물에 바이너리를 중복 보관하게 됩니다. Release에 버전별로 보관하고 사용자 안내에서 링크하는 방식을 선택했습니다. 개발 README 전체를 그대로 게시하면 진단·빌드 안내와 과거 검증이 함께 노출되므로, 사용에 필요한 내용만 별도 페이지에 작성합니다.

## 영향과 이행

기존 FolderState 문서 주소는 유지합니다. 사용자는 홈페이지와 프로그램 받기 메뉴에서 두 도구를 찾을 수 있습니다. 새 Excel 파일이 준비되기 전까지는 이전 공개 RC7에 연결하며, 문구 교정 미반영과 취소·제거 실패를 안내합니다. 이는 기존 RC8의 배포 보류 판정을 변경하지 않습니다.

## 실패와 복구

다운로드 자산이 없거나 표시한 버전과 다르면 해당 링크를 바로잡고 사이트를 다시 게시합니다. 파일을 새로 만들었다는 이유만으로 이전 파일의 실제 시험 결과를 새 파일에 적용하지 않습니다. 사이트는 Markdown 원본을 수정해 다시 빌드하며 생성된 HTML을 직접 고치지 않습니다.

## 검증

`python -m mkdocs build --strict`와 `python scripts/check-site.py site`로 공개 페이지·로컬 링크·자산·검색·사이트맵을 확인합니다. 게시할 때는 Release 자산과 Pages 배포 결과, 실제 공개 URL도 확인합니다. 로컬 빌드와 실제 게시 확인은 별도 결과로 기록합니다.
