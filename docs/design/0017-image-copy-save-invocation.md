# ADR-0017 · 그림 명령의 호출 상태와 결과 연결

상태: 채택(구현 선택), 실기 검증 전  
날짜: 2026-09-25  
결정 담당: 도구 개발 담당  
관련 요구: [v1.1 CPY-11, SAV-01~03, SAV-07, NFR](../tools/image-copy-save/ImageCopySave_Requirements_v1.1.md)  
적용 정책: [추가 도구 개발 기준](../policies/tools.md)  
선행 결정: [ADR-0016](0016-image-copy-save-direct-menu.md)

## 맥락

기존 native 후보는 명령과 경로만 helper에 전달했다. helper가 시작되기 전에 사용자가 새 내용을 복사하면 오래된 복사 요청이 새 클립보드를 덮을 수 있었다. 콘솔 출력도 사용자 안내와 호출한 탐색기 보기로 연결되지 않았다.

## 결정

Invoke 진입 시 클립보드 sequence를 확보하고 경로·호출 보기와 함께 고정한다. helper의 별도 Shell 모드는 이 기준값을 worker까지 전달한다. 복사는 게시 잠금 안에서 비교하고, 저장은 읽기 잠금 안에서 데이터 요청 전에 비교한다. 시작 지연 중 내용이 바뀌면 조용히 대체하지 않고 상태 변화로 중단한다. 잠금 후 지연 렌더링에 따른 sequence 변경은 이미 확보하는 스냅샷을 무효화하지 않는다.

helper는 WinExe와 WPF로 짧은 비모달 진행·취소·결과 안내를 제공한다. 시작과 완료 시 포커스를 활성화하지 않으며 자동으로 닫힌다. 기존 개발용 CLI와 독립 worker는 유지한다. 저장 성공 경로는 명시적 UTF-8 stdout으로 전달한다.

native 모듈은 제한된 표준 핸들만 상속하고, 별도 스레드에서 최대 30초 동안 결과를 수집한다. 성공 결과는 호출 폴더 바로 아래의 PNG 경로만 받는다. 원래 IFolderView를 `IAgileReference`로 보존하고, 동일 보기의 창·현재 폴더·가시성·전경 루트가 일치할 때만 선택한다. 실패·시간 초과 시에도 marshal stream을 다른 apartment에서 수동 해제하지 않는다. 이 수명 관리 방식은 [Microsoft의 RoGetAgileReference 계약](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-rogetagilereference)에 따른다. 전경 창 탐색으로 저장 대상을 추정하지 않는다. 저장 선택 실패는 저장 실패가 아니며 helper의 결과 위치 안내를 유지한다.

## 검토한 대안

Explorer에서 픽셀 데이터를 직접 읽으면 지연 렌더러가 탐색기를 지연시킬 수 있어 사용하지 않는다. 시작 뒤 새 상태를 기준으로 삼으면 원래 호출과 다른 내용이 처리될 수 있다. 전체 클립보드 백업은 임의 형식을 복원할 수 있다는 보장이 없고 요구 범위를 넘는다. ShellWindows를 검색해 활성 창에 결과를 선택하는 방식은 다른 탭을 변경할 수 있어 사용하지 않는다.

## 실패와 복구

worker의 기존 제한시간·협력 취소·자기 프로세스 종료를 유지한다. 강제 종료 또는 커밋 뒤 결과 유실은 완료 여부 불확실로 안내한다. 결과 전달 실패로 완료된 저장을 취소하거나 파일을 지우지 않는다. helper 시작 자체가 실패하면 native 비모달 오류 안내를 시도한다. Explorer를 강제로 종료하거나 다른 앱의 프로세스·클립보드를 복원하지 않는다.

## 검증과 남은 조건

자동시험은 오래된 호출 기준값, 잠금 후 지연 렌더링, 결과 경로 거절, worker 수명과 오류·취소 상태를 확인한다. WPF는 창을 띄우지 않는 렌더링으로 시각 점검한다. 실제 첫 메뉴, 호출한 창·탭, 실제 포커스 보존, 취소 버튼, 외부 앱 붙여넣기와 설치 수명주기는 [PC 확인 안내](../tools/image-copy-save/local-verification.md)에 따라 별도로 실행한다. 이 결정은 G0 통과나 배포 승인을 뜻하지 않는다.
