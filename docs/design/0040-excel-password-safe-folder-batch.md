# ADR-0040 · ExcelPasswordSafe 폴더 일괄 작업과 실패 기록

상태: 채택 · 날짜: 2026-11-16 · 결정 담당: 도구 개발
관련: [후속 요청](../tools/excel-password-safe/original-request.md), [제품 명세](../tools/excel-password-safe/specification.md)의 REQ-EPS-012~016, [추가 도구 개발 기준](../policies/tools.md)
대체 범위: [기존 파일 처리 설계](0018-excel-password-safe-explorer.md)의 단일 파일 전용 범위와 정상 완료 후 중간 파일 보관. 파일의 암호·검증·원본 교체 계약은 유지한다.

## 맥락

사용자는 폴더의 모든 하위 Excel 파일에 같은 암호 작업을 적용하고, 실패를 최대 3회 시도한 뒤 실패 목록을 화면과 Excel 파일로 확인하기를 요청했다. 기존 파일 오른쪽 클릭 동작은 유지하고 처음 제공한 배치 도구처럼 중간 작업 파일이 남지 않도록 요청했다.

## 결정

폴더의 `Excel 암호 관리` 아래 `암호 설정 / 암호 해제 / 암호 변경` 메뉴를 등록한다. 선택한 폴더와 하위 폴더를 검색하여 지원 Excel 파일의 목록·전체 경로를 미리보기로 확정한다. 실행 후 추가된 파일은 포함하지 않는다. 배치 엔진은 각 파일을 처음 읽을 때 해시를 확정하고 재시도 동안 고정한다. 폴더 목록 승인 이후 첫 해시 계산 전 변경을 감지하는 계약은 아니다. 기존 단일 파일의 UI 승인 해시는 유지한다. 재분석 지점·오프라인 경로에는 진입하지 않고, 읽을 수 없는 폴더나 제외된 위험 항목은 표시하여 전체 성공으로 오인하지 않게 한다.

사용자가 확인한 목록에 공통 현재 암호·새 암호를 적용한다. 각 파일은 기존 엔진의 백업·실제 Excel 저장·재열기 검증·원자 교체를 따르며 순서대로 실행한다. 폴더 전체를 한 번에 되돌리는 트랜잭션은 만들지 않는다. 이미 성공한 파일은 다음 파일의 실패나 취소 때문에 자동 복원하지 않는다.

안전하게 끝난 실패만 최초 시도 포함 최대 3회 처리한다. 다음 시도 전 원본 해시, 이전 writer 종료와 작업 파일 정리를 확인한다. 현재 암호가 다른 파일은 같은 입력으로 3회 실패할 수 있다. 원본 변경·백업 변조·교체 상태 불확실·남은 Excel·정리 실패는 자동 재시도하지 않는다. 발견 단계에서 접근하지 못한 항목은 처리 시도 0회로 구분한다. 안전한 진행이 불가능하면 남은 파일을 미처리로 기록한다.

최종 실패에는 파일명·전체 경로·이유·실제 시도 수를 기록한다. 실패가 있을 때만 현재 사용자 전용 실행 폴더에 XLSX 보고서를 만든다. 제품의 LocalAppData 트리는 그 상위를 선택해도 검색에서 제외하여 보고서·백업을 재귀 입력에 섞지 않는다. 보고서는 UI에서 열 수 있으며 모든 셀은 수식이 아닌 문자열로 저장한다. 암호·암호문·원시 예외는 넣지 않는다. 보고서 작성 실패를 성공으로 표시하지 않는다.

정상 완료·안전한 실패·취소 후에는 해당 실행의 작업 복사본·임시 결과·암호 전달 파일을 정리한다. 검증된 원본 백업은 유지하고 정상 커밋의 중복 recovery는 결과·백업을 확인한 뒤 정리한다. 정리가 안전하지 않은 경우에는 필요한 복구 자료를 남기고 원인과 경로를 표시한다. 모든 `.eps-*` 파일을 이름만 보고 삭제하거나 기존 실행의 자료를 추정해서 정리하지 않는다.

## 검토한 대안

동시에 여러 Excel 인스턴스를 돌리면 잠금·프로세스 소유·취소 경계가 복잡해진다. 기존 파일 단위 검증을 재사용한 순차 처리로 범위를 제한한다. 실패 보고서를 선택 폴더에 만들면 다음 폴더 작업에 포함되므로 실행 폴더에 보관한다. 무조건 3회 재시도하거나 모든 중간 파일을 강제로 지우면 원본 변경과 불확실한 교체의 복구 근거를 훼손하므로 허용하지 않는다.

## 영향과 이행

파일 메뉴와 기존 3개 작업 입력은 유지한다. 폴더 메뉴·미리보기·진행 수·실패 목록·보고서 열기를 추가한다. MSI는 HKCU의 제품 고유 폴더 메뉴만 추가하고 제거 시 자기 메뉴만 제거한다. 새 동작의 명세·안내·테스트·실제 결과를 1.4.0 기록에 함께 관리한다. 1.2.0과 1.3.0 기록, 첨부 원본은 수정하지 않는다.

## 실패와 복구

파일별 원본 백업과 완료 결과는 보존한다. 안전한 실패는 한도까지 재시도한 뒤 표시하며 다른 파일과 분리한다. 취소 후 진행하지 않은 파일은 실패나 성공으로 숨기지 않는다. 교체 상태가 불확실하면 자동 재시도·롤백을 하지 않고 현재 파일·백업·필요한 recovery를 확인하게 한다. 암호가 없던 원본 백업은 평문일 수 있으며 프로그램 제거로 삭제하지 않는다.

기존 늦은 MSI 설치 실패에서 제품 등록이 남는 제한은 이 기능으로 해결된 것으로 간주하지 않는다. 같은 MSI로 제거한 뒤 재설치하는 안내를 유지한다.

## 검증

필수 범위는 중첩 폴더·빈 목록·접근 실패·재분석점, 승인 후 변경, 최대 3회와 재시도 중지 분기, 성공·실패 혼합 보고서와 실패 0건, 수식처럼 보이는 파일명, 안전한 정리·취소·불확실 복구 보존이다. 실제 Explorer 폴더 하위 메뉴, 기존 파일 메뉴, 합성 문서의 일괄 작업과 MSI 업그레이드·제거를 확인한다. 결과는 [1.4.0 검증 기록](../delivery/excel-password-safe-folder-20261116.md)에 실제 수행 범위로 구분한다.

## 성능 후속 결정 · 2026-11-17

상태: 채택·버전 3 구현과 관련 검증 완료. 위 1.4.0 결정·당시 결과는 이력으로 보존한다. 관련 요구는 REQ-EPS-024이며 [성능 개선 기록](../delivery/excel-password-safe-performance-20261117.md)에 실제 시간·검증 범위와 게시 확인 위치를 구분한다.

작은 합성 파일의 기준 계측에서 반복되는 Excel 시작·종료 비용이 확인됐다. 단일 파일은 기존 파일별 worker를 유지하고, 폴더 배치는 첫 처리 가능한 파일에서만 소유 PowerShell/Excel worker를 시작해 같은 배치와 안전한 재시도에서 재사용한다. 세션 설명 파일은 현재 사용자 전용 실행 폴더에 두며 사용자 Excel에 연결하지 않는다. 암호 구현은 Excel 저장·재열기를 유지한다.

파일별 writer 종료 조건은 열린 통합문서가 모두 닫히고 파일별 COM 참조가 해제됐으며 일반 통합문서와 Protected View 창이 모두 0개임을 확인하는 것이다. worker 결과는 이 확인 뒤에만 전달한다. 엔진은 고정한 Excel PID·시작 시각, 세션 토큰·순번·idle ACK를 대조한 뒤 기존 원본·백업·결과 해시와 원자 교체 검증을 수행한다. 불확실 상태의 즉시 `unsafe.json` 표시도 커밋 전에 검사한다. 다음 작업은 앞 파일의 커밋·정리가 끝난 뒤에만 시작한다. 확인된 대기 세션 외의 남은 Excel을 허용하는 변경은 아니다.

커밋 직전 UI 소유 PID·시작 시각과 취소를 다시 확인해 교체 전 원본을 보존한다. worker·프로토콜·RPC·정리가 불확실하면 배치를 멈추고 복구 자료를 유지하며 Excel을 강제 종료하지 않는다. 종료 시 중지 요청·대기·종료 완료 확인을 수행하고, Quit 직전에는 경고 표시를 복원한 뒤 일반 통합문서·Protected View 창이 없는지 다시 확인한다. 실패하면 루트 `NeedsInspection`과 실패 보고서를 남긴다. 이미 커밋한 파일을 자동 롤백하지 않는다.

이 변경은 배치의 세션 소유·작업 순서·닫힘 확인·취소·실패 중단에 직접 연결되는 회귀와 같은 조건의 전체 시간을 검증했다. 순수 배열의 계산 시간이나 기존 파일별 시험만으로 세션 재사용의 안전성과 실제 작업 속도가 입증됐다고 표시하지 않으며, 실제 Excel·격리 회귀·단일 관측 성능 결과와 이전 미실행 범위를 구분한다.
