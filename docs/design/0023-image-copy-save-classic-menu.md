# ADR-0023 · 공통 클래식 메뉴와 무서명 관리자 MSI

상태: 사용자 요구 채택 · 클래식 직접 표시 일부·MSI 수명주기 시나리오 실증, 전체 G0·제품 인수 미완료

날짜: 2026-09-27
결정 담당: 사용자(메뉴 경로·시험 전환 승인), 도구 개발·검증 담당
관련 요구사항·정책: [요구명세 v1.2](../tools/image-copy-save/ImageCopySave_Requirements_v1.2.md), [추가 도구 개발 기준](../policies/tools.md), [정책 문서 작성 규칙](../policies/documentation.md)
대체 관계: [ADR-0016](0016-image-copy-save-direct-menu.md)의 Windows 11 첫 메뉴 필수 조건과 package identity 경로를 대체한다. [ADR-0021](0021-image-unsigned-msi.md)의 무서명 목표와 [ADR-0022](0022-image-admin-install.md)의 관리자 설치·일반 사용자 실행은 유지하고, 필수 설치 경로를 클래식 COM 등록으로 변경한다.

## 맥락

이전 요구는 Windows 11 기본 새 메뉴의 첫 단계에서 명령을 제공하는 것이었다. 관리자·SYSTEM의 unsigned sparse 등록 가능성은 별도로 확인했지만, 현재 PC의 클래식 직접 표시 설정과 새 메뉴의 실제 상태를 구분해야 했다. 등록 또는 진단 MSI 성공만으로 제품 G0를 통과시킬 수 없다.

사용자는 이제 두 메뉴 모드에서 공통 클래식 메뉴를 사용하도록 요구했다. Windows 11 기본 메뉴에서는 ‘더 많은 옵션 표시’ 뒤에, Windows 10 스타일로 클래식 메뉴를 직접 여는 설정에서는 바로 두 명령에 접근한다. 이번 시험의 임시 모드 전환과 원래 설정 복구도 승인했다. 이 변경으로 첫 Windows 11 메뉴용 package identity를 제품의 필수 등록 경로로 고집할 이유가 없어졌다.

## 결정

1. 저장·복사 명령은 공통 클래식 메뉴의 독립 항목으로 제공한다. 이미지 없음의 완전 숨김, 지원 파일 한 개만 복사, 빈 상위 메뉴·중복 부재는 유지한다.
2. native IExplorerCommand를 ExplorerCommandHandler로 등록하는 경로를 구현·검증한다. 제품 MSI가 HKLM의 x64 COM·폴더 배경·지원 이미지 verb와 프로그램 파일을 소유하며, 실제 Explorer가 GetState와 호출 문맥을 기대대로 사용하는지는 실기로 확인한다.
3. 최종 배포 목표는 별도 서명 없는 자체 포함 MSI다. 설치·업데이트·제거 시 정상 관리자 승인을 허용하고 런타임 Explorer/helper는 일반 사용자 권한으로 동작한다. 클래식 경로가 실제 시험을 통과하면 제품의 MSIX/sparse identity와 사용자별 패키지 등록을 설치 의존성에서 제외한다.
4. 기존 기본 연결·‘새로 만들기’·타사 메뉴·업무 파일·사용자 PNG를 보존한다. 메뉴를 열 때 상태 메타데이터만 판정하고 이미지 처리·쓰기·게시·피드백은 helper가 담당한다. 상주 감시기·서비스·반복 등록 변경은 추가하지 않는다.
5. 제품 설치기는 메뉴 표시 모드를 변경하지 않는다. 이번 시험만 승인된 설정을 잠시 바꾸고 원래 상태를 복구하며, 설정·권한·화면·복구 증거를 남긴다.
6. Windows 11에서 클래식 메뉴를 직접 표시한 시험을 실제 Windows 10 OS의 지원 인증으로 사용하지 않는다.
7. 사용자의 “불필요한 반복테스트는 지양하도록 합니다.” 지시에 따라 고정 20회 반복을 완료 관문에서 제외한다. 미확인 기능은 대표 1회 확인하고 실패나 관련 변경이 있을 때만 해당 시험을 다시 수행한다. 이미 수행한 횟수와 결과는 보존하며 나머지는 사용자 지시에 따라 반복 생략으로 기록한다. 기본 Windows 11 메뉴 경로와 설정 원상복구는 필수로 유지한다.

Microsoft는 IExplorerCommand를 shortcut menu 구현에 사용할 수 있음을 설명하고, 공식 샘플은 ExplorerCommandHandler와 COM 등록을 연결한다. 이는 설계 후보의 API 근거이며 제품의 실제 표시·숨김·설치 통과 증거는 아니다. [Microsoft 인터페이스 안내](https://learn.microsoft.com/en-us/windows/win32/shell/how-to-create-cascading-menus-with-the-iexplorercommand-interface) · [공식 등록 샘플](https://github.com/microsoft/Windows-classic-samples/blob/main/Samples/Win7Samples/winui/shell/appshellintegration/ExplorerCommandVerb/RegisterExtension.cpp) · [GetState 계약](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iexplorercommand-getstate)

## 검토한 대안

| 대안 | 판단 |
|---|---|
| Windows 11 첫 메뉴 + package identity 유지 | 이전 요구의 후보와 증거는 보존한다. 새 공통 클래식 메뉴의 필수 설치 경로로 사용하지 않는다. |
| HKLM native IExplorerCommand + ExplorerCommandHandler | 기존 엔진·명령 인터페이스를 유지하며 MSI가 소유하는 클래식 등록을 직접 시험할 수 있어 선택했다. 실기 전에는 지원 성공을 단정하지 않는다. |
| 항상 표시하는 static command 또는 회색 항목 | 이미지 없음의 완전 숨김 요구를 충족하지 않아 제외한다. |
| 상주 감시·반복 registry 변경·기본 메뉴 패치 | 무상주·기존 동작 보존 계약에 어긋나 제외한다. |

## 영향과 이행

v1.0/v1.1 원본을 바꾸지 않고 v1.2 변경 계약으로 MNU-01·04, 설치 경계와 G0·AT-07·08·09·40·41의 판정을 갱신한다. 44개 AT 번호를 유지한다. 이전 첫 메뉴 차단을 새로운 클래식 요구의 실패로 복사하거나 이전 엔진 PASS를 새 메뉴 PASS로 변환하지 않는다.

제품 MSI의 COM 등록·수정·제거는 설치 트랜잭션과 소유 범위에 포함한다. 기존 설치·타사 등록·시험 identity가 있으면 정확한 소유·충돌을 확인하고 덮어쓰지 않는다. 운영체제나 조직이 무서명 설치를 차단하면 그 결과를 기록하며 인증서·개발자 모드·UAC·보안 정책을 변경해서 통과시키지 않는다.

## 실패와 복구

메뉴 숨김·실행 문맥이 틀리면 해당 사례를 FAIL로 남기고 메뉴 상태를 고정하거나 감시기를 추가해 대신 통과시키지 않는다. 설치 중단·업데이트 실패는 앱 소유 변경만 롤백해야 하며 사용자 PNG와 알 수 없는 외부 변경을 보존한다. 로드된 DLL 때문에 제거가 지연되면 재시작 필요와 실제 잔재를 구분한다. 제품이 Explorer를 임의 강제 종료하지 않는다.

시험용 메뉴 모드 전환 전에는 원래 설정의 존재·형식·값을 기록한다. 시험 종료 시 복구하고 실제 원래 모드가 돌아왔는지 확인한다. 복구 중 외부 변경·실패가 있으면 완료로 보고하지 않는다. 이 시험 승인으로 제품의 영구 모드 설정 변경이 승인된 것은 아니다.

## 검증

2026-09-27 후속 중간 실기에서 Windows 11 클래식 직접 표시 모드의 독립 저장·이미지 없음 완전 숨김과 실제 PNG 저장·이미지 복사를 확인했다. 실제 Explorer 파일 복사로 만든 CF_HDROP 클립보드에서도 저장 항목은 없고 일반 Paste는 유지됐다. 무서명 자체 포함 MSI의 0.1.0 설치·손상 DLL Repair, 0.1.0→0.1.1 업데이트, 제거·깨끗한 상태의 의도된 설치 실패 롤백·0.1.1 재설치는 실제 관리자 실행에서 PASS다. 실패 주입 단계는 예상 exit 1603 뒤 제품 설치·등록 잔여 없음으로 판정했고 나머지는 exit 0이었다. 모든 단계에 재부팅 요구와 Explorer 재시작이 없었다. 실제 저장 중 설치된 0.1.0 helper와 Explorer 모두 비상승임도 읽기 전용 토큰 조회로 확인했다. 0.1.1 설치 상태에서도 클래식 메뉴로 시험 폴더 A의 8×8 PNG 저장·클립보드 sequence 불변과 PNG 선택 파일의 실제 이미지 복사를 확인했다.

이 결과는 아래 전체 인수를 대체하지 않는다. 클래식 직접 표시 전환 15회·46개 관찰 행은 모두 PASS다. 1~8회는 0.1.0, 9~15회는 0.1.1이며 버전별 실제 범위를 구분한다. 02:53 UTC에는 새 시험 Explorer 창으로 기존 창 활성화 실패를 넘어 진행했고 그 시점의 기존 창·Explorer 프로세스를 보존했다. 이후 03:05 UTC의 승인된 메뉴 모드 시험에서 수동 Explorer 재시작 한 차례와 Workspace 창 경로 복원을 수행했다. 제품 설치기는 Explorer를 재시작하지 않았다. 16~20회는 사용자 지시에 따라 반복 생략하며 제품 실패나 필수 잔여로 분류하지 않는다. HKCU 메뉴 설정을 백업·이동한 뒤에도 관찰 메뉴는 클래식이어서 기본 새 메뉴 경로는 미확인이다. 03:11 UTC 설정 복원은 Owner·Group·DACL 보존과 백업 키 제거까지 PASS였으나 03:21 UTC에 다시 시험 상태로 진입했다. 03:27:33 UTC 최종 복원은 원본 키·값·Owner·Group·DACL 보존, 백업 키 제거와 journal RESTORED로 PASS다. 물리 우클릭 비교 결과를 확보하지 못해 요청과 추가 재시도는 중단했다. 기본 새 메뉴 경로는 미확인으로 남긴다. 최초 UAC 취소, 다음 요청의 실제 업데이트 PASS, 그 결과를 읽던 시험 실행기의 UTF-8·빈 JSON 키 처리 오류와 수정 회귀 PASS를 각각 보존했다. 잔여 3단계는 재승인 후 실행하여 완료했다. 최종 상태는 메뉴 검증을 위한 0.1.1 설치 유지다. [G0 기록](../tools/image-copy-save/G0_Menu_Feasibility.md)의 개별 행과 로컬 증거를 기준으로 나머지를 갱신한다.

재시작 후 두 번째 배경 우클릭에서 Explorer ‘응답 없음’을 관찰한 뒤 자체 회복했다. 단일 최소덤프의 95개 스레드에서 제품 DLL 프레임은 0개였고 메뉴 메시지 대기를 관찰했다. 단일 시점과 심볼 제약 때문에 원인은 미확정이며 제품 무관 또는 자동화만의 원인으로 결론 내리지 않는다. 해당 진단은 메뉴 안정성 전체 PASS를 뜻하지 않는다.

- Windows 11 기본 새 메뉴 → 더 많은 옵션 표시와 클래식 직접 표시 모드 각각의 저장·복사 진입.
- 모드별 미확인 상태 전환의 대표 확인, 지원 밖 선택·위치, 회색·빈 메뉴·중복 부재. 횟수 채우기 반복은 생략하고 실패·변경에 관련된 사례만 재시험.
- 메뉴 진입만으로 이미지 디코딩·파일 생성·클립보드 변경이 없고, 실제 명령은 호출한 폴더·탭과 파일에 적용되는지.
- 관리자 MSI 설치·재설치·업데이트·실패 복구·제거, 비상승 helper, 사용자 파일·타사 메뉴·기본 연결 보존.
- 모드 설정 원상복구와 시험 소유 프로세스·등록·창 정리.

Windows 10 OS, 다른 OS 빌드·사용자 프로필·PC·외부 앱은 실제 수행한 범위만 기록한다. 미실행 범위를 포함한 상용 승인·광범위 배포를 선언하지 않는다.
