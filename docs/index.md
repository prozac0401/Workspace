# 정리가 일이 되지 않는 업무 기준

**정리 자체가 새로운 업무가 되지 않는 것을 가장 중요한 원칙으로 합니다.** 필요한 자료를 다시 찾고, 하던 일을 이어가고, 다른 사람에게 넘길 수 있으면 충분합니다.

정리를 위한 별도 시간을 만들기보다 **새 업무·착수·문제·완료·종료라는 업무 사건에 정리를 붙입니다.**

<div class="grid cards" markdown>

- **지금 판단이 필요하다면**

    “어디에 두지?”, “새 폴더가 필요한가?”, “완료해도 되나?”에 바로 답합니다.

    [빠른 판단 기준](quick-reference.md)

- **처음 도입한다면**

    현재 업무 한 회차부터 시작하고, 실제로 필요한 규칙만 남깁니다.

    [처음 도입하는 순서](getting-started.md)

- **기본 기준을 확인한다면**

    폴더의 역할, MASTER 키트, 일정, 이메일과 원본 시스템을 확인합니다.

    [기본 구조와 원본](policies/workspace.md)

- **진행 상태를 표시한다면**

    폴더명과 경로를 유지하면서 네 가지 아이콘으로 상태를 표시합니다.

    [FolderState 사용 안내](tools/folderstate/index.md)

## 업무가 흐르는 네 단계

1. **어디에 둔다** — 새 자료의 용도가 모호하면 Inbox, 현재 업무의 결과물이면 해당 Active 회차에 둡니다.
2. **어떻게 시작한다** — 반복 업무는 미착수 상태의 MASTER를 복사해 시작합니다.
3. **어디까지 했나** — 단계 상태는 FolderState, 마감과 담당은 Schedule, 결정 이유는 Decision Log에서 확인합니다.
4. **끝나면 어디로 보낸다** — 미완료·이슈를 확인하고 종료한 회차 전체를 Archive로 옮깁니다.

같은 정보를 여러 곳에서 각각 수정하지 않습니다. Inbox를 매일 비우거나 과거자료 전체를 다시 분류할 필요도 없습니다. 자동화는 반복되는 불편과 복구 방법이 명확할 때 추가합니다.

## 반복되는 불편이 생겼을 때만

기본 흐름으로 충분하면 여기서 시작하세요. 회신 누락이나 인수인계 문제가 반복될 때 [운영 개선안 — 선택 적용](policies/folder-workflow.md)에서 해당 항목만 골라 한 회차에 적용합니다. 별도 대장이나 승인 절차를 기본 체계에 일괄 추가하지 않습니다.

!!! info "문서 상태"
    운영 정책은 제안 단계입니다. 회사의 저장 위치·보존기간·공식 원본·백업 체계는 [결정 목록](policies/decisions.md)에서 조직별로 확정합니다. 예시는 가상이며 실제 업무자료는 공개 문서에 저장하지 않습니다. FolderState v0.1.0은 검증용 배포입니다. [설치 안내](tools/folderstate/installation.md)에서 사용 환경과 제한을 확인하세요.
