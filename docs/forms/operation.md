# 업무 정보와 일정 양식

반복하는 업무를 준비할 때 필요한 항목입니다. 이미 회사 시스템이나 파일에 있는 정보는 그 위치만 연결하세요. 이 문서는 항목을 제안하며 Excel 파일을 자동으로 만들지는 않습니다.

## 복사해서 쓸 기본 폴더 준비하기

기본 폴더(MASTER)에는 빈 양식과 업무 순서만 둡니다. 실제 업무는 기본 폴더를 복사한 뒤 복사본에서 시작하세요.

FolderState로 상태를 표시한다면 기본 폴더의 각 단계는 **시작 전**(`todo`)으로 둡니다. 상태 표시를 쓰지 않는 폴더에는 미리 상태 파일을 만들 필요가 없습니다. 진행 중·완료·확인 필요는 실제 업무의 복사본에서 사용합니다.

기본 폴더에 잘못된 상태가 있으면 그 단계만 고칩니다. 정상적인 복사본 전체를 매번 고칠 필요는 없습니다. **상태 표시 지우기**는 ‘시작 전’으로 바꾸는 버튼이 아닙니다. 저장된 상태와 FolderState의 표시를 없앱니다. 자세한 차이는 [반복 업무 시작과 일정 관리](../policies/kits.md#master)를 확인하세요.

## 기본 정보 (기존 이름: Overview)

| 적을 내용 | 예시 또는 작성 방법 |
|---|---|
| 업무 이름 | 2026-10_교육운영 |
| 시작일·종료일 | 일정표에서 사용하는 날짜 |
| 장소·대상·인원 | 업무에 필요한 내용만 작성 |
| 담당자 | 누가 무엇을 언제까지 하는지 확인할 수 있는 위치 |
| 최신 자료 위치 | 결과물·명단·일정을 실제로 고치는 파일이나 회사 시스템 |
| 기본 폴더의 버전·복사일 | 어떤 틀로 시작했는지 알 수 있는 표시 |
| 보관 위치 | 업무를 끝내고 옮긴 위치 |

## 일정 (기존 이름: Schedule)

아래 날짜는 설명용 예시입니다. 회사 일정으로 확정된 값이 아닙니다. 시작일을 D, 종료일을 E로 표시합니다. 휴일을 포함해 셀지, 근무일만 셀지도 정해야 합니다.

| 할 일 | 날짜를 정하는 방법 | 실제 마감일 | 담당자 | 이 일정을 정한 근거 |
|---|---|---|---|---|
| 모집 시작 | 시작일 30일 전 (D-30) | 이번 업무의 날짜 입력 | 담당 역할 | 회사에서 정한 일정 |
| 입과 안내 | 시작일 10일 전 (D-10) | 이번 업무의 날짜 입력 | 담당 역할 | 회사에서 정한 일정 |
| 설문 | 종료일 1일 후 (E+1) | 이번 업무의 날짜 입력 | 담당 역할 | 회사에서 정한 일정 |
| 비용 처리 | 종료일 7일 후 (E+7) | 이번 업무의 날짜 입력 | 담당 역할 | 회사에서 정한 일정 |

## 세부 확인사항 (기존 이름: Checklist)

필요한 항목만 **단계 / 확인할 것 / 담당자 / 확인일** 순서로 적습니다. 예: `입과 안내 / 받는 사람 주소 확인 / 발송 담당 / 10월 2일`.

FolderState에서 이미 표시하는 단계의 완료 여부를 여기에 또 적을 필요는 없습니다.

## 연락처 (기존 이름: Contacts)

**역할 / 소속 / 업무용 연락수단 / 맡은 일**을 적습니다. 비밀번호와 불필요한 개인정보는 적지 않습니다.

## 문제와 결정 이유 (기존 이름: Issues / Decision Log)

다시 확인할 필요가 있는 문제만 **날짜 / 문제 / 결정 / 이유 / 담당자 / 근거 위치 / 다음에 할 일** 순서로 적습니다. 예: `10월 2일 / 강의실 사용 불가 / 다른 강의실로 변경 / 기존 강의실 공사 / 운영 담당 / 승인 메일 링크 / 참석자에게 안내`.

프로그램 설계의 결정 이유는 개발용 설계 기록(ADR)에 따로 남깁니다.

## 기본 폴더를 고쳤을 때

**버전 / 바꾼 이유 / 바꾼 단계 / 시험한 업무 / 적용일**을 적습니다. 이미 진행 중인 업무의 폴더를 새 기본 폴더로 덮어쓰지 않습니다.

회신 누락이나 업무 전달 문제가 반복될 때만 [일을 이어서 하고 다른 사람에게 넘기기](../policies/folder-workflow.md)에서 필요한 항목을 고르세요. 쓰지 않거나 다른 곳에 같은 내용을 또 적게 하는 항목은 줄입니다.
