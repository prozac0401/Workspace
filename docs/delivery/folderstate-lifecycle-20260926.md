## 실패와 수정

첫 도구 자식 프로세스 시험은 설치/메뉴/CLI 존재를 확인했으나 installed CLI works에서 실패했고 정리 제거는 종료0이었다. 초기에는 CLI 출력이 증거에 남지 않아 구체적 실패 원인은 단정하지 않는다. 과거 File List 검증에서 사용한 WMI 일반 사용자 실행 경로로 같은 패키지를 시험했을 때 CLI 실행이 성공했다. 보안 설정·실행 정책·등록 값을 완화하지 않았다.

첫 업데이트 시험에서 실제 업데이트는 종료0, 구버전 설치는1603으로 차단됐다. 시험 스크립트는 ‘더 최신 버전’ 문구만 찾았으나 실제 MSI는 ‘더 새로운 버전’을 출력해 판정이 실패했다. 두 문구와 WIX_DOWNGRADE_DETECTED의 제품 GUID를 함께 확인하도록 수정했다. 임의의1603을 PASS로 인정하지 않는다. CLI JSON/종료 코드도 로컬 증거에 남기도록 보완했다.

수정 후 업데이트 경로 전체를 다시 실행하여18개 검사를 통과했다. 이전 실패 로그·합성 폴더는 보존했다. 제품 엔진·WPF·MSI는 변경하지 않아 엔진 재시험/화면 재렌더는 실행하지 않았다. 문서 strict 빌드와 생성 사이트 검사는 별도로 수행한다.

원시 로그·설치 경로·프로세스 진단은 로컬 artifacts/audit/backlog-20260926과 작업 트리 artifacts/msi-smoke-*에만 둔다. 공개 사이트에 포함하지 않는다. 미서명 평가 패키지이며 상용 승인을 뜻하지 않는다.

## 2026-09-27 · 실제 Explorer와 관리 화면 후속 확인

같은 공개 MSI를 일반 사용자로 `artifacts/folderstate-ui-20260927/installed`에 설치했다. 기존 설치·HKCU 양쪽 레지스트리 보기·기본 설치 폴더·프로세스가 없음을 사전 검사했다. 설치 종료0 뒤 전용 합성 폴더 세 개만 사용했다. 각 폴더의 이름과 고정 `keep.txt` 해시를 확인했으며 업무 폴더를 열거나 하위 목록을 검색하지 않았다.

기존 사용자 아이콘 복원 직후 목록에는 기본 폴더 그림이 남았다. 폴더 재선택으로 세부 정보의 원래 아이콘을 확인했고, F5 뒤 목록도 원래 아이콘으로 돌아왔다. 상태 전환 중 오른쪽 세부 정보에 이전 그림이 남는 현상도 확인했다. 기존 [오류 해결 안내](../tools/folderstate/troubleshooting.md)의 재선택·F5 안내에 해당하며 모든 화면의 즉시 갱신으로 기록하지 않는다. Explorer 재시작·전체 아이콘 캐시 삭제·보안 설정 변경은 하지 않았다.

최종적으로 세 폴더 이름과 합성 파일 해시가 모두 같았고 상태 파일은 없었다. 원시 단계 기록·메타데이터 사본·실패 안내 접근성 기록·설치 로그는 전용 시험 폴더에만 보관한다. 기존 미지 정보의 초기화 거절과 외부 아이콘 충돌은 의도한 보존 동작이다. 제품 소스·MSI는 변경하지 않아 기존 엔진·WPF 자동검사를 재실행한 것으로 기록하지 않는다.

문서 strict 빌드와 공개 19페이지·404·생성 링크·비공개 제외 검사는 통과했다. 별도 .NET 미설치 PC, 재로그인·재부팅, 화면 읽기·배율, 공유·동기화·조직 보안 환경은 미실행이다. 현재 PC의 실기 완료가 이 환경이나 상용 배포 승인을 대신하지 않는다.
