## 실패와 수정

첫 도구 자식 프로세스 시험은 설치/메뉴/CLI 존재를 확인했으나 installed CLI works에서 실패했고 정리 제거는 종료0이었다. 초기에는 CLI 출력이 증거에 남지 않아 구체적 실패 원인은 단정하지 않는다. 과거 File List 검증에서 사용한 WMI 일반 사용자 실행 경로로 같은 패키지를 시험했을 때 CLI 실행이 성공했다. 보안 설정·실행 정책·등록 값을 완화하지 않았다.

첫 업데이트 시험에서 실제 업데이트는 종료0, 구버전 설치는1603으로 차단됐다. 시험 스크립트는 ‘더 최신 버전’ 문구만 찾았으나 실제 MSI는 ‘더 새로운 버전’을 출력해 판정이 실패했다. 두 문구와 WIX_DOWNGRADE_DETECTED의 제품 GUID를 함께 확인하도록 수정했다. 임의의1603을 PASS로 인정하지 않는다. CLI JSON/종료 코드도 로컬 증거에 남기도록 보완했다.

수정 후 업데이트 경로 전체를 다시 실행하여18개 검사를 통과했다. 이전 실패 로그·합성 폴더는 보존했다. 제품 엔진·WPF·MSI는 변경하지 않아 엔진 재시험/화면 재렌더는 실행하지 않았다. 문서 strict 빌드와 생성 사이트 검사는 별도로 수행한다.

원시 로그·설치 경로·프로세스 진단은 로컬 artifacts/audit/backlog-20260926과 작업 트리 artifacts/msi-smoke-*에만 둔다. 공개 사이트에 포함하지 않는다. 미서명 평가 패키지이며 상용 승인을 뜻하지 않는다.
