## 요청과 게시 기준

사용자는 도구 설명의 각 세부 챕터에 이해를 돕는 삽화를 넣고, 다른 도구도 모두 작성한 뒤 게시해 달라고 요청했습니다. 게시 전에 원격 main이 로컬 작업 기준보다 116개 커밋 앞서 있음을 확인했습니다. `5db4e8a85c2d67c4128ea30cd065046cb3579e46`의 최신 공개 문서를 기준으로 삽화만 통합했습니다.

현재 본문·버전·다운로드·메뉴를 보존합니다. FolderState 통합 안내와 두 이전 주소 이동, Excel 명단 비교 0.2.1, 업무 책갈피 0.2.8, 새 다운로드 이름 유지와 Office Automation Tools 안내도 유지합니다. 이전 로컬 7도구 문서 전체를 원격에 덮어쓰지 않았습니다. 제품 소스·설치 파일·설치 상태는 변경하지 않습니다.

충분한 완료 근거는 최신 본문 보존, 모든 챕터의 삽화 포함, 문서 strict 빌드·공개 범위·링크 검사, Pages 워크플로 성공 및 실제 공개 내용 확인입니다. 사용자 이해도나 제품의 기능·설치 시험으로 확장하지 않습니다.

## 실제 확인 결과

- 최신 원격 본문과 삽화를 제외한 본문을 대조했습니다. 공백 정규화 후 9페이지 모두 동일하며 모든 H2/H3 113개와 정의 113개가 순서대로 일치합니다.
- SVG 226개의 XML 구조·제목·설명과 생성기 검사를 통과했습니다. Windows 맑은 고딕 글꼴 치수와 SVG 좌표로 패널 글자 2,005개를 검사했으며 이미지 바깥 글자나 서로 겹치는 글자는 없었습니다. 이는 정적 배치 검사이며 브라우저 렌더링 검사로 표시하지 않습니다.
- 기존 렌더러·CSS의 이전 PC·모바일 검사 결과를 재사용했습니다. 이번 통합본의 로컬 브라우저 접근은 보안 승인에서 거부되어 화면 검사를 다시 수행하지 않았으며 다른 브라우저 접근으로 우회하지 않았습니다.
- `python -m mkdocs build --strict`와 `python scripts/check-site.py site`를 통과했습니다. 공개 21페이지·이전 주소 이동 2개·404, 검색·사이트맵, 공개 자산, 로컬 경로와 반응형 이미지 `srcset`을 확인했습니다.
- 세 명이 도구별 최신 본문과 삽화 정의를 검토했습니다. Office 연습 명단의 ‘데이터 2행’을 ‘데이터 시작 2행’으로 보완했습니다.

로컬의 Store Python 가상환경 실행기는 현재 환경에서 실행되지 않아 제공된 Python 3.12와 기존 문서 의존성을 사용했습니다. 원시 출력과 스테이징 자료는 로컬 `artifacts/publication-20261006/`에 보관하며 게시하지 않습니다.

## 게시 상태

게시용 파일 252개와 원격 기준 트리로 GitHub tree 생성을 요청했으나, 도구가 승인을 요구하고 세션 승인 정책이 `never`여서 호출이 차단됐습니다. 반환 결과는 `MCP tool call requires approval, but approval policy is never`입니다. 같은 외부 쓰기를 다른 경로로 우회하지 않았습니다.

이번 게시 요청으로 원격 커밋·main 변경·Pages 배포는 수행하지 못했습니다. Documentation 실행 성공과 실제 공개 반영은 미확인입니다. 승인 가능한 세션에서 아래 준비 파일을 사용하되, 그때의 원격 main이 기준 커밋 이후 바뀌었다면 변경 파일을 다시 대조해야 합니다.

검토·재개용 자료는 로컬 `artifacts/publication-20261006/`의 `publication.patch`, `publication-files.zip`, `manifest.json` 및 `stage/`입니다. 패치의 기준은 위에 적은 원격 커밋이며, 기존 사용자 작업이 있는 로컬 checkout에는 바로 적용하지 않습니다. 저장소의 기존 `.git`·작업 변경은 보존했습니다.

실제 휴대전화·다른 브라우저·화면 읽기 프로그램·초보 사용자 이해도 검사는 수행하지 않았습니다. 회사 정책의 제안 상태와 제품별 실제 지원·보존 제한을 유지합니다.
