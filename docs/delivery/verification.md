## 쉬운 문구와 사용 순서 · 2026-09-16

공개 안내 14개 페이지와 FolderState 화면·메뉴·설치·오류·도움말을 고쳤습니다. [문구 점검 기록](wording-review.md)에 범위, 바꾼 이유, 문구별 목록을 만드는 방법을 정리했습니다. 이번 변경은 로컬 반영이며 GitHub 푸시와 Pages 게시를 하지 않았습니다.

- `scripts/review-wording.py`: 수정 전 1,492개, 수정 후 1,966개 문구 단위를 추출했습니다. 제목·문장·표의 칸·버튼·메시지를 포함하며, 변경된 출처 파일은 29개입니다. 단위 수 증가는 문장 분리와 용어 풀이를 포함하며 이해도 향상을 수치로 입증하지 않습니다. 결과는 로컬 `artifacts/wording/`의 `before.md`, `after.md`, `changes.md`, `items.json`입니다.
- .NET SDK 10.0.401을 사용한 `scripts/build.ps1` 전체 빌드에서 엔진 테스트 **27/27**과 기본 WPF 렌더를 통과했습니다. 중단 복원·동시 처리·외부 설정 보존·초기화 호환성 등 기존 시험을 포함합니다. 엔진 변경은 안내 문자열이며 저장 처리와 형식은 유지합니다.
- WPF 렌더러로 960×740 기본 화면, 760×680 기본 화면, 작은 화면의 선택 설정 펼침, 긴 결과 안내와 아래쪽 스크롤을 확인했습니다. 4개 아이콘이 표시되고, 버튼·설명이 읽히며 아래 도움말·기록 버튼에 스크롤로 도달합니다. 화면 확인 후 왼쪽 안내의 어색한 줄바꿈을 고쳤고 다시 렌더했습니다. 실제 키보드·화면 읽기·여러 DPI 시험은 이번에 수행하지 않았습니다.
- 문서 `python -m mkdocs build --strict`, `python scripts/check-site.py site` 통과. 공개 14개 페이지와 404, 검색·사이트맵·자산의 공개 범위 및 로컬 연결을 확인했습니다. 검토 목록과 개발 기록은 사이트에 포함되지 않습니다.
- 로컬 서버와 headless Edge에서 14페이지 × 데스크톱 1365×960·모바일 390×844, **28건**의 가로 넘침 검사를 통과했습니다. 문서 내부 링크 **396개**가 유효하며 브라우저 오류가 없었습니다. 화면 캡처를 육안 검토했고, 빠른 안내의 붙어 보이던 바로가기를 벌린 뒤 다시 검사했습니다. 새 프로그램 화면으로 사용 안내의 이미지를 갱신했습니다.
- 문구 추출에서 보간 문자열의 따옴표 선택지, 펼침 제목, 접근성 도움말, 중복 없는 식별자를 확인했습니다. 이미지 안의 글자나 실행 중 생기는 외부 오류 내용은 자동 추출 범위가 아닙니다.
- 오프라인 도움말은 1000×800과 390×844에서 열어 가로 넘침이 없는지 확인했습니다. 좁은 창의 표에서 버튼 이름이 한 글자씩 끊어지던 부분은 첫 번째 칸의 너비와 줄바꿈을 고친 뒤 다시 렌더해 확인했습니다.
- 최종 화면·도움말 수정 후 `scripts/build.ps1 -SkipTests`로 다시 패키징했습니다. 이 명령은 앞서 통과한 엔진 시험을 반복하지 않는 패키징 실행입니다. `scripts/verify-msi.ps1` 통과: 사용자별 설치, HKCU만 사용, 명령 6개, 포함 파일 414개. MSI 안의 상위 메뉴와 작업 이름 7개가 새 문구인지 확인했고, 패키징용 도움말과 원본의 SHA-256, MSI와 `.sha256` 파일의 값이 일치했습니다. 설치 화면의 모든 컨트롤이 각 대화상자 경계 안에 있는지도 정적으로 확인했습니다. 실제 설치 화면 조작 시험은 아닙니다.

최종 로컬 패키지: `artifacts/release/FolderState-0.1.0-win-x64.msi`, 50,452,923바이트, SHA-256 `6f77936ad99cf7fbea8baf323813afc59fc9d23337330536833e7c880dfe3345`, 서명 `NotSigned`. 검증 환경은 Windows 11 build 22631입니다. 메뉴·패키지 검사 결과는 로컬 `artifacts/wording/msi-verification.json`, `package-content.json`에 남겼습니다.

위 검증은 실제 사용자 대상 이해도 시험을 포함하지 않습니다. 참고용 PPTX와 원본 명세, 별도 Excel 시험 프로젝트는 수정하지 않았습니다. MSI 패키지는 계속 서명 없는 평가용이며 상용 승인 상태가 아닙니다. 설치·복구·업그레이드·제거를 실제로 실행하는 시험은 이번 문구 변경에서 다시 수행하지 않았습니다.

## 2026-09-16 · Excel RC8 후속 보완

취소 오류 전달·상태 복원·설치 폴더의 제거 실행을 보완하고 후속 시험을 마쳤다. **Esc 3회와 첫 대화형 설치가 실패해 RC8 배포를 보류했다.** 자동 설치·원복 49개는 분할 실행으로 통과했고, 대화형 설치 재시도와 등록된 제거·설치 폴더 CMD 제거는 성공했다. 최종적으로 제품 설치·Excel·시험 예약 작업이 없으며 Office·PowerShell 14개 그룹의 값·형식도 시작 전과 같다. 파일 해시, 실패와 성공의 범위는 [RC8 검증 기록](../../tools/ExcelSmartListCompare/docs/RC8_COMPLETION_REPORT.md)을 따른다. 아래 이전 기록은 당시 결과로 보존하며 공개 릴리즈·사이트 게시와 배포용 RC8 ZIP은 만들지 않았다.


## Excel RC7 잠금 해제 후 실제 화면 검증 · 2026-09-15

동일 RC7 배포 파일로 두 파일 열기 방식, 8종 우클릭, 실제 비교·바꾸기·비우기·대화상자와 단일 EXE 설치 화면을 확인했다. **Esc 취소는 2회 실패했고 최초 GUI 제거도 접근 거부 코드 5로 실패했다.** 시험 설치는 복구 절차로 정리했으며 제품·관리 폴더·앱 항목·Excel 프로세스가 없고 Office·PowerShell 설정 14개 그룹도 시작 전과 같다. 상세 판정·원시 증거 범위·미확정 원인은 [실기 보고서](../../tools/ExcelSmartListCompare/docs/UNLOCKED_UI_REPORT.md)를 따른다. 제품 바이너리·릴리즈·공개 사이트는 갱신하지 않았으며 전체 인수 완료가 아니다.

## 설치 수명주기

기존 FolderState 메뉴가 없는 개발 PC의 **권한 상승 없는 세션**에서 저장소 내부의 전용 시험 폴더를 사용했습니다. 실행 기록의 `elevated`는 `false`입니다.

1. MSI 설치 후 HKCU 메뉴, 자체 포함 CLI 실행과 상태 저장을 확인했습니다.
2. 설치된 아이콘 하나를 삭제한 뒤 MSI 복구로 같은 설치 경로에 복원되는지 확인했습니다.
3. 동일 최종 프로그램과 설치 정의로 만든 **0.1.1 시험 전용 패키지**를 사용해 MSI 상위 버전 교체를 확인했습니다. 실제 차기 제품의 데이터 형식 변경 시험은 아닙니다.
4. 0.1.0 재설치가 최신 버전 존재를 이유로 차단되는지 확인했습니다. 종료 코드 1603과 해당 버전 오류 문구를 함께 검사했습니다.
5. 제거 후 메뉴·프로그램이 없어지고 업무파일·폴더 상태정보의 바이트가 유지되는지 확인했습니다.

설치·복구·업그레이드·제거는 모두 종료 코드 0이었습니다. 이 시험은 개발 PC에서의 실제 동작 근거이며 깨끗한 별도 PC의 검증을 대체하지 않습니다.
