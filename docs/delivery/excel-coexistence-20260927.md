# Excel 네 도구 공존 기록 · 2026-09-27

상태: 현재 PC의 합성 자료 대표 경로 완료 · 책임: 개발·검증 담당

백로그 T12의 네 도구를 한 Excel 세션에서 차례로 사용하고, 변경 제품을 하나씩 제거한 뒤 남은 도구의 자동 로드와 메뉴를 확인했다. 제품 소스 변경 없이 현재 후보 패키지를 검증했다. 사용자 지정에 따라 합성 폴더와 합성 통합문서만 사용했다.

## 대상과 환경

| 도구 | 실제 사용한 패키지·상태 |
|---|---|
| 선택범위 내보내기 | 0.1.0-rc.10 x64 EXE, 2,137,629 bytes, SHA-256 `9171be45330ce9af86ce7b5eb06614211e3620bd47893912b03dd6ff2829114a` |
| 보이는 칸 붙여넣기 | 공개 0.1.1 ZIP을 포함한 단일 EXE, 177,664 bytes, SHA-256 `bd55f32f3a9d467ed288696c8e80dd7f5e9eb97a280ba12a25fe622a5d26b464` |
| File List to Excel | 공개 1.2.0 x64 MSI, 50,880,300 bytes, SHA-256 `7690bab04bafd6d83bb1fb88c2fbf681204fb8f8a6b1f8993847ccd1a6933364`, Excel 구성 요소 포함 |
| 명단 비교 | 기존 R12 설치를 유지하고 대표 비교만 실행. 재설치·제거·설정 변경 없음 |

현재 Windows/Excel x64, Excel 16.0 build 20326, 일반 사용자 환경이다. 시험 전 Excel과 File List helper가 없고 세 대상 제품이 설치되어 있지 않음을 확인했다. 설치·기능 실행·제거·재시작을 모두 순차 수행했다. 매크로 보안, Office 정책, 신뢰 저장소를 변경하지 않았다.

## 한 세션에서의 대표 기능

T10의 합성 재귀 목록을 새 `coexist.xlsx`로 복사하고 `OwnedCoexist` 시트를 추가했다. 원래 T10 통합문서는 수정하지 않았다. 기능 실행은 실제 Excel UI로 수행했으며 읽기 전용 프로브는 결과만 검사했다. 프로브에서 추가 기능 연결, 셀, Excel 상태 플래그, 통합문서 수명은 변경하지 않는다.

| 순서 | 실행과 실제 결과 |
|---|---|
| 초기 실행 | 세 COM 추가 기능 자동 연결, 기존 명단 비교 설치 유지. 실제 우클릭에서 네 제품 메뉴가 함께 표시됨 |
| 붙여넣기 | H1:J1의 85·90·78을 복사해 E2:E5의 보이는 세 칸에 붙여넣음. 숨김 E3와 범위 밖 E6 보존, 22검사 PASS |
| 되돌리기 | 실제 `마지막 붙여넣기 되돌리기` 실행. E2/E4/E5의 원래 문자열 복구, 22검사 PASS |
| 선택범위 내보내기 | E2:E5에서 새 Excel로 내보내기. 새 미저장 통합문서의 `선택범위` 시트 A1:A3에 before2·before4·before5만 존재, 수식 없음. 28검사 PASS |
| 명단 비교 | L6:L8의 Alpha·Beta·Beta와 M6:M8의 Alpha·Beta·Gamma 비교. Beta 2/1, Gamma 0/1만 결과에 표시, 같은 Alpha 제외. 원본 여섯 값 보존, 27검사 PASS |
| 파일 복사 | Files 시트 A2:A14에서 실제 `선택한 파일 복사…` 실행. 13행 중 파일 10개/195바이트 복사, 폴더 3개 제외, 실패 0 |
| 기능 후 종료 | 각 미저장 결과는 저장 없이 닫고 원본 보존·Excel 상태 복원 22검사 PASS. Excel Alt+F4로 정상 종료, 디스크 fixture SHA-256 불변 |

복사 결과의 `중복 이름.txt`와 `중복 이름 (2).txt`는 각각 해당 원본의 내용을 유지했다. 출력에는 기대한 파일 10개만 존재하며 내부 경로 보고서는 포함되지 않았다. 이번 작업의 별도 보고서와 실제 복사 경로·해시를 대조했다. 합성 원본 10개/폴더 3개의 목록·속성, 파일 수정 시각·해시, T10 통합문서 여섯 개의 바이트도 유지됐다. T10에서 이미 기록한 폴더 수정 시각 기준의 한계는 그대로이며 폴더 시각 불변을 주장하지 않는다.

## 순차 제거와 남은 제품 보존

각 단계에서 Excel이 정상 종료되어 프로세스가 없을 때에만 다음 제거를 시작했다. 세 제거 프로그램은 모두 종료 0이었다.

| 제거 후 새 Excel 세션 | 자동 로드와 실제 우클릭 메뉴 | 읽기 전용 검사 |
|---|---|---|
| 선택범위 내보내기 제거 | 붙여넣기/되돌리기·파일목록·명단 비교 유지, 선택범위 메뉴 없음 | 22 PASS |
| 붙여넣기 제거 | 파일목록·명단 비교 유지, 붙여넣기와 선택범위 메뉴 없음 | 22 PASS |
| 파일목록 제거 | 명단 비교 유지, 세 시험 제품 메뉴 없음 | 22 PASS |

남은 제품의 설치 파일 전체 목록·SHA-256과 LoadBehavior=3을 매 단계 대조했다. HKCU/HKLM의 32/64비트 Office 정책·Excel/Common 보안·다른 COM 추가 기능 등록과 명단 비교 설정을 기준 지문과 비교했다. 기존 명단 비교의 다섯 관리 파일 해시도 동일했다. 마지막 세션까지 정상 종료했으며 최종 검사에서 Excel/helper 프로세스 부재, 세 시험 설치 폴더/추가 기능 등록 부재, 소유 표식의 세 제품 모두 제거 상태를 확인했다.

## 재현과 근거

- `scripts/test-excel-coexistence.ps1`: 정확한 패키지 해시·일반 사용자·기존 설치와 프로세스 부재를 확인한 뒤 Prepare, 단계별 Remove, Verify를 수행한다. 남은 설치 payload와 기존 환경 지문을 검사하며 기존 명단 비교를 설치/제거하지 않는다. 실제 Excel UI 시험은 별도다.
- `scripts/create-excel-coexistence-fixture.py`: repository artifacts의 합성 File List 통합문서를 새 파일로 복사해 시험 시트를 추가한다. 출력 덮어쓰기를 거부한다.
- `scripts/ExcelCoexistReadProbe.cs`: 기존 `ExcelProbe.Attach`로 지정 PID에 연결해 정확한 fixture와 예상 미저장 결과만 읽는다. `all/noexport/fileonly/none` 설치 단계와 `before/pasted/undone/export/roster` 결과를 구분한다. COM 참조는 반환한다.
- `scripts/check-excel-coexistence.py <evidence> <T10-fixture>`: 결과 기록, 중복 없는 실제 메뉴, 원본/복사본, 경로 대응과 디스크 바이트를 대조한다. **135개 증거 검사 PASS**, 아홉 시점의 읽기 전용 Excel 검사 **209 PASS**를 확인했다. 209는 반복되는 보존 검사도 포함한 누적 수다.

근거는 작업 트리 `artifacts/excel-coexistence-20260927` 및 원본 저장소 `artifacts/audit/backlog-20260926/t12-*`에 있다. 설치 로그·사용자 경로를 포함한 UI 텍스트·복사 보고서는 local-only로 유지하고 공개 사이트에 포함하지 않는다.

초기 Prepare는 시험 실행기의 msiexec 스위치 인용 오류로 설치 클라이언트가 진행하지 못해 실패했다. MSI 로그·제품 등록이 생기기 전이었고 UI 도구에서도 해당 창을 선택할 수 없었다. 사용자의 작업 재개 후 PID·부모 PID·명령행·시험 경로와 미등록 상태를 확인하고 **시험 소유 MSI 클라이언트 한 개만 종료**했다. Excel을 강제 종료한 적은 없다. 인수 전달을 수정하고, 이미 설치한 두 제품과 원래 환경이 그대로임을 대조한 ResumeFileList로 재개해 설치 종료 0을 확인했다. 초기 실패 기록은 보존하며 제품 실패로 분류하지 않는다.

명단 비교 검사기의 첫 목록 개수 열은 결과 헤더에 맞춰 D열로 바로잡고 D8/F8 헤더까지 검사하도록 했다. 수정 후 실제 명단 검사를 수행했으며 제품 소스는 바꾸지 않았다. 문서 strict 빌드와 공개 링크 검사 결과는 백로그 작업 기록에 남긴다.

## 남은 범위

이 결과는 현재 PC의 합성 자료 대표 경로에 한정한다. R12 전체 재검증(T11), 업무 자료, x86 Office, 새 PC, 재부팅과 조직별 정책 환경은 미실행이다. 전체 설치 순서/제거 순열을 모두 시험한 것은 아니다. T03 격리 사전 조건, T04 MSIX 설치 신뢰, T08 스티커 입력 UI 제약은 별도 미완료 상태로 유지한다. 패키지 공개·push·상용 승인으로 분류하지 않는다.
