# FolderState 0.1.1 · 실제 Windows 강건성 검증

실행: 2026-09-14~15 KST · 판정: 서명 없는 평가용 배포 후보 · 상용 승인 아님

## 수정 사항

사용자가 보고한 상태 변경 후 아이콘 지연을 실제 Windows 11 Explorer에서 재현했다. Portable의 고정 아이콘 파일 덮어쓰기와 비동기 알림만으로는 반복 전환이 안정적으로 반영되지 않았다. 0.1.1은 내용 해시별 아이콘 경로, Windows 폴더 설정 API, 해당 폴더 PIDL 동기 알림을 사용한다. [ADR-0005](../design/0005-explorer-refresh.md)에 선택 이유와 호환성을 기록했다.

상태 형식 2로 전환하며 형식 1 복구·초기화를 유지한다. 알 수 없는 메타데이터는 보존하고, 안전하게 초기화할 수 없으면 충돌로 중단한다. 이전 아이콘이 잠긴 상태의 롤백과 중단된 저장 복구를 보완했다. 상태 작업은 선택 폴더의 고정 메타데이터만 접근하며 업무 파일 내용과 하위 폴더를 검색하지 않는다.

## 환경과 실행 대상

Windows 11 Pro 10.0.22631 x64, 일반 사용자, 로컬 NTFS의 전용 합성 폴더에서 실행했다. 완전 빌드는 `scripts/build.ps1`, MSI 검사는 `scripts/verify-msi.ps1`, 설치 수명주기는 사전 미설치 확인 후 `scripts/test-installer.ps1`로 수행했다.

- 제품: 0.1.1, 현재 사용자 MSI, HKCU 메뉴 6개, 자체 포함 런타임, 패키지 파일 414개.
- MSI SHA-256: `5ff4051b25fe26da48e247e71266afc051f638e6626206d1ec78840c9db1037b`.
- 코드 서명: NotSigned. 관리자 권한·시작 프로그램 등록을 추가하지 않았다.

## 실패 시도와 제한

수정 전 및 중간 캐시 알림 방식은 Explorer 화면 갱신에 실패했다. 이 화면들을 최종 통과 증거로 사용하지 않았다. 서로 다른 AppData/HKCU 보기에서 실행한 CLI·Explorer를 섞은 관측도 일반 데스크톱 검증과 구분했다. 가상화된 실행 호스트에서 남은 로그를 실제 MSI 제거 실패로 판단했던 초기 가설은 일반 데스크톱 재검증에서 기각됐다.

일반 Explorer의 오른쪽 세부 정보 선택 미리보기는 목록 아이콘이 갱신된 후에도 이전 그림을 보일 수 있었다. 전역 캐시 삭제나 Explorer 강제 재시작은 추가하지 않았다. 이 표시 제한을 [문제 해결](../tools/folderstate/troubleshooting.md)과 [캡처 퀵가이드](../tools/folderstate/quick-guide.md)에 안내한다.

한 번의 MSI 시험 작업 호스트가 접근 위반 코드로 종료되어 완료 표식을 쓰지 못했다. 자식 시험의 최종 기록은 PASS/원복 완료였고 별도 확인 후 임시 예약 작업을 제거했다. 이를 제품 MSI 실패나 작업 호스트 정상 종료로 바꾸어 기록하지 않았다. 원시 진단은 로컬 artifacts에만 보존한다.

| 수행하지 않은 항목 | 이유·영향 |
|---|---|
| 실제 Windows 재부팅·로그오프 | 사용자의 다른 업무를 중단하지 않음. 메뉴는 MSI가 지속 등록하며 상태는 파일에 저장하지만 재부팅 실행 시험은 미실행 |
| OneDrive·SMB·NAS·다른 PC·32비트 OS | 해당 환경 미시험. 로컬 NTFS 결과를 확대 해석하지 않음 |
| MSI 설치창 클릭·캡처 | UI 도구가 msiexec 접근을 차단. 실제 명령줄 설치·제거와 제품 사용 캡처는 수행 |
| 모든 Explorer 확장·보기 조합 | Windows와 타 확장의 캐시 지연을 보장하지 않음 |
| HTML 가이드의 브라우저 배치 검토 | 로컬 파일 브라우저 접근이 도구에서 차단. 내장 이미지·링크·파일 검사를 별도로 수행 |

설치 직후 별도 첫 실행이나 부팅 시 상주 실행은 필요하지 않다. 우클릭할 때 제품 프로세스가 실행된다. 재부팅 후 메뉴 유지의 설계와 실제 재부팅 미시험을 구분한다.
