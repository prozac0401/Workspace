## 초기 실패와 제한

처음 작성한 시험의 단일 HKCU Uninstall 경로 조회는 MSI의 실제 설치와 일치하지 않았다. Windows Installer의 [RelatedProducts API](https://learn.microsoft.com/en-us/windows/win32/msi/installer-relatedproducts)로 동일 UpgradeCode의 제품을 열거하고 VersionString·ProductState를 확인하도록 바꿨다. 단순히 등록 검사를 생략하지 않았다.

artifacts 아래에 INSTALLFOLDER를 지정한 초기 시험에서는 복구·제거 후 해당 사용자 지정 경로에 실행 파일이 남았다. 기본 경로 시험의 PASS로 이 실패를 덮지 않는다. 현재 공개 설치 화면은 설치 경로 변경 기능을 제공하지 않는다. 아래 후속 조사에서 경로 보존 결함을 수정했으며, 초기 시험 산출물은 로컬 증거로 남겼다.

실제 앱을 실행하지 않았으므로 한글 IME, 창 전환 자동 저장, 저장 실패 초안, 스티커 위치·여러 모니터, 작업 재개, 실행 중 제거, 재로그인·재부팅은 NOT_RUN이다. DB 해시 보존은 이 UI 시험과 구분한다. 기존 209개 Desktop 회귀검사도 이번 패키지 실기 결과로 옮겨 쓰지 않는다.

진단·MSI 로그는 로컬 artifacts/audit/backlog-20260926과 작업 트리 artifacts/bookmark-lifecycle-*에만 보관한다. 사용자 DB·설정·로그 원문은 Git이나 공개 사이트에 포함하지 않는다. 위 공개 MSI 시험 당시 제품 소스·공개 MSI·별도 BookMark 저장소는 변경하지 않았다. 설치본은 시험 후 제거했으며 기존 포터블 앱과 데이터는 남아 있다.

## 후속: 사용자 지정 설치 경로 수정

BookMark 저장소의 668df2a에서 분리한 `codex/backlog-20260927` 작업 트리에서 **def9141**로 수정·검증 기록을 커밋했다. 원본 main과 공개 0.2.3은 보존했다.

실패 로그에서 0.2.3 복구·제거의 INSTALLFOLDER가 기본 경로로 돌아가는 것을 확인했다. 0.2.4 후보는 설치 시 HKCU 제품 소유 키에 경로를 기록하고 이후 유지 관리·업데이트의 CostInitialize 전에 복원한다. 다른 경로를 명시해도 기존 경로를 유지하며, 위치 변경은 제거 후 신규 설치로 수행한다. DB v5와 UI 코드는 변경하지 않았다.

후보 MSI는 75,451,327 bytes, SHA-256 `aebd7bb3844951a02b7323ffa1d1ddd16b06ff542f0bc90691de3eb1f6f370f3`이다. 미서명 로컬 후보이며 공개 배포·상용 승인이 아니다.

| 검증 | 실제 결과 |
|---|---|
| 기존 전체 자동검사 | Core/SQLite52·IPC17·Desktop209·나머지 어댑터/브라우저322, 합계600 PASS |
| MSI 구조 | 50 PASS, WiX 4.0.6, 빌드 경고·오류0 |
| 사용자 지정 설치→파일 삭제→경로 없는 복구 | 원래 경로 복원, 기본 폴더 미생성 |
| 다른 경로를 명시한 복구 | 기존 경로 유지, 다른 폴더 미생성 |
| 경로 없는 업데이트→복구→제거 | 원래 경로 유지, 새 등록 하나, 제품 파일·등록·바로가기 제거 |
| 설치 폴더의 별도 파일 | 제거 후 내용 해시 보존, 나머지 payload 파일 없음 |
| 공개 0.2.3 기본 설치→0.2.4→복구→제거 | PASS, 기본 폴더 잔재 없음 |
| 공개 0.2.3 사용자 지정 경로의 명시적 제거→0.2.4 설치→경로 없는 제거 | PASS, 각 설치 폴더 제거 |
| 모든 실기 단계 | 118/118 체크포인트 PASS, MSI 작업14회 종료0, DB/설정 해시·자동 실행 선택 유지, 자동 앱 실행 없음 |

경로를 기억하는 버전 간 업데이트에는 같은 payload·동작을 가진 로컬 MSI 복사본의 식별자·버전·업그레이드 경계만 시험용 0.2.5로 바꿨다. 이 fixture를 0.2.5 릴리스로 분류하지 않는다. 실제 공개 0.2.3 업데이트 시험은 별도로 수행했다.

초기 실행 파일 접근 오류와 WiX 버전 조회 실패는 로그를 보존하고 재시도에서 통과한 범위만 기록했다. 원인을 확정하거나 보안 설정을 변경하지 않았다. 새 시험 코드의 PowerShell 예약어와 MSI SQL 기본키 UPDATE 오류도 별도 보존했다. SQL 오류 후에는 시험 설치를 정상 제거하고 행 삭제·재삽입으로 fixture 작성 코드를 고쳐 최종 전체 실기를 통과했다.

0.2.3 이전 MSI는 경로를 기록하지 않았으므로 새 MSI가 과거 제거 코드를 소급 고칠 수 없다. 기존 사용자 지정 설치는 **원래 MSI와 INSTALLFOLDER를 명시하여 제거한 뒤** 새 후보를 설치한다. 경로가 불명확하거나 이미 여러 위치에 파일이 생겼다면 설치 로그·바로가기를 먼저 확인하며 일괄 삭제하지 않는다.

시험 설치는 모두 제거했으며 과거 실패의 artifacts와 사용자 데이터는 유지했다. BookMark의 `scripts/test-install-location.ps1`, `docs/evidence/install-location-2026-09-27/README.md`, 설치 안내·결정 기록에 재현 방법과 제한을 함께 보관한다. 한글 IME·실제 창 전환·작업 재개·재부팅은 여전히 별도 검증이다.
