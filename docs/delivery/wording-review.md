# 사용자가 읽는 문구 점검

상태: 로컬 수정 · 날짜: 2026-09-16 · 책임 역할: 문서·제품 담당

## 무엇을 고쳤나요?

처음 읽는 사람이 바로 할 일을 찾을 수 있도록 공개 안내 14개 페이지와 FolderState 문구를 고쳤습니다. 제목, 설명, 표의 각 칸, 버튼, 도움말, 오류를 나눠 검토했습니다.

| 고치기 전 | 고친 뒤 | 바꾼 이유 |
|---|---|---|
| 최소 도입 | 업무 하나로 시작하기 | 시작할 대상을 바로 알려 줍니다. |
| 업무 컨테이너 | 이번 업무의 자료를 모은 폴더 | 외워야 하는 새 용어를 줄입니다. |
| MASTER 키트 | 복사해서 쓰는 기본 폴더(MASTER) | 실제 이름을 유지하고 사용 방법을 먼저 설명합니다. |
| 업무 사건에 정리를 붙인다 | 일을 시작하거나 끝낼 때 정리하기 | 정리할 시점을 알려 줍니다. |
| 미착수 | 시작 전 | 상태를 일상적인 말로 표현합니다. |
| 이슈 | 확인 필요 | 확인이나 결정이 필요한 상태임을 알려 줍니다. |
| 상태 초기화 | 상태 표시 지우기 | 버튼을 누른 결과를 설명합니다. |
| 상태 아이콘 복구 | 아이콘 다시 표시 | 저장된 상태로 아이콘을 다시 설정함을 설명합니다. |
| 로컬 로그 열기 | 작업 기록 열기 | 사용자가 찾아볼 내용을 말합니다. |

공개 안내의 기본 순서는 **자료를 둘 곳 정하기 → 기본 폴더 복사하기 → 이번 업무 진행하기 → 끝난 업무 보관하기**입니다. 회신 누락, 업무 전달, 자동화 안내는 불편이 반복될 때 찾아보도록 했습니다. 문서 전체를 먼저 공부해야 시작할 수 있는 구조를 줄였습니다.

프로그램은 **폴더 선택 → 상태 선택** 순서를 화면에 표시합니다. 상태 버튼을 누르면 바로 저장된다는 설명을 넣었습니다. 아이콘 저장 위치는 선택 사항으로 접어 두고, 바꾼 위치가 언제 적용되는지 적었습니다.

## 문구를 하나씩 보는 방법

저장소에서 아래 명령을 실행합니다. 문서 빌드에 쓰는 Python 환경을 사용하세요.

```powershell
python scripts/review-wording.py --base HEAD
```

결과는 공개 사이트에 포함되지 않는 `artifacts/wording/`에 생깁니다.

| 파일 | 내용 |
|---|---|
| `before.md` | 고치기 전 문구를 하나씩 분리한 목록 |
| `after.md` | 고친 뒤 문구를 하나씩 분리한 목록 |
| `changes.md` | 출처별 변경 전후 비교 |
| `items.json` | 출처·종류·본문을 담은 재사용 가능한 목록 |

각 목록에는 출처 파일과 문구 번호가 있습니다. 번호는 해당 추출본 안의 위치입니다. 문장을 나누거나 옮긴 곳은 변경 묶음으로 비교하며, 관련 없는 문장을 임의로 일대일 대응시키지 않습니다. 나중에 다시 비교할 때는 `items.json`에 기록된 `base_commit`을 `--base`에 넣습니다.

추출 범위는 공개 안내, README, 업무 양식, 프로그램 화면·메시지, 설치 화면, 탐색기 메뉴, 오프라인 도움말입니다. 이미지 안의 글자, 실행 중 생기는 경로·날짜·외부 오류 내용은 자동 추출하지 않습니다. 원본 명세와 과거 검증 기록, 참고용 PPTX, 별도 `ExcelE2E-20260914/` 작업 폴더는 이번 수정 대상이 아닙니다.

## 기존 동작과의 관계

사용자가 보는 상태명만 바꿨습니다. 저장 값 `todo / doing / done / issue`, 명령 `reset / repair`, 파일 형식, 업무파일 보호, 설치 권한은 유지합니다. 예전 버전의 안내와 새 이름의 관계는 FolderState 사용 안내에도 남겼습니다. 구체적인 대응은 [요구사항 대응표](../tools/folderstate/traceability.md)를 확인하세요.

‘시작 전’은 상태를 저장합니다. ‘상태 표시 지우기’는 저장한 상태를 지웁니다. 두 행동을 같은 뜻으로 쓰지 않습니다. 다른 프로그램에서 바꾼 설정을 보호하는 기존 동작도 유지합니다.

회사별 저장 위치·보관 기간·권한 등은 계속 제안 또는 미확정으로 표시합니다. 이번 문구 변경으로 회사 규칙이 승인되거나 새로운 기능이 구현된 것으로 표시하지 않습니다.

## 확인 방법과 남은 일

자동 검증과 화면 확인 결과는 [검증 기록](verification.md)에 남깁니다. 문서·화면 검토가 실제 사용자 이해도 시험을 대신하지는 않습니다.

이번 검증에서는 엔진 시험 27개, 문서 빌드와 공개 범위·링크 검사, PC·모바일 화면 확인, WPF 화면 렌더, MSI 구조 검사를 통과했습니다. 수정 전 1,492개와 수정 후 1,966개의 문구 단위를 분리했습니다. 새 설치 파일은 로컬 `artifacts/release/FolderState-0.1.0-win-x64.msi`에 있으며, 서명 없는 평가용입니다. 실제 설치 시험과 웹 게시를 이번에 다시 수행하지는 않았습니다.

처음 사용하는 사람에게 아래 일을 설명 없이 해 보게 하면 다음 수정점을 찾을 수 있습니다. 별도 전문용어 시험은 필요하지 않습니다.

1. 새 자료를 둘 위치를 찾습니다.
2. 반복 업무 하나를 기본 폴더에서 복사해 시작합니다.
3. 시험용 폴더를 ‘진행 중’으로 표시하고, 확인할 문제가 생긴 상태로 바꿉니다.
4. ‘시작 전’과 ‘상태 표시 지우기’ 중 목적에 맞는 버튼을 고릅니다.
5. 일이 끝난 뒤 자료를 보관할 위치와 아직 남은 일을 확인합니다.

읽다가 멈춘 문구, 예상과 달랐던 버튼 결과, 도움을 요청한 지점만 적습니다. 실제 사용자 대상 시험은 아직 하지 않았습니다.
