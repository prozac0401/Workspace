# GitHub Pages 운영

문서 주소: [Workspace 운영 기준](https://prozac0401.github.io/Workspace/)

## 원본과 게시

docs/의 Markdown과 mkdocs.yml을 편집합니다. main 반영 후 문서 워크플로가 strict 빌드와 공개 범위·링크 검사를 통과하면 GitHub Pages용 정적 파일을 배포합니다. 저장소 Settings → Pages의 Source는 GitHub Actions로 설정합니다.

워크플로 파일을 추가한 것만으로 게시 완료로 간주하지 않습니다. Actions의 성공과 실제 URL의 HTTP 응답·문서 내용을 확인합니다. 계정 로그인이나 Pages 설정 권한이 없는 환경에서는 설정 안내와 빌드 결과를 남깁니다.

## 검토 범위

GitHub Pages에는 업무 운영 정책과 FolderState 사용법만 게시합니다. 빠른 판단 기준·10대 기본원칙·도입 순서와 조직별 결정 목록은 업무 정책의 일부로 포함합니다. 메뉴는 시작 → 기본 운영 → FolderState → 운영 개선(선택)으로 구분하며, 고급 개선안을 기본 도입의 선행 조건으로 두지 않습니다. 개발 정책·원문 명세·설계·양식·배포·검증 기록과 assets/help.html·assets/verification.json은 게시하지 않습니다. 문서 원본은 삭제하지 않고 저장소에서 관리합니다. 공개 Git 저장소의 파일과 이력 자체는 계속 열람 가능하며, Pages 제외는 접근 통제가 아닙니다.

mkdocs.yml의 exclude_docs는 전체 파일을 제외한 뒤 지정한 문서와 검토한 자산 8개(CSS, FolderState 화면, PPTX에서 추출한 WebP 6개)만 허용합니다. PPTX 원본은 사이트에 복사하지 않으며, 이미지의 출처와 변환 내역은 [검증 기록](verification.md)에 남깁니다. 메뉴에서만 숨기는 방식은 사용하지 않습니다. 공개 페이지의 개발 문서 링크와 저장소·편집 바로가기도 제거했습니다. 사용자에게 필요한 평가판·지원 환경 제한은 설치 안내에 남깁니다. DEC-020의 제품 게시자·서명 결정은 [품질 기준](quality.md)에서 계속 관리합니다. 공개 업무 결정 목록에는 이관·번호 유지 표시와 설치 안내 링크만 남겨 누락 오해를 방지합니다.

로컬 업무 경로·메일·명단·사용자 로그·인증서·설치 진단 파일은 포함하지 않습니다. site/ 출력 전체가 공개된다는 기준으로 검토합니다.

업무효율화의 확장 순서는 Work Inbox·업무 지식·자동화·Agent의 선택 적용을 설명하는 공개 운영 정책입니다. 실제 업무 기록이나 조직별 AI 설정은 게시하지 않습니다.

## 게시 전 검사

```powershell
python -m mkdocs build --strict
python scripts/check-site.py site
```

검사기는 공개 14개 페이지와 404 이외의 HTML, 제외한 원본 자산의 복사, 비공개 문서의 검색·사이트맵 노출, 깨진 로컬 링크를 실패로 처리합니다. 공개 문서 추가 시 설정과 검사기의 명시 목록을 함께 검토합니다. 기존에 노출된 개발 문서 주소는 새 배포 후 404가 되어야 합니다. 검색엔진이나 브라우저의 과거 캐시 삭제까지 보장하지 않습니다.

## 운영

오류가 있으면 이전 정상 문서 원본 커밋으로 되돌려 빌드합니다. 생성된 HTML만 직접 편집하지 않습니다. 제품 릴리스와 문서 게시를 연결하되 미검증 상태를 숨기지 않습니다.
