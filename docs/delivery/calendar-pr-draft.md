# PR 설명 · 정적 달력 통합

제목: Workspace에 1983~2099년 달력과 KASI 정적 데이터 파이프라인 통합

## 변경

Workspace 다음 최상위 탭에서 1983~2099년 중 연도와 공식/수동 휴일을 설정하고, 같은 불변 모델로 미리보기와 편집 가능한 XLSX를 한 해씩 받습니다. 전달된 날짜/미리보기/ZIP·OOXML 코드를 재사용하며 브라우저는 상대 경로의 공개 JSON만 읽습니다. 이전 서버 proxy와 메모리 캐시는 서버 없는 일일 수집 구조로 바꿉니다.

공식 데이터가 없거나 준비되지 않은 해를 빈 공휴일로 취급하지 않습니다. 24시간 이후는 명시적 stale 동의, 30일 초과는 공식 다운로드 차단을 적용합니다. 수동 개인/회사 입력을 보존하고 공식 휴일과 구분합니다. 설정 변경 중 다운로드와 이전 연도 응답 적용을 차단합니다.

기존 docs workflow 하나에 검증→수집/재사용→calendar-data 저장→고정 SHA 빌드→Pages 배포를 연결합니다. 검증된 JSON 한 파일만 영속 브랜치에 보관하고 부분 실패 시 이전 연도의 성공 시각과 내용을 유지합니다. 실제 수집 오류는 기본 배포 skip이며, 데이터 저장 후 배포 실패도 다음 실행에서 같은 SHA로 복구합니다. 처음 조회한 optional 연도가 정상 0건이면 미제공 상태로 명시하며 현재 해가 이번 수집에 성공하고 실제 오류가 없을 때 게시할 수 있습니다. PR에는 Secret/데이터 쓰기/배포 권한을 주지 않습니다.

117개 연도×12개월의 기본 요청은 1,404회이며 재시도를 포함해 실행당 2,000회로 제한합니다. 전체 범위의 자료 제공을 보장하지 않습니다. schemaVersion 2가 연도별 준비 상태와 성공 시각을 보존합니다.

## 운영 활성화와 남은 확인

사용자가 Secret을 직접 등록했고 Pages/Actions/github-pages 설정을 확인했습니다. 2026-10-11 후속 요청에서 원격 반영·최초 실제 수집·배포를 승인했습니다. `CALENDAR_ENABLED`는 미설정이면 운영 job을 막습니다. PR 검사 후 main 반영, 활성화 변수 등록, 최초 collect/initialize dispatch 순서로 진행하며 실제 수집 성공 전에는 첫 배포를 하지 않습니다. 실행 결과는 이 PR의 후속 기록에 source/data SHA와 함께 남깁니다.

PR 작성 시점에 실제 KASI 수집·원격 CI·Pages 배포 후 검증은 실행 전입니다. 실제 계정 할당량·사용량은 미확인이고 custom domain은 없음으로 확인했습니다. LibreOffice·종이 인쇄는 NOT RUN입니다. 기존 24h/30d 기준을 유지하므로 스케줄 지연 시 stale 동의가 필요합니다. 운영 절차와 데이터 복구는 [README](../../tools/calendar/README.md), 후속 검증은 [운영 기록](calendar-publication-20261011.md)에 있습니다.
