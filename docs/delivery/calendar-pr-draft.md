# PR 설명 초안 · 원격 PR 미생성

제목: Workspace에 정적 달력과 검증된 KASI 데이터 파이프라인 통합

## 변경

Workspace 다음 최상위 탭에서 연도·공식/수동 휴일을 설정하고 같은 불변 모델로 미리보기와 편집 가능한 XLSX를 받습니다. 전달된 날짜/미리보기/ZIP·OOXML 코드를 재사용하며 브라우저는 상대 경로의 공개 JSON만 읽습니다. 이전 서버 proxy와 메모리 캐시는 서버 없는 일일 수집 구조로 바꿉니다.

공식 데이터가 없거나 준비되지 않은 해를 빈 공휴일로 취급하지 않습니다. 24시간 이후는 명시적 stale 동의, 30일 초과는 공식 다운로드 차단을 적용합니다. 수동 개인/회사 입력을 보존하고 공식 휴일과 구분합니다. 설정 변경 중 다운로드와 이전 연도 응답 적용을 차단합니다.

기존 docs workflow 하나에 검증→수집/재사용→calendar-data 저장→고정 SHA 빌드→Pages 배포를 연결합니다. 검증된 JSON 한 파일만 영속 브랜치에 보관하고 부분 실패 시 이전 연도의 성공 시각과 내용을 유지합니다. 수집 실패는 기본 배포 skip이며, 데이터 저장 후 배포 실패도 다음 실행에서 같은 SHA로 복구합니다. PR에는 Secret/데이터 쓰기/배포 권한을 주지 않습니다.

## 운영 활성화와 남은 확인

**구현 완료, 미배포.** `CALENDAR_ENABLED`는 미설정이면 운영 job을 막습니다. 원격 data branch/Secret/권한/Pages 설정은 바꾸지 않았습니다. 사용자 Secret 등록, 관리자 설정 검토, 병합과 활성화, 최초 dispatch/배포는 별도 승인 단계입니다. 첫 승인 실행 전에는 기존 Pages를 유지합니다.

실제 KASI 계정·할당량·원격 CI·Pages 배포 후 검증, LibreOffice·종이 인쇄는 NOT RUN입니다. 현재 custom domain/계정 사용량은 미확인입니다. 기존 24h/30d 기준을 유지하므로 스케줄 지연 시 stale 동의가 필요합니다. 운영 절차와 데이터 복구는 [README](../../tools/calendar/README.md)에 있습니다.
