# 선택범위 내보내기 · Undo 조사와 수정 검증

기록일: 2026-09-26 · 대상 수정 버전: 0.1.0-rc.10 · 서명 없는 평가판

제품 책임: 도구 개발·검증 담당

관련 문서: [원작업지시](../tools/excel-selection-export/specification.md), [인수 대응표](../tools/excel-selection-export/acceptance.md), [ADR-0018](../design/0018-excel-selection-export-undo.md), [rc.9 평가 기록](excel-selection-export-evaluation-20260924.md)

## 문제와 판정 범위

rc.9 실제 메뉴 시험에서 내보내기 전에 활성화됐던 원본 편집의 Undo가 내보낸 뒤 비활성화됐다. 원본 값·수식 전후 동일 검사와 다른 부작용이다. 당시 시험은 여러 편집의 전체 Undo·Redo 순서를 확인하지 않았으므로, 내부 기록의 삭제 범위·개수를 확정한 시험으로 설명하지 않는다. 사본에 원본의 이력을 넘기는 기능도 요구하지 않는다.

사용자는 원인 조사와 수정을 요청했다. 이 기록은 원인 분리용 실측, 수정 설계, rc.10 완성 제품의 검증을 구분한다. rc.9의 실패와 미실행 기록을 소급해 통과로 바꾸지 않는다.

## 원인 분리 실측

아래 결과는 각 단계의 합성 원본 Undo 활성 여부를 실제 비교한 것이다. 특정 COM 호출이 원본 인스턴스의 Undo를 비활성화하는지 확인하며, 전체 제품 검증을 대체하지 않는다.

| 단계·동작 | 관찰 결과 | 판정 |
|---|---|---|
| 원본에 실제 UI 편집 | Undo 활성 | 기준 상태 확인 |
| Interactive·ScreenUpdating·EnableEvents 변경 | Undo 활성 유지 | 이 조사에서 단독 원인 아님 |
| 같은 인스턴스의 Workbooks.Add(-4167) | Undo 활성 유지 | 빈 통합문서 생성만으로 현상 재현 안 됨 |
| 새 결과 worksheet.Name 대입 | Undo 활성 → 비활성 | 현상 재현 |
| 시트 이름 대입을 제외한 뒤 Normal.Font.Name 대입 | Undo 활성 → 비활성 | 서식 쓰기에서도 재현 |
| 시트 이름·기본 글꼴 대입을 모두 제외한 뒤 셀 기록 | Undo 비활성 | 해당 두 속성 제거만으로 해결되지 않음 |
| 완성한 .xlsx를 원본 Workbooks.Add(template)로 새 결과 생성 | Undo 활성 유지 | 출력 분리 방식의 근거 |

원인은 사본의 Undo 기록을 만들기 위해 원본 이력을 일부 소비한 것이 아니다. 같은 Excel 인스턴스에 결과 내용을 COM으로 쓰는 경로가 원본의 기존 실행 취소를 사용할 수 없게 만들었다. Excel 내부 기록이 전부 삭제됐는지에 대한 추측과, 실제 Undo가 비활성화된 관찰을 구분한다.

## 수정 내용

원본 선택을 값·허용 서식 DTO로 읽은 뒤 별도 숨김 Excel에서 기존 writer로 결과를 작성하고 검증한다. 검증된 결과를 사용자 임시 폴더의 제품 전용 GUID 경로에 .xlsx로 저장한다. 작업용 문서를 닫고 전용 Excel을 정상 종료한 뒤, 원본 인스턴스의 Workbooks.Add(template)로 저장 전 새 결과를 만들고 값을 다시 검증한다. 임시 파일을 정리하고 결과를 표시한다.

원본 인스턴스에는 결과의 셀·서식·시트 이름을 쓰지 않는다. 템플릿 결과의 Saved 상태를 false로 표시하는 설정만 허용해 닫을 때 Excel의 보통 저장 확인이 나오게 한다. 사용자 메뉴와 저장 흐름은 같다. 최종 결과는 같은 원본 Excel 인스턴스의 시트 한 개·Path가 빈 새 문서다. 중간 파일이 로컬 임시 폴더에 생기는 변경과 강제 종료 시 잔존 가능성을 사용 안내에 명시했다. 세부 선택 이유·실패 복구 경계는 ADR-0018에 남긴다.

## rc.10 후보 시험에서 발견한 추가 수정

첫 실제 메뉴 후보 시험에서 템플릿으로 만든 결과는 Path가 비었지만 Saved=true여서 exported 검사가 실패했다. 저장하지 않은 새 결과임에도 닫을 때 저장 확인을 생략할 수 있는 문제다. 새 결과의 Saved=false를 설정하는 분리 프로브에서는 원본 Undo가 계속 활성화됐다. 이 설정 후 문자열·숫자·수식 편집을 Undo 세 번과 Redo 세 번으로 되돌리는 8개 체크포인트·110개 검사를 통과했으며, 원본 값·수식과 내보낸 사본의 고정된 내용도 확인했다.

이 110개 검사는 후보 시험 중 플래그를 보완한 결과다. 수정 전 후보의 첫 실패와 함께 기록하며 최종 설치 제품 전체 통과로 집계하지 않는다. 최종 소스에 새 결과의 Saved=false 설정을 반영하고 재빌드·설치한 뒤 같은 실제 메뉴 시험을 다시 실행했다. 최종 설치본의 8체크포인트·110개 검사는 모두 통과했으며 아래에 후보와 별도로 기록한다.

Saved=false 수정 후 첫 설치 패키지의 API 기능 시험에서는 결과가 자동 활성화되지 않아 실패했다. 제품의 지연 완료 콜백에서 결과를 Activate한 뒤 정확한 결과 창 Hwnd에 전면 표시를 요청하고, Application.ActiveWindow.Hwnd가 같은지 확인하도록 보완했다. 이 API 확인은 Excel 내부 활성 창을 증명하며 OS 전면 표시는 실제 UI 관찰과 구분한다. 이 보완을 포함한 재빌드·설치를 마친 뒤 11사례·930개 API 검사를 모두 통과했다. 첫 실패는 출력 데이터 오류와 구분해 남긴다.

| 완전 제거·전체 공존·회사 정책·서명·배포 승인 | NOT_RUN | 기존 인수 제한 유지 |

Undo 회귀 시험은 UI로 A1에 History-A, B1에 314, B2에 =B1+1을 순서대로 편집하고 A1:B2를 선택한 뒤 시작한다. UndoHistoryTests의 before 검사 → 실제 메뉴 실행 → 원본으로 돌아와 exported 검사 → Ctrl+Z 세 번 각각 undo1~undo3 검사 → Ctrl+Y 세 번 각각 redo1~redo3 검사를 수행한다. 최종 시험에서 원본 값·수식의 정확한 역순/정순 변화, Undo·Redo 활성 상태, 내보낸 결과의 고정된 내용, 동일 인스턴스·빈 결과 Path·Saved=false를 확인했다. 검사 도구는 읽기 전용이며 직접 셀을 쓰거나 Undo·Redo를 실행하지 않는다.

후보 소스의 API 시험 뒤에도 창 없는 원본 시험용 Excel이 남았다. 각 합성 fixture 표식·PID·실행 명령·Excel 실행 파일·표시 창 없음을 확인한 빈 시험용 프로세스만 별도 정리했다. 업무용 Excel은 정리 대상이 아니다. 숨김 작업용 Excel은 정상 종료했고 제품 임시 파일은 남지 않은 것을 확인했으므로, 두 종료 경로를 합쳐 통과나 실패로 판정하지 않는다.

최종 설치본에서도 ExcelProbe close 종료0 뒤 원본 시험용 Excel의 빈 프로세스 잔류를 확인했다. 정확한 PID·Excel 실행 파일·합성 fixture 실행 명령·표시 창 없음을 확인한 해당 빈 시험프로세스만 명시적으로 정리하고 종료를 확인했으며 final-source-close.txt·final-cleanup.json에 기록했다. 작업용 Excel은 강제 종료 없이 정상 종료했다.

원본 값·수식 보존, Undo 보존, 결과 서식 보존, 작업용 프로세스 종료, 원본 Excel 자연 종료는 각각 별도 판정이다. 원본 API 종료 제한은 미해결이며 rc.9의 관련 FAIL을 해소됐다고 표시하지 않는다.

최종 제품 증거는 artifacts/selection-export/undo-20260926에 보관한다. 실제 UI 각 시점의 로그는 final-history-before/exported/undo1~3/redo1~3.txt이며, 기능 시험은 final-api.txt, 출력단계 취소는 final-output-cancellation.txt, 설치는 rc10-final-install.json, 해시는 final-artifact-hashes.json, 제품 빌드 입력15개 대조는 final-build-input-verification.json이다. 로그 원문과 실제 사용자 절대 경로는 공개 문서에 복사하지 않는다.

문서 검증 로그는 artifacts/selection-export/rc10-docs의 build.txt·links.txt·source-links.json에 보관한다. 문서 확인은 제품의 Undo·기능·설치 시험을 대신하지 않는다.
