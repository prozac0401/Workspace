# 처음 도입하는 순서

**정리가 일이 되지 않도록 현재 업무 한 회차부터 시작합니다.** 이미 사용 중이고 지금 판단만 필요하다면 [빠른 판단 기준](quick-reference.md)을 보세요.

## 최소 도입

| 단계 | 실제 행동 | 완료 기준 |
|---|---|---|
| 1. 위치 결정 | 조직이 허용한 Work 루트와 공식 원본·권한·백업 담당을 정합니다. | 필요한 조직 설정을 내부 [결정 기록](policies/decisions.md)에 남김 |
| 2. 기본 구조 | Inbox, Active, Operations, Reference, Archive, Temp와 메일 Inbox / Action / Archive를 만듭니다. | 위치별 용도를 구분할 수 있음 |
| 3. MASTER 준비 | 과정운영·비용처리 중 실제 반복하는 업무부터 표준 틀을 만듭니다. | 실데이터 없이 복사할 수 있고 단계 상태는 미착수로 유지됨 |
| 4. 한 회차 시범 | MASTER를 Active로 복사하고 회차명·기본정보·일정을 입력합니다. | 현재 자료·다음 마감·담당·결정 이유를 찾을 수 있음 |

폴더별 용도는 [기본 구조와 원본](policies/workspace.md), MASTER와 운영현황은 [업무 키트와 일정](policies/kits.md)을 따릅니다. 이미 사내 시스템에 일정·담당·결정 기록이 있다면 원본 링크로 연결합니다.

과거 자료 전체를 다시 분류하지 않습니다. 도입 기준일 이전 자료는 기존 위치를 유지하고 실제 재사용하는 자료부터 새 구조에 편입합니다. Projects와 Waiting은 필요할 때 추가합니다.

## 이후에는 업무 사건에 붙입니다

정리를 위한 별도 시간을 만들기보다 업무를 처리하는 순간 필요한 위치와 상태만 바꿉니다.

| 업무 사건 | 그때 할 일 |
|---|---|
| 새 반복 업무 발생 | 미착수 상태의 MASTER를 복사해 Active에서 시작 |
| 단계 착수 | 해당 단계만 진행 중으로 표시 |
| 진행을 막는 문제 발생 | 이슈로 표시하고 필요한 결정·이유를 기존 Issues에 기록 |
| 단계 완료 | 필요한 결과물·승인·전달 확인 후 완료로 표시 |
| 회차 종료 | 미완료·이슈와 보관 조건 확인 후 전체를 Archive로 이동 |

위 상태 표시는 FolderState를 사용하는 경우의 수동 행동입니다. 업무파일 변경이나 메일 수신에 따라 자동 실행되지 않습니다. 매일 Inbox 비우기나 매주 전체 폴더 정리는 기본 도입 조건이 아닙니다. 실제 업무 마감·회신 확인과 조직에서 정한 백업·보존 점검 일정은 유지합니다.

## 필요가 확인되면 추가합니다

- **단계 상태를 찾기 어렵다면** 시험용 폴더에서 [FolderState 설치·초기화·복구](tools/folderstate/index.md)를 확인한 뒤 도입합니다. 상태를 표시하는 MASTER는 항상 `todo`로 유지합니다. 미사용 MASTER에 상태 파일을 미리 만들 필요는 없습니다.
- **한 회차 또는 약 한 달을 사용한 뒤** 찾기 실패·중복 기록·불필요한 분류·놓친 확인사항만 기존 회고에 남깁니다. 이는 도입 효과 확인이며 정기적인 전체 재정리 절차가 아닙니다.
- **회신 누락·인수인계 문제가 반복된다면** [운영 개선안 — 선택 적용](policies/folder-workflow.md)에서 해당 항목만 고릅니다. 기본 운영을 시작하기 위한 선행 조건은 아닙니다.
