# 보이는 칸 붙여넣기 — Codex 개발 작업지침

- 문서 버전: 1.0
- 작성일: 2026-09-24
- 제품명: **보이는 칸 붙여넣기**
- 내부 식별자: `VisibleCellsPaste` / `VCP`
- 문서의 성격: 구현·설치·제거·시험을 지시하는 개발 명세. 프로그램을 이미 구현하거나 실제 Excel에서 검증했다는 보고서가 아니다.

> **선택한 범위 밖으로 나가지 않고, 숨겨진 칸에 쓰지 않고, 복사한 순서대로만 넣는다.**
>
> 사용자는 한 번 설치한 뒤, 평소처럼 Excel을 실행하고 `Ctrl+C → 대상 범위 선택 → 우클릭 → 보이는 칸에 붙여넣기`만 수행한다. VBA 편집기 열기, 모듈 가져오기, 매크로 직접 실행, 매번 추가 기능 열기는 사용자 절차에 포함하지 않는다.

## 1. 이번 작업의 목표와 작업 원칙

이 문서를 읽고 **설계 설명만 제출하지 말고**, 현재 작업공간에서 독립 제품의 구현, 테스트, 배포 구성, 사용자 안내까지 진행한다. 작업공간의 `AGENTS.md` 등 상위 개발 지침은 함께 준수한다.

### 1.1 제품 경계

- 명단대조기, FileListToExcel, 선택 범위 내보내기와 **별도의 설치·제거·릴리스 단위**로 개발한다.
- 현재 작업공간이 WORKSPACE 모노레포라면 기존 디렉터리 관례에 맞는 독립 하위 프로젝트로 만든다. 다른 도구가 설치되어야 실행되는 종속 제품으로 만들지 않는다.
- 기존의 배포·로깅·메뉴 등록 코드를 재사용할 수 있지만, 다른 제품의 메뉴·설치 식별자·설정·실행 취소 기록은 공유하지 않는다.
- 기존 소스와 작업 중인 변경 내용을 먼저 확인한다. 사용자 변경 사항을 덮어쓰거나 다른 프로젝트를 정리하지 않는다.
- 별도 지시 없이 원격 저장소 생성, push, 배포 사이트 변경, 공개 릴리스 발행은 하지 않는다. 로컬 산출물과 검증 결과를 완성한다.

### 1.2 최우선 요구사항

1. 숨겨진 행과 선택 범위 밖의 셀 내용·수식을 직접 수정하지 않는다.
2. 복사 항목 수와 대상의 보이는 셀 수가 다르면 **0개 수정**으로 중단한다.
3. 복사한 순서와 빈 항목의 위치를 유지한다. 이름·사번 매칭, 정렬, 빈칸 제거, 개수 맞추기를 하지 않는다.
4. 설치 후 Excel을 정상 실행했을 때 메뉴와 이벤트 처리가 자동으로 준비된다.
5. 실행 중 오류의 복구와 최근 한 번의 사용자 되돌리기를 구현한다.
6. 실제 Windows Excel에서 설치→정상 시작→실행→재시작→제거를 검증한다. 시험하지 않은 것은 `미검증`으로 보고한다.

이 문서의 요구사항을 충족하기 어려운 부분은 조용히 삭제하지 않는다. 기술 검증 결과, 재현 절차, 제한 사항과 남은 작업을 남긴다. 실행 환경이 부족해도 가능한 소스·자동화·문서 작업은 진행한다.

## 2. 사용 시나리오와 UI

### 2.1 대표 시나리오

원본에서 한 열의 `85, 90, 78`을 복사한다. 대상 Excel에서는 2·5·8행만 필터에 남아 있다. 사용자가 `E2:E8`을 선택하고 선택 영역 안에서 우클릭하여 실행한다.

| 셀 | 상태 | 결과 |
|---|---|---|
| E2 | 보임 | 숫자 85 입력 |
| E3:E4 | 숨김 | 기존 내용·수식 유지 |
| E5 | 보임 | 숫자 90 입력 |
| E6:E7 | 숨김 | 기존 내용·수식 유지 |
| E8 | 보임 | 숫자 78 입력 |

스크롤 밖에 있어도 선택 범위 안에서 숨김 처리되지 않은 셀은 대상이다. **‘보이는 칸’은 현재 화면의 뷰포트가 아니다.**

### 2.2 메뉴 문구

셀 우클릭 메뉴에 다음 두 명령을 제공한다.

- `보이는 칸에 붙여넣기`
- `마지막 붙여넣기 되돌리기`

도움말은 제품의 별도 작은 메뉴나 추가 기능 탭에 둘 수 있지만, 정상 사용에 도구 창을 열도록 강제하지 않는다. 필수 설정 창, 원본 등록 버튼, 방향 선택, 붙여넣기 모드 선택은 만들지 않는다.

### 2.3 정상 경로와 확인 창

정상적인 소량 작업에는 실행 전 미리보기나 완료 확인 버튼을 강요하지 않는다. 성공 시 상태 표시줄 등에 `보이는 17칸에 붙여넣었습니다.`처럼 알린 뒤 기존 상태로 되돌린다.

다음에만 확인 창을 띄우고, 사유가 겹치면 **한 창으로 합친다.**

- 기존의 일반 수식을 값으로 덮어쓰는 경우.
- 원본 빈칸 때문에 내용이 있는 대상 셀을 비우는 경우.
- 6절의 대량·다중 구간 경고 조건에 해당하는 경우.

일반적인 기존 상수 값 덮어쓰기는 보통의 붙여넣기처럼 동작한다. 오류·제한 안내에는 항상 **변경 여부**를 명시한다.

### 2.4 매칭 기능이 아님을 안내

도움말과 경고 설명에 다음을 포함한다.

> 복사한 순서대로 입력합니다. 이름이나 사번을 찾아 연결하지 않습니다. 원본과 대상의 개수가 같아도 사람의 순서까지 일치한다는 뜻은 아닙니다.

| 구분 | 요구사항 |
|---|---|
| 환경 | Windows 데스크톱 Excel. 개발 PC의 Office 버전·빌드·비트 수를 기록한다. |
| 복사 출처 | Excel에서 일반 복사한 한 행 또는 한 열의 셀 데이터. 단일 셀 포함. |
| 원본 방향 | 한 열이면 위→아래, 한 행이면 왼쪽→오른쪽. |

| 대상 내용 | 일반 상수·일반 수식은 덮어쓸 수 있다. 수식 덮어쓰기는 사전 확인한다. |
| 필터 상태 | 필터 조건, 정렬 순서, 행·열 숨김 상태를 변경하지 않는다. |
| 저장 | 대상 통합문서를 자동 저장하지 않는다. 원본 파일도 수정·저장하지 않는다. |
| 되돌리기 | 해당 Excel 프로세스에서 최근 성공한 본 도구의 작업 1회. 엄격한 유효성 검사 필요. |

### 3.1 v1 제외 및 중단 조건

- 여러 행과 여러 열로 된 2차원 원본 표를 임의의 순서로 펴서 붙여넣는 기능.
- 가로 대상에 배치, 시작 셀에서 자동으로 대상 확장, 한 값을 여러 칸에 반복 채우기.
- 행 전체·열 전체·시트 전체 선택. `UsedRange`로 자동 축소해서 처리하지 않는다.
- 사용자가 Ctrl 등으로 직접 지정한 다중 영역 대상 선택. 단, **연속 선택에서 가시 셀을 구한 결과가 다중 영역인 것은 정상 지원**한다.
- 원본 또는 수정 대상의 병합 셀, 대상의 배열 수식/동적 배열 spill 범위, 피벗 결과 셀.
- 보호된 워크시트, 읽기 전용 통합문서, Protected View, 여러 시트 그룹 선택.
- 서식 있는 표의 헤더·합계 행 및 계산 열. 값만 담긴 표 데이터 영역은 아래 3.2 조건으로 지원한다.
- 외부 파일·그림·웹 페이지·메신저 텍스트의 일반 클립보드 입력. 확실하지 않은 입력을 Excel 셀 복사로 간주하지 않는다.
- 잘라내기 이동. `Ctrl+X`를 지원하지 않으며, 원본 제거·이동 완료 신호를 보내지 않는다.
- 데이터 유효성 검사 규칙의 자동 수정·자동 승인. v1은 수정 대상에 검증 규칙이 있으면 지원 제외 안내 후 중단한다.
- 공동편집이나 외부 자동화가 동시에 같은 셀을 수정하는 상황의 일관성 보장. 감지되면 중단하고, 감지가 완전하지 않다는 한계도 문서화한다.

불지원 상황을 만나면 대상 데이터를 건드리지 않고 이유를 안내한다. 32/64비트 등 구현상 호환성을 목표로 하더라도 실행 시험하지 않은 조합을 지원 검증 완료로 표시하지 않는다.

### 3.2 일반 범위와 서식 있는 표

일반 범위의 AutoFilter뿐 아니라 `ListObject.DataBodyRange`의 **값 열**에서도 시험한다. 표 계산 열 자동 채우기가 숨긴 행이나 선택 밖으로 번질 수 있는 구성을 v1에서 허용하지 않는다.

표의 계산 열 여부는 선택한 보이는 부분만 보고 판단하지 않는다. 같은 표 열의 다른 행에 수식이 있는 혼합 열도 보수적으로 제외한다. 표를 일반 범위로 변환하거나 사용자의 Excel 자동 고침 설정을 영구 변경해서 해결하지 않는다.

## 4. 값과 빈칸의 계약

### 4.1 보존할 의미

내부 항목은 적어도 다음 종류를 구분한다.

```text
Empty          실제 빈 셀
String         문자열, 빈 문자열 포함
Number         Excel 숫자 값
Boolean        논리 값
Error          Excel 오류 값
```

원본 수식은 원본 수식 문자열이 아니라 **계산 결과의 종류와 값**으로 다룬다. 수식을 다시 계산하거나 원본 통합문서를 강제로 갱신하지 않는다.

- 문자열 `00123`은 문자열 그대로 남아야 한다.
- 문자열로 저장한 긴 식별번호는 숫자로 바꾸지 않는다.
- 앞뒤 공백, 중복, 한글, 셀 내부 줄바꿈·탭을 보존한다.
- `=1+1`, `+001`, `@abc`처럼 수식으로 해석될 수 있는 문자열을 실행 가능한 수식으로 바꾸지 않는다. `Evaluate`를 사용하지 않는다.
- Excel 오류 값 `#N/A`와 문자열 `"#N/A"`를 구별한다.
- 진짜 빈 셀은 1개 항목이며 대응하는 대상 내용을 비운다. 가운데·처음·마지막 빈칸 모두 같다.
- 원본이 전부 빈칸이어도 행·열 개수가 확실하면 그 개수만큼 처리한다. 개수가 불명확하면 추측하지 말고 중단한다.
- 수식 `=""`의 결과는 빈 문자열 결과로 구분해 읽는다. 대상 Excel에서 이를 상수로 저장하는 실제 동작을 시험하고, 빈 셀과 완전히 구별해 저장할 수 없는 경우 그 한계를 명시한다. **항목 수와 위치는 절대로 바꾸지 않는다.**

문자열을 안전하게 쓰기 위해 임시로 표시 형식을 변경하는 구현을 사용한다면, 개별 원래 형식을 정확히 복구하고 글자·수식 여부를 다시 확인한다. 셀에 보이는 작은따옴표를 데이터로 추가하는 방식은 허용하지 않는다. 별도의 `문자 그대로` 모드는 만들지 않는다.

### 4.2 표시 모양과 실제 값은 다르다

`123`에 표시 형식 `00000`을 적용해 `00123`으로 보이는 숫자와, 실제 문자열 `00123`은 다르다. 본 도구는 **표시 화면을 복사하는 기능이 아니라 값 붙여넣기**다.

숫자는 숫자로 유지하며 날짜·시간 표시 셀은 기본적으로 Excel의 숫자 값 의미로 다룬다. `Range.Value2`는 Date/Currency 전용 형식 대신 숫자 값을 사용한다.[S03]

- 원본 표시 형식을 대상에 덮어쓰지 않는다. 따라서 날짜가 일반 숫자로 보일 수 있다.
- 1900/1904 날짜 체계가 다른 통합문서 간의 ‘달력상 같은 날짜’ 자동 변환은 v1 범위가 아니다. 임의로 날짜를 추정하거나 일수를 보정하지 않는다.
- 날짜 체계 차이와 대상 서식 차이에 대한 시험·안내를 제공한다. `모든 날짜를 동일하게 보존`했다고 광고하지 않는다.
- 텍스트의 `1-2`, `1,234`, `12%` 등을 현재 로캘로 추측 변환하지 않는다.

### 4.3 원본 필터의 책임 범위

도구는 **클립보드에 실제로 복사되어 있는 항목**을 입력으로 사용한다. 원본 워크시트를 다시 읽어 숨긴 행을 재분류하거나, 대상 개수에 맞춰 원본 항목을 줄이지 않는다.

원본도 필터된 사례를 반드시 시험한다. 클립보드에 들어온 실제 항목 수와 순서를 설명하고, 모양·빈칸 개수를 확정할 수 없으면 쓰기 전에 중단한다. 현재 활성 셀을 ‘아까 복사한 원본’이라고 가정해서 다시 읽는 것은 금지한다.

## 5. 기술 선택과 선행 검증

### 5.1 기본 구현 후보

기본 후보는 **독립 Excel 추가 기능 `.xlam` + 설치/제거 런처**다. 사용자 문서에 코드를 삽입하지 않고, 제작 환경에서 빌드된 완성 추가 기능을 배포한다.

- 내부적으로 VBA가 자동 실행되는 것은 허용한다. **사용자가 VBA를 직접 실행해야 하는 흐름은 금지**한다.
- 기본 제품 실행을 위해 Python, Node.js, 개발 SDK 또는 별도 서버 설치를 요구하지 않는다.
- Win32 API를 사용한다면 Office 32/64비트에 맞는 `PtrSafe`·포인터 선언과 버퍼 수명 관리를 적용한다.
- 필요 시 작은 보조 구성요소를 패키지에 포함할 수 있지만, 이유·라이선스·런타임 의존성·제거 방법을 기록한다.
- 기존 작업공간에 더 적합한 추가 기능 기반이 있으면 재사용 가능하다. `.xlam` 외 방식으로 변경할 때는 동등한 자동 로드·클립보드·되돌리기·설치 시험을 통과시키고 ADR에 근거를 남긴다.

사용자 요구는 특정 언어가 아니라 **자동 로드되는 작은 독립 도구**다. 기술 선택 때문에 사용 절차를 늘리지 않는다.

### 5.2 M0에서 먼저 증명할 두 가지

**A. 자동 로드**

설치→Excel을 평소 방식으로 새로 실행→셀 우클릭에서 자체 메뉴 확인까지 작은 시제품으로 증명한다. 테스트에서 `.xlam`을 미리 열거나 등록 매크로를 수동 호출해서 결함을 감추지 않는다.

**B. 클립보드 손실 없는 읽기**

다음 입력을 실제 Excel의 `Ctrl+C`로 복사하여, 다른 통합문서와 별도 Excel 프로세스에서도 순서·개수·값 종류를 읽을 수 있는지 증명한다.

```text
85 / 문자열 00123 / 빈칸 / 한글 및 셀 내부 줄바꿈 / 마지막 빈칸
```

숫자·문자열·수식 결과·마지막 빈칸을 보존하지 못하는 상태에서 메뉴부터 완성하고 핵심 구현을 뒤로 미루지 않는다. 단순 TSV 문자열 분할만으로 이 요구사항을 만족했다고 선언하지 않는다.

## 6. 크기 제한과 성능 기본값

다음은 **이 문서에서 정한 초기 설계값**이다. 실제 벤치마크 근거로 조정할 수 있지만, 제한을 없애거나 사전 경고 없이 대량 처리를 수행하지 않는다.

| 항목 | 초기값 |
|---|---:|
| 원본 항목/대상 보이는 셀 최대 수 | 50,000개 |
| 대상 선택 범위 검사 최대 크기 | 200,000셀 |
| 입력으로 읽을 클립보드 페이로드 합계 | 32 MiB |
| 보이는 연속 구간 최대 수 | 20,000개 |
| 대량 사전 경고 | 보이는 셀 5,000개 이상 또는 구간 1,000개 이상 |
| 동일 작업 중복 실행 | 금지 |

- `CountLarge` 등 큰 선택 범위의 크기를 안전하게 확인할 수 있는 방법을 사용한다. 전체 열의 셀을 하나씩 돌기 전에 거절한다.
- 크기·차원·XML/HTML 확장 인덱스를 확인한 뒤 메모리를 할당한다. 실제 페이로드보다 선언된 행 수가 터무니없이 큰 입력도 방어한다.
- 보이는 **연속 구간 단위**로 배열을 만들어 쓰되, 문자열·빈칸의 안전한 처리 때문에 구간을 더 나누는 것은 허용한다.
- COM 객체 접근은 Excel의 적절한 실행 스레드에서 수행한다. 병렬 스레드가 같은 Excel 객체를 동시에 수정하게 하지 않는다.
- 대량 작업은 검사/쓰기/복구 단계를 구별해 진행 상황을 보여준다. 쓸 때 취소하면 중간 결과를 성공으로 남기지 말고 복구 절차로 간다.
- 취소·메시지 처리 중에도 재진입을 막는다. 실행 중 다른 붙여넣기 명령은 거절한다.
- 이 숫자를 ‘Excel에서 보장되는 한계’나 ‘검증된 처리 속도’로 표현하지 않는다.

## 7. 대상 범위 확정 알고리즘

1. 명령 실행 시점의 Excel 인스턴스, 통합문서 객체, 워크시트 객체, 사용자가 선택한 범위를 확보한다.
2. 워크시트 셀 선택인지, 단일 시트인지, 연속 한 열인지, 전체 행·열 선택이 아닌지 먼저 검사한다.
3. 선택 크기 제한을 확인한다. 선택 범위를 `CurrentRegion`이나 `UsedRange`로 확장·축소하지 않는다.
4. 숨김·필터를 반영한 가시 셀을 구한다. Excel에서는 `SpecialCells(xlCellTypeVisible)`를 사용할 수 있다.[S01]
5. 반환 범위를 다시 원래 선택 범위와 교차시켜, **원래 선택 밖 주소가 들어갈 가능성을 제거**한다. 단일 셀 입력도 시험한다.
6. 대상 열 숨김, 행 숨김을 다시 확인하고 실제 행 번호 오름차순으로 정렬한다. `Areas`의 열거 순서만 신뢰하지 않는다.
7. 중복 주소, 다른 시트, 원래 선택 밖 주소가 하나라도 있으면 구현 오류로 중단한다.
8. 병합·보호·spill·피벗·표 계산 열·검증 규칙 등 제외 대상을 쓰기 전에 모두 확인한다.
9. 원본 항목 수와 대상 주소 수를 비교한다. 정확히 일치할 때만 다음 단계로 간다.
10. 확인 창을 거쳤다면 실제 쓰기 직전에 대상 객체·주소·가시 상태를 재검증한다. 달라졌으면 자동 재매칭하지 말고 중단한다.

개념 의사코드:

```text
selection = capture_current_user_selection()
validate_selection_shape_and_limits(selection)
visible = intersect(selection, get_visible_cells(selection))
targets = unique_cells_sorted_by_row(visible)
validate_no_target_outside_selection(targets, selection)
validate_all_destinations_before_write(targets)
require(source.items.count == targets.count)
```

주의: 다중 영역 Range에 2차원 배열을 한 번에 대입하는 방식은 사용하지 않는다. Microsoft는 다중 영역 배열 대입을 피하도록 안내한다.[S02]

우클릭한 한 셀로 기존 선택 전체를 잘못 축소하지 않는다. 반대로 사용자가 다른 곳을 우클릭해 선택이 실제 변경되었다면 오래된 선택으로 실행하지 않는다. 두 경우 모두 UI 시험이 필요하다.

## 8. 클립보드 어댑터 구현 지침

### 8.1 읽기 계약

```text
ClipboardSnapshot
  capture_id
  source_format
  clipboard_sequence
  source_rows
  source_columns
  shape_is_verified
  items[] : { kind, value }
  format_specific_evidence
```

- 사용자 통합문서 수정이나 임시 붙여넣기 **이전**에 복사 데이터를 불변 스냅샷으로 확보한다.
- 한 행/열/셀인지 신뢰성 있게 확인하고 방향을 결정한다. 다차원 입력을 조용히 평탄화하지 않는다.
- 시작·가운데·마지막 빈칸, 연속 빈칸, 전부 빈칸도 정확히 센다.
- 시스템 클립보드를 비우거나 새로운 내용으로 바꾸는 방식을 기본 경로로 사용하지 않는다.
- 읽기 중 내용이 바뀌었는지는 sequence 등으로 확인한다. 지연 렌더링도 고려해 짧고 제한된 재시도를 사용한다.[S09]
- 읽기가 끝난 뒤에는 메모리의 일관된 스냅샷을 사용한다. 실행 중 다른 앱에서 새로 복사한 내용을 옛 스냅샷으로 덮어쓰지 않는다.

### 8.2 형식 선택

Windows 클립보드에는 같은 자료의 여러 형식이 함께 있을 수 있다. 일반 텍스트만으로는 원본 자료형·구조를 잃을 수 있다.[S07]

1. 실제 Excel이 제공하는 구조화 형식을 조사하고, 선택 차원과 자료형을 보존하는 경로를 우선한다.
2. 등록 형식 `XML Spreadsheet` 등이 실제 제공된다면 조사 후보로 삼을 수 있다. **모든 Excel에서 항상 제공된다고 가정하지 않는다.** 관찰한 형식명·Office 버전·표본을 기록한다.
3. CF_HTML을 쓰면 등록 이름은 `HTML Format`이며 UTF-8과 **바이트 기준 offset**을 올바르게 처리한다.[S08] 셀 내부 줄바꿈을 행 경계로 오인하지 않는다.
4. HTML의 모양만으로 자료형을 추측하지 않는다. 필요한 타입·숫자·차원 메타데이터가 없으면 lossless 경로라고 부르지 않는다.
5. 일반 텍스트/TSV 보조 파서는 따옴표와 셀 내부 탭·개행을 처리할 수 있어야 한다. `Trim`, 빈 줄 제거, 마지막 개행 일괄 제거로 항목 수를 맞추지 않는다.
6. 구조화 입력을 해석할 수 없다고 일반 문자열로 자동 강등하여 쓰지 않는다. 숫자·문자열·빈칸 차원이 모호하면 **무변경 중단**한다.

Excel의 native 붙여넣기로 별도 임시 통합문서에 값을 풀어 읽는 방식을 선택할 수도 있지만, M0에서 클립보드 보존·자료형·끝 빈칸·다른 프로세스·포커스·실행 취소 영향까지 입증한 경우에만 채택한다. 사용자 통합문서의 빈 셀이나 숨긴 시트를 임시 공간으로 쓰지 않는다. 단순히 ‘숨김 통합문서면 부작용이 없다’고 가정하지 않는다.

XML은 외부 엔터티·DTD·네트워크 접근을 차단하고, HTML은 스크립트 실행·외부 리소스 로딩 없이 데이터로만 해석한다. 실제 사용자 클립보드 내용을 개발 로그나 외부 서비스에 보내지 않는다.

### 8.3 잘라내기와 원본 위치

- 같은 인스턴스의 `CutCopyMode`만으로 다른 프로세스 클립보드까지 판정하지 않는다.
- 이동 의미가 명시된 입력은 거절한다. 이동 여부를 구분할 수 없는 형식에서는 제한을 보고하고 지원 완료로 표시하지 않는다.
- 어떤 경로에서도 원본 셀 삭제, 원본 통합문서 저장, 잘라내기 완료 통지는 수행하지 않는다.
- `GetObject`로 우연히 얻은 Excel 인스턴스의 활성 범위를 원본으로 쓰지 않는다.
- 원본과 대상이 겹쳐도, 먼저 확정한 스냅샷을 입력으로 사용하여 덮어쓰기 중 원본이 바뀌는 문제를 막는다.

## 9. 쓰기·검증·실패 복구

### 9.1 상태 전이

```text
Idle → Snapshot → Validate → Confirm(if needed)
     → Backup → Apply → Verify → CommitUndo → Completed

쓰기 전 취소/실패: 대상 0개 수정
쓰기 이후 취소/실패: Rollback → VerifyRollback
복구 확인 실패: RecoveryRequired (성공 메시지 금지)
```

### 9.2 사전 백업

쓰기 전에 **수정할 모든 셀**의 다음 정보를 메모리에 보관한다.

- 통합문서/워크시트의 실행 중 객체 식별 정보와 절대 주소.
- 실제 빈 셀인지, 상수인지, 수식인지.
- 상수의 자료형과 값 또는 원래 수식 문자열.
- 수식 복구에 사용한 속성 종류. `Formula2`/`Formula`를 임의로 섞지 않는다.[S12]
- 작업 도중 건드릴 수 있는 표시 형식 등 속성의 원래 값.

사용자 시트에 숨긴 백업 시트·이름 정의·주석을 추가하지 않는다. 정상 경로에서 값 백업을 디스크에 자동 저장하지 않는다.

### 9.3 값 쓰기

- 실제 빈 원본은 `ClearContents`에 해당하는 동작으로 **내용만** 비운다. `Clear`로 서식까지 지우지 않는다.
- 문자 값은 리터럴 값으로 쓴다. `=...` 문자열의 수식 실행을 막는다.
- 숫자·논리·오류 값은 지원되는 실제 Excel 타입으로 전달한다.
- 원본 수식 자체를 `.Formula`/`.Formula2`로 대상에 쓰지 않는다.
- 숨김 셀을 포함하는 큰 사각형에 배열을 한 번에 쓰지 않는다. 보이는 연속 구간별로 계획한다.
- 이벤트/계산 상태는 13절대로 한시적으로 제어한다. 명령 실행으로 의도하지 않은 이벤트 매크로가 연쇄 실행되지 않게 한다.

### 9.4 사후 검증

기대한 상수 값·타입·빈칸 여부·수식 여부와 실제 대상 값을 비교한다. 원본 수식이 없던 대상에 원치 않는 수식이 생성되면 실패로 처리한다.

일반 실행에서는 검사 범위를 제한해 성능을 관리한다. **E2E에서는 테스트용 워크시트 전체의 상수·수식·서식·숨김 상태를 전후 비교**하여 숨김·선택 밖 쓰기가 없음을 확인한다.

중요: 대상 값을 참조하는 다른 셀의 수식 계산 결과는 정상 재계산으로 바뀔 수 있다. ‘숨긴 셀을 건드리지 않음’은 **그 셀의 상수·수식 정의·서식 등을 직접 덮어쓰지 않음**을 의미한다. 의존 수식의 계산 결과까지 고정한다는 약속은 하지 않는다.

### 9.5 복구의 범위와 한계

Excel COM의 여러 쓰기는 데이터베이스 트랜잭션이 아니다. 완전한 원자성을 보장한다고 표현하지 않는다.

- 오류·취소 시 현재 호출에서 부분 변경됐을 가능성까지 고려하여 백업한 대상 전체를 복구 대상으로 검토한다.
- 복구 성공을 재확인한 경우에만 `작업을 취소했고 변경 내용을 되돌렸습니다.`라고 표시한다.
- 복구 일부 실패 시 변경 가능 범위·복구 실패 주소·오류 코드를 표시한다. 원래 실패와 복구 실패를 함께 기록한다.
- 복구 실패 시 사용자 확인 없이 재시도·계속 쓰기·자동 저장을 하지 않는다. 가능한 복구 기록을 메모리에 보존하고 후속 쓰기를 차단한다.
- Excel 강제 종료, OS 장애, 외부 동시 수정까지 완전 복구하는 기능은 v1 범위가 아니다.

## 10. 최근 한 번 되돌리기

### 10.1 기본 계약

- 성공한 가장 최근 작업 1회만 기록한다. 실패한 새 작업은 기존 유효 기록을 무조건 지우지 않는다.
- 통합문서가 열려 있고 같은 Excel 프로세스에 있는 동안만 유효하다. 닫기·다시 열기·Excel 재시작을 넘겨 복구하지 않는다.
- 최근 기록이 가리키는 통합문서가 아닌 파일에서 되돌리기를 실행하면, 뒤에서 다른 파일을 수정하지 말고 대상 파일로 이동하라는 안내를 한다.
- 사용자 데이터의 같은 이름 파일·같은 시트명만으로 대상을 찾지 않는다. 원래 객체와 수명을 확인한다.

### 10.2 충돌 시 거절

되돌리기 직전에 모든 대상의 현재 내용이 **본 도구가 기록한 실행 직후 상태와 일치하는지** 확인한다. 바뀐 셀이 있으면 전체 되돌리기를 거절하고 일부만 복구하지 않는다.

정렬·행 삽입/삭제·시트 교체·통합문서 닫기 등 구조 변경이 감지되면 기록을 무효화한다. 사용자 편집이나 다른 추가 기능의 후속 작업으로 ‘최근 작업’임을 확신할 수 없어도 보수적으로 무효화한다.

값이 같은 행을 이동하면 값 비교만으로 구조 변경을 알아낼 수 없으므로, **주소/값 비교만으로 충돌 보호가 완성됐다고 주장하지 않는다.** 객체 참조, 구조 변경 감지, 편집 유효 기간, Excel 실행 취소 상태 등 실제 구현에서 확인 가능한 근거를 조합한다. 안전 여부를 증명할 수 없는 경우 자체 되돌리기를 비활성화한다.

M0/M2에서 구조 변경 감지 범위와 남는 한계를 검증하고 `docs/undo-safety.md`에 적는다. 정상 실행 직후의 되돌리기가 동작해야 하며, 지원하지 않는 변경 이후 잘못된 행을 덮어쓰는 것보다 기능을 거절하는 편을 선택한다.

### 10.3 Excel 실행 취소와의 관계

`Application.Undo`는 VBA가 수행한 변경을 되돌리는 API가 아니다.[S04] 자체 백업·복구를 구현한다.

`.xlam` 구현에서는 가능한 경우 `Application.OnUndo`로 같은 복구 절차를 Excel 실행 취소 명령에 연결한다. 등록 이후 다른 작업에 의해 덮일 수 있으므로 문서의 사용 주의와 호출 순서를 따른다.[S05]

- `Ctrl+Z` 연결이 가능하더라도 기존 Excel 다단계 실행 취소 기록 전체를 보존한다고 설명하지 않는다.
- 전역 `Ctrl+Z` 단축키를 가로채는 구현으로 대신하지 않는다.
- 자체 메뉴와 Excel 실행 취소가 서로 다른 복구 로직을 갖지 않게 한다.
- 되돌리기 자체 실패 시에도 9.5절의 실패 보고 원칙을 적용한다.

## 11. 메뉴 자동 등록과 충돌 방지

고유 태그 예시:

```text
VCP.VisibleCellsPaste.Paste.v1
VCP.VisibleCellsPaste.Undo.v1
```

- `.xlam`이면 `Workbook_Open`, 필요한 추가 기능 이벤트 및 애플리케이션 이벤트 수명 관리를 통해 자동 초기화한다.[S10]
- 설치 등록과 실제 초기화는 별개다. `AddIns.Add`는 목록 등록이며 설치 상태 지정이 따로 필요하다.[S06]
- 같은 초기화가 여러 번 호출되어도 메뉴는 각각 하나만 존재해야 한다.
- 등록·정리는 **자기 태그**로 식별한 메뉴만 대상으로 한다. `CommandBars.Reset`, 전체 컨트롤 삭제, 다른 추가 기능 비활성화는 금지한다.[S11]
- `OnAction` 콜백은 자체 추가 기능을 정확하게 한정한다. 공백·한글·작은따옴표가 포함된 설치 경로도 시험한다.
- 일반 셀과 표 데이터 셀의 우클릭 메뉴를 실제 Excel에서 확인한다. 같은 컨텍스트를 여러 메뉴 바 이름으로 중복 등록하지 않는다.
- `Ctrl+C`, `Ctrl+V`, `Ctrl+Z`의 전역 키 바인딩을 바꾸지 않는다.
- 클립보드 상시 감시, 키보드 훅, 트레이 상주, 주기적 전체 시트 스캔은 만들지 않는다.
- 셀 선택이 아닌 상태, 편집 모드, 작업 실행 중에는 메뉴를 안전하게 비활성화하거나 안내한다.

## 12. 설치·제거·릴리스

### 12.1 사용자 흐름

```text
배포 폴더 받기
→ Install.cmd 또는 동등한 설치 실행 파일 1회 실행
→ Excel을 평소처럼 실행
→ 우클릭 메뉴 사용

제거: Uninstall.cmd 또는 동등한 제거 실행 파일 1회 실행
```

설치 시 Excel이 실행 중이면 저장·종료 후 다시 실행하라는 안내를 한다. 사용자 Excel을 강제 종료하거나 열려 있는 통합문서를 닫지 않는다.

### 12.2 설치 원칙

- 사용자별 설치 위치 기본값: `%LOCALAPPDATA%\VisibleCellsPaste`.
- 관리자 권한을 기본 요구하지 않는다.
- 배포 폴더에서 `.xlam`을 매번 직접 여는 방식이 아니라, 설치된 고정 경로에서 자동 로드한다.
- Add-ins 등록이나 해당 환경의 적절한 사용자별 자동 로드 방식을 검증한다. 다른 추가 기능의 등록을 덮어쓰지 않는다.
- 파일, 버전, 해시, 소유한 등록 정보 등을 설치 매니페스트로 관리한다.
- 재설치/업그레이드가 중복 메뉴·중복 로드·이전 파일 잠금 문제를 남기지 않아야 한다.
- `PERSONAL.XLSB`, 사용자의 일반 문서, 다른 도구 폴더는 수정하지 않는다.
- 설치 스크립트의 원래 경로와 사용자명에 공백·한글이 있어도 동작해야 한다.
- 설치 완료는 파일 복사 성공과 자동 로드 확인 상태를 구분하여 표시한다.

### 12.3 보안 정책과 빌드 분리

Office는 파일 출처와 매크로 정책에 따라 추가 기능 코드 실행을 차단할 수 있다.[S13] 다음을 지킨다.

- 모든 매크로 허용, 전역 신뢰 센터 완화, 회사 정책 무력화를 하지 않는다.
- 사용자 PC에서 `AccessVBOM`을 켜거나 VBE에 코드를 주입해서 `.xlam`을 생성하지 않는다.
- 신뢰할 수 있는 위치를 임의로 광범위하게 등록하거나, 다운로드 표시를 폴더 전체에서 일괄 제거하지 않는다.
- 승인된 제작 환경에서 완성 `.xlam`을 빌드하고, 필요한 경우 조직의 승인된 서명·배포 절차를 사용한다.
- 서명 인증서가 없으면 서명했다고 표기하지 않는다. 승인·신뢰가 필요한 환경은 설치 진단에서 명확하게 구분한다.
- `Install` 뒤에 `Alt+F8로 Init 실행`, `개발 도구에서 매크로 실행`, `매번 콘텐츠 사용 클릭`이 붙는 흐름은 정상 완성 경로가 아니다.
- 정책 차단을 코드로 우회하지 말고, 차단 사실과 필요한 승인 조건을 문서화한다. **자동 실행 가능한 환경에서만 무수동실행 요구를 검증 완료로 표시**한다.
- 개발 환경의 빌드 도구·VBA 프로젝트 접근 권한 요구는 최종 사용자 설치 요구와 분리해 적는다.

VBA 소스 파일만 배포하고 사용자가 모듈을 가져오게 해서는 안 된다. 빌드 불가 환경이라면 소스와 빌드 절차를 제공하되 `배포용 추가 기능 미생성`으로 정확히 보고한다. 이름만 바꾼 가짜 `.xlam`을 만들지 않는다.

### 12.4 제거 원칙

- 자기 제품의 자동 로드 등록부터 해제하고, 그 후 파일을 제거한다.
- 자기 메뉴와 사용 중인 이벤트 참조만 정리한다. 다른 제품 메뉴가 살아 있는지 확인한다.
- 잠긴 파일은 성공 삭제한 척하지 않는다. Excel 종료 후 재실행 경로를 안내한다.
- 설치 전부터 있던 등록이나 사용자 파일을 삭제하지 않는다.
- 제거를 다시 실행해도 안전해야 한다.
- 제거 뒤 Excel을 정상 시작했을 때 메뉴, 자동 실행, 누락된 추가 기능 경로 경고가 없어야 한다.

## 13. 애플리케이션 상태·개인정보 보호

작업 전 실제 값을 보관하고 성공·취소·예외·복구 실패의 모든 경로에서 원래 상태로 돌린다.

```text
EnableEvents
ScreenUpdating
Calculation (변경했다면)
StatusBar
DisplayAlerts (변경했다면)
EnableCancelKey (변경했다면)
그 밖에 구현이 실제 변경한 Excel 전역 속성
```

- 무조건 `EnableEvents=True`, `Calculation=Automatic`으로 끝내지 않는다. 시작 시 False/Manual이었을 수 있다.
- 꼭 필요한 속성만 바꾼다. 클립보드와 `CutCopyMode`를 무조건 초기화하지 않는다.
- 외부 링크 새로 고침·쿼리 갱신·원본 수식 재계산을 일부러 실행하지 않는다.
- 성공 시 문서가 수정 상태가 되는 것은 정상이다. `Saved=True`로 미저장 변경을 숨기지 않는다.
- 임시 파일/통합문서가 필요하면 자기 소유만 정리하며, 사용자 문서에는 저장하지 않는다.
- 값·이름·이메일·원본 수식·전체 클립보드·전체 파일 경로는 기본 로그에 쓰지 않는다.
- 로그는 작업 ID, 제품 버전, 범위 크기, 구간 수, 단계, 시간, 오류 코드 등 진단 정보 중심이다.
- 테스트 클립보드 덤프는 합성 데이터로만 만든다. 외부 API, AI 호출, 네트워크 전송, 텔레메트리는 없다.

## 17. 실제 Excel E2E 실행 방법의 필수 조건

1. 사용자의 실제 업무 파일 대신 시험 전용 폴더와 합성 통합문서를 사용한다.
2. 기존 Excel 프로세스의 PID·파일 상태를 기록한다. 시험이 소유하지 않은 프로세스를 종료하지 않는다.
3. 자동 로드 검증은 정상 Excel 시작 경로로 수행한다. 시작 메뉴/실행 파일을 통한 시작을 UI 자동화해도 된다.
4. **메뉴가 나타나는지 검사하기 전에** `.xlam`을 열거나 `Application.Run("VCP_Initialize")` 등을 호출하지 않는다.
5. 자동 로드가 확인된 뒤 로직 시험을 위한 COM 읽기·시험용 콜백 호출은 사용할 수 있다. 이것을 실제 메뉴 클릭 시험의 대체로만 쓰지는 않는다.
6. 대표 흐름에는 실제 셀 선택, `Ctrl+C`, 대상 선택, 우클릭 메뉴 클릭을 포함한다. 클립보드를 테스트 코드가 미리 만든 문자열로 채우는 것만으로 원본 복사를 검증했다고 하지 않는다.
7. 파일 간/프로세스 간 시험을 구분한다. 한 프로세스에서 창만 두 개 띄운 것은 별도 프로세스 시험이 아니다.
8. 전후 내용을 검사하고 결과를 기계 판정한다. 스크린샷만으로 데이터 보존을 판정하지 않는다.
9. 종료·재시작과 제거 후 검증도 실제 사용자 시작 경로로 반복한다.
10. 개발 환경에 Windows Excel이 없으면 가능한 단위 시험만 실행한다. E2E 스크립트·절차를 남기고 `BLOCKED: Windows Excel 없음`으로 보고한다. 완료한 척하지 않는다.

## 18. 마일스톤과 각 단계의 완료 조건

### M0 — 작업공간 조사와 핵심 위험 시제품

기존 프로젝트와 설치 패턴을 조사하고, 5.2절의 자동 로드 및 클립보드 타입/빈칸 시제품을 검증한다. 되돌리기 구조 변경 감지 방안도 확인한다.

산출물: 환경 기록, 구조 결정 ADR, 클립보드 표본/형식 조사, 자동 로드 증거, 위험 목록. 이 단계의 핵심 가정이 실패하면 설계를 수정한다.

### M1 — 파서·자료형·대상 계획

클립보드 모델/파서, 대상 제한/가시 셀 계획, 개수 검사, 오류 모델을 구현한다. Excel 쓰기 없이 실행할 수 있는 단위 시험을 먼저 갖춘다.

완료 조건: D/R 목록 중 순수 로직 항목 통과. 빈칸 제거·단순 문자열 분할로 개수 맞추는 코드 없음.

### M2 — Excel 쓰기·복구·되돌리기

값 쓰기, 타입 보존, 수식 문자열 비실행, 백업, 중간 실패 복구, 최근 1회 되돌리기와 충돌 검사를 구현한다.

완료 조건: 대표 실제 Excel 데이터 시험, 숨김/선택 밖 보존, U01/U02/U08/U09/U12 통과. Windows Excel 미확보 시 구현 상태와 실행 미검증을 분리한다.

### M3 — 자동 로드·메뉴·설치·제거 통합

완성 추가 기능의 제작 빌드, 설치/제거 런처, 고유 메뉴, 멱등 초기화, 보안 진단을 통합한다.

완료 조건: 설치 후 정상 시작과 2회 재시작, 제거 후 정상 시작을 수동 VBA 0회로 통과. 다른 추가 기능 훼손 없음.

### M4 — 회귀·대량·배포물·문서

시험 목록을 실행하고 성능·오류 주입·경계값을 검증한다. 완성 배포 ZIP, 해시, README, 알려진 제한, 시험 보고서를 만든다.

완료 조건: 수용 기준 충족. 미검증 플랫폼이나 남은 위험이 있으면 릴리스 상태를 제한하고 구체적으로 보고한다. 임의로 시험을 생략하고 완제품이라고 선언하지 않는다.

각 마일스톤에서 변경 파일, 실행한 테스트 명령, 결과, 미해결 항목을 남긴다. 매번 사용자 승인을 요구하며 멈추지 말고 다음 단계로 진행하되, 보안 승인·접근 권한이 필요한 부분은 우회하지 않는다.

- [ ] 중간 쓰기 실패와 복구 실패를 각각 시험했다.
- [ ] Excel 전역 상태와 다른 추가 기능을 보존한다.
- [ ] 전체 열과 과대 입력을 먼저 차단하고 대량 경고/진행 표시가 있다.
- [ ] 정상 Excel 시작·2회 재시작·제거 후 정상 시작을 검증했다.
- [ ] 자동 로드 시험을 수동 초기화 호출로 대체하지 않았다.
- [ ] 회사 보안 정책을 낮추거나 사용자 PC에 코드를 주입하지 않는다.
- [ ] 시험하지 않은 환경·항목은 미검증으로 구분했다.
- [ ] 소스만이 아니라 재현 가능한 빌드·배포·제거·시험 자료를 제출했다.
