## 판정과 증거 원칙

상태는 `PASS`(실행·기대값 일치), `FAIL`(실행·불일치), `PARTIAL`(일부 조건만 확인), `NOT_RUN`(미실행)으로 구분한다. 구현 코드의 존재나 빌드 성공으로 실제 Excel·사용자 조작·설치 수명주기 시험을 통과 처리하지 않는다. 서로 다른 시험 층의 결과를 합산해 전체 인수 통과라고 표시하지 않는다.

원작업지시는 깨끗한 Windows 사용자 프로필 또는 격리 VM의 자동 로드 시험을 우선 요구한다. 후속 사용자 지시는 현재 PC에서 가능한 시험을 진행하고 격리 환경·재로그인·재부팅 미실행을 명시하도록 허용했다. 현재 PC M1 메뉴·실제 콜백을 확인한 뒤 로컬 기능 구현을 진행하더라도 원명세 전체 배포 게이트는 별도다.

현재 판정은 아래에 적은 증거 버전의 범위다. rc.7은 외부 COM 검사 없이 실제 우클릭 뒤 합성값 4개가 있는 새 결과 창이 자동으로 전면에 나타나고 정상 UI 종료되는 것을 확인했다. rc.7에 이어 rc.9 정식 COM 콜백 API11사례·930 assertions가 통과했다. rc.8은 출력 중 입력 재차단 수정과 빌드183회·현재 사용자 설치를 확인했다. rc.9는 전역 상태 복원이 끝나지 않았을 때 성공으로 보고하지 않는 보완을 포함한다. 빌드191회·x64 설치와 실제 메뉴의 결과 자동 전면 표시를 확인했고 실제 진행 창 취소11 assertions도 통과했다. 직접 엔진 부정 조건은 실행9사례·92 assertions 통과, 부분 병합1사례 미실행이다. **rc.9 실제 UI 시험에서 내보내기 전 원본의 편집 Undo가 활성 상태였다가 내보낸 뒤 비활성화됐다. 실행 취소 기록 보존은 실패했으며 원본 값·수식 보존과 구분한다.** **rc.9 API 시험을 마친 Excel은 합성 통합문서를 닫은 뒤 수분 동안 창 없이 남았다. API 경로의 자연 종료는 FAIL이며 원인은 미확정이다. 외부 COM 없는 실제 UI 종료 PASS와 구분한다.** 직접 엔진, COM 콜백 API, 활성화 검사를 제외한 데이터 진단, 실제 사용자 메뉴 클릭을 각각 구분한다. 이후 결과는 실행 환경, 산출물 해시, 명령·방법, 기대값, 관찰값과 증거 위치를 기록하고 해당 행만 갱신한다. 업무 데이터·실제 사용자 경로·설치 진단 원문은 이 문서나 공개 사이트에 넣지 않는다. 세부 증거는 저장소 `artifacts/selection-export` 아래 로컬 디렉터리에 보관한다.
