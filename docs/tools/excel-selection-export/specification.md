# Codex 작업지시 — Workspace의 독립 제품 ‘선택범위 내보내기’

작성일: 2026-09-24 / 작업명세 v1.0
대상 저장소: `prozac0401/Workspace`
제안 제품/프로젝트명: `ExcelSelectionExport` / 사용자 표시명: `선택범위 내보내기`

> 이 문서를 실행 지시로 읽고 설계·구현·테스트·설치 패키징까지 진행하라. 계획서나 VBA 예제만 제출하지 않는다.
> 현재 요청은 ‘선택범위를 새 Excel로 꺼내는 별도 제품’이다. 명단대조기와 파일목록 도구에 기능을 끼워 넣지 않는다.

## 1. 착수와 저장소 경계

1. 현재 체크아웃, `git status`, `AGENTS.md`, `docs/policies/tools.md`, `docs/policies/documentation.md` 및 관련 개발/배포 문서를 먼저 읽는다. 사용자의 미커밋 변경을 지우지 않는다.
2. 기존 `tools/ExcelSmartListCompare`의 메뉴/설치/검증 방식을 참고하되, 그 제품을 수정하거나 런타임 의존성을 만들지 않는다.
3. 신규 경로는 우선 `tools/ExcelSelectionExport`로 검토한다. 저장소의 실제 디렉터리 정책과 충돌하면 같은 제품 경계를 유지하는 다른 위치를 선택하고 이유를 기록한다.
4. 독립 제품명·설치 항목·제거 항목·버전·릴리스 산출물을 만든다. 명단대조기나 FolderState를 설치해야 동작하는 구조는 금지한다.
5. 공개 문서는 `docs/`의 소스를 수정한다. 내부 경로/실제 업무 데이터/진단 로그를 공개 문서나 테스트 fixture에 넣지 않는다.
6. 본 문서는 새 작업 요구사항이다. 과거 도구의 배포 관행보다 아래 ‘수동 VBA 실행 없음’ 조건을 우선한다.

### 조사 시 확인한 출발점 — 실행 시 다시 확인할 것

2026-09-24 조회한 Workspace의 `AGENTS.md`는 기존 명세·개발 정책 우선 확인, 도구별 테스트, 실제 검증과 미검증 구분을 요구한다. 당시 명단대조기 README는 별도 설치 제품과 VBA 기반 동작을 설명한다. 이것을 신규 제품의 기술 선택으로 자동 승계하지 말라. 이 문서는 새 프로그램의 코드를 이미 구현·시험했다는 보고서가 아니다.

## 공통 최우선 조건 — 사용자에게 VBA 실행을 요구하지 않는다

이 절은 기능 구현보다 우선하는 출시 조건이다.

### 자동으로 할 일과 사용자가 할 일을 구분한다

- 사용자는 제품 설치 프로그램을 한 번 실행한다. 설치 시 기능 설명 확인, 설치 동의, 필요한 경우 작업 저장 후 Excel 재시작은 허용한다.
- 설치 프로그램이 해당 제품의 Excel 추가 기능 등록과 정상적인 시작 시 로드 설정을 담당한다.
- 이후 사용자는 평소처럼 Excel을 연다. 메뉴와 이벤트 연결은 자동으로 준비된다.
- **사용자에게 Alt+F8, Alt+F11, VBA 코드 붙여넣기, .bas 가져오기, .vbs 실행, 초기화 매크로 실행, 추가 기능 찾아보기/체크, 매번 런처 실행을 요구하지 않는다.**
- 매번 ‘콘텐츠 사용/매크로 허용’을 눌러야 하는 배포도 합격이 아니다.
- 자동 실행은 ‘메뉴 준비/이벤트 연결’을 뜻한다. 파일을 열거나 셀을 선택했다는 이유만으로 내보내기·복사·저장을 시작하지 않는다. 실제 처리는 사용자가 해당 메뉴를 클릭한 뒤에만 실행한다.
- 개발자의 빌드 작업과 최종 사용자의 설치를 구분한다. 사용자 PC에서 VBA 프로젝트를 조립하거나 `Trust access to the VBA project object model`을 요구하는 방식은 금지한다.

### 구현 방식

1. 기본 후보는 **컴파일된 설치형 Excel COM 추가 기능**이다. 기존 C++/C# 도구 체계를 확인하여 결정한다. 지원되는 VSTO 방식도 검토할 수 있으나 런타임·서명·신뢰·설치 조건을 실제 확인해야 한다.
2. VBA를 꼭 써야 한다는 요청이 아니다. `Workbook_Open` 매크로만 붙여놓고 자동 실행이 완료됐다고 판단하지 않는다.
3. 기존의 VBA 기반 도구를 참고하더라도, 그 배포 방법과 보안 설정 변경을 그대로 복제하지 않는다. 기본 납품 경로는 VBA 실행에 의존하지 않게 한다.
4. 다른 구조가 명백히 더 적절하면 ADR(설계 결정 기록)에 이유와 자동 로드 실증 결과를 남긴다. 수동 매크로 실행을 우회안으로 제시하지 않는다.
5. COM/VSTO를 택해도 조직의 추가 기능 정책, 서명 요구, Office 비활성화 정책은 적용된다. 어떤 PC에서든 무조건 무경고로 실행된다고 주장하지 않는다.

### 보안·설치 조건

- 일반 사용자/HKCU/LocalAppData 설치를 우선한다. 설치기가 제품 소유의 정상적인 COM/추가 기능 등록을 자동으로 수행하는 것은 허용한다.
- 매크로 보안을 낮추거나, ‘모든 매크로 허용’, 광범위한 신뢰 위치, Trust Center/그룹 정책 완화, MOTW 일괄 해제, 임의 인증서 신뢰 등록으로 무조작 요구를 충족시키지 않는다.
- 사내 정책/서명/필수 런타임 때문에 불가능한 환경에서는 원인과 필요한 승인 조건을 진단한다. 기능 불가를 숨기고 ‘설치 성공’으로 끝내지 않는다.
- 사용자가 비활성화한 추가 기능이나 Office가 문제로 차단한 추가 기능을 감시하며 강제로 재활성화하지 않는다.
- 서명 키/인증서는 하드코딩하거나 저장소에 올리지 않는다. 서명되지 않은 평가 빌드와 배포 승인된 빌드를 구분한다.
- 기존 Excel 창을 강제 종료하거나 저장하지 않은 파일을 자동 저장하지 않는다. 설치·업데이트·제거에 재시작이 필요하면 저장 후 닫도록 한 번 안내한다.
- 최종 사용자가 별도 Python/개발 SDK/스크립트 실행 정책을 설정하지 않게 패키징한다.

### Excel 메뉴 수명주기와 공존

- 제품별 COM CLSID/ProgID, 메뉴 Tag/ID, 설치 폴더, 설정, 제거 소유권을 분리한다.
- 시작 시 동일 메뉴/이벤트가 중복 등록되지 않게 한다. 종료·연결 해제 시 자신이 만든 컨트롤과 이벤트만 해제한다.
- Office의 기본 메뉴나 명단대조기 등 다른 제품 메뉴를 초기화/전체 삭제하지 않는다. `CommandBars.Reset` 방식은 금지한다.
- `CommandBars`를 사용하면 자신의 컨트롤에 고유 Tag와 적절한 임시 수명을 적용한다. Ribbon/컨텍스트 메뉴 방식을 선택해도 같은 소유권 원칙을 지킨다.
- 메뉴 클릭을 컴파일된 콜백에 연결한다. 존재하지 않는 VBA 매크로 이름을 `OnAction`에 넣는 껍데기만 구현하지 않는다.
- Excel Application/Workbook/Worksheet/Selection은 해당 추가 기능이 연결된 **현재 Excel 인스턴스**에서 얻는다. 임의 `GetActiveObject` 하나로 여러 Excel 프로세스 중 대상을 추측하지 않는다.
- 우클릭 이벤트의 Target은 마우스 근처 셀이지 전체 선택범위가 아니다. 실제 Selection과 교차 관계를 확인한다. 선택 안을 우클릭했을 때 여러 셀 선택을 한 셀로 잃지 않는지 시험한다.
- 메뉴 표시 시 파일 내용 읽기·네트워크 검사·대규모 계산을 하지 않는다. 무거운 검사는 명령 실행 후에 한다.
- Excel COM 객체는 허용되는 UI/STA 문맥에서 다룬다. 백그라운드 작업에는 값과 경로를 복사한 DTO만 전달한다.
- Excel이 종료된 뒤 남는 전용 상주 서비스/감시 프로세스를 두지 않는다. 작업용 helper는 해당 작업이 끝나면 종료한다.

### 가장 먼저 통과할 자동 로드 시험

깨끗한 Windows 사용자 프로필 또는 격리된 테스트 VM에서 진행한다.

1. VBA 프로젝트 접근 신뢰는 꺼두고, 문서 VBA 매크로를 허용하지 않은 상태를 유지한다. 단, 설치형 추가 기능 자체는 조직 정책상 허용된 시험 환경이어야 한다.
2. 완성된 설치 프로그램만 실행한다. VBE/매크로 실행/추가 기능 수동 체크를 하지 않는다.
3. Excel을 열고 해당 컨텍스트 메뉴가 준비되는지, 실제 메뉴 클릭이 기능으로 이어지는지 확인한다.
4. Excel을 완전히 닫았다가 다시 연다. Windows 재로그인/재부팅 후에도 같은 시험을 한다.
5. 서로 다른 Excel 프로세스 두 개, 여러 통합문서, 기존 명단대조기와의 동시 설치를 시험한다.
6. 설치·업그레이드·제거 이후 중복 메뉴, 유령 메뉴, 다른 도구 삭제, 남는 helper가 없는지 확인한다.
7. 정책 차단, 비트수 불일치, 누락 런타임, 로드 실패는 각각 다른 진단으로 보고한다.

**개발용 Excel에서 `Run`을 눌러 성공한 것은 자동 로드 시험을 통과한 것이 아니다. Windows/Excel 환경이 없으면 해당 시험은 미실행으로 남기고, 소스/단위시험/설치 패키지 검사와 구분한다.**

## 2. 사용자 흐름과 메뉴

기본 흐름:

```text
평소처럼 Excel 실행
→ 필요한 직사각형 셀 범위 선택
→ 셀 안에서 우클릭
→ ‘선택범위 내보내기 > 새 Excel로’
→ 선택한 내용만 들어 있는 저장 전 새 통합문서 표시
```

- 정상적인 작은 작업은 메뉴 클릭 뒤 추가 설정 없이 끝난다.
- 저장 위치는 실행할 때 묻지 않는다. 결과는 **아직 디스크에 저장하지 않은 새 통합문서**이며, 저장할 때 Excel의 보통 저장 흐름을 이용한다.
- ‘파일 복사’, ‘명단 비교’, ‘PDF 출력’, ‘메일 발송’ 기능은 포함하지 않는다.
- 기본 진입점은 셀 컨텍스트 메뉴다. 기본 단축키를 새로 선점하지 않는다.
- 현재 Selection이 Range가 아니거나 차트/개체/시트 여러 개 선택/보호된 보기 등 지원 범위 밖이면 비활성화하거나 짧은 이유를 표시한다. 보호를 해제하지 않는다.

## 3. 입력 계약 — 선택을 추측하거나 넓히지 않는다

### 지원

- 한 워크시트의 명시적인 직사각형 셀 선택, 한 셀, 한 행/열의 유한 부분 범위.
- 선택 범위 안에서 필터·수동 숨김으로 제외되지 않은 행/열만 읽는다.
- 화면 밖으로 스크롤된 셀도 선택 범위에 있고 숨기지 않았다면 포함한다.
- 가로·세로 구조를 유지하며, 빈 셀/빈 행/빈 열을 의미 없이 제거하지 않는다.
- 선택자가 표 제목·합계를 포함했다면 보이는 범위에 한해 그대로 포함한다. 첫 행을 제목으로 추정하거나 이름을 바꾸지 않는다.
- 일반 셀 범위와 Excel Table 내부 범위를 지원한다.

### 초기 버전에서 명확하게 제한

- 사용자가 Ctrl로 고른 서로 떨어진 여러 사각형은 거절한다. 다만 하나의 사각형에서 숨김을 제외한 뒤 생기는 여러 Visible Areas는 정상 처리한다.
- 전체 행/전체 열/워크시트 전체 선택은 무조건 순회하지 말고 유한 범위를 다시 선택하도록 안내한다. UsedRange로 원래 의도를 임의 추정하지 않는다.
- 병합 셀은 선택과 보이는 행·열에 병합 영역 전체가 포함된 경우만 유지한다. 일부만 포함되거나 숨김 때문에 잘리는 병합은 사전 검사에서 명확히 거절한다.
- 도형, 차트, 이미지, 스파크라인, 개체 내 텍스트는 대상이 아니다. 이를 ‘완벽한 화면 복제’로 안내하지 않는다.

## 4. 결과 데이터 계약

| 원본 | 결과 |
|---|---|
| 일반 값 | 타입과 값을 보존 |
| 수식 | 실행 시점에 Excel이 가지고 있는 계산 결과만 기록 |
| 날짜/백분율/통화/앞자리 0 표시 | 실제 값과 숫자 표시 형식을 함께 보존 |
| 문자열 사번 `001234` | 문자열 그대로 보존 |
| 빈 셀·선택한 빈 행/열 | 구조상 위치 유지 |
| 필터/수동 숨김 행·열 | 결과에서 제외하고 남은 행/열을 원래 순서대로 연결 |
| 기본 글꼴·크기·굵기·배경·테두리·정렬·줄바꿈·너비/높이 | 기본 보존 대상 |
| 메모·댓글·하이퍼링크·정의 이름·외부 연결·검증 규칙 | 복사하지 않음 |
| 원본 VBA/숨긴 시트/다른 시트/제품 식별 정보 | 복사하지 않음 |

추가 조건:

- `Value2` 등 타입을 보존하는 방식으로 읽고 표시 서식을 별도로 캡처한다. 셀의 `.Text`만 수집해서 숫자·날짜를 문자열로 바꾸지 않는다. [MS-E]
- 원본의 `Date1904` 설정을 결과의 날짜 기준과 맞춰 날짜가 어긋나지 않게 한다. [MS-G]
- `=`, `+`, `-`, `@`, 작은따옴표 등으로 시작하는 **원본 문자열**을 새 수식으로 해석하지 않게 쓴다. 실제 값과 문자열의 앞자리/공백을 임의로 제거하지 않는다.
- 실제 Excel 오류값과 오류처럼 보이는 문자열을 구분해 유지한다. #N/A 등을 빈칸으로 조용히 바꾸지 않는다.
- 계산 진행 중이면 완료 전 작업을 막고 안내한다. 수동 계산 모드에서 값의 최신성을 보장한다고 주장하지 않는다. 원본 재계산/외부 연결 갱신은 강제하지 않는다.
- 기본 서식과 조건부 서식의 효과를 구분한다. 일반적인 글자색·배경색·테두리·숫자 형식은 현재 표시된 효과를 정적 서식으로 옮기는 것을 목표로 한다. 조건부 서식 규칙 자체는 옮기지 않는다. [MS-F]
- 데이터 막대/아이콘처럼 셀 서식만으로 옮길 수 없는 효과가 선택 범위에 있으면 실행 전에 한 번 안내한다. 대체 표현을 추측해서 값을 바꾸지 않는다.
- 병합에 속한 값은 왼쪽 위 셀 기준으로 처리하고, 결과 행/열 좌표에 맞춰 전체 병합만 다시 구성한다.
- 새 통합문서에는 결과 시트 하나만 만든다. 원본 워크시트를 통째로 복제한 뒤 필요 없는 곳을 삭제하는 방식은 금지한다.
- 제목 추론, 자동 Excel Table 생성, 임의 정렬, 빈칸 채우기, 명단 정규화, 원본 수정은 하지 않는다.

## 5. 구현 구조

권장 분리:

```text
자동 로드되는 Excel 추가 기능
  → 선택 검증 / 현재 인스턴스 고정
  → VisibleRangePlanner (행·열 재배치 계획)
  → SelectionSnapshot (타입·값·허용 서식·병합 정보)
  → ExportWriter (새 통합문서 생성)
  → 완료/제약 안내
```

1. 메뉴 클릭 때 원본 Application/Workbook/Worksheet/Selection을 고정한다. 결과 통합문서를 만들고 나서 `ActiveWorkbook`을 다시 읽어 원본으로 쓰는 실수를 막는다.
2. 값은 연속 영역별로 묶어서 읽고, 보이는 행/열의 인덱스 표로 결과 배열을 만든다. `Areas`를 단순 세로 이어붙여 표가 뒤틀리지 않게 한다. [MS-H]
3. 서식은 같은 속성 묶음을 캐시해서 셀당 불필요한 COM 호출을 줄인다. 테마 의존 색은 결과에서 실제 보이는 색을 유지하도록 검사한다.
4. 사용자 클립보드 전체를 비우거나 UI 복사/붙여넣기를 반복하는 구현을 기본 경로로 쓰지 않는다.
5. 출력은 같은 Excel 인스턴스의 `Workbooks.Add`로 만든다. 수식이나 외부 링크가 결과에 남지 않는지 검사한다.
6. 작업 중 원본이 바뀌지 않도록 UI 재진입을 막고, 긴 스냅샷을 나누어 읽을 때 변경/종료 이벤트를 감지해 중단한다. 파일 스냅샷 수준의 원자성을 보장한다고 주장하지 않는다.
7. `ScreenUpdating`, `EnableEvents`, `Calculation`, `StatusBar` 등을 변경했다면 finally에서 기존 값으로 복원한다. 계산 모드는 가능한 한 건드리지 않는다.
8. 취소/실패 시 자신이 새로 만든 불완전한 통합문서만 안전하게 닫는다. 원본·다른 문서에 `Quit`, 강제 저장, 강제 닫기를 하지 않는다.
9. 원본 값·서식·필터·숨김 상태·저장 여부를 바꾸지 않는 회귀 시험을 만든다. Excel 실행 취소 기록의 보존 여부는 별도 실측하고, 확인 없이 보장하지 않는다.

## 6. 규모와 응답성 — 초기 제한값은 제품 설계값

- 보이는 출력 셀 최대 100,000개, 원문 문자열 합계 최대 10,000,000자.
- 사전 검사에서도 무제한 순회를 하지 않게 입력 사각형의 셀 위치 수는 1,000,000개 이내로 제한한다.
- 보이는 셀 20,000개 초과 또는 대량 표시 서식 처리 예상 시에만 실행 전 경고를 한 번 띄운다.
- 700ms를 넘는 작업은 현재 단계·처리 수·취소를 표시한다. 전체 시간을 모르면 부정확한 퍼센트/남은 시간을 꾸며내지 않는다.
- 이 수치는 초기 보호 장치다. 실제 Excel/비트수별 측정 결과로 조정하고 근거를 기록한다. 사용자 데이터를 조용히 잘라내는 제한은 금지한다.
- Excel COM을 Task.Run에서 호출하는 것으로 UI 응답성을 해결하려 하지 않는다. UI 스레드 작업을 제한된 단위로 처리하는 방식을 시험한다.

## 7. 패키징과 호환

- Windows 11 x64 + 설치형 Excel을 대상으로 한다. Excel x86/x64를 구분해 추가 기능 비트수를 맞춘다. OS가 x64라고 Excel도 x64라고 가정하지 않는다.
- 두 비트수를 목표로 빌드하고 각각 검증한다. 한쪽 미검증이면 배포 표에서 명확히 표시하고 지원 확정으로 쓰지 않는다.
- Excel 웹/Mac/대체 스프레드시트 앱은 이번 제품 대상이 아니다.
- 독립 설치/업데이트/제거를 제공한다. 설치된 앱 이름은 ‘선택범위 내보내기’로 사용자가 알아볼 수 있게 한다.
- 기존 도구를 건드리지 않는 고유 등록과 제거를 구현한다. 사용자가 만든 결과 파일은 설치기 소유 파일이 아니다.
- 기존 Excel이 열려 있어 바로 반영하지 못하면 ‘저장 후 Excel 재시작 필요’를 안내한다. 데이터 손실 없는 자동 연결이 실증된 경우만 즉시 반영한다.
- 도움말은 설치→Excel 실행→선택→우클릭의 흐름으로 끝나야 한다. ‘VBA 실행 방법’ 장이 필요하다면 설계를 다시 검토한다.

## 8. 구현 순서 — 자동 로드를 먼저 증명

| 단계 | 작업 | 통과 조건 |
|---|---|---|
| M0 | 저장소/정책/기술/비트수 확인, ADR | 독립 제품과 배포 방식 결정 |
| M1 | 최소 추가 기능 + 설치/제거 | 설치 후 Excel 시작만으로 메뉴와 실제 콜백 작동 |
| M2 | 가시 범위 계획/타입 모델 | 필터·숨김·빈칸·병합 좌표 단위시험 |
| M3 | 새 통합문서 출력 | 값·날짜·기본 모양 보존, 수식/링크 유입 없음 |
| M4 | 규모·취소·예외 | 원본 무변경, 상태 복구, UI 응답 |
| M5 | 실제 Excel·공존·업그레이드 | 자동 로드와 데이터 정확성 통합 시험 |
| M6 | 독립 설치 산출물·문서 | 재현 빌드와 실제/미실행 검증 보고 |

M1이 안 되는 상태에서 기능을 먼저 크게 늘리지 말라. 차단 조건을 기록하되 가능한 단위시험·배포 수정은 계속한다. 안전/승인 장벽을 수동 VBA 실행 안내로 대체하지 않는다.

## 9. 필수 수용 시험

### 데이터

- 한 셀 / 가로 목록 / 세로 목록 / 일반 2차원 표.
- 필터 제외 행 + 수동 숨김 행 + 숨김 열이 동시에 존재.
- 100행 중 18행만 보이고 내부 빈칸도 있는 표: 결과가 18행의 올바른 관계를 유지.
- 범위에 포함한 제목/합계는 유지, 포함하지 않은 제목은 자동 추가하지 않음.
- 문자열 `001234`, 숫자에 `000000` 형식, 날짜/시간/백분율/통화, 1900/1904 날짜 기준.
- 일반 수식·외부 참조 수식·동적 배열 값: 현재 계산 결과만 남고 참조/수식 없음.
- 리터럴 `=1+1`, `+123`, `@name`, 작은따옴표, 실제 오류값, 오류 모양 문자열, 한글/줄바꿈.
- 일반 서식/조건부 글자·배경색/지원 밖 아이콘 효과.
- 병합 전체 포함은 유지, 부분 병합/숨김으로 잘린 병합은 사전 거절.
- Ctrl 비연속 선택, 전체 행·열, 다중 시트, 개체 선택, 0개 보이는 셀은 잘못된 출력 없이 안내.
- 상한 직전/직후와 장문 셀. 데이터가 조용히 누락되지 않음.

### 사용·공존

- 메뉴 클릭 후 원본 파일을 저장하라고 요구하지 않음.
- 새 결과에 다른 원본 시트, 댓글, 링크, 매크로, 파일목록의 작업용 표식이 없음.
- 서로 다른 Excel 프로세스에서 각각 선택한 값만 내보냄.
- 명단대조기/File List Excel 연동과 동시 설치·업데이트·각각 제거.
- 원본 저장 상태·필터·숨김·값·서식 무변경.
- 실패/취소 후 Excel 상태 복구와 불완전한 새 문서 정리.
- 공통 ‘자동 로드 시험’ 전 항목. 새 Windows 세션에서도 사용자 VBA action 0회.

2. 자동 로드 기술, 등록 항목, 비트수/런타임/서명 조건.

5. 빌드/단위시험/실제 Excel 시험/미실행 항목을 분리한 결과.
6. 보존한 데이터·서식과 제한, 실패·취소 동작, 기존 도구 공존 결과.
