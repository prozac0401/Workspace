# ExcelPasswordSafe · 제품 명세

도구 ID: ExcelPasswordSafe  
버전·상태: 1.4.0 · 로컬 평가 후보
제품 책임: 도구 개발·검증 담당  
적용 정책: [추가 도구 개발 기준](../../policies/tools.md), [정책 문서 작성 규칙](../../policies/documentation.md)  
관련 ADR: [파일 처리 설계](../../design/0018-excel-password-safe-explorer.md), [ADR-0040 폴더 일괄 처리](../../design/0040-excel-password-safe-folder-batch.md)
요구 근거: [최초 요청·첨부 원본](original-request.md)

## 사용자와 목적

탐색기에서 Excel 파일 하나 또는 폴더 하나를 오른쪽 클릭하여 열기 암호를 설정·해제·변경한다. 폴더 작업은 하위 폴더까지 포함한 지원 Excel 파일을 같은 작업·암호로 순서대로 처리한다. 현재 암호를 아는 사용자가 파일을 관리하는 도구이며, 잊은 암호 찾기나 시트 보호·통합문서 구조 보호·쓰기 암호 해제는 범위에 포함하지 않는다.

## 범위와 금지 동작

파일 하나 또는 폴더 하나를 명시적으로 선택한다. 폴더는 모든 하위 폴더의 지원 Excel 파일을 포함한다. 재분석 지점·링크 하위로 진입하지 않으며 접근할 수 없는 항목을 전체 성공으로 간주하지 않는다. 로컬 고정 NTFS 경로를 대상으로 하며 네트워크·UNC·이동식 드라이브, 재분석 지점, 읽기 전용·잠긴 파일은 처리하지 않는다. 동기화 폴더는 별도 로컬 복사본으로 작업한다. 도구의 백업·실행 자료와 Excel 잠금 파일은 입력 문서로 다시 처리하지 않는다.

| 확장자 | 실제 Excel FileFormat |
|---|---|
| `.xls` | 56, Excel 97–2003 BIFF8 |
| `.xlsx` | 51 또는 Strict 61 |
| `.xlsm` | 52 |
| `.xlsb` | 50 |

확장자와 실제 형식이 다르면 변환하지 않고 중단한다. 서명된 문서·VBA, 공유 통합문서, 쓰기 예약 파일과 발견된 Excel 4.0 매크로 시트는 지원하지 않는다. 도구 자체는 Office 보안 정책·기본 파일 연결을 변경하거나 파일 내용을 외부로 전송하지 않는다. Excel의 데이터 연결·추가 기능·Office 백그라운드 통신까지 차단하는 기능은 아니다.

Excel 자동화는 별도 인스턴스에서 VBA 자동 실행·이벤트·링크 갱신을 끈다. `AutomationSecurity`는 Excel 4.0 매크로를 모두 억제하지 못하므로 해당 파일에서 보안 확인 또는 제한시간 초과가 발생할 수 있다. 세부 계약은 [Microsoft 문서](https://learn.microsoft.com/en-us/office/vba/api/excel.application.automationsecurity)를 따른다.

## 데이터 계약

UI가 처리할 파일의 전체 경로와 SHA-256을 확정한다. 엔진은 `schemaVersion=1` 요청의 `path`, `mode`, `expectedHash`, `oldSecret`, `newSecret`를 읽는다. 작업은 `Encrypt`, `Decrypt`, `ChangePassword` 중 하나다. 알 수 없는 버전·작업이나 잘못된 필수 값은 원본 수정 전에 거절한다.

폴더 요청은 `schemaVersion=1`, `root`, `mode`, `files[{path,expectedHash?}]`, `oldSecret`, `newSecret`를 사용한다. UI는 루트와 하위 파일 목록·전체 경로를 미리보기에서 확정하여 경로 목록을 전달한다. 실행 도중 새로 발견한 파일을 추가하지 않는다. 배치 엔진은 각 파일을 처음 읽을 수 있을 때 SHA-256을 확정하고 모든 재시도에 같은 해시를 사용한다. 따라서 폴더 UI의 목록 승인 이후 첫 해시 계산 전 변경까지 감지하는 계약은 아니다. 기존 단일 파일 UI의 승인 해시는 유지한다.

폴더의 모든 파일에 공통 현재 암호·새 암호를 적용하며, 서로 다른 현재 암호를 가진 파일은 실패로 남길 수 있다. 암호를 추측하거나 파일별 암호를 탐색하지 않는다. 선택적인 `discoveryIssues[{path,category}]`는 검색 중 접근 불가·위험 제외 항목을 실패·시도 0회로 기록한다. 실제 파일 없이 검색 오류만 있는 경우에는 암호 없이 실패 기록을 만들 수 있다. UI는 `ownerPid`, `ownerStartTicks`도 전달하여 창의 실행 프로세스가 사라지면 현재 파일 처리 뒤 남은 파일을 중지한다.

새 암호는 1~15자로 제한한다. 이는 기존 형식과 Excel `SaveAs`의 공통 호환 계약이며 보안 강도 등급이 아니다. 현재 암호는 해제·변경에 필요하다. 암호 설정은 이미 암호가 있는 파일을 임의의 새 암호로 바꾸지 않는다. 해제·변경 대상이 이미 암호 없는 파일이면 원본을 유지한다. [Microsoft Workbook.SaveAs](https://learn.microsoft.com/en-us/office/vba/api/excel.workbook.saveas)

각 실행은 현재 사용자 전용 `%LocalAppData%\ExcelPasswordSafe\Runs\실행ID` 폴더를 사용한다. `original.확장자` 원본 백업, 원본·결과 해시, 진행 단계와 결과를 보관한다. 암호는 현재 사용자 DPAPI 암호문으로 전달하고 종료 시 요청·작업 전달 파일을 제거한다. Excel 호출 중 암호 평문이 메모리에 잠시 존재하는 제한은 남는다. 실행 기록은 로컬 진단이며 공개 사이트나 설치 패키지에 넣지 않는다.

폴더는 `Runs\배치ID` 아래 GUID 시도 폴더를 사용한다. 배치 `result.json`에는 파일별 `Success`, `Skipped`, `Failed`, `Cancelled`, `NotProcessed`, `NeedsInspection` 결과와 건수·`reportPath`를 기록한다. `Failed` 또는 `NeedsInspection`, 취소 외의 배치 실패로 인한 `NotProcessed`가 있으면 같은 배치 폴더에 `failure-report.xlsx`를 만들며 미처리 항목도 포함한다. 실패 없는 사용자 취소·UI 종료·전체 성공에는 보고서를 만들지 않는다.

실패 보고서는 업무자료 대신 현재 사용자 전용 실행 위치에 생성한다. 제품의 `%LocalAppData%\ExcelPasswordSafe` 트리는 상위 폴더를 선택해도 검색에서 제외하므로 보고서·백업이 입력에 섞이지 않는다. 보고서의 8개 열은 파일명 또는 폴더명, 전체 경로, 작업, 시도 횟수, 결과, 실패 이유·확인 코드, 원본 백업, UTC 시각이다. 암호·DPAPI 암호문·원시 예외를 넣지 않으며 모든 셀을 문자열로 저장하여 파일명·경로가 수식으로 실행되지 않게 한다. 작성 실패는 `FailureReportFailed`로 명시하고 JSON 결과를 보존하며 UI에서 생성된 것처럼 표시하지 않는다.

## UX

`Excel 암호 관리`를 선택하면 파일명·전체 경로와 `암호 설정 / 암호 해제 / 암호 변경`을 표시한다. 작업에 필요한 입력만 사용한다. 새 암호는 확인 입력과 비교한다. 실제 작업 전 원본이 교체되고 백업이 남는다는 안내를 표시하고 실행 버튼으로 해당 작업을 확정한다. 파일 없이 앱을 실행하면 파일을 선택할 수 있어야 한다.

폴더 메뉴에서는 `Excel 암호 관리 → 암호 설정 / 암호 해제 / 암호 변경`으로 작업을 고른다. 창에는 루트 경로, 하위 폴더 포함, 대상 파일 수와 미리보기, 공통 암호 입력을 표시한다. 처리 중에는 현재 파일·완료 수·시도 수를 보여 주고 최종 결과에는 성공·건너뜀·실패·취소/미처리를 구분한다. 최종 실패의 파일·경로·이유·시도 수를 확인하고 생성된 실패 XLSX를 여는 동작을 제공한다. 대상이 없을 때는 실행하지 않고 빈 상태를 표시한다.

진행 중에는 작업 변경·중복 실행을 막고 취소를 제공한다. 취소는 현재 Excel 호출이 끝나는 데 시간이 걸릴 수 있으며, 원본 교체가 시작된 뒤에는 취소가 완료된 것처럼 표시하지 않는다. 성공·건너뜀·실패·취소를 구분하고 백업·진단 위치와 다음 행동을 보여준다. 키보드 탐색, 암호 마스킹, 읽을 수 있는 오류 문구를 제공한다.

1.3.0은 사용자의 화면 개편 요청에 따라 노랑·초록 계열 강조를 제거하고 차가운 흰색 바탕, 슬레이트 회색, 짙은 남색과 코발트 파란색을 사용한다. 파일·작업·입력 영역을 둥근 카드로 정리하고 작업 선택을 이어진 선택 버튼으로 구분한다. Tab 이동·키보드 초점·선택 상태·비활성 상태를 식별할 수 있어야 한다. 작은 창에서도 실행·취소와 결과·오류를 읽을 수 있도록 배치하며, 내용이 길어지면 스크롤을 제공한다. 이 개편은 엔진 요청 스키마·암호 조건·백업·교체·복구 계약을 바꾸지 않는다.

## 동시 실행과 복구

엔진은 사용자별 뮤텍스로 중복 처리를 막는다. 기존 Excel이 실행 중이면 사용자가 정상 종료한 뒤 다시 시도하도록 한다. 사용자 Excel을 연결해 재사용하거나 강제 종료하지 않는다.

승인한 SHA-256과 원본의 현재 해시가 일치해야 한다. 원본에 쓰기를 허용하지 않는 읽기 핸들을 유지하고, 접근 제한된 백업을 만든 뒤 해시를 대조한다. 같은 폴더의 작업 복사본을 Excel로 저장·닫기·재열기하여 형식·암호 상태·의미 비교가 통과한 결과만 `File.Replace`로 교체한다. 재열기 검증 전후의 출력 해시, 작업 후 입력 복사본 해시와 교체 직전 원본·백업·결과 해시가 일치해야 한다. 삭제 후 이동으로 우회하지 않는다.

`state.json`에 교체 전후 상태와 경로·해시를 남긴다. 교체 전 오류·취소에서는 원본을 유지한다. 교체 이후 해시 확인이나 상태 기록이 실패하면 성공으로 표시하지 않고 원본·결과·백업·recovery를 조사하도록 안내한다. 자동 롤백은 외부 변경을 덮어쓸 수 있으므로 하지 않는다. 복구할 때는 현재 파일도 별도 보관한 뒤 백업 해시와 대상 경로를 확인하여 수동으로 복원한다.

폴더 작업은 파일별 커밋이며 전체 폴더를 하나의 트랜잭션으로 되돌리지 않는다. 실패해도 안전하게 끝난 파일은 계속 처리할 수 있다. 안전한 실패는 최초에 고정한 해시와 같은 암호로 최초 1회와 추가 최대 2회, 총 3회까지 시도한다. 암호가 다른 파일의 실패도 이 한도에 포함한다. 성공·건너뜀은 다시 처리하지 않으며 취소·원본 변경·백업 변조·교체 상태 불확실·남은 Excel 프로세스·정리 실패에서는 자동 재시도하지 않는다. 안전하게 계속할 수 없는 상태는 배치를 중단하고 남은 파일을 미처리로 표시한다.

정상 종료와 안전한 실패·취소 뒤에는 해당 실행이 소유한 입력 복사본·임시 결과·암호 전달 파일을 정리한다. 재시도 전에 앞선 시도의 writer 종료와 정리 결과를 확인한다. 원본 백업은 보존하며 정상 교체 후 중복 recovery를 정리하려면 결과와 보존 백업이 모두 확인되어야 한다. 교체 결과 불확실·프로세스 종료 불확실·정리 실패에서는 필요한 복구 자료를 보존하고 경로를 안내한다. 이 경우 중간 파일이 없다고 표시하지 않는다. 비정상 종료 후 타 실행이나 사용자 파일을 이름만 보고 일괄 삭제하지 않는다.

백업·필요한 recovery에는 암호가 없던 원본이 그대로 남을 수 있다. 앱 제거 시 백업·복구 자료와 실패 보고서를 자동 삭제하지 않는다.

## 설치·업그레이드·제거

Windows x64용 MSI가 현재 사용자의 `%LocalAppData%\Programs\ExcelPasswordSafe`에 앱·런타임 스크립트·안내를 설치한다. HKCU의 확장자별 `SystemFileAssociations`에 기존 파일 메뉴를 유지하고 `Directory`에 제품 고유 폴더 하위 메뉴를 추가한다. Windows 11은 `더 많은 옵션 표시` 안의 메뉴가 대상이다. 기본 프로그램, 타 도구 메뉴, Explorer 설정은 보존한다.

최소 OS는 Windows 10 버전 2004 x64 또는 Windows 11 x64다. Windows PowerShell 5.1, .NET Framework 4.8 및 데스크톱 Microsoft Excel이 필요하다. MSI에 Excel을 포함하지 않는다. 새 버전 설치는 Windows Installer의 업그레이드 정책을 사용하며 설치 중단·복구·제거에서 업무 파일과 사용자 백업을 보존한다. 코드 서명·배포 주체·조직 승인 조건은 미결정이며 서명 없는 패키지는 로컬 평가용으로 표시한다.

1.2.0의 늦은 설치 실패 주입에서는 파일·메뉴 제거 뒤 제품 등록이 남는 제한이 확인됐다. 폴더 기능 추가로 이 제한이 해결됐다고 간주하지 않는다. 같은 MSI의 제거·재설치 복구 안내와 평가판 표시를 유지한다.

## 검증·지원

단위·통합 시험에는 잘못된 요청, 암호 길이, 승인 후 원본 변경, 잠금·읽기 전용, 백업·임시 파일 변조, 중단된 기록, 취소, 중복 실행과 원자 교체를 포함한다. 실제 Excel 시험은 합성 문서만 사용하여 설정→변경→해제와 잘못된 암호 실패를 확인한다. 한글·공백·특수문자 경로, WPF 화면, MSI 등록·복구·제거를 별도로 검증한다.

의미 비교는 파일 전체의 바이트 동일성, 그림 픽셀, OLE 내부 데이터, 매크로 동작, 외부 참조의 모든 특성을 보증하지 않는다. Office 버전·비트 수별 지원과 긴 경로 지원은 실제 시험한 범위만 주장한다. 일반 사용자 사용성·Windows 11 실제 메뉴와 서명 신뢰도 자동 빌드 성공으로 갈음하지 않는다.
