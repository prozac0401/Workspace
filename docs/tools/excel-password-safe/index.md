# Excel 파일·폴더의 암호 설정·해제·변경

ExcelPasswordSafe 1.4.0은 파일 하나 또는 폴더 아래의 Excel 파일에 열기 암호를 설정·해제·변경합니다. Windows 10 버전 2004 이상 또는 Windows 11 x64와 데스크톱 Microsoft Excel, Windows PowerShell 5.1, .NET Framework 4.8이 필요합니다. 실제 확인 범위는 [1.4.0 검증 기록](../../delivery/excel-password-safe-folder-20261116.md)에 구분합니다.

## 설치하고 시작하기

MSI로 현재 사용자에게 설치하고 열려 있는 Excel을 모두 정상 종료합니다. Windows 11 메뉴는 **더 많은 옵션 표시** 안에 있습니다.

| 대상 | 시작 방법 |
|---|---|
| Excel 파일 하나 | 파일 오른쪽 클릭 → **Excel 암호 관리** → 창에서 작업 선택 |
| 폴더와 모든 하위 폴더 | 폴더 오른쪽 클릭 → **Excel 암호 관리 → 암호 설정 / 암호 해제 / 암호 변경** |

`.xls`, `.xlsx`, `.xlsm`, `.xlsb`를 지원합니다. 파일 메뉴의 사용 방법은 이전 버전과 같습니다. 시작 메뉴에서 앱을 열어 파일을 선택할 수도 있습니다.

폴더 작업에서는 루트 경로와 하위 폴더를 포함한 대상 목록을 확인합니다. 표시된 목록에 공통 암호를 적용하며, 목록을 확정한 뒤 새로 추가한 파일은 이번 실행에 포함하지 않습니다. 접근할 수 없는 항목과 제외한 링크 경로도 확인하세요. 대상이 없는 폴더는 실행하지 않습니다.

## 작업과 암호

| 작업 | 입력할 내용 | 결과 |
|---|---|---|
| 암호 설정 | 새 암호 + 확인 | 다음에 파일을 열 때 암호가 필요함 |
| 암호 해제 | 현재 암호 | 다음에 파일을 열 때 암호가 필요하지 않음 |
| 암호 변경 | 현재 암호 + 새 암호 + 확인 | 새 암호로 파일을 열 수 있음 |

새 암호는 1~15자이며 대소문자를 구분합니다. 폴더 안 파일의 현재 암호가 서로 다르면 입력한 암호와 다른 파일은 실패할 수 있습니다. 암호 찾기나 셀·시트·통합문서 구조·쓰기 보호 해제는 제공하지 않습니다.

대상과 백업 안내를 확인한 뒤 실행합니다. 원본을 백업하고 복사본을 Excel에서 저장·다시 열어 검증한 다음 같은 경로의 파일을 교체합니다. 폴더는 하나씩 처리하므로 일부 성공과 일부 실패가 함께 있을 수 있습니다. 이미 성공한 파일은 다른 파일의 실패·취소 때문에 자동으로 되돌리지 않습니다.

취소는 현재 Excel 호출이 끝날 때까지 기다릴 수 있습니다. 이미 교체가 시작된 파일을 취소됐다고 표시하지 않으며 아직 처리하지 않은 파일은 구분합니다.

## 재시도와 실패 보고서

폴더 작업에서 안전하게 끝난 실패는 **최초 시도 포함 최대 3회** 처리합니다. 입력한 암호는 재시도 중에 바뀌지 않습니다. 파일 변경·백업 이상·교체 상태 불확실·남은 Excel·정리 오류에서는 3회 이전에도 멈춥니다. 검색 단계에서 접근하지 못한 항목은 시도 수가 0입니다.

최종 결과에서 실패한 파일명·전체 경로·이유·시도 수를 확인합니다. 실패가 있으면 **실패 보고서 열기**로 XLSX를 엽니다. 보고서는 `%LocalAppData%\ExcelPasswordSafe\Runs\배치ID\failure-report.xlsx`에 생성하므로 업무 폴더에 새 Excel 파일이 섞이지 않습니다. 안전 문제로 중단했다면 미처리 항목도 함께 확인합니다. 실패 없이 끝났거나 실패 없이 취소했다면 보고서를 만들지 않습니다. 보고서 생성 오류가 표시되면 실행 폴더의 결과 기록을 확인하세요.

보고서에는 파일 경로와 실패 이유가 들어가므로 다른 사람에게 전달하기 전에 내용을 확인하세요. 암호는 기록하지 않습니다.

## 백업과 중간 파일

**백업·기록 보기**로 실행 폴더를 엽니다. 파일 작업의 백업은 `%LocalAppData%\ExcelPasswordSafe\Runs\실행ID\original.확장자`, 폴더 작업의 백업은 배치 폴더 아래 각 시도 폴더의 `original.확장자`입니다.

정상 완료·안전한 실패·취소 뒤에는 해당 실행의 작업 복사본·임시 결과·암호 전달 파일과 확인된 중복 recovery를 정리합니다. **원본 백업은 남깁니다.** 암호 없는 원본의 백업도 암호가 없습니다. 필요가 끝난 백업은 확인한 뒤 직접 정리하세요. 앱 제거는 백업·보고서를 지우지 않습니다.

교체 결과나 Excel 종료가 불확실하면 필요한 복구 파일을 보존하고 경로를 안내합니다. 정리 오류가 표시되면 중간 파일이 남을 수 있습니다. 바로 다시 실행하지 말고 현재 파일·백업·필요한 recovery와 기록을 확인하세요. 복원하려면 Excel을 닫고 현재 파일을 별도로 보관한 뒤 원본 해시와 백업을 대조하여 복사합니다.

## 지원 범위와 오류 해결

로컬 고정 NTFS 경로를 사용합니다. 네트워크·이동식 드라이브·링크·오프라인·읽기 전용 파일은 제외합니다. 동기화 폴더는 별도 로컬 복사본으로 작업하세요. `.xls`는 BIFF8만 지원하며 형식을 자동 변환하지 않습니다. 서명된 문서·VBA, 공유·쓰기 예약 파일과 발견된 Excel 4.0 매크로 시트는 지원하지 않습니다.

`.xls`의 구형 RC4 암호화는 보안상 한계가 있어 민감한 자료 보호용으로 권장하지 않습니다. [Microsoft 암호화 명세](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-offcrypto/78b227ba-bb55-49d0-aa41-83644ca1963b)

파일 열기 실패는 암호 오류뿐 아니라 손상·보안 제한일 수 있습니다. 파일이 변경되었거나 잠겨 있으면 다른 앱에서 닫고 다시 선택하세요. 시간 초과나 Excel이 남아 있다는 안내에서는 Excel과 실행 기록을 먼저 확인합니다. 사용자 Excel을 강제 종료하지 않습니다.

수식·값·시트·도형 목록을 비교하지만 그림 픽셀·삽입 개체 내부·매크로 동작·외부 참조의 완전한 동일성은 보증하지 않습니다. 대표 파일의 복사본으로 확인하고 결과를 Excel에서 검토하세요.

## 설치 복구와 제거

설치 실패 후 앱 항목만 남거나 재설치해도 메뉴가 없으면 **같은 MSI를 다시 열어 프로그램 제거를 선택한 뒤 재설치**하세요. 이전 늦은 설치 실패 시험에서 설치 등록이 남는 사례가 확인됐으며 이번 버전에서 해결된 것으로 표시하지 않습니다. 레지스트리나 Windows 보안 설정을 직접 바꾸지 마세요.

제거는 **Windows 설정 → 앱 → 설치된 앱 → ExcelPasswordSafe → 제거**를 사용합니다. 프로그램과 자기 파일·폴더 메뉴만 제거하고 Excel 파일·기본 연결·다른 앱 메뉴·백업·보고서는 보존합니다. 패키지는 미서명 평가 상태이며 조직 배포 승인을 의미하지 않습니다.
