# 그림 복사·저장 — 요구명세 v1.1

- 작성일: 2026-09-24
- 개정일: 2026-09-25
- 문서 식별자: ImageCopySave-REQ-1.1
- 상태: 사용자가 저장 명령의 독립 메뉴 배치를 승인했다. 변경된 메뉴 배치·설치 경로의 실제 구현성은 G0 검증 전이다.
- 변경 범위: MNU-01·AT-08과 연관 시나리오·G0 시험 위치를 변경했다. 나머지 요구와 AT-01~AT-44 번호는 유지한다.
- 원본·결정 근거: [v1.0 원명세](ImageCopySave_Requirements_v1.0.md)는 수정하지 않고 보존한다. 메뉴 위치 변경은 [ADR-0016](../../design/0016-image-copy-save-direct-menu.md)를 따른다.
- 산출물 성격: 개발 착수용 요구명세. 구현 완료 보고서나 Windows 실기 시험 결과가 아니다.
- 플랫폼 기준: Windows 11 x64. 실제 검증한 에디션·버전·빌드만 지원 목록에 기재한다.

> 이미 복사한 그림을 현재 폴더에 저장하고, 이미 선택한 그림 파일을 이미지 자체로 복사한다.
> 이미지가 없는 상황에서는 저장 메뉴도 없어야 한다.

## 1. 제품의 경계

### 1.1 포함하는 기능

| ID | 기능 | 입력 | 출력 |
|---|---|---|---|
| PR-01 | 복사한 그림 저장 | 현재 클립보드의 지원 이미지 데이터 + 우클릭한 폴더 | 해당 폴더의 PNG 파일 1개 |
| PR-02 | 그림으로 복사 | 탐색기에서 선택한 지원 그림 파일 1개 | 다른 프로그램에 붙여넣을 수 있는 이미지 데이터 |
| PR-03 | 맥락에 따른 메뉴 표시 | 현재 폴더·선택 항목·클립보드의 지원 형식 유무 | 실행 대상이 없는 명령은 메뉴에서 숨김 |

두 기능은 하나의 독립 제품으로 설치·제거한다. 파일목록, 명단대조, 썸네일 도구에 임의로 합치지 않는다.

### 1.2 제외하는 기능

썸네일/사진 목록 생성, 캡처 도구, 이미지 편집, 크기 조절, 자르기, 여러 그림 합치기, 일괄 처리, OCR, AI 분석, 클립보드 기록, 자동 분류, 텍스트·표·HTML을 새 그림으로 렌더링하기, URL에서 이미지 다운로드, 이미지 파일 경로를 따라가서 대신 저장하기는 제외한다.

별도 메인 화면, 설정 대시보드, 계정, 앱 자체의 데이터베이스·클라우드 동기화·자동 업데이트 서비스도 두지 않는다. 일반 사용을 위해 PowerToys 등 다른 앱을 설치하도록 요구하지 않는다.

## 3. 메뉴 이름·위치 및 구현 검증 관문 G0

### 3.1 요청된 메뉴 위치

**저장 명령의 요청 위치**

```text
실제 로컬 파일시스템 폴더의 빈 공간에서 Windows 11 첫 우클릭 메뉴 열기
└─ 복사한 그림 저장    ← 독립 명령. 지원 이미지 데이터가 있을 때만 표시
```

**복사 명령의 요청 위치**

```text
지원 그림 파일 한 개에서 우클릭
└─ 그림으로 복사
```

| ID | 요구 |
|---|---|
| MNU-01 | 저장 명령 ‘복사한 그림 저장’은 실제 로컬 파일시스템 폴더 빈 공간의 Windows 11 첫 우클릭 메뉴에 독립 명령으로 배치한다. 기존 ‘새로 만들기’ 내부에는 넣지 않는다. |
| MNU-02 | 이미지가 없으면 저장 명령을 완전히 숨긴다. 사용자가 다음에 메뉴를 열 때 최신 상태가 반영되어야 한다. |
| MNU-03 | 복사 명령은 지원 파일 1개 선택 시에만 노출한다. 여러 파일·혼합 선택·폴더·지원하지 않는 확장자에서는 숨긴다. |
| MNU-04 | Windows 11의 첫 우클릭 메뉴에서 접근 가능해야 한다. ‘더 많은 옵션 표시’ 안에만 존재하는 구현은 목표 UX를 달성한 것이 아니다. |
| MNU-05 | 앱 전용의 비어 있는 상위 메뉴, 불필요한 구분선, 중복 명령을 남기지 않는다. Windows의 다른 ‘새로 만들기’ 항목은 건드리지 않는다. |
| MNU-06 | 메뉴를 열고 닫는 것만으로 이미지 저장·디코딩·전체 파일 읽기·클립보드 갱신을 시작하지 않는다. |

### 3.2 사실과 요구사항의 구분

Microsoft 공식 문서는 일반 탐색기 명령 확장에서 `IExplorerCommand.GetState`와 `ECS_HIDDEN` 등의 상태를 설명한다. v1.1에서는 native `IExplorerCommand`와 package identity를 사용하는 독립 명령 경로를 검증한다. 지원 이미지가 없거나 판정할 수 없으면 `ECS_HIDDEN`으로 완전히 숨긴다. 기본 ‘새로 만들기’의 `ShellNew` 등록은 이 저장 명령에 사용하지 않는다. [R01][R02][R03]

사용자는 ‘새로 만들기’ 내부에 두지 않아도 된다고 승인했으며, 이 개정은 **첫 우클릭 메뉴의 독립 명령 위치에서 조건부 숨김을 유지하고 검증하라**는 요구를 확정한다. 위치 승인이나 최소 구현을 해당 경로의 실제 작동·설치·배포 통과로 간주하지 않는다.

### 3.3 G0: 메뉴·설치 방식의 선행 검증

전체 제품 개발에 앞서 최소 시험용 확장으로 다음을 입증한다.

1. 실제 로컬 폴더 빈 공간의 Windows 11 첫 우클릭 메뉴에 독립 명령 ‘복사한 그림 저장’이 표시된다.
2. 이미지 → 텍스트만 있는 상태 → 빈 상태 → 이미지 상태로 바꾼 뒤 매번 메뉴를 다시 열면 표시/숨김이 즉시 맞게 바뀐다.
3. 숨겨야 할 때 회색 항목·유령 항목·빈 앱 하위 메뉴가 남지 않는다.
4. 동적 표시를 위해 상주 감시 프로그램, 반복적인 레지스트리 수정, Explorer 강제 재시작이 필요하지 않다.
5. 일반 사용자 설치·제거와 Windows 11 첫 메뉴 진입 방식이 함께 성립한다.

**G0 결과 처리**

- PASS: Windows 빌드, 등록 방식, 사용 API, 설치 권한, 화면 증거를 남긴 뒤 그 방식으로 개발한다.
- BLOCKED/FAIL: 시도한 방법과 결과를 기록한다. 이 개정에서 정한 독립 명령 위치를 다시 바꾸는 대안은 변경안으로만 보고한다. 추가 사용자 합의 없이 위치를 바꾸거나 항상 표시하는 방식으로 제품을 완성했다고 보고하지 않는다.
- G0 미통과 상태에서도 독립적인 이미지 엔진과 자동 테스트는 진행할 수 있다. 다만 전체 제품의 배포 가능 상태로 판정하지 않는다.
- 고정 `ShellNew` 템플릿/빈 PNG 생성, 사용자가 항상 보는 명령, OS 내부 메뉴 패치·비공개 후킹은 허용된 우회안이 아니다.

## 4. 클립보드 이미지 판정 계약

### 4.1 표시할 때와 숨길 때

| ID | 클립보드 내용 | 저장 메뉴 |
|---|---|---|
| CLP-01 | 지원 이미지 형식이 제공됨 | 표시 |
| CLP-02 | 이미지 형식과 텍스트 형식이 함께 제공됨 | 표시 |
| CLP-03 | 일반 글자·URL·HTML만 있음 | 숨김 |
| CLP-04 | 파일 목록/파일 경로만 있음. 파일명이 `.png`여도 동일 | 숨김 |
| CLP-05 | 클립보드가 비어 있음 | 숨김 |
| CLP-06 | 지원하지 않는 전용 형식/벡터 형식만 있음 | 숨김 |
| CLP-07 | 형식 판정에 실패하거나 신뢰할 수 없는 상태 | 숨김. 메뉴를 닫고 다시 열 때 재평가 |

파일이 화면에서 그림 아이콘/썸네일로 보이는 것과 클립보드에 이미지 데이터가 있는 것은 구분한다. 파일 목록만 복사된 경우 이 도구가 경로를 열어 그림으로 변환하지 않는다. Windows에는 파일 목록용 형식과 이미지용 형식이 구분되어 있다. [R04][R05]

같은 내용에 여러 클립보드 형식이 함께 제공될 수 있다. 출처가 Excel이나 브라우저라는 이유로 일괄 제외하지 않는다. 원본 앱이 이미 지원하는 이미지 형식을 제공했다면 저장 대상으로 삼되, 텍스트/HTML만 있는 내용을 이 도구가 렌더링하지는 않는다. [R06]

### 4.2 v1 이미지 입력 계약

- 저장 입력 후보: 등록 형식 이름 `PNG`, `CF_DIBV5`, `CF_DIB`, `CF_BITMAP`.
- `PNG`는 이 제품이 지원하기로 한 등록 형식 이름이다. `CF_*` 표준 형식과 구분해 구현한다.
- 벡터만 있는 `CF_ENHMETAFILE`, `CF_METAFILEPICT`, HTML/OLE 전용 데이터는 v1에서 직접 래스터화하지 않는다.
- 여러 이미지 표현이 함께 있으면 투명도와 품질 정보를 가장 잘 유지하는 지원 표현을 우선한다.
- 단순히 확장자 문자열·파일 경로·HTML의 이미지 태그가 있다는 이유로 ‘그림이 있다’고 판정하지 않는다.

### 4.3 빠른 표시 판정과 실제 검증의 구분

**CLP-08 — 형식 가용성과 정상 데이터 여부를 분리한다.**

메뉴를 여는 시점에는 **지원 형식이 제공되는지**만 빠르게 확인한다. `IsClipboardFormatAvailable` 등의 형식 확인과 실제 이미지 읽기/디코딩을 분리한다. 지원 형식 이름이 있다고 데이터가 정상이라는 보장은 없으므로 손상된 데이터, 과대 크기, 읽기 실패는 실행 시 검증한다. [R04][R07]

‘정상적인 비이미지에는 메뉴가 없음’과 ‘지원 이미지라고 제공되었으나 손상되어 실행 실패’는 서로 다른 상황이다. 후자는 오류 안내가 가능하지만 전자의 대체 UX로 사용하지 않는다.

메뉴를 이미 열어 둔 동안의 실시간 표시 변경은 v1 요구가 아니다. 메뉴를 다시 열 때 재평가하는 것은 필수이며, 실제 명령 실행에서도 상태를 다시 확인한다.

## 5. 기능 A — 복사한 그림 저장

### 5.1 정상 시나리오

```text
그림 복사/캡처
→ 저장할 실제 폴더의 빈 공간 우클릭
→ 첫 우클릭 메뉴의 복사한 그림 저장
→ 그 폴더에 PNG 생성
→ 생성된 파일 선택
```

| ID | 확정 동작 |
|---|---|
| SAV-01 | 저장 위치는 명령을 호출한 폴더의 실제 경로다. 최근 사용 경로, 프로세스 작업 폴더, 나중에 활성화된 다른 탐색기 창으로 추측하지 않는다. |
| SAV-02 | 실행 시 현재 클립보드를 읽어 확보한 이미지 한 장을 사용한다. 메뉴 표시 시 과거 이미지의 전체 바이트를 캐시해 두었다가 저장하지 않는다. |
| SAV-03 | 클립보드 데이터를 유효한 스냅샷으로 복사한 뒤에는 그 스냅샷을 처리한다. 처리 도중 새로 복사된 내용과 섞지 않는다. |
| SAV-04 | 출력 형식은 PNG로 고정한다. 형식 선택·저장 위치·파일명 입력을 요구하지 않는다. |
| SAV-05 | 기본 파일명은 PC 현지 시각 기준 `그림_YYYYMMDD_HHMMSS.png`다. |
| SAV-06 | 같은 이름이 있으면 `_2`, `_3` 등을 붙인다. 병렬 실행에서도 기존 파일을 덮어쓰지 않는다. |
| SAV-07 | 성공 후 원래 작업 폴더에 파일을 반영하고 가능하면 해당 탐색기 보기에서 선택한다. 이미지 뷰어·새 탐색기 창·자동 이름변경 모드를 열지 않는다. |
| SAV-08 | 저장은 클립보드의 기존 내용을 의도적으로 비우거나 교체하지 않는다. 연속으로 다른 폴더에도 저장할 수 있어야 한다. |
| SAV-09 | 최종 PNG는 유효하게 인코딩된 결과만 나타나게 한다. 빈 PNG를 먼저 만들고 후처리하는 방식은 금지한다. |
| SAV-10 | 실행 시 이미지가 없어졌거나 유효하지 않으면 파일을 만들지 않는다. 메뉴 이후 상태 변화, 데이터 손상, 접근 실패 등 실행 단계에서 발견되는 예외는 안내하되 정상적인 비이미지 상태의 메뉴 노출을 대신하는 방식으로 쓰지 않는다. |

예시 파일명:

```text
그림_20260924_183000.png
그림_20260924_183000_2.png
```

클립보드 변경 여부 추적에 시퀀스 번호를 사용할 수 있으나, 지연 렌더링에 따른 변화와 사용자의 새로운 복사를 구분 없이 취급하지 않는다. 시퀀스 번호만으로 데이터 일관성이 보장된다고 가정하지 말고 실제 스냅샷 수집을 안전하게 구현한다. [R08]

### 5.2 파일 생성 안전성

같은 대상 폴더에 충돌 없는 앱 소유 임시 파일로 기록하고, 인코딩과 쓰기 완료 후 덮어쓰기 없는 최종 이름 전환을 수행한다. 이름 존재 확인 후 무조건 덮어쓰는 경쟁 조건을 만들지 않는다.

정상적인 오류/취소에서는 자신이 만든 임시 파일을 정리한다. 강제 종료·전원 차단으로 임시 파일이 남는 경우까지 ‘절대 잔재 없음’이라고 보장하지 않는다. 잔재 정리는 명백히 앱이 만든 파일만 대상으로 하며, 다른 파일을 이름 패턴만으로 삭제하지 않는다.

저장은 성공했지만 화면 선택만 실패한 경우 저장 자체를 실패로 보고하지 않는다. 결과 경로를 확인할 수 있는 비모달 안내만 제공하고, 새 창을 강제로 열지 않는다. 사용자가 이미 다른 탭으로 이동한 경우 포커스를 빼앗지 않는다.

**실패 시 보존의 한계:** 이미지 준비 이전/도중의 실패와 잠금 획득 실패는 기존 클립보드를 보존해야 한다. 다만 운영체제에 실제 클립보드를 교체하는 도중 생긴 실패까지 임의의 모든 원본 형식을 완전히 복구한다고 약속하지 않는다. 커밋 전 모든 자원을 준비하고, 커밋 실패를 성공으로 숨기지 않으며, 오류 보고에 보존 여부를 정확히 기록한다. 다른 앱의 임의 형식까지 무조건 백업·복원하는 별도 기능은 만들지 않는다.

복사 처리 도중 사용자가 더 최근에 다른 내용을 복사한 것이 확인되면, 오래 걸린 작업이 그 새 내용을 뒤늦게 덮어쓰지 않도록 중단하는 정책을 적용한다. 지연 렌더링에 의한 시퀀스 변화는 실제 사용자 입력과 구분해 시험한다.

**초기 안전 상한 — 이 제품의 설계값이며 Windows의 공식 한계가 아님**

- 가로·세로 각각 최대 16,384 픽셀.
- 총 픽셀 수 최대 50,000,000.
- 입력 파일 또는 단일 압축 클립보드 페이로드 최대 128 MiB.
- 정규화된 단일 4바이트/픽셀 이미지 버퍼 최대 256 MiB.
- 크기·stride·오프셋·헤더 길이 계산에 정수 오버플로를 허용하지 않는다.
- 실제 메모리 확보가 불가능하면 안전하게 실패한다. 상한 안이라고 모든 환경에서 성공하는 것은 아니다.

경계값은 코드 상수와 테스트에서 일치시킨다. 실측 후 변경이 필요하면 명세 버전을 갱신하며, 기능을 성공시키기 위해 몰래 축소하지 않는다.

Microsoft의 Windows Imaging Component에는 PNG/JPEG/BMP 관련 기본 코덱이 제공된다. 이 제품은 이러한 OS 이미지 기능을 활용하는 경량 구현을 우선 검토하되, 설치된 타사 코덱 전체로 지원 범위를 자동 확장하지 않는다. [R11]

## 11. 권장 구현 경계 — 요구사항을 바꾸지 않는 범위

```text
Explorer / Shell 통합 모듈
  ├─ 현재 선택·폴더 식별
  ├─ 지원 형식/선택 수의 빠른 확인
  └─ 명령 실행을 helper에 위임

작업 helper
  ├─ 클립보드 스냅샷 확보 또는 선택 파일 읽기
  ├─ 지원 범위/데이터 크기/헤더 검증
  ├─ PNG 생성 또는 이미지 클립보드 게시
  ├─ 필요한 최소 피드백과 정리
  └─ 종료
```

C++ 기반 native Shell 통합과 Win32/WIC 처리 계층을 우선 검토한다. 언어 자체보다 G0·보안·응답성·설치 기준 충족이 중요하다. 공식 문서상 IExplorerCommand의 native COM DLL, 패키지 등록, sparse package 방식 등이 검토 대상이다. v1.1은 native IExplorerCommand와 package identity 경로의 최소 구현을 검증 대상으로 삼으며, 일반 사용자 설치·동적 숨김·첫 우클릭 메뉴 배치는 실제 G0 시험 전까지 입증된 것으로 보지 않는다. [R01]

테스트를 위해 Shell과 이미지 엔진을 분리한다. helper 호출 경로에는 외부 입력에 의해 임의 명령이 실행되지 않도록 구조화된 인수 전달·경로 검증을 적용한다. 명령행 문자열을 붙여 shell 해석으로 실행하지 않는다.

## 13. 마일스톤과 완료 정의

### M0 — G0 실제 메뉴/패키징 검증

요청한 실제 로컬 폴더 빈 공간의 독립 명령 위치, 동적 숨김, Windows 11 첫 메뉴, 사용자별 설치 가능성을 먼저 시험한다. 요구를 만족하지 못한 고정 메뉴를 완성품으로 제출하지 않는다.

### M1 — 이미지 엔진과 자동 시험

클립보드 스냅샷, 이미지 디코딩, PNG 인코딩, 충돌 없는 파일 생성, 지속 가능한 클립보드 게시, 손상/상한 검증을 Shell과 독립적으로 만든다. 단위시험 결과를 남긴다.

### M2 — Shell 연결과 실제 사용 시험

호출 폴더·탭 식별, 파일 선택 표시, 메뉴 재평가, 작업 후 피드백을 연결한다. 실제 탐색기와 대상 프로그램 붙여넣기를 검증한다.

### M3 — 배포·제거·회귀 검증

깨끗한 Windows 환경에서 설치부터 제거까지 시험하고, 사용자에게 수동 준비 작업이 남지 않는지 확인한다.

**완료 조건**

- PR/UX 및 G0 요구를 충족한다.
- 표의 해당 필수 시험을 실제 확인하고, PASS/FAIL/BLOCKED/NOT RUN을 구분한다.
- 특정 앱 호환성을 확인하지 않았다면 그 앱을 지원한다고 포괄 표기하지 않는다.
- 재현 가능한 소스·빌드 절차·설치/제거 패키지·시험 증거를 함께 제공한다.
- ‘이미지가 없는데 명령이 남음’, ‘더 많은 옵션 안에만 존재’, ‘helper 종료 후 붙여넣기 실패’, ‘원본/기존 파일 훼손’, ‘사용자 수동 등록 필요’ 중 하나라도 있으면 출시 기준 미달이다.
- 이 개정의 메뉴 위치 변경은 사용자 승인에 따른다. 이후 메뉴 위치를 다시 바꿔야 할 경우 별도 요구 변경으로 취급한다. 위치 변경 승인만으로 G0 미통과 상태가 해소되지는 않는다.

- 2026-09-25 · v1.1: 사용자가 ‘새로 만들기’ 내부 배치 조건을 해제했다. 저장 위치를 실제 로컬 폴더 빈 공간의 Windows 11 첫 우클릭 메뉴 독립 명령으로 정하고 MNU-01·AT-08과 연관 G0·사용 시나리오를 갱신했다. 이미지가 없으면 완전 숨김, 무상주, 기존 New 무변경, 첫 메뉴 접근, 일반 사용자 설치 기준과 44개 AT 번호는 유지한다. 최종 경로의 G0 실기 검증은 NOT RUN이며 구현 완료·실기 PASS·출시 승인을 뜻하지 않는다. 서명·패키지 신뢰·조직 정책은 이번 위치 승인으로 결정되지 않았다.
