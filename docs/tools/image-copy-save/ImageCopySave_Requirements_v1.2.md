# 그림 복사·저장 — 요구명세 v1.2 변경 계약

- 작성·개정일: 2026-09-27
- 문서 식별자: ImageCopySave-REQ-1.2
- 상태: 사용자 승인 요구 채택. 새 등록 방식과 실제 메뉴·제품 MSI 시험은 별도 검증 대상이다.
- 제품 책임: 도구 개발·검증 담당
- 적용 정책: [추가 도구 개발 기준](../../policies/tools.md), [정책 문서 작성 규칙](../../policies/documentation.md)
- 관련 결정: [ADR-0023](../../design/0023-image-copy-save-classic-menu.md), 설치 권한의 [ADR-0022](../../design/0022-image-admin-install.md)
- 원본 보존: [v1.0](ImageCopySave_Requirements_v1.0.md)과 [v1.1](ImageCopySave_Requirements_v1.1.md)은 당시 요구와 근거로 보존한다.

## 1. 적용 방식과 변경 범위

이 문서는 v1.1 전체 요구에 적용하는 변경 계약이다. 아래에서 대체한 문구와 그 직접적인 사용 시나리오·관문·판정이 우선한다. 나머지 PR, UX, CLP, SAV, CPY, IMG, NFR, SEC 요구와 AT-01~AT-44 번호는 유지한다. v1.1의 “Windows 11 첫 우클릭 메뉴”, “더 많은 옵션 표시 전용은 불합격”, “관리자 권한 없는 사용자별 설치”를 현재 조건으로 다시 적용하지 않는다.

목적은 이미 복사한 이미지를 호출한 실제 폴더에 PNG로 저장하고, 선택한 지원 이미지 파일 한 개를 이미지 데이터로 복사하는 것이다. 이번 변경은 공통 클래식 메뉴의 위치와 설치 경로를 바꾸며 이미지 처리·원본 보존·완전 숨김·무상주 계약을 바꾸지 않는다.

## 4. 등록·권한·데이터 경계

현재 검증 대상으로 native IExplorerCommand의 ExplorerCommandHandler 등록을 선택한다. MSI가 HKLM의 제품 소유 x64 COM·폴더 배경·지원 이미지 verb 등록과 프로그램 파일을 관리하는 방식이다. 실제 클래식 메뉴가 이 등록을 사용하여 GetState의 숨김과 호출 문맥을 충족하는지는 G0 실기로 확인한다.

이 방식의 인수에 성공하면 제품의 MSIX/sparse package identity·사용자별 패키지 등록을 필수 설치 경로에서 제외한다. 이전 MSIX 시험·진단 MSI와 오류 기록은 이력으로 보존한다. 인증서 신뢰 저장소·개발자 모드·보안 정책을 바꾸거나 서명된 내부 패키지를 숨겨 넣지 않는다.

기존 PNG/JPEG/BMP의 기본 연결, 일반 복사·붙여넣기, Windows ‘새로 만들기’, 타사 메뉴는 보존한다. 원본 이미지는 읽기 전용이고 저장 파일은 기존 파일을 덮어쓰지 않는 PNG 생성 계약을 유지한다. 저장은 클립보드를 변경하지 않는다. 복사는 준비가 완료된 후에만 클립보드를 교체하고 확인된 더 새로운 복사를 뒤늦게 덮어쓰지 않는다.

## 5. 시험을 위한 메뉴 모드 전환과 복구

사용자는 이번 검증을 위해 메뉴 모드를 잠시 전환하고 원래 상태로 복구하는 작업을 승인했다. 이 승인은 시험 작업에 한정되며 제품 설치기가 사용자의 메뉴 모드를 바꾸는 기능을 뜻하지 않는다.

시험 시작 전에 관련 설정의 존재 여부·값·형식과 원래 메뉴 상태를 기록한다. 변경은 승인된 메뉴 모드 설정에 한정하고 업무 파일과 다른 설정은 보존한다. 시험 후 원래 상태를 복구하고 두 모드의 실행 결과·복구 결과를 구분해 남긴다. 새로 생긴 외부 변경이 있으면 시작 시 스냅샷으로 무조건 덮어쓰지 않고 충돌로 기록한다.

제품의 DEP-08은 유지한다. 평소 명령이나 설치가 Explorer 강제 종료를 정상 흐름으로 요구하지 않는다. 이번 사용자 승인 시험의 모드 갱신과 제품의 무상주·무강제종료 요구를 별개로 기록한다. 복구 미실행·실패가 있으면 완료로 표시하지 않는다.

| AT-10~AT-12 | 메뉴 열기만으로 파일·클립보드를 변경하지 않고, 지원 이미지 한 개에서만 복사 명령을 제공하는 기존 기준을 유지한다. |
| AT-40 | MSI 설치·재설치·업데이트·실패 복구·제거, 중복 등록·잔재 부재, 사용자 PNG·기존 파일·타사 설정 보존을 실제 확인한다. |

| AT-42·AT-44 | 무상주·기존 연결·복사/붙여넣기·다른 메뉴 회귀를 확인한다. 모드 전환 시험 후 원래 설정 복구도 별도로 기록한다. |

AT-13~AT-39와 AT-43의 이미지 기능·실패·성능·외부 앱·원본·로그 계약은 유지한다. 과거 엔진/helper·Paint·관리자 identity 시험의 PASS는 당시 범위에서만 인정하며 새 클래식 G0·MSI·Windows 10 OS의 통과로 소급 변환하지 않는다.

M1은 기존 독립 이미지 엔진·자동시험, M2는 개정 메뉴와 실제 호출·피드백·탭 문맥, M3는 최종 제품 MSI의 설치 수명주기와 지원 범위를 검증한다. 최종 결과는 PASS/FAIL/BLOCKED/NOT RUN을 구분한다. 설치·G0가 미완료면 제품 배포 가능 또는 상용 승인 상태로 분류하지 않는다.

## 7. 현재 검증 상태와 기록 위치

2026-09-27 후속 중간 실기에서 Windows 11 클래식 직접 표시 모드의 독립 저장 명령, 합성 이미지 실제 PNG 저장·PNG 파일 이미지 복사, 텍스트·빈 상태·URL/HTML·실제 파일 클립보드에서 저장 항목 완전 숨김, 이미지+텍스트에서 표시를 확인했다. 무서명 자체 포함 MSI의 0.1.0 설치·손상 DLL Repair, 0.1.0→0.1.1 업데이트·제거·깨끗한 상태의 의도된 설치 실패 롤백·0.1.1 재설치는 확인한 시나리오에서 PASS다. 각 단계에 재부팅 요구와 Explorer 재시작이 없었고 합성 보존 PNG 해시를 유지했다. 실제 설치 helper·Explorer의 비상승 실행은 앞선 0.1.0 실제 저장에서 확인했다.

클래식 직접 표시의 상태 전환은 0.1.0에서 8회 통과했다. 0.1.1 재설치 후 9회차 재개 시 UI 도구의 창 활성화 오류가 반복되어 추가 UI 관찰은 0건이다. 20회 시험은 미완료이며 제품 메뉴 실패로 계상하지 않는다. 앞선 0.1.0 실제 메뉴 결과를 0.1.1 실기로 대신하지 않는다. 기본 새 메뉴의 ‘더 많은 옵션 표시’ 경로와 모드 원상복구는 이 중간 기록에서 **NOT RUN**이다. 메뉴 설정은 Inspect로 읽기만 했으며 실제 모드 전환은 하지 않았다. 최초 업그레이드 요청의 UAC 취소와 이후 실제 업데이트 완료를 구분하고, 완료된 업데이트 결과를 읽던 시험 실행기의 JSON 파싱 오류·수정·재실행 이력도 보존한다. 최종 시험 상태는 0.1.1 설치 유지이며 전체 G0·제품 배포 가능 판정은 미완료다. 개별 사례와 로컬 증거는 [G0 기록](G0_Menu_Feasibility.md), [구현 대응표](index.md), [수용시험 기록](../../../tools/ImageCopySave/TEST_RESULTS.md)에 연결한다.

2026-09-27 · v1.2: 클래식 직접 표시·파일 클립보드 숨김, 설치·Repair·업데이트·제거·설치 실패 롤백·재설치, 비상승 런타임의 실기 결과를 범위별로 기록했다. 사용자가 공통 클래식 메뉴를 요구하고 시험용 모드 전환·원상복구를 승인했다. 관리자 무서명 MSI·일반 사용자 실행을 결합하고, 이전 첫 Windows 11 메뉴의 필수 조건을 대체했다. 원본 v1.0/v1.1과 이전 실행 기록은 보존한다.
