문서 목적
브라우저에서 연도와 공휴일을 설정한 뒤, 1월부터 12월까지 한 시트에 담긴 편집 가능한 .xlsx 달력을 내려받는 MVP를 정의한다. 각 주는 날짜 1행과 빈 작성칸 3행으로 구성한다. 한국천문연구원 특일 정보 API를 공식 공휴일의 기본 출처로 사용한다.
이 문서는 구현 착수와 인수 검수의 기준이다. 기존 2027년 예시 엑셀은 형식 논의를 위한 산출물이며, 웹 생성기는 아직 구현되지 않았다. 사용자는 API 인증키를 발급받은 상태다. 인증키 값은 이 문서와 예제에 포함하지 않는다.
요구사항의 구분
확정은 사용자가 요청하거나 동의한 요구사항이다. 구현 기본값은 개발을 바로 시작할 수 있도록 제안한 설계 선택이며, 사용자 확정 사항으로 취급하지 않는다. 기본값 변경 시 관련 테스트와 명세 버전을 함께 갱신한다.

MVP 완료의 핵심
공식 공휴일 조회의 성공 여부가 분명하고, 미리보기와 파일이 같은 데이터를 사용하며, 모든 유효 날짜에 독립적인 빈 작성 셀 3개가 있어야 한다. API 장애를 공휴일 없음으로 바꾸어 조용히 다운로드시키지 않는다.

지원 범위
한국의 양력 달력과 공휴일 정보를 대상으로 한다. 제안하는 연도 입력 범위는 1900~2100년의 정수다. 달력 계산 가능 범위와 API 자료 가용 범위는 별개다. 특정 연도의 자료 존재 여부를 응답 없이 보장하지 않는다.
제외 범위
웹에서 일정 내용을 입력하거나 서버에 저장하는 기능, 음력 날짜와 24절기 표시, 주별 또는 월별 별도 시트, 달력 구독과 동기화, 로그인, 결제, 조직별 권한, 기존 엑셀 파일 업로드 및 재편집은 MVP에 포함하지 않는다. 다운로드 후 작성한 내용은 앱에서 다시 읽거나 갱신하지 않는다.
모바일에서도 설정 및 다운로드를 제공하되, 미리보기는 가로 스크롤을 허용한다. 인쇄 및 상세 편집은 데스크톱 엑셀을 기준으로 검수한다. 특정 호스팅 업체나 유료 서비스 계약은 이 명세에서 선택하지 않는다.
2 화면 흐름과 상태
기본 흐름
① 연도 선택 → ② 공식 공휴일 조회 → ③ 휴일 목록 확인 및 수동 추가 → ④ 12개월 미리보기 → ⑤ 엑셀 다운로드 순서로 진행한다. 조회 중에는 진행 상황을 표시하고, 연도를 바꾸면 이전 연도의 조회 결과와 미리보기를 무효화한다.
연도 변경 시 작성 중인 수동 휴일이 있으면 해당 연도 목록을 버릴지 확인한다. 다운로드 시점에 미리보기와 동일한 불변 스냅샷을 사용한다. 설정 변경 후 새 미리보기가 준비되지 않았다면 다운로드를 막는다.
상태 | 화면과 허용 동작
idle / loading | 연도 입력 또는 12개월 조회 중. 공식 휴일 기반 다운로드 비활성화.
ready | 12개월 수집 완료. 공식 휴일 수, 수동 휴일 수, 조회 시각, 출처 표시. 다운로드 가능.
partial / error | 실패한 월과 재시도 안내. 정상 월만 합쳐 완성된 연간 달력처럼 내보내지 않음.
stale | 이전 완전 캐시만 있음. 기준 시각과 최신성 경고 표시. 사용자의 명시적 선택 후에만 다운로드.
manual | 사용자가 수동 자료만 사용하기를 선택. 공식 자료 미확인 경고와 직접 입력 목록 검토 필수.
exporting / done | 중복 클릭 방지. 완료 알림 또는 파일 생성 실패 시 재시도. 완료는 브라우저 파일 생성 기준.

수동 휴일 편집
날짜, 이름, 구분(개인 또는 회사 휴일)을 입력한다. 수동 항목만 삭제·수정할 수 있다. 같은 날짜의 공식 휴일과 수동 휴일은 함께 표시하며, 수동 입력으로 공식 휴일을 덮어쓰거나 삭제하지 않는다. 공식 자료 정정·제외 기능은 MVP에서 제공하지 않는다.
이름은 앞뒤 공백을 제거한 1~50자, 줄바꿈 및 제어문자는 거부한다. 날짜는 선택 연도 내 실재하는 YYYY-MM-DD만 허용한다. 최대 100개를 허용하고, 날짜·정규화 이름·출처가 모두 같은 항목의 중복 입력은 거부한다.
장애 시 명시적 선택
일반 오류 화면의 기본 동작은 재시도다. 캐시 또는 수동 모드 선택은 별도 확인 동작으로 처리한다. 공식 휴일이 전혀 검증되지 않은 상태에서 경고 없이 계속 진행하는 버튼을 두지 않는다. 수동 모드에서 휴일을 하나도 입력하지 않으면 그 사실을 재확인한다.
3 엑셀 시트와 좌표 규칙
파일명은 calendar_YYYY.xlsx, 시트명은 YYYY년 달력으로 한다. 아래 행 번호는 1부터 시작한다. 연간 제목·안내와 월 제목 외의 셀은 병합하지 않는다.
위치 | 내용
A1:G1 병합 | 연간 제목 YYYY년 달력
A2:G2 병합 | 자료 출처 · 자료 기준 시각 · 생성 시각 · ready/stale/manual 상태
A3:G3 병합 | 범례 및 공식 공휴일의 추가·변경 가능성 안내

s+1행 | A:G에 일 월 화 수 목 금 토
s+2 이후 | 각 주마다 날짜 행 1개와 빈 작성 행 3개
월 마지막 이후 | 빈 구분 행 1개 후 다음 월 시작

좌표 계산
1월의 시작 행 s₁=5. 월 첫날 요일 o는 일=0부터 토=6이다. 월의 일 수를 n이라 할 때 주 수 w=ceil((o+n)/7)로 계산한다. 따라서 월별로 4주, 5주 또는 6주가 생긴다. 무조건 6주를 만들지 않는다.
날짜 d의 위치 k=o+d−1, 주 번호 q=floor(k/7), 열 c=(k mod 7)+1이다. 날짜 행 r=s+2+4q, 작성 행은 r+1, r+2, r+3이다. 다음 월의 시작 행은 s다음=s+3+4w이다. 마지막 12월 뒤의 구분 행은 인쇄 영역에서 제외한다.
월 시작 이전과 월 끝 이후의 칸은 날짜와 작성칸 모두 빈 상태로 둔다. 인접 월 날짜를 중복해서 넣지 않는다. 외부 월 영역은 옅은 회색 배경으로 구분하지만 값을 만들거나 셀을 잠그지 않는다.
검증용 예시
2027년 1월은 금요일 시작, 31일, 6주다. 1월 시작은 5행이고, 1일은 F7, 작성칸은 F8:F10이다. 31일은 A27, 작성칸은 A28:A30이다. 31행은 구분 행이며 2월 제목은 32행이다. 이는 좌표 규칙 확인용이며 해당 날짜의 공휴일 API 실응답을 검증한 예시는 아니다.
날짜 행의 표시 문자열은 “1” 또는 “1
신정”과 같이 일자 및 휴일명이다. 날짜 의미는 별도의 달력 모델에서 ISO 날짜로 유지한다. 표시 셀은 계산용 날짜 일련번호가 아닌 텍스트로 저장한다.
4 표시 규칙과 인쇄
셀 표현의 기본값
A:G 열 너비는 동일하게 18 문자 단위를 초기값으로 사용한다. 날짜 행은 최소 34pt, 작성 행은 각각 22pt로 설정한다. 글꼴은 맑은 고딕 10pt를 요청하되, 설치되지 않은 환경의 대체 글꼴 차이를 허용한다. 글꼴과 줄 높이의 실제 결과는 지원 엑셀 환경에서 검수한다.
날짜 행은 위쪽·왼쪽 정렬, 자동 줄바꿈이다. 공휴일명이 여러 개면 날짜 다음 줄에 공식 휴일 먼저, 수동 휴일 다음 순서로 한 줄씩 표시한다. 같은 출처 내에서는 이름 오름차순으로 고정한다. 동일 이름은 표시에서 한 번만 쓰되 출처 메타데이터는 보존한다.
긴 이름은 생략 부호로 자르거나 작성 행을 침범하지 않는다. 열 너비에 따른 예상 줄 수를 계산해 같은 주의 날짜 행 전체 높이를 늘린다. 엑셀과 브라우저에서 글꼴 폭이 다를 수 있으므로 여유를 둔다. 겹침이 과도하여 지원 가능한 행 높이 안에 이름을 담을 수 없으면 해당 날짜와 사유를 표시하고 다운로드를 막는다. 이름을 조용히 생략하지 않는다.
대상 | 시각 규칙
평일 | 검정 글자와 흰 배경
일요일 또는 공식 공휴일 | 짙은 빨강 글자. 공식 휴일이 토요일이면 빨강 우선.
토요일 | 파랑 글자. 공식 공휴일 규칙이 있으면 그 규칙 우선.
수동 휴일 | 이름 앞에 [회사] 또는 [개인] 표기. 주말·공식 휴일 색을 유지하며 그 외는 짙은 보라.
주 및 날짜 구역 | 모든 셀 얇은 회색 테두리. 각 주 바깥 경계는 약간 굵게 하여 4행 묶음 식별.
작성 3행 | 안내 문자와 휴일명을 쓰지 않는다. 빈 값 상태로 테두리·정렬·스타일만 지정.

인쇄 기본값
달력 파일은 A4 세로, 너비 1페이지 맞춤, 높이 자동으로 설정한다. 2~12월 제목 앞에 수동 페이지 나눔을 둔다. 목표는 월당 1페이지이나, 긴 휴일명으로 월 높이가 커지면 잘라내지 않고 추가 페이지를 허용한다. 페이지 나눔과 크기 맞춤 조합은 실제 엑셀에서 확인하고, 충돌하면 월당 1페이지 강제보다 내용 가독성을 우선한다.
인쇄 영역은 A1부터 G열의 12월 마지막 작성 행까지다. 별도 표제 행 반복은 설정하지 않는다. 눈금선은 화면·인쇄에서 숨기되 셀 테두리는 유지한다. 시트 보호, 매크로, 외부 링크, 데이터 연결, 자동 실행 스크립트는 포함하지 않는다.
5 공식 공휴일 조회와 장애 처리
출처는 한국천문연구원 특일 정보의 공휴일 조회 기능 getRestDeInfo다. 기념일 전체를 공휴일로 취급하지 않는다. isHoliday가 Y인 항목만 공식 휴일 목록에 사용한다. 토요일·일요일은 달력 계산으로 별도 처리하며 API에 매주 주말이 포함된다고 가정하지 않는다.
호출 주소: https://apis.data.go.kr/B090041/openapi/service/SpcdeInfoService/getRestDeInfo
요청과 파싱
서버가 solYear=YYYY와 solMonth=01~12를 항상 제공하여 월별로 조회한다. ServiceKey, pageNo, numOfRows를 전달한다. MVP는 XML을 기준 포맷으로 구현한다. JSON 지원과 CORS 동작은 사전 검증되지 않았으므로 의존하지 않는다. 키 인코딩 방식은 개발자의 승인된 테스트에서 한 번 확인하고 이중 URL 인코딩을 방지한다.
월별 첫 페이지부터 totalCount에 도달할 때까지 페이지를 읽는다. pageNo=1, numOfRows=100을 제안하며 허용 범위는 실제 서비스 응답으로 확인한다. 단일 item과 복수 item, 정상적인 빈 items를 모두 배열로 정규화한다. 페이지 정체·중복 반복·응답 총건수 변동·날짜 범위 불일치는 수집 오류로 처리한다.
HTTP 성공과 XML 파싱 성공만으로 충분하지 않다. 업무 응답 resultCode=00, 필수 필드, totalCount 및 페이지 일관성까지 확인한다. 오류 XML·게이트웨이 오류·HTML 응답도 실패다. totalCount=0인 정상 응답은 해당 월의 유효한 빈 결과다. 휴일 필터 이전의 원본 건수로 페이지 완전성을 검증한다.
완전성과 최신성
12개월의 모든 페이지가 정상 수집되어야 complete=true다. 이는 조회가 완전하다는 뜻이며 미래에 지정될 임시공휴일까지 확정되었다는 뜻은 아니다. 정상 빈 월을 허용하되 연간 공식 휴일이 0개면 자료 미공개 가능성 오류로 처리한다. 공식 조회를 ready로 만들지 않으며 재시도 또는 수동 모드를 선택하게 한다.
완전한 연간 스냅샷만 캐시에 반영한다. 제안 TTL은 24시간, 이전 캐시 사용 상한은 30일이다. 조회 실패 시 최신 완전 캐시가 있으면 stale로 제시하고 동의 후 사용한다. 캐시 없음 또는 상한 초과이면 기본 다운로드를 막고 재시도나 명시적 수동 모드만 제공한다.
재시도와 운영 한계
요청별 제한시간은 8초, 일시적 네트워크·429·5xx는 최초 호출 후 최대 2회 재시도한다. 1초·2초 지수 대기와 무작위 지연을 적용하고 Retry-After가 있으면 우선한다. 인증·권한·입력 오류는 자동 반복하지 않는다. 동시 상위 호출은 최대 3개, 연간 조회 총 제한시간은 60초를 제안한다.
대체공휴일 반영은 공식 공지·관보 공포 이후 자료 확인이 필요하며, 임시공휴일의 즉시 반영을 보장하지 않는다. 조회 시각과 이 한계를 화면 및 파일에 표시한다. 정기 자동 갱신이나 사용자에게 배포된 파일의 사후 수정은 MVP 범위 밖이다.
6 데이터 모델과 내부 API 계약
아래는 애플리케이션 자체 계약이며 외부 제공기관의 원본 스키마를 그대로 노출하지 않는다. 날짜는 YYYY-MM-DD 문자열, 조회 시각은 UTC ISO 8601로 저장하고 화면·파일에서는 Asia/Seoul로 표시한다. 날짜만 있는 값을 UTC 자정으로 변환하여 하루가 이동하는 처리를 금지한다.
모델과 필드 | 형식과 의미
CalendarConfig | year: 정수 1900~2100; writingRows: 상수 3; weekStartsOn: 상수 0; locale: ko-KR; layout: vertical
HolidayRecord | date: ISO 날짜; name: 1~50자; source: official/manual; category: public/company/personal; sourceId: 출처 식별자
OfficialRaw | locdate: 8자리 날짜; dateName: 이름; isHoliday: Y/N; seq 및 dateKind는 수신 시 보존
HolidaySnapshot | year; snapshotId; status: ready/stale; complete; fetchedAt; expiresAt; monthResults[12]; holidays[]; warnings[]
monthResults | month: 1~12; status: success/error; rawCount; pages; fetchedAt. complete일 때 모든 월 success.
CalendarModel | config + 선택된 공휴일 스냅샷 + 수동 항목 + mode + generatedAt + 12개 MonthModel
DayModel | date 또는 null; weekday; dayNumber 또는 null; labels[]; sources[]; displayText; styleToken; excelRow; excelColumn

GET /api/holidays?year=2027
정상 응답은 HTTP 200이며 year, snapshotId, status, complete=true, fetchedAt, expiresAt, monthResults, holidays, warnings를 반환한다. 캐시가 낡았지만 사용 가능한 경우에도 200과 status=stale로 반환하되, 프런트엔드는 사용 승인 전 다운로드를 허용하지 않는다. 부분 결과는 완전 스냅샷 응답과 혼용하지 않는다.
실패 응답: error={code,message,retryable,failedMonths,requestId}. 입력 오류는 400 INVALID_YEAR, 내부 호출 제한은 429 RATE_LIMITED, 제공기관 인증·파싱·불완전 결과는 502 UPSTREAM_ERROR, 응답 시간 초과는 504 UPSTREAM_TIMEOUT, 키 미설정은 503 CONFIGURATION_ERROR를 사용한다. 비밀키·원문 요청 URL·원문 상위 오류는 클라이언트에 반환하지 않는다.
결합 규칙
원본 날짜를 엄격히 검증한 뒤 날짜·이름·출처 기준으로 중복 제거한다. 한 날짜에 서로 다른 이름은 모두 보존한다. 공식 항목과 같은 이름의 수동 항목은 화면에서 중복 표시하지 않되 출처 집합을 유지한다. 정렬은 날짜 오름차순, 공식 우선, 이름 오름차순이다. 수동 모드는 공식 스냅샷이 없음을 명시한 별도의 CalendarModel을 만든다.
7 권장 구조와 보안
구현 기본 구조
동일 출처의 웹 프런트엔드와 백엔드 공휴일 프록시를 권장한다. 브라우저는 설정·수동 항목·미리보기·.xlsx 생성을 담당하고, 백엔드는 인증키 보관·외부 API 호출·검증·캐시만 담당한다. 수동 회사 휴일 및 작성 내용은 서버로 전송하지 않는다.
TypeScript 기반 구현을 권장한다. 화면 라이브러리와 엑셀 생성 라이브러리는 구현 시 공식 배포처, 라이선스, 브라우저 번들 크기, 행 높이·스타일·인쇄·빈 셀 지원을 검증하여 고정한다. 버전과 라이선스는 실제 선택 시 기록한다. 특정 패키지가 모든 인쇄 설정을 지원한다고 미리 가정하지 않는다.
모듈 경계
date-core는 윤년과 월 좌표 계산만, holiday-client는 상태 및 정규화 결과 처리만, calendar-model은 결합과 정렬만 담당한다. preview-renderer와 xlsx-exporter는 같은 CalendarModel을 읽는다. UI에서 날짜를 따로 계산하거나 엑셀 내보내기 때 휴일을 다시 조회하지 않는다.
사용자 계정과 관계형 DB는 필요하지 않다. 최초에는 메모리 캐시와 동일 연도 요청 병합으로 시작할 수 있다. 인스턴스 재시작 또는 다중 인스턴스에서 캐시가 공유되지 않는 점을 문서화한다. 운영 호출량이 커지면 승인된 공유 캐시를 추가하되 계정 기능으로 확대하지 않는다.
비밀키와 입력 안전
KASI_SERVICE_KEY 같은 서버 전용 환경변수 또는 배포 환경의 비밀 저장소를 사용한다. 브라우저 번들, 공개 환경변수 접두어, 소스 저장소, 예제 파일, 오류 응답, 로그, 분석 도구에 키를 남기지 않는다. 전체 요청 URL 로깅을 끄고 HTTP 클라이언트·프록시·오류 추적기의 쿼리 마스킹도 확인한다. 실제 키는 배포 담당자가 별도 안전한 절차로 설정한다.
요청 대상 호스트와 경로를 고정하여 임의 URL 프록시가 되지 않게 한다. XML 외부 엔티티와 DTD를 비활성화하고 응답 크기·항목 수를 제한한다. 화면 문자열은 HTML로 삽입하지 않는다. 수동 휴일명은 엑셀 수식으로 변환하지 않고 명시적인 텍스트 셀로 쓴다. =, +, -, @로 시작하는 이름도 수식 실행 없이 문자로 유지되는지 확인한다.
운영 기본값
클라이언트별 분당 10회 연간 조회 요청을 초기 제한으로 제안한다. 프록시 신뢰 설정과 제공기관 실제 할당량을 배포 시 점검한다. 오류 코드·월·소요 시간·캐시 상태·익명 요청 식별자만 최소 로깅한다. 로그인·분석 추적·사용자 일정의 서버 보관은 기본으로 넣지 않는다.
목표 지원 환경은 출시 시점 Chrome·Edge 최근 2개 주요 버전과 Excel Microsoft 365 데스크톱이다. LibreOffice 및 Excel 웹에서는 구조·편집·기본 표시를 점검하되 인쇄 결과 차이를 기록한다. 파일에는 수식·매크로·외부 참조가 없어야 한다.

9 개발 순서와 참고 자료
권장 개발 순서
1단계: 날짜 계산과 CalendarModel을 순수 함수로 구현하고 4·5·6주 및 윤년 테스트를 먼저 통과시킨다.
2단계: 고정된 휴일 테스트 자료로 엑셀 출력과 실제 빈 작성칸·인쇄 규칙을 검증한다.
3단계: 서버 프록시, XML 정규화, 페이지네이션, 캐시와 오류 상태를 구현한다.
4단계: 설정·수동 휴일·미리보기·다운로드 UI를 연결한다.
5단계: 배포 담당자가 안전하게 키를 설정한 뒤 실제 조회 및 보안·호환성 인수 테스트를 수행한다.
개발 산출물
프런트엔드와 백엔드 소스, 비밀값 없는 환경변수 예제, 설치·실행 안내, API 계약, 테스트 코드, 검수 결과, 2027년 샘플 .xlsx를 제공한다. 배포 안내에는 제공기관 할당량, 캐시 위치, 키 교체 방법, 장애 재시도 및 오류 확인 방법을 포함한다. 산출물 제공과 실제 운영 배포·도메인 구매·계정 생성은 별도 작업이다.
배포 전에 필요한 결정
운영 담당자와 배포 환경, 실제 지원할 엑셀 버전, 제공기관 운영 할당량을 확정해야 한다. 인증키 원문을 문서나 채팅으로 제출할 필요는 없다. 월 세로 배치·날짜 행의 휴일명·인쇄 기본값은 별도 변경 요청이 없다면 본 명세의 제안으로 구현하고 첫 샘플 파일 검수에서 확인한다.

변경 관리
요구사항 변경은 ID와 변경 이유, 데이터 영향, 기존 테스트 수정 내용을 함께 기록한다. 주당 3개 빈 작성칸과 연간 1시트라는 핵심 형식은 사용자 요청 없이 변경하지 않는다. 휴일 자료가 나중에 바뀌면 새 파일을 생성해야 하며 이미 배포된 엑셀은 자동 갱신되지 않는다.
