# DownloadVersionManager · 0.2.0 폴더 감시 명세

도구 ID: DownloadVersionManager · 버전: 0.2.0 · 상태: **무서명 기능 평가 prerelease 준비 완료, MSI 공개 게시 전**

결정일: 2026-10-04 KST · 제품 책임: 개발 담당 · 결정 근거: 사용자의 폴더 감시 전환·입력 규칙 확인·MSI 릴리즈 지시

정책: [추가 도구 개발 기준](../../policies/tools.md), [문서 작성 규칙](../../policies/documentation.md) · 설계: [ADR-0028](../../design/0028-download-version-manager-folder-input.md) · 이전 버전: [0.1.0 원본 명세](specification.md)

## 최우선 원칙

**각 구현 단계에서 과도한 테스트와 확인된 요구 없이 선제적으로 복잡도를 늘리지 않는다.** 확인된 동작과 실제 파일·설치 위험을 판단할 최소 검증만 수행한다. 기존 성공 근거를 재사용하며 실제 FAIL/NOT RUN을 보존한다.

0.1.0은 미완료 평가 버전으로 보존한다. 이번 사용자 지시는 0.2.0의 구현부터 실제 설치·구동 가능한 단일 MSI 릴리즈까지다. 명세 작성만으로 설치·게시 완료를 선언하지 않는다.

## 사용자와 목적

브라우저나 웹 프로그램의 종류와 관계없이 지정 폴더에 들어오는 파일을 감지한다. 확인된 같은 이름 규칙의 신규 파일 자체가 원래 이름을 갖고, 바이트가 다른 이전 내용만 그 폴더의 `_history`에 보관한다. 브라우저 확장이나 스토어 설치는 필요하지 않다.

## 이름·완료·최신의 입력 계약

처음 감시할 폴더를 사용할 때, 파일명·수정 시각·크기와 같은 이름 규칙의 그룹을 보여준다. 수정 시각과 suffix 번호는 참고 정보다. 사용자가 번호 파일을 최신으로 선택하면 전체 그룹의 처리 순서를 보여 주고 `선택대로 정리`를 눌렀을 때만 실행한다. 나머지 번호 파일은 표시된 파일명 순서로 처리하고 선택한 파일을 마지막에 처리한다. 매 단계에서 직전 원래 파일은 내용이 다르면 History, 같으면 삭제한다.

원래 이름의 파일을 선택하거나 `이 그룹 보존`을 누르면 그 그룹 전체를 현재 이름 그대로 보존한다. `남은 그룹 모두 보존`도 가능하다. 창을 닫아 검토를 취소하면 감시를 시작하지 않는다. 미리보기 이후 파일이 바뀌거나 처리 단계가 실패하면 해당 그룹의 남은 파일을 보존하고 멈춘다. 이 확인은 최초 감시 또는 선택 폴더 변경의 경계이며 로그인마다 기존 파일을 자동 정리하지 않는다.

이후에는 같은 폴더의 기존 대상이 있고 파일명의 마지막 ` (n)`이 양의 정수인 새 파일을 대상으로 연결한다. 이 규칙은 사용자가 채택한 이름 관례이며 실제 다운로드 출처나 원래 사이트 파일명을 증명하지 않는다. 원래 이름 자체가 `(1)`인 별개 문서도 이 규칙에 맞으면 처리될 수 있으므로, 이런 파일을 별개로 다루는 폴더에는 감시를 적용하지 않는다.

3초 동안 관찰한 객체·크기·쓰기 시각이 바뀌지 않고 처리 핸들을 확보할 수 있으면 처리한다. 이는 **앱이 다운로드를 완료했다는 증명은 아니다.** 느린 쓰기의 긴 중단이나 완료 후 다시 쓰는 앱까지 보장하지 않는다. 신규 객체는 처리 직전 잠금 핸들에서 관찰값을 다시 대조한다.

브라우저 `endTime`을 사용하지 않는다. 단일 후보가 처리 가능해진 시점의 신규 유입을 최신으로 받아들인다. 같은 원래 대상의 후보가 함께 대기하면 모두 보존하고 해당 감시 세션의 그 대상 자동 처리를 보류한다. 사용자가 파일을 직접 확인한다.

## 범위와 금지 동작

선택 폴더의 바로 아래만 감시한다. `_history`, 내부 `.dvm-…pending`, Office 임시 파일과 알려진 다운로드 임시 확장자는 처리하지 않는다. OS 폴더 변경 알림을 사용하며 반복 전체 스캔·전체 디스크 탐색·재귀 정리를 추가하지 않는다. 최초 이름 그룹 확인은 선택 폴더의 이름·파일 정보만 읽고 실제 비교는 승인된 source/target 두 객체로 제한한다.

직접 덮어쓴 이전 바이트의 사후 복구, 앱 내부 DB·드라이버·서비스·앱별 연동·범용 규칙 엔진·restore UI·클라우드 전송·telemetry·자동 업데이트는 범위 밖이다. Windows 11 x64의 고정 로컬 NTFS를 대상으로 하며 UNC·네트워크·reparse·클라우드 연결·ARM64 지원은 선언하지 않는다.

## 동시 실행과 복구

프로그램은 사용자 세션당 하나이며 동일 대상의 파일 변경에는 기존 mutex를 사용한다. 폴더 입력은 기존 브라우저용 `CompletionOrder` 상태를 읽거나 수정하지 않는다. 기존 경로·잠금·비교·History 충돌 처리와 rollback을 재사용한다.

이전 파일 이동 후 신규 이름 이동이 실패하면 이전 파일 복구를 시도한다. 강제 종료·전원 장애의 자동 재생이나 잔재 일괄 정리는 없다. 이전·신규 객체를 남긴 위치에서 직접 확인한다. 알림 누락이나 후보 한도 초과 시 감시를 중지하고 보존한다.

## 설정과 설치·제거

네이티브 C++ x64, 정적 CRT(`/MT`), Windows API로 제작한다. 제품 버전은 새 빌드의 0.2.0이며 기존 `version.json`의 0.1.0 / protocol 2와 기존 빌드 경로는 역사적 구현으로 보존한다.

`DownloadVersionManager-Watcher-0.2.0-x64.msi` 한 파일을 일반 사용자 LocalAppData·HKCU에 설치한다. 설치 경로와 MSI 제품/upgrade 식별자를 0.1.0과 분리하고 구버전 설치·브라우저 등록·순서 상태를 자동 이행하거나 삭제하지 않는다. 로그인 자동 실행은 기본 선택이며 위자드에서 해제할 수 있다. 프로그램 창을 닫으면 현재 감시는 종료한다.

기본 위치는 하드코딩한 `Downloads`가 아니라 Windows `FOLDERID_Downloads`를 해석한다. OS가 관리하는 리디렉션·환경 변수 포함 위치를 반영한다. 기본 위치 추종을 선택한 경우 앱 시작과 User Shell Folders 변경 알림에서 다시 해석하고 감시 폴더를 전환한다. 새 위치의 첫 이름 그룹 확인도 거친다. 직접 고른 사용자 폴더는 Windows 다운로드 위치 변경과 무관하게 유지한다.

제거는 프로그램과 제품이 소유한 설치 등록·선택한 시작 항목을 대상으로 한다. 감시 폴더 파일·History와 사용자 실행 설정을 보존한다. 코드 서명은 없으며 조직의 도입·상용 승인 여부는 미결정이다.

## 검증·배포 상태

폴더 엔진 8건·OS 알림 watcher 대표 세션 15건·최초 그룹 처리 4건은 PASS다. production 제작·MSI 구조와 문서 strict·공개 링크, 수정 후보의 설치/실행·repair·제거·파일 보존 5건, 화면 높이 수정 후보의 설치/실행·제거·보존 4건도 PASS다. 실제 위자드의 현재 기본 위치·체크·취소를 확인했다. 최종 안내 문구 수정에는 관련 설치 근거를 재사용했다. 표준 MSI 폴더 선택의 경로 표시·설정 전달·취소는 최종 파일에서 별도로 확인했다. 새 MSI late-failure에서 제품 등록 rollback 실패는 남으며 다음 로그인·실행 중 OS 위치 변경과 공개 자산 확인은 NOT RUN이다. [실제 시험 기록](../../../tools/DownloadVersionManager/TEST_RESULTS.md)과 [이번 배포 기록](../../delivery/download-version-manager-watcher-release-20261004.md)에 후보 지문·한계를 구분한다.

0.1.0의 Win11 rollback access denied(5)·재설치 1638·`installerFailureRecovery FAIL`, 단일 배포 FAIL, 브라우저 NOT RUN은 당시 판정으로 보존한다. 다른 MSI 식별자와 간소화된 새 구조만으로 과거 실패가 해결됐다고 판단하지 않는다. 새 설치 구조의 관련 실패 복구를 확인한다. 확장/Store 전용 관문과 과거 전체 시험표는 0.2.0에 복제하지 않는다.
