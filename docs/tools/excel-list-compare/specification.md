사용자는 원격 환경에서 재시작·관리자 작업 없이 현재 가능한 파일을 배포하도록 명시했다. [ADR-0015 제한 평가판 결정](../../../tools/ExcelSmartListCompare/docs/ADR-0015-Limited-evaluation-release.md)에 따라 `limited-evaluation` 프로필과 `LIMITED_EVALUATION` 등급으로 [RC9 prerelease를 공개했다](https://github.com/prozac0401/Workspace/releases/tag/excel-smart-list-compare-v0.2.0-rc.9). 기존 전체 인수는 `NOT_MET`이며 실패·부분 검증·미실행은 그대로다. 서명 없는 EXE·ZIP의 제작·게시 성공을 새 EXE 설치 수명주기나 정식 지원 승인으로 표시하지 않는다.

## 사용자와 목적

Windows 데스크톱 Excel에서 두 목록의 값과 중복 개수를 비교한다. 첫 번째 Selection 전체를 독립 스냅샷으로 담고 두 번째 Selection과 비교하며, 차이·중복·오류가 있으면 별도 결과 통합문서를 만든다. 사용자에게 모드나 방향을 선택하게 하지 않는다.

이번 변경의 목적은 기존 오류를 실제로 재실험하고, 개선 가능한 원인은 수정·재검증한 뒤, 실제 완료를 확인한 환경과 입력 범위를 명세와 배포 안내에 일치시키는 것이다. 아래 기존 수치나 과거 PASS를 이번 최종 파일의 완료 보장으로 사용하지 않는다.

## 범위와 금지 동작

- 읽는 업무 데이터는 사용자가 선택한 가시 셀의 저장된 값과 비교에 필요한 범위·필터·표 메타데이터다. 전체 행·열 선택은 Excel의 사용 범위로 한정한다. 서식으로 사용 범위가 커진 경우 원본을 자동 정리하지 않는다.
- 첫 목록과 작업 상태는 현재 Excel 프로세스 메모리에 둔다. Excel을 완전히 종료하면 사라지며 프로세스 간 공유·자동 저장·외부 서비스 전송 기능은 없다.
- 결과는 새 통합문서로 만들며 사용자가 직접 저장한다. 기존 파일을 자동 저장·닫기·덮어쓰기하지 않는다.
- 병합 셀은 지원하지 않는다. 일반 범위 첫 행을 제목이라고 추측하거나, 한 Selection을 두 목록으로 자동 분리하지 않는다.
- 회사 보안 정책, 전체 매크로 허용, 영구 PowerShell 실행 정책, 타 추가 기능, PERSONAL.XLSB와 전역 단축키를 임의로 바꾸지 않는다.
- 테스트는 합성 자료와 직접 만든 Excel 인스턴스만 사용한다. 소유 PID·시작 시각·창을 확인하고 정상 종료를 우선한다. 사용자 Excel 전체 강제 종료와 업무 문서 자동 저장·종료는 금지한다.

## 데이터 계약

정규화는 저장된 값에 적용한다. 숫자 `123`과 텍스트 `123`·`123.0`·`1.23e2`는 같게 보며 텍스트 `00123`은 보존한다. 셀 서식으로만 표시한 앞자리 0이나 Excel에서 이미 반올림된 긴 숫자는 복구하지 않는다. 메일 도메인은 비교하지 않으며 복수 메일 주소나 `이름 <주소>`를 분해하지 않는다. 날짜·통화의 표시 형식에 별도 의미를 부여하지 않는다.

결과는 비교에 쓴 값, 처음 발견한 원래 값의 예와 셀 주소, 각 목록의 개수와 남은 개수를 표시한다. 출처·선택 범위·담은 시각 및 제외 집계도 기록한다. 모든 발생 위치를 열거한다는 보장은 없다. 오류 셀을 뺀 일치와 원본 전체의 완전 일치를 구분한다.

### 기존 입력 안전 상한

아래 값은 현재 소스와 README의 방어 수치다. **정상 완료가 확인된 최대값도, 그 값까지의 성능·취소 보장도 아니다.** candidate-07은 기존 안전 상한을 유지하며 실제 완료 범위는 다음 표로 한정해 안내한다.

| 대상 | 기존 경고 | 기존 중단 조건 | 해석 |
|---|---|---|---|
| 한 목록의 가시 선택 셀 | 현재 선택과 담은 목록 합계 20,000셀 이상 | 한 목록 100,000셀 초과 | 빈칸·제목 제외 전, 겹침 중복이 사전 계산에 포함될 수 있음 |
| 필터 등으로 나뉜 영역 | 500개 이상 | 5,000개 초과 | 선택 및 가시성 확인에서 영역 수 검사 |
| 가시성 확인 대상 | 200,000셀 이상 | 2,000,000셀 초과 | 숨김 판정 전 보호, 실제 값 항목 수와 다름 |
| 한 셀 문자열 | 없음 | 4,096자 초과 | 잘라서 비교하지 않음 |
| 한 목록 원문 문자열 합계 | 없음 | 5,000,000자 초과 | 잘라서 비교하지 않음 |
| 작업 처리 시간 | 해당 없음 | 체크포인트에서 약 30초 초과 | Excel 내부 호출 동안 즉시 중단을 보장하지 않음 |

읽기 청크 8,192셀은 내부 처리 단위다. 사용자 지원량이나 취소 지연 보장으로 해석하지 않는다. 사용자가 제한을 바꾸는 설정은 제공하지 않는다.

candidate-07에서 20,000셀 경고 아니요·빈 두 번째 목록·병합 셀·4,097자 셀·선택 100,001셀·원문 5,000,001자·가시성 검사 2,000,001셀의 보호 7조건을 실제 대화상자·버튼 응답과 상태 보존으로 확인했다. 별도 읽기 전용 평가는 PASS이며 준비 중 `owner` 필드 접근으로 실패한 원래 조정기 기록도 보존한다. 이 검사는 처리 중 Esc 성공이나 모든 입력 상한 조합을 확인한 것은 아니다.

두 실패에서 실제 시간 초과 안내와 오류 `-2147219401`을 확인했다. 읽기·비교·출력 호출 경과는 각각 31.229초·31.616초이며 대화상자 대기를 포함한다. 원본 해시/Saved·Excel 설정·시험 XLAM 해시 유지와 소유 Excel 정상 종료는 확인했지만 이를 출력 완료로 집계하지 않는다. 100,000셀 입력 허용은 같은 값의 성공 사례도 포함하기 위한 안전 상한이며, 서로 다른 대량값은 범위를 나누어 실행하도록 안내한다.

앞선 RC7은 입력 조건 12가지 중 각 20,000개 고유값까지 완료했지만 각 50,000개 비교는 지연 보호로 중단됐다. [RC7 오류 재실험 기록](../../../tools/ExcelSmartListCompare/docs/RETEST_20260917.md)은 해당 RC7 해시의 결과로 보존하며 RC9 대용량 완료 증거로 사용하지 않는다.

짧은 값의 단일 범위 한 번이 성공해도 긴 값·영역 조각·양쪽 모두 다른 값·대량 결과까지 지원한다고 확대하지 않는다. 범위를 축소할 필요가 있으면 실측 근거와 미지원 입력의 거절 동작을 함께 남긴다. 원본 보존·수식 방지·실패 복구와 설치 소유권 요구는 지원량 축소로 제거하지 않는다.

이번 RC7에서 각 목록 1,000개 × 4,096자, 1,221셀에 원문 합계 정확히 5,000,000자, 지수 `e1000` 형태 텍스트 각 1,000개도 완료했다. 이들은 서로 다른 시험이며 긴 고유값과 20,000셀을 조합해 검증한 것이 아니다. 셀 100,000개 상한 안에서 실패가 실제 발생했으므로 입력 허용 상한을 정상 완료 보장이라고 안내해서는 안 된다.

RC7 실제 입력 시험은 Esc 누름 길이와 작업에 따라 결과가 달랐다. 비교의 즉시 down/up 입력은 취소되지 않고 지연 보호가 실행됐으며, 약 100ms·500ms 누른 비교 입력에서는 취소 안내와 첫 목록 보존을 관찰했다. **첫 목록 바꾸기는 약 500ms 입력에도 취소되지 않고 기존 42개가 100,000개로 교체됐다.** 오래 누르면 안전하게 취소된다고 안내하거나 물리 키보드·모든 입력 길이로 결과를 확대하지 않는다. 설치도 수정 CMD와 RC7 기존 본체 조합의 추가 설치 코드 1 실패가 남았다. 이후 출력 수집 재실행 10개 작업 성공은 해당 실패의 해결을 입증하지 않는다.

수정 전 RC9 candidate-05에서도 100ms 비교 취소는 관찰했지만 바꾸기는 100ms 재실행과 500ms 모두 취소되지 않았다. 첫 시험 호스트 충돌 후 보조 코드를 보강하자 다음 시험·Excel 종료는 정상 완료됐지만 바꾸기 취소 실패가 다시 나왔다. 이 결과는 해당 파일의 역사적 실패로 보존한다.

candidate-07은 현재 작업 중인 Excel 창에 한정해 눌린 Esc를 추가 확인한다. 같은 바꾸기 작업의 키 입력 없는 대조는 100,000개 교체를 완료했고 100ms 요청 두 시험은 더 일찍 반환해 기존 42개 목록·후속 일치를 보존했다. 별도 평가에서 해당 구성의 상태 보존을 대조군을 둔 동작 추론 PASS로 분류했다. 실제 취소 안내·내부 오류 코드·직접 키 수신은 관찰하지 못했으므로 해당 항목을 PASS로 표시하지 않는다. 순간 입력·모든 작업·일정 시간 내 취소·다른 PC나 정책으로 확대하지 않으며 전체 취소 인수는 별도 확인한다.

## UX

목록이 없으면 **첫 번째 목록 담기**, 담은 뒤에는 **두 번째 목록 담아 비교**와 **첫 번째 목록: N개 항목**을 표시한다. 비우기는 메모리의 목록만 지우며 원본 셀을 지우지 않는다. 바꾸기는 현재 Selection으로 새 스냅샷을 만든다. 비교 성공 뒤에는 첫 번째 목록 담기 상태로 돌아간다.

경고는 값을 읽기 전에 표시하며 기본 버튼은 **아니요**다. 거절 시 이전 첫 목록을 유지한다. 실패 안내는 원인과 사용자가 할 일을 알려야 한다. 실제 Esc 취소가 검증되지 않은 버전은 취소 키 입력만으로 중단됐다고 안내하지 않는다. Excel VBA 실행 뒤 기본 실행 취소(Undo) 기록 보존은 보장하지 않는다.

실제 버튼·우클릭·창 전환 검증과 `Application.Run`·메뉴 등록 검사를 별도로 기록한다. 화면 도구가 없으면 실제 화면 인수는 `NEEDS_MANUAL`이며 등록 API 성공으로 대체하지 않는다. 이벤트를 끈 경우 기존 추가 기능 도구 모음의 상태가 늦게 갱신되는 경계는 유지한다.

## 동시 실행과 복구

제품 작업 재진입을 막고 설치·제거에는 제품 전용 잠금을 사용한다. 첫 목록 교체는 값 읽기·상태 표시·마지막 취소 확인 후 확정한다. 확정 전 오류·취소에는 이전 목록을 유지하며 확정 후 상태 복원 실패를 취소 성공으로 표시하지 않는다. 결과 작성 실패에는 이번에 만든 미완성 결과만 정리한다.

작업 중 변경한 Excel 설정은 완료·오류·취소마다 복원한다. 외부에서 변경한 상태표시 문구는 덮지 않는다. 기존 소스는 작업 전 상태 문자열 `FALSE`를 Excel 기본 False 표식으로 처리하므로, 외부 기능이 의도적으로 넣은 같은 문자열의 보존에는 제한이 있다. 이 경계의 변경 여부도 실제 재검증 결과로 결정한다.

설치 실패·업데이트 중단은 제품 소유 기록에 따라 복구하고 알 수 없는 형식·더 최신 설치·외부 변경은 덮어쓰지 않는다. 전원 손실과 임의 중단의 모든 시점이 검증됐다고 주장하지 않는다. 시험 후에는 제품 설치·파일·등록·정책 상태를 시작 전 상태로 복원하고 잔여 항목을 기록한다.

## 설치·업그레이드·제거

설치 경로는 현재 사용자의 `%LOCALAPPDATA%\ExcelSmartListCompare`다. 제품 소유 파일, HKCU Excel 자동 로드 등록과 소유 기록을 관리하며 단일 EXE는 Windows 앱 등록과 제거 관리 파일도 관리한다. 일반 설치는 완성 XLAM을 사용하므로 Python이나 VBA 편집기·프로젝트 가져오기 권한이 필요하지 않다. 빌드용 개발 권한과 일반 설치 요구를 구분한다.

제품 폴더만 신뢰 위치로 관리하고 새 항목은 하위 폴더를 포함하지 않는다. 기존 사용자 설정·타 신뢰 위치·회사 정책은 유지한다. 신뢰 위치가 정책으로 금지되면 중단한다. 현재 실행기는 그룹 정책·AllSigned를 존중하며 그 외에는 자기 `Setup.ps1`만 다운로드 차단 해제하고 자식 프로세스에 한해 RemoteSigned를 적용한다. 영구 정책은 바꾸지 않는다.

열린 Excel이 있으면 설치·제거를 중단한다. 같은 버전은 재설치하고 인식 가능한 이전 버전은 제품 범위에서 업데이트한다. 알 수 없는 기록과 더 최신 버전은 보존하고 중단한다. 제거는 변경되지 않은 자기 파일·등록만 지우고 설치 폴더에 추가한 사용자 파일, 다른 추가 기능과 PERSONAL.XLSB를 보존한다. 제거용 임시 실행 복사본은 사용자 임시 폴더에 남을 수 있으며 업무 내용은 포함하지 않는다.

### 판정 규칙

`PASS`, `FAIL`, `PARTIAL`, `BLOCKED_ENV`, `BLOCKED_POLICY`, `NEEDS_MANUAL`, `NOT_RUN`을 사용한다. 실행하지 않은 항목은 PASS로 바꾸지 않는다. 테스트 도구 부재·정책 차단은 동작 실패의 원인 해결이나 요구 충족을 뜻하지 않는다. 같은 파일 재시도 성공도 앞선 실패를 삭제하지 않는다. 제한 평가판의 배포 결정은 이 개별 판정이나 전체 인수 `NOT_MET`를 변경하지 않는다.

성능 상수 변경과 지원 범위 축소는 실제 관찰에 근거해야 한다. 실제 Esc와 최초 설치의 기존 인수 실패는 재검증 결과나 명시적인 요구 변경 근거 없이 삭제하지 않는다. 반복 시험에서 정상 완료하는 범위가 확인되더라도 데이터 보존·복구·수식 방지·설치 계약이 실패하면 그 범위를 정상 지원으로 선언하지 않는다.
